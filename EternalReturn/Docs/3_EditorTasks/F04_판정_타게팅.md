끝나면 스킬 시스템(F07)이 이 함수들을 믿고 쓸 수 있고, **F01의 미검증 3건도 같이 해결된다** —

- [ ] ⭐ **에디터를 재시작한다.** `Config/DefaultEngine.ini` 에 콜리전 채널을 추가했다.

- [ ] [F01 에디터 작업](F01_코어골격_팀ID.md)이 끝나 있다 (팀 배정이 동작해야 팀 필터를 볼 수 있다)

# ① 에디터 작업

> 애셋·설정을 **실제로 바꾸는** 일.

## 1-1. `SkillTarget` 채널이 생겼는지 확인

- [ ] **Edit > Project Settings > Engine > Collision**
- [ ] **Trace Channels** 목록에 **`SkillTarget`** 이 있다
- [ ] Default Response 가 **`Ignore`** 다

| 항목 | 값 |
|---|---|
| 이름 | `SkillTarget` |
| 종류 | **Trace Channel** (Object Channel 아님) |
| Default Response | **Ignore** |

> ⚠ **여기서 채널을 직접 추가하거나 이름을 바꾸지 않는다.**
> `Config/DefaultEngine.ini` 와 `Source/EternalReturn/ERCollisionChannels.h` 가 짝을 이루고 있다.
> 한쪽만 바뀌면 **조용히 엉뚱한 채널을 긁는다.**
>
> 안 보이면 에디터를 닫고 재빌드 후 다시 연다.

## 1-2. `BP_ERCharacterBase` 의 캡슐 응답 확인

애셋: **`/Game/ERCharacter/Blueprints/BP_ERCharacterBase`**

- [ ] 애셋을 열고 컴포넌트 목록에서 **`CollisionCylinder`** (캡슐) 선택
- [ ] Details 패널 **Collision > Collision Responses** 펼치기
- [ ] **`SkillTarget`** 행이 **`Overlap`** 인지 확인

> C++ 생성자에서 이미 켜뒀으므로 **`Overlap` 이어야 정상이다.** 손댈 필요가 없다.
>
> ⚠ 만약 `Ignore` 로 보이면 **BP 가 옛 값을 덮어쓰고 있는 것**이다.
> 그 경우에만 `Overlap` 으로 바꾸고 Compile → Save 한다.

## 1-3. 테스트용 대상 액터 배치

판정을 확인하려면 **맞을 대상**이 필요하다. 캐릭터를 여러 개 놓는 게 가장 간단하다.

- [ ] 맵 **`/Game/ERCharacter/Maps/TopDownMap`** 을 연다
- [ ] `BP_ERCharacterBase` 를 뷰포트에 **4~5개 배치**한다
- [ ] 배치 간격을 대략 알 수 있게 둔다 — **1m = 100 유닛**

권장 배치 (플레이어 스폰 지점을 원점으로):

| 대상 | 위치 (X, Y) | 확인 용도 |
|---|---|---|
| A | (50, 0) | 0.5m — `RangeMin` 1.0m 에 걸려 **제외**돼야 함 |
| B | (200, 0) | 2m — 정면 |
| C | (400, 0) | 4m — 정면, 관통 확인용 |
| D | (200, 200) | 정면에서 약 45° — 부채꼴 65°(±32.5°) **밖** |
| E | (200, 100) | 정면에서 약 27° — 부채꼴 **안** |

> ⚠ **Z(높이)는 전부 같게 둔다.** 지금 판정은 `bIgnoreZ = true` 라 높이를 무시하지만,
> 나중에 끄고 테스트할 때 기준이 필요하다.

- [ ] 배치 후 맵 **저장**

# ② 테스트

> **임시 콘솔 커맨드로 검증한다.** `Source/EternalReturn/Combat/ERTargetingDebug.cpp` 가
> `ER.Targeting.Test` 를 등록해 둔다. **F07(스킬) 착수 시 이 파일을 삭제한다.**

## 2-0. 커맨드 사용법

PIE 실행 후 콘솔(`~`)에 입력. 인자 없이 치면 사용법이 나온다.

```
ER.Targeting.Test Sphere <반경m> [enemy|ally|all]
ER.Targeting.Test Cone <사거리m> <전체각도> [필터]
ER.Targeting.Test Projectile <사거리m> <관통0|1> [필터]
ER.Targeting.Test Dual <중앙m> <외곽m> [필터]
ER.Targeting.Test Single <사거리m> [필터]
ER.Targeting.Test Alpha <거리> <하한> <상한>
```

**시전자는 콘솔을 친 월드의 로컬 폰**이고, 방향은 그 폰의 정면이다.
결과는 Output Log(`LogEternalReturn`)와 화면에 **5초간** 그려진다.

| 색 | 뜻 |
|---|---|
| 🟡 노랑 | 판정 형상 (반경·부채꼴·직선) |
| 🔴 빨강 | `HitActors` — 맞은 대상 |
| 🟢 초록 | `InnerHitActors` — 이중 반경의 중앙 |

> ⚠ **`RangeMin` 이 항상 1.0m 로 걸려 있다** (Dual 제외). 시셀라 Q 의 하한을
> 매번 같이 확인하려는 의도다. 0.5m 지점 대상은 **모든 테스트에서 제외되는 게 정상**이다.

## 2-1. 판정 7종

PIE: `Play As Client`, `Number of Players: 2`. 배치한 대상들 근처로 이동해서 실행.

- [ ] `ER.Targeting.Test Sphere 5 all` — 반경 5m 안 대상이 **가까운 순**으로 로그에 나온다
- [ ] ⭐ **0.5m 지점 대상(A)이 목록에 없다** — `RangeMin` 1.0m 가 걸렸다
- [ ] `ER.Targeting.Test Single 5 all` — **1개만** 나온다
- [ ] `ER.Targeting.Test Projectile 10 0 all` — 일직선상에 여럿 있어도 **가장 가까운 1명만**
- [ ] `ER.Targeting.Test Projectile 10 1 all` — 직선상 **전부**, 가까운 순
- [ ] `ER.Targeting.Test Cone 5 65 all` — 정면 대상은 맞고 **옆 45° 대상(D)은 안 맞는다**
- [ ] `ER.Targeting.Test Cone 5 360 all` — Sphere 와 **같은 결과**
- [ ] `ER.Targeting.Test Dual 1.25 2.25 all` — 중앙은 🟢, 외곽은 🔴 로 갈린다

## 2-2. ⭐ 이중 반경 중복 검사

- [ ] `ER.Targeting.Test Dual 1.25 2.25 all` 실행
- [ ] ⭐ Output Log 에 **`⚠ 중복 포함!` 에러가 없다**

> 커맨드가 자동으로 검사한다. 한 액터가 Inner 와 Hit 양쪽에 있으면
> `LogEternalReturn: Error` 로 찍는다. 나오면 **레니 W 피해가 두 배로 들어간다는 뜻**이다.

## 2-3. 거리 보간 (카티야 Q)

- [ ] `ER.Targeting.Test Alpha 1 1 5` → **0.0000**
- [ ] `ER.Targeting.Test Alpha 5 1 5` → **1.0000**
- [ ] `ER.Targeting.Test Alpha 3 1 5` → **0.5000**
- [ ] `ER.Targeting.Test Alpha 0 1 5` → **0.0000** (범위 밖 클램프)
- [ ] `ER.Targeting.Test Alpha 3 5 5` → **0.0000** (하한==상한, 0으로 안 나눔)

## 2-4. ⭐ 팀 필터 — F01 미검증 3건이 여기서 풀린다

PIE: `Play As Client`, `Number of Players: 4`, **`Team Size = 2`**.

두 클라 창에서 각각 실행해서 비교한다.

- [ ] `ER.Targeting.Test Sphere 30 all` — 4명 전부 나온다. 각 줄의 `Team N` 확인
- [ ] `ER.Targeting.Test Sphere 30 ally` — **같은 팀만** 나온다
- [ ] `ER.Targeting.Test Sphere 30 enemy` — **다른 팀만** 나온다
- [ ] ⭐ 로그 첫 줄의 `Instigator=...(Team N)` 이 **클라마다 자기 팀을 올바로 읽는다**
- [ ] ⭐ 로그가 `Client` 월드에서 실행됐음을 보여준다 (`/ Client /`)
- [ ] 시전자 본인이 결과 목록에 **없다**

**팀 없는 액터 확인** — 맵에 배치한 `BP_ERCharacterBase` 는 플레이어가 빙의하지 않아
PlayerState 가 없다. 즉 `Team -1`(무소속)이고 **야생동물과 같은 취급**을 받는다.

- [ ] ⭐ `enemy` 필터에 **`Team -1` 액터가 포함된다** — 안 그러면 야생동물을 못 때린다
- [ ] ⭐ `ally` 필터에 **`Team -1` 액터가 없다**

| 결과 | 뜻 |
|---|---|
| `enemy` 에 Team -1 이 나옴 | ✅ `IsHostile` 이 맞게 동작 |
| `enemy` 에 Team -1 이 없음 | ❌ `!IsSameTeam` 으로 짠 것과 같은 증상 → 야생동물을 못 때린다 |
| `ally` 에 Team -1 이 나옴 | ❌ 무소속이 아군으로 잡힌다 |

## 2-5. 채널 응답 누락 감지

- [ ] 아무 판정이나 실행했을 때 대상이 있는데 **0개로 나오면**
      Output Log 에 `맞은 대상 0개. ... SkillTarget 채널 응답이 Overlap 인지 확인할 것` 경고가 뜬다
- [ ] 그 경고가 뜨면 ①-1-2 로 돌아가 캡슐 응답을 확인한다

> ⚠ 이게 커스텀 채널을 고른 대가다. 응답을 빠뜨린 액터는 조용히 안 맞으므로
> **경고 로그가 유일한 단서**다.

## 주의점

- ⚠ **채널 이름·번호를 에디터에서 바꾸지 않는다.** `.ini` 와 `ERCollisionChannels.h` 가 짝이다.
- ⚠ **벽 차폐는 지금 없다.** `SkillTarget` 채널에 벽이 응답하지 않아 **모든 판정이 벽을 통과**한다.
  레이피어 D(벽 통과)는 의도대로지만, 벽에 막혀야 하는 스킬은 F07 에서 별도 트레이스를 붙인다.
- ⚠ 새로 만드는 판정 대상 액터는 **`SkillTarget` 응답을 켜야 한다.** 빠뜨리면 **그 액터만 조용히 안 맞는다** —
  커스텀 채널을 고른 대가다 ([Argument 2](../4_Argument/2_판정콜리전_설계.md) A-5).
- ⚠ 거리 단위는 **m**다. 뷰포트 유닛(uu)과 100배 차이 — 배치할 때 헷갈리기 쉽다.
- ⚠⚠ **`ERTargetingDebug.cpp` 는 임시 파일이다.** F07(스킬)이 `ERTargeting` 의 실제 호출자가 되면
  **통째로 삭제한다.** 다른 파일에 참조가 없어 파일만 지우면 된다.
  `#if !UE_BUILD_SHIPPING` 으로 감싸 두어 배포 빌드에는 안 들어간다.
