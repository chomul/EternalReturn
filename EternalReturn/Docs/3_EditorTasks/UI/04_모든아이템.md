## 목적

이터널 리턴의 **아이템 제작 창 › "모든 아이템" 탭**을 UMG 로 미리 만들어 둔다.
끝나면: `DT_Items` 의 모든 행이 등급 색 프레임이 붙은 칸으로 격자에 뜨고, 왼쪽 분류 · 검색으로 걸러지며, 칸에 마우스를 올리면 툴팁이 뜬다.
**서버와 통신하지 않는 순수 클라 로컬 화면**이다 (§3).

## 선행 조건

- 이 문서의 C++ 할 일(§8)이 끝나고 빌드 · **에디터 재시작** 뒤에 §9 ②~를 한다. (새 `UCLASS`/`UFUNCTION` 이 생긴다)
- C++ 없이도 §9 ① (이미지 조각 · `WBP_ItemSlot` 외형)은 지금 할 수 있다.
- 창을 여는 입력 · HUD 연결은 F17(UI · HUD) 소관이고 **❌ 미구현** — `Docs/1_Task/00_기능목록_및_의존성.md:69` "F17 ⬜ 미작성".

## 3. 네트워크

- **복제 없음 · RPC 없음.** `DT_Items` 는 모든 클라가 같은 표를 갖는 **정의** 데이터다 (`ERItemData.h:18`). 도감은 그것을 읽기만 한다.
- 데디 서버에서 이 위젯은 만들어지지 않는다 (위젯은 로컬 플레이어 전용). C++ 헬퍼는 UMG 를 몰라도 되게 짠다 (§8) — 서버 타겟 빌드에 영향 없음.
- 크레딧 · 구매(초록 `C`)가 붙으면 그때부터 서버 권위 (F15, ❌ 미구현).

## 레이아웃 표

> **측정 방법** — `모든 아이템.png` (1100×819) 를 Python PIL 로 직접 쟀다: 한 줄을 따라 색이 바뀌는 구간(run) 경계 · 밝은 픽셀 bbox · 열/행 투영. 눈대중 값 없음. ±1px 흔들리는 곳은 `(근사)`.
> **좌표계** — **창 내부 좌표**(창 좌상단 = 캡처 (0,0)). 창 셸(제목 · 탭 · 크레딧 · 닫기) · 오른쪽 패널 · 퀵바는 `아이템 제작.png` 와 **같은 좌표로 측정**됐다(±0px) → 원본은 [03 레이아웃 표](03_아이템제작.md#레이아웃-표). 이 문서는 **왼쪽 패널 + 공용 위젯 크기**만 정의한다.
> **배율** — 캡처 1px = 1080p 1px 로 본다 `(근사 · 미확인)`. 근거: 도감 슬롯 66×41 (1440p 캡처였다면 1080p 에서 50×31 — 아이콘이 읽히기 어렵다) · 검색 자리표시 "검색" 한글 높이 14px = UMG 12pt 본문. 03 의 배율 표와 같은 결론.

## 영역별 내부 구조

> §1 의 영역(①–④)마다 **위젯 트리를 잎까지** 적고, 위젯마다 *부모 슬롯 설정* 과 *위젯 자체 설정* 을 적었다. 이 절만 보고 UMG 디자이너에서 위에서 아래로 따라 만들면 된다. 형식은 [02 §2.2c](02_캐릭터선택.md#22c-영역별-내부-구조) 와 같다.
> - 수치는 `모든 아이템.png` 를 PIL 로 **다시 잰 값**이다 (행/열 run · 밝기 bbox · 픽셀 덤프). [레이아웃 표](#레이아웃-표)와 다르면 **실측을 따르고 `⚠ 실측`** 으로 표시했다
> - **색은 픽셀에서 뽑은 sRGB Hex** → 색 선택기의 **`Hex sRGB`** 칸에 넣는다 (`Hex Linear` 아님). 알파를 안 적었으면 1.0
> - 좌표 = **창 내부 좌표** (레이아웃 표와 같다). 이 탭 본문의 원점은 창 (0, 83) — 탭 바(41~82) 바로 아래
> - 표시만 하는 위젯(텍스트 · 장식 이미지)은 Visibility = **`Not Hit-Testable (Self & All Children)`** ([00 §4.7](00_UI_공통원칙.md)). 표에서 `NHT` 로 줄인다
> - **Bind 드롭다운은 어디에도 쓰지 않는다** · Canvas Panel 없음 · Event Tick 없음 ([00 §2.4 · §4.5 · §4.8](00_UI_공통원칙.md))
> - **BindWidget 대상**(나중에 C++ 베이스가 이름으로 잡을 위젯)은 **굵게**. 지금 C++ 베이스가 없으므로 이름만 미리 맞춘다
> - `(추가)` = §4 트리에 없던 위젯을 이 절에서 보탠 것. 기존 이름은 그대로 둔다
> - 텍스처 이름 `T_~` 는 §7 의 가안 이름. 원본 조각 이미지는 아직 없다 **(미확인 — 원본 소스 없음)**

**슬롯 칸 읽는 법** — Overlay/Box 슬롯: `HAlign · VAlign · Padding(L,T,R,B) · Size(Auto/Fill)`. 크기를 박아야 하는 곳은 그 위젯을 **SizeBox** 로 감싸 `Width Override / Height Override` 를 쓴다 (Box 슬롯에는 크기 칸이 없다).

**`RB(W, 색)` 줄임말** — 텍스처 없이 "테두리 + 안쪽 단색" 을 만드는 브러시: Draw As **Rounded Box** · Outline Settings › **Rounding Type = Fixed Radius** · Corner Radii **0,0,0,0** · Width **W** · Color **색** · 브러시 Tint = 안쪽 색.
⚠ Outline 의 기본 Rounding Type 은 `HalfHeightRadius` 다 (`Engine/Source/Runtime/SlateCore/Public/Styling/SlateBrush.h:137-141`) — **Fixed Radius 로 안 바꾸면 알약 모양**이 된다.

## 5. ⭐ 격자 = `TileView` 가상화 + `WBP_ItemSlot` (공용 정의)

### 5.1 왜 TileView 인가 (WrapBox/UniformGridPanel 에 칸을 다 만들지 않는 이유)

| 근거 | 출처 |
|---|---|
| *"A virtualized list that allows up to thousands of items to be displayed."* *"only creates as many entry widgets as can fit on screen. For example, a scrolling ListView of 200 items with 5 currently visible will only have created 5 entry widgets."* | `Engine/Source/Runtime/UMG/Public/Components/ListView.h:18-21` (`UTileView : public UListView`, `TileView.h:15`) |
| 반대로 일반 패널은 *"All children inside a widget are loaded and constructed regardless of whether they are visible."* | [Optimization Guidelines for UMG](https://dev.epicgames.com/documentation/unreal-engine/optimization-guidelines-for-umg-in-unreal-engine) |
| 엔트리 위젯은 풀에서 재사용 — `EntryWidgetPool.GetOrCreateInstance` | `ListViewBase.h:598` · `FUserWidgetPool EntryWidgetPool` `:733` |

→ 수백 개 아이템이어도 **위젯은 보이는 칸 수(5열 × 보이는 행 + 여유)만** 생긴다. 이미지 기준 보이는 격자는 대략 5×10 칸.

### 5.2 아이템 데이터 = UObject (C++ `UERItemListEntryData`)

TileView 는 `UObject*` 목록을 받는다 (`ListView.h:41` `SetListItems`, BP 는 `:281` `BP_SetListItems(TArray<UObject*>)`).

- 탭이 **처음 열릴 때 한 번**, 행마다 `UERItemListEntryData`(필드: `ItemId` FName 하나)를 만들어 `AllEntries` 배열에 보관한다.
- 필터를 바꿀 때는 **새 UObject 를 만들지 않고** `AllEntries` 의 부분집합 배열만 만들어 `SetListItems` 한다.
- 정의 데이터는 UObject 에 복사하지 않는다 — 엔트리가 `ItemId` 로 그때그때 찾는다 (`ERItem::Find` 는 해시 조회 O(1), `ERItemData.h:87`).

### 5.3 필터링할 때 드는 비용

`SetListItems` → `RequestRefresh` (`ListView.h:55`). 엔진 주석:

> *"refreshing ... will only release entries that no longer have items and generate entries for new items (or newly visible items). It does NOT account for changes within existing items"* — `ListViewBase.h:549-556`

| 단계 | 비용 | 판단 |
|---|---|---|
| 필터 계산 (전 행 순회 + 조건 비교 + 검색 부분일치) | O(행 수). 수백 행 문자열 비교 | 키 입력마다 해도 됨 — (미확인) 실측 필요. §10 ② 의 `stat slate` 로 확인 |
| UObject 생성 | 0 (재사용) | |
| 엔트리 위젯 생성 | 보이는 칸이 **늘어날 때만** 풀에서 꺼냄. 이미 있으면 재사용 | 위젯 Construct 는 거의 일어나지 않는다 |
| 엔트리 데이터 갱신 | 보이는 칸마다 `OnListItemObjectSet` 1회 (`IUserObjectListEntry.h:33-37`) | 아이콘 비동기 로드 요청 포함 (§5.4) |

- `RegenerateAllEntries` (`ListViewBase.h:519-525`)는 쓰지 않는다 — 필터 결과가 바뀌는 건 "아이템 목록 변화"이므로 `SetListItems` 로 충분하다.
- 필터 바뀔 때 `ScrollToTop` (`ListViewBase.h:529`).
- ⚠ **TileView 를 Invalidation Box 로 감싸지 않는다.** 스크롤 · 필터는 자식 추가 · 제거라 무효화 중 가장 비싼 종류다 — *"if your UI does it each frame, it can be a substantial performance bottleneck."* ([Invalidation in Slate and UMG](https://dev.epicgames.com/documentation/unreal-engine/invalidation-in-slate-and-umg-for-unreal-engine)). 정적인 도구줄 ① · ② · ③ 만 감싸는 것은 허용 — 같은 문서 *"you should try using Invalidation Boxes first."* (필수 아님. 프로젝트가 Global Invalidation 을 켜면 내부 Invalidation Box 는 비활성화된다 — 같은 문서.)

### 5.4 `WBP_ItemSlot` — 공용 정의 (03 도 이걸 쓴다)

> 위젯별 슬롯 · 브러시 · 색 값은 위 [영역별 내부 구조](#영역별-내부-구조) 의 **④ "엔트리 `WBP_ItemSlot` 내부"** · 툴팁은 같은 절 **"공용 · `WBP_ItemTooltip` 내부"**

**부모 클래스:** `UserWidget` (BP). **Class Settings > Interfaces** 에 `UserObjectListEntry` 추가 — TileView 엔트리가 되려면 필수 (`ListView.h:24-26`, `UCLASS(meta=(EntryInterface="/Script/UMG.UserObjectListEntry"))`).
리스트 밖(03 제작 트리 · 가방)에서는 인터페이스를 쓰지 않고 `SetItem` 을 직접 부른다 — 한 위젯이 두 용도를 다 한다.

```
WBP_ItemSlot   (SizeBox: 고정 크기 — 값은 00 공통원칙 · (미확인) 원작 칸 픽셀)
└ Overlay
  ├ Image  Img_GradeBG        등급 배경 (§7 조각)
  ├ Image  Img_Icon           아이콘 (Scale To Fit)
  ├ Image  Img_GradeFrame     등급 테두리 — 선택 · 호버 강조 겸용 (선택)
  ├ Image  Img_CreditBadge    초록 C — 기본 Collapsed  ❌ 데이터 없음
  └ TextBlock Txt_Count       수량 — 도감에선 Collapsed
```

| 함수 / 이벤트 | 하는 일 |
|---|---|
| `Event On List Item Object Set (Object)` | `Cast To ERItemListEntryData` → 실패 시 Print 아닌 경고 후 리턴 → `SetItem(ItemId, 0)` |
| `SetItem(ItemId : Name, Count : Int)` | C++ `GetItemDisplay(ItemId)` 1회 호출 → 등급 브러시 선택 · `Img_Icon` 에 **`Set Brush from Soft Texture`** · Count ≤ 0 이면 `Txt_Count` Collapsed |
| `On Mouse Enter` | 공유 툴팁에 `ItemId` 전달 (§6) |

- 아이콘은 **`Set Brush from Soft Texture`** (`Image.h:139`) — 비동기 로드. 엔트리가 재사용돼 빨리 다른 아이템으로 바뀌어도 안전하다: 새 요청 전에 이전 스트리밍을 취소하고(`Image.cpp:317` `CancelImageStreaming`), 로드 완료 시 경로가 바뀌었으면 버린다(`Image.cpp:336`). `ERItemData.h:54` 의 "수백 행이 한꺼번에 텍스처를 로드하면 안 된다" 원칙과 맞다.
  - 아이콘이 None 이면(현재 52행) → 대체 이미지 `T_ItemIcon_Missing` 을 넣는다.
- **바인딩(Bind 버튼) 금지** — *"they poll the attribute every frame"*, *"Never use raw attribute binding."* ([Optimization Guidelines for UMG](https://dev.epicgames.com/documentation/unreal-engine/optimization-guidelines-for-umg-in-unreal-engine)). 값은 `SetItem` 에서 한 번 넣는다.
- **Tick 금지** — 엔트리가 Tick 하지 않으면 입력이 없는 동안 Slate 가 잠들 수 있다. *"Slate sleeps whenever ... no user action, and no active timer due to run"* ([Slate UI Sleeping and Active Timers](https://dev.epicgames.com/documentation/unreal-engine/slate-ui-sleeping-and-active-timers-in-unreal-engine)). 단 같은 문서는 실시간 뷰포트가 있는 게임 UI 에는 Active Timer 를 권하지 않는다 — 이 게임은 뒤에서 월드가 계속 그려지므로 **"잠들기 이득"보다 "매 프레임 할 일을 안 만든다"가 목적**이다. 호버 강조는 `On Mouse Enter/Leave` 이벤트로.
- 호버 · 선택 강조는 색 · 브러시만 바꾼다 — Paint 무효화(색 · 머티리얼)는 Layout 무효화(렌더 트랜스폼 · 크기)보다 싸다 ([Invalidation in Slate and UMG](https://dev.epicgames.com/documentation/unreal-engine/invalidation-in-slate-and-umg-for-unreal-engine) "Paint vs Layout"). → 호버 시 **크기 키우기 · 스케일 애니메이션은 쓰지 않는다.**
- Overlay 는 레이어마다 draw call 이 는다 (*"Overlay panels also increment their Layer IDs"*, 같은 Optimization 문서). 레이어를 위 5개 이상 늘리지 않는다.

## 6. ⭐ `WBP_ItemTooltip` — 하나 만들어 공유 (공용 정의)

### 6.1 방식 비교

| 방식 | 생성 비용 | 엔트리 재사용과의 궁합 |
|---|---|---|
| A. 엔트리마다 툴팁 위젯을 자식/변수로 갖기 | 엔트리 수만큼 툴팁 위젯 생성 — 안 보여도 생성됨 (*"loaded and constructed regardless of whether they are visible"*) | 재사용 시 내용 갱신 필요 |
| B. `Get Tool Tip Widget` 바인딩(델리게이트)에서 호버마다 `Create Widget` | 호버마다 생성 → GC 대상 누적 | ⚠ 엔진이 **처음 만든 결과를 캐시**한다 (`UMG/Private/Components/Widget.cpp:73-83` `if (CachedToolTip.IsValid()) return ...`). 엔트리가 다른 아이템으로 재사용돼도 **옛 툴팁이 남을 수 있다** |
| **C. 하나만 만들어 공유** (채택) | **1개** | 호버 시 내용만 바꾼다 |

→ **C 채택.** `WBP_AllItemsTab` 의 `Event Construct` 에서 `WBP_ItemTooltip` 을 1개 만들어 변수로 들고, TileView 의 `On Entry Initialized` 에서 각 `WBP_ItemSlot` 에 `Set Tool Tip (Widget)` (`Widget.h:549`) 으로 그 하나를 지정한다. `On Mouse Enter` 에서 `Tooltip.SetItem(ItemId)` 만 부른다.
- (미확인) 같은 UWidget 을 여러 위젯의 툴팁으로 지정했을 때 Slate 가 문제 없이 돌려 쓰는지 — 한 번에 툴팁은 하나만 뜨므로 될 것으로 보이나 **PIE 로 확인한다** (§10 ② T5). 안 되면 방식 A 로 후퇴 — 엔트리가 수십 개뿐이라(§5.1) 비용은 감당 가능.
- 03 의 제작 트리 칸도 같은 공유 툴팁을 쓴다 — 공유 인스턴스를 누가 소유하는지(탭 위젯 vs 창 셸)는 03 과 맞춘다 (미확인 — 창 셸이 소유하는 쪽이 자연스럽다).

### 6.2 내용 (데이터가 있는 것만)

```
WBP_ItemTooltip
└ Border  (등급 색 테두리)
  └ VerticalBox
    ├ HorizontalBox  [WBP_ItemSlot 작은 것] [Txt_Name] [Txt_Grade]
    ├ TextBlock  Txt_SlotType        "무기 · 저격총" / "머리" / "재료"
    ├ VerticalBox  StatLines          "공격력 +25" 줄 반복 (C++ GetStatLines)
    ├ HorizontalBox  Materials        재료 A + 재료 B (없으면 Collapsed)
    └ TextBlock  Txt_Description     ❌ 데이터 없음 — Collapsed 로 자리만
```

- 스탯 줄은 위젯을 행마다 만들지 않고 **줄 TextBlock 하나에 줄바꿈 텍스트**로 넣는 게 가장 싸다 (스탯 수가 아이템마다 다름 → 자식 추가 · 제거를 피한다, §5.3 Invalidation 근거와 같다).
- 어트리뷰트 → 한글 표시 이름 표는 ❌ 미구현 (미확인 — 프로젝트에 대응표가 있는지 못 찾음. `ERItemDebug.cpp` 는 어트리뷰트 영문 이름을 로그로만 찍는다).
