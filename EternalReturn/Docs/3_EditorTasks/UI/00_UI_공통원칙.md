# UI 공통 원칙 (UMG / Slate)

`01_인게임HUD.md` `02_캐릭터선택.md` `03_아이템제작.md` `04_모든아이템.md` 가 **공통으로 따르는 규칙**이다.
이미지별 문서는 여기 있는 내용을 다시 쓰지 않고 `§번호` 로 링크한다.

**목적:** 끝나면 모든 UI 위젯이 같은 계층·네이밍·데이터 흐름·최적화 규칙으로 만들어져,
서버 권위 값이 바뀔 때만 UI 가 갱신되고(폴링 없음) BP 에는 배치·스타일·애니만 남는다.

**선행 조건**
- ⚠ **현재 `EternalReturn.Build.cs` 에 `UMG` · `Slate` · `SlateCore` 가 없다** (§0). C++ 위젯 베이스를 만들기 전에 추가해야 한다 — `*.Build.cs` 수정은 보고 대상(CLAUDE.md §9)

## 1. 위젯 계층

### 1.1 구조

```
AERPlayerController (로컬 컨트롤러에서만)
 └─ WBP_ER_HUD  (루트 · C++ 부모 UERHUDWidget)      ← 하나만 AddToViewport
     ├─ WBP_ER_StatusPanel   (체력·SP·레벨)
     ├─ WBP_ER_SkillBar      (스킬 슬롯 ×N → WBP_ER_SkillSlot)
     ├─ WBP_ER_Inventory     (가방 → WBP_ER_ItemSlot)
     ├─ WBP_ER_Minimap
     └─ ...
 └─ (전체 화면 창) WBP_ER_CraftWindow / WBP_ER_ItemList 등 — 열 때 생성, 닫으면 제거
```

- **루트 HUD 는 하나.** 레이아웃용 `Canvas Panel` 은 루트에서만 쓴다 — 근거 §4.5
- 생성은 **로컬 컨트롤러에서만**: `AERPlayerController::BeginPlay` 가 이미 `IsLocalController()` 로 가른다 (`Source/EternalReturn/Core/ERPlayerController.cpp:41`). 데디케이티드 서버에는 UI 를 만들지 않는다
- `AHUD` 를 쓸지, 컨트롤러가 직접 만들지는 **(미확인 — 01_인게임HUD 작업에서 결정)**. Lyra 는 `ALyraHUD` + `ULyraHUDLayout` + CommonUI 구조다 (`Samples/Games/Lyra/Source/LyraGame/UI/LyraHUD.h`, `LyraHUDLayout.h`). CommonUI 도입은 별도 결정 사항이다 — 이 문서는 전제하지 않는다

### 1.2 하위 위젯으로 나누는 기준

| 나눈다 | 나누지 않는다 |

| **같은 모양이 2번 이상** 나온다 (슬롯·아이콘·팀원 프레임) | 한 곳에만 나오는 장식 |

| 리스트 행 (ListView/TileView 엔트리) | |

## 2. 데이터 흐름 — UI 는 클라 전용, 이벤트로만 받는다

### 2.1 원칙

1. **UI 는 게임 상태를 바꾸지 않는다.** 입력은 컨트롤러 → `Server` RPC / 어빌리티 발동으로 간다 (CLAUDE.md §6, `Docs/0_GameDesign/Systems/UI_HUD_역기획서.md` §1)
2. **값은 서버 권위로 이미 복제된 것을 읽기만 한다.** UI 를 위해 새 복제를 만들지 않는다 — 필요한 값이 복제 안 되면 그 기능 작업에서 합의
3. **갱신은 이벤트(푸시)로만.** UMG 프로퍼티 바인딩 · Tick 폴링 금지

```
[서버] GE 적용 → 어트리뷰트 변경 → 복제
[클라] ASC AttributeValueChangeDelegate ─┐
       OnRep_XXX → C++ 델리게이트 ────────┼─→ UER~Widget::OnXChanged() → 텍스트/프로그레스 갱신
       GameplayTag 이벤트 (쿨다운·CC) ────┘
```

### 2.2 이벤트 소스 대응표

| 바뀌는 것 | 구독할 것 | 비고 |
|---|---|---|
| GAS 어트리뷰트 | `UAbilitySystemComponent::GetGameplayAttributeValueChangeDelegate(Attr)` | 어트리뷰트 단위 구독 (`ERAttributeSet.h:120`) |
| 쿨다운 · CC 상태 | `UAbilitySystemComponent::RegisterGameplayTagEvent(Tag)` | 태그는 `ERGameplayTags.h` 에서 (CLAUDE.md §8) |
| 복제 변수 (`ReplicatedUsing`) | `OnRep_XXX` 안에서 **C++ 델리게이트 Broadcast** | UI 가 OnRep 를 직접 오버라이드하지 않는다 |
| 인벤토리 | `UERInventoryComponent` 의 델리게이트 | 가방은 아직 없음 (§0) |

### 2.3 구독 시점과 해제

- 플레이어 ASC 는 **PlayerState** 에 있다 (CLAUDE.md §8). 클라에서 ASC 가 준비되는 시점은 `AERCharacterBase::OnRep_PlayerState` 이후 (`ERAttributeSet.h:123-124`, `Source/EternalReturn/Character/ERCharacterBase.h:67`)
  → 위젯 `NativeConstruct` 시점에 ASC 가 없을 수 있다. **"준비되면 알려주는" 경로가 필요하다 (미확인 — 01_인게임HUD 에서 정한다)**
- **구독 직후 현재 값으로 한 번 초기화한다.** 이벤트는 "바뀔 때"만 오므로, 이미 복제된 값은 이벤트 없이 놓친다
- `NativeDestruct` 에서 반드시 해제 (`RemoveAll(this)` — `ERAttributeSet.h:127-129`)
- ⚠ **OnRep 는 서버에서 호출되지 않는다.** PIE 에서 `Play As Listen Server` 로 호스트 화면을 보면 OnRep 기반 UI 가 안 바뀐다. UI 테스트는 **`Play As Client`** 로 한다 (데디케이티드 서버 구성과 같다)

### 2.4 UMG 프로퍼티 바인딩 금지 — 근거

- *"Never use raw attribute binding."* 바인딩은 매 프레임 폴링한다. 이벤트로 밀어주면 *"ensures that the UI only changes on the frame when the value changes."*
  ([Optimization Guidelines for UMG](https://dev.epicgames.com/documentation/unreal-engine/optimization-guidelines-for-umg-in-unreal-engine) "Ticking and Programming")
- *"Whenever possible, you should avoid using On Tick or On Paint to run logic in your UI."* — 같은 문서
- 이 프로젝트: 3인 × 8팀 = 24명. 체력바를 바인딩하면 매 프레임 전부 돈다 (`ERAttributeSet.h:130-132`)
- 바인딩이 있는 위젯은 Invalidation 캐시도 깰 수 있다 **(미확인 — Epic Invalidation 문서는 바인딩을 언급하지 않는다)**

## 3. C++ / BP 경계

CLAUDE.md §7 그대로: **로직·데이터 연결은 C++, BP 는 배치·스타일·애니.**

| C++ 베이스 (`UER~Widget`) | WBP |
|---|---|
| 델리게이트 구독·해제, 값 → 표시 변환(포맷·퍼센트) | 위젯 트리 배치, 앵커·패딩 |
| 하위 위젯 참조: `UPROPERTY(meta=(BindWidget))` | 브러시·폰트·색 지정 |
| 리스트에 데이터 넣기 (`SetListItems`) | 위젯 애니메이션 (`Anim_~`) |
| 입력 → 컨트롤러/어빌리티 호출 | `BlueprintImplementableEvent` **연출 훅**만 받아 애니 재생 |

- `BindWidget`: 이름이 같은 위젯이 WBP 에 없으면 컴파일 에러. 없어도 되는 것만 `BindWidgetOptional` (`Engine/Source/Editor/UMGEditor/Private/WidgetBlueprintEditorUtils.cpp:2108-2109`)
- 위젯 애니를 C++ 에서 재생해야 하면 `meta=(BindWidgetAnim)` + `Transient` **(미확인 — 엔진 소스 미대조)**
- BP 그래프에 로직(분기·계산)을 두지 않는다. Event Graph 에 남는 건 연출 훅 → `Play Animation` 정도
- `BlueprintReadWrite` 금지, BP 노출 `UFUNCTION` 은 근거 한 줄 (CLAUDE.md §7)

## 4. 최적화

출처 약어 — **[OPT]** [Optimization Guidelines for UMG](https://dev.epicgames.com/documentation/unreal-engine/optimization-guidelines-for-umg-in-unreal-engine) ·
**[INV]** [Invalidation in Slate and UMG](https://dev.epicgames.com/documentation/unreal-engine/invalidation-in-slate-and-umg-for-unreal-engine) ·
**[SLP]** [Slate UI Sleeping and Active Timers](https://dev.epicgames.com/documentation/unreal-engine/slate-ui-sleeping-and-active-timers-in-unreal-engine)

⚠ 세 문서는 2026-10-12 에 최신판으로 읽었다(SLP 는 5.8 표기). **5.4 판과 차이가 있는지는 (미확인).** 엔진 코드로 확인한 항목은 `파일:라인` 을 따로 달았다.

### 4.1 Invalidation Box / Global Invalidation

- *"Invalidation is a system that reduces the CPU usage of UI by limiting how often it repaints widgets."* — 바뀐 위젯과 자식만 다시 그리고 나머지는 캐시 [INV]
- *"Invalidation Box widgets cache their child widgets' geometry, then monitor those widgets for changes."* [INV]
- *"Global Invalidation ... effectively wrapping your entire UI in an Invalidation Box."* `Slate.EnableGlobalInvalidation=true` 로 켠다. 켜면 창 안의 Invalidation Box 는 비활성화된다 [INV]
  - 5.4 기본값은 **꺼짐**: `bool GSlateEnableGlobalInvalidation = false;` (`Engine/Source/Runtime/SlateCore/Private/SlateCoreClasses.cpp:46`). 프로젝트 `Config/*.ini` 에도 설정 없음 (grep)
- **이 프로젝트 방침:** 우선 **HUD 의 잘 안 바뀌는 덩어리를 Invalidation Box 로 감싼다** (스킬바 틀, 인벤토리 틀, 팀원 프레임). Global Invalidation 은 켜지 않는다 — 켤지는 프로파일 후 결정 **(미확인 — 측정 전)**

| 무효화 종류 | 비용 [INV] | 예 |
|---|---|---|
| Volatile/Visibility | 매우 낮음 | Is Volatile·Visibility 변경 |
| Paint | 낮음 | 색·머티리얼 변경 |
| Layout | 중간 | 크기·위치, 렌더 트랜스폼 변경 |
| Child | 높음 | 자식 추가·삭제 — *"If your UI does it each frame, it can be a substantial performance bottleneck"* |

→ **매 프레임 자식을 추가·삭제하지 않는다.** 슬롯은 미리 만들어 두고 내용만 바꾼다. 리스트는 §4.6

### 4.2 Volatile 지정 기준

*"When a widget is marked as Volatile, the Invalidation system does not cache its Paint data or its childrens' Paint data."* Details 패널 **Performance > Is Volatile** [INV]

| Volatile 로 | Volatile 아님 |
|---|---|
| **매 프레임** 바뀌는 것: 미니맵 아이콘 위치, 쿨다운 진행 중 숫자·게이지, 시전 바 | 이벤트 때만 바뀌는 것: 체력바(피격 시), 레벨, 인벤토리 슬롯 |
| 레이아웃을 바꾸는 애니가 도는 위젯 [OPT "Animation"] | |

⚠ Volatile 은 **가장 작은 단위에만.** 상위 패널을 Volatile 로 하면 그 아래 전체가 캐시를 잃는다.

### 4.3 Retainer Box

- *"Retainer Panels flatten their child widgets into a single texture before painting them."* 프레임 단위로 렌더를 줄일 수 있다 [OPT][INV]
- 단점: 각자 렌더 타깃을 가져 메모리가 더 들고 다시 그릴 때 *"a high overhead"* [INV]
- *"you should try using Invalidation Boxes first."* [INV]
- **이 프로젝트 방침:** 기본 사용 금지. 쓰는 경우는 ① 위젯 전체에 머티리얼 효과(블러·디졸브)가 필요하거나 ② 미니맵처럼 갱신률을 낮춰도 되는 복잡한 덩어리. 쓸 때는 이미지별 문서에 이유를 적는다

### 4.4 시간으로 변하는 것 (쿨다운·버프 남은 시간)

- ⚠ **Active Timer 는 게임 HUD 용이 아니다.** [SLP]: Active Timer 는 *에디터 UI* 를 위한 것이고 실시간 뷰포트가 있는 게임 UI 용이 아니라고 적고 있다. Sleeping 은 "입력도 없고 Active Timer 도 없을 때" Slate 가 틱을 건너뛰는 것이고, Active Timer 는 하나라도 돌면 Slate 전체가 틱한다(*all-or-nothing*)
  → 게임 중에는 뷰포트가 매 프레임 그려지므로 Sleeping 이득을 기대하지 않는다. `SWidget::RegisterActiveTimer` 는 **커스텀 Slate 위젯을 직접 만들 때만** 고려한다
- **이 프로젝트 방침:**
  1. 시작·끝은 **이벤트**로 안다 — 쿨다운 GE 의 태그 `RegisterGameplayTagEvent` (§2.2). 남은 시간은 쿨다운 GE 의 시작 시각·지속시간으로 계산 (서버가 다시 보내지 않는다)
  2. **진행 중일 때만** 갱신한다. 숫자는 `FTimerManager` 주기 타이머(예: 0.1초)로, 끝나면 타이머 해제 (CLAUDE.md §2 "주기적 처리는 FTimerManager")
  3. 원형 게이지는 **머티리얼 파라미터**로 그린다 — *"Material-only animations incur no CPU cost as these are handled by the GPU."* [OPT]. 다만 UI 머티리얼의 `Time` 과 월드 시간을 맞추는 방법은 **(미확인)** — 맞추지 못하면 2번 타이머에서 스칼라 파라미터를 넣는다
  4. 진행 중인 게이지·숫자는 Volatile (§4.2)

### 4.5 레이아웃·위젯 선택

| 규칙 | 근거 |
|---|---|
| `Canvas Panel` 은 **루트 HUD / 창 루트에만.** 개별 위젯 안 레이아웃은 Overlay · Horizontal/Vertical/Grid Box | Canvas 는 자식 Layer ID 를 올려 드로콜이 는다. *"you should avoid using them to lay out individual custom widgets"* [OPT] |
| 고정 크기 빈칸은 `Spacer` (Size Box 아님) | *"Size Boxes use multiple passes to calculate their size"* [OPT] |
| `Scale Box` + `Size Box` 조합 금지 | 매 프레임 크기가 뒤집히는 루프가 생길 수 있다 [OPT] |
| `Rich Text` 는 꼭 필요할 때만 (아이템 툴팁 키워드 강조 등). 단순 텍스트는 `Text` + 스타일 폰트 | *"very expensive compared with standard text boxes"* [OPT] |
| 짧고 자주 나오는 연출(피격 깜빡임)은 머티리얼 > BP 트윈 > Sequencer 순으로 고른다 | Sequencer 는 CPU 비용 높음, 렌더 트랜스폼 변경은 Layout 무효화 [OPT] |
| 레이아웃을 바꾸는 애니(크기 변경)는 피한다. 써야 하면 Volatile | [OPT] "Animation" |

### 4.6 리스트는 ListView / TileView (가상화)

- 아이템 수가 가변이고 스크롤되는 목록(`04_모든아이템`, 제작 재료 목록)은 **`ListView` / `TileView`** 를 쓴다. `ScrollBox` 에 위젯을 Add 하지 않는다
- 엔트리 위젯은 `IUserObjectListEntry` 를 구현하고 `NativeOnListItemObjectSet` 에서 데이터를 받는다 (`Engine/Source/Runtime/UMG/Public/Blueprint/IUserObjectListEntry.h:33`). 데이터는 `UER~ListItem` UObject
- 근거: Epic 3문서에는 ListView 가상화 언급이 **없다.** 보이는 줄만 엔트리 위젯을 만들고 재사용한다는 동작은 **(미확인 — 엔진 `SListView` 소스 미대조)**. 가방처럼 칸 수가 고정이면 미리 만든 슬롯으로 충분하다
- 엔트리는 재사용되므로 **`NativeOnListItemObjectSet` 에서 이전 구독을 해제하고 새로 구독**한다

### 4.7 Visibility

엔진 주석 (`Engine/Source/Runtime/UMG/Public/Components/SlateWrapperTypes.h:20-33`):

| 값 | 의미 | 쓸 때 |
|---|---|---|
| `Collapsed` | 안 보임 + **레이아웃 공간 없음** | 오래 숨기는 것 (닫힌 창, 비어 있는 버프 칸) |
| `Hidden` | 안 보임 + **공간 차지** | 자주 껐다 켜는데 주변이 밀리면 안 될 때 |
| `HitTestInvisible` | 보임, 자신·자식 클릭 불가 | 순수 표시용 (체력바·데미지 텍스트) |
| `SelfHitTestInvisible` | 보임, 자신만 클릭 불가 | 자식 버튼이 있는 패널 |

- 클릭할 일 없는 위젯은 **기본이 `Visible`(히트 테스트 함)이므로 `HitTestInvisible` 로 바꾼다.** 성능 이득 크기는 **(미확인 — 측정 전)**
- `Collapsed` 와 `Hidden` 중 어느 쪽이 Prepass 비용이 더 싼지는 Epic 3문서에 없다 **(미확인)**
- ⚠ 숨겨도 **생성·로드 비용은 이미 냈다** (§1.2 인용). 거의 안 여는 창은 숨기지 말고 열 때 생성

### 4.8 Tick 끄기

- `UUserWidget::UpdateCanTick` (`Engine/Source/Runtime/UMG/Private/UserWidget.cpp:2029-2054`): `TickFrequency == Auto` 일 때 **C++ 부모가 있는 WBP 는 `ClassRequiresNativeTick()` 으로 틱이 켜질 수 있다**. BP Tick 구현·래턴트 액션·재생 중 애니가 있어도 켜진다
- 엔진 주석: *"To disable native ticking use add the class metadata flag "DisableNativeTick""* (`UserWidget.h:116`)
- **이 프로젝트 방침:** 모든 `UER~Widget` 베이스는 `UCLASS(meta=(DisableNativeTick))` 를 기본으로 하고 `NativeTick` 을 오버라이드하지 않는다. 매 프레임이 정말 필요한 위젯(미니맵)만 예외로 이유를 적는다
- WBP 에서 `Event Tick` 노드를 쓰지 않는다 (C++/BP 경계 §3 과도 맞다)

### 4.9 오버드로 · 머티리얼

- 반투명 이미지를 겹겹이 쌓지 않는다 — 배경 패널 하나 + 내용. 프레임·테두리는 9-slice 한 장 (§5)
- UI 머티리얼은 **Material Domain = User Interface**. 쿨다운 원형·체력 감소 잔상처럼 값 하나로 그리는 것은 머티리얼 파라미터로 처리 (§4.4)
- 오버드로의 정량 기준은 Epic 3문서에 없다 **(미확인)** — 이미지별 문서에서 숫자 기준을 만들지 않는다

## 5. 이미지 애셋 임포트 규칙 (에디터 작업)

### ① 에디터 작업 — 텍스처 1장마다

- [ ] 저장 위치 `/Game/UI/Textures/<화면>/T_UI_<이름>` **(폴더 미확인 — §1.3)**
- [ ] 텍스처 Details > **Level Of Detail > Texture Group** = `UI`
  - 엔진 기본 LOD 그룹이 `TEXTUREGROUP_UI` 를 **`MipGenSettings=TMGS_NoMipmaps`** 로 둔다 (`Engine/Config/BaseDeviceProfiles.ini:164`) → 그룹만 바꾸면 Mip 이 안 생긴다
- [ ] **Level Of Detail > Mip Gen Settings** = `NoMipmaps` (그룹 기본값과 같지만 명시)
- [ ] **Compression > Compression Settings** = `UserInterface2D (RGBA)` (`TC_EditorIcon` 의 표시 이름 — `Engine/Source/Runtime/Engine/Classes/Engine/TextureDefines.h:388`)
- [ ] **sRGB** 체크 유지 (색 이미지). 마스크·그레이스케일 데이터로 머티리얼에서 쓰는 텍스처만 끈다 **(미확인 — 원본 이미지 확인 후 이미지별 문서에서 결정)**
- [ ] 크기: 2의 거듭제곱 강제는 하지 않는다 — Mip 이 없으면 NPOT 도 쓸 수 있다 **(미확인 — 플랫폼별 제약 미대조)**
- [ ] 아이콘 여러 장을 하나로 합친 아틀라스 사용 여부 **(미확인 — 드로콜 측정 후 결정)**

### ① 에디터 작업 — 9-slice (프레임·버튼·패널 배경)

- [ ] `Image` / `Button` 스타일의 Brush > **Draw As** = `Box`
- [ ] **Margin** = 모서리 두께 ÷ 텍스처 크기 (0~1 비율). 예: 64px 텍스처, 모서리 16px → `0.25`
- [ ] 모서리가 늘어나면 안 되는 테두리만 `Border` (Draw As = Border, 가운데 비움)
- [ ] 원본 이미지가 이미 화면 크기로 늘어난 상태면 9-slice 로 못 쓴다 → 모서리만 잘라 다시 만들어야 한다 (이미지별 문서에 표시)

### ① 에디터 작업 — 위젯 BP 공통

- [ ] WBP 부모 클래스 = 대응 `UER~Widget` (File > Reparent Blueprint)
- [ ] `BindWidget` 이름과 WBP 위젯 이름 일치 (다르면 WBP 컴파일 에러)
- [ ] 표시 전용 위젯 Visibility = `Not Hit-Testable (Self & All Children)` (§4.7)
- [ ] Event Graph 에 Tick · 프로퍼티 바인딩(`Bind` 드롭다운) 없음 (§2.4, §4.8)

### ② 테스트 — 모든 UI 문서 공통

- [ ] `Play As Client`, Number of Players: 2 이상 (§2.3 — Listen Server 호스트는 OnRep 이 안 온다)
- [ ] 콘솔 `stat slate` — 값이 안 바뀌는 동안 UI 시간이 튀지 않으면 성공 **(미확인 — 기준 수치 없음, 첫 HUD 에서 기준선을 측정해 기록)**
- [ ] Widget Reflector (`Tools > Debug > Widget Reflector`) 로 Invalidation Box 가 캐시 중인지 확인 **(미확인 — Epic 3문서에 절차 없음)**
- [ ] 서버에서 값 변경(`GE` 적용) → 클라 UI 가 **그 프레임에만** 바뀌는지

| 증상 | 고칠 곳 |
|---|---|
| 클라에서 값이 처음에 0/빈칸 | §2.3 구독 직후 초기화 누락 |
| 호스트 화면만 안 바뀜 | Listen Server 로 테스트함 — `Play As Client` 로 |
| 위젯 닫은 뒤 크래시 / 로그에 dangling | `NativeDestruct` 구독 해제 누락 |
| 리스트 스크롤 시 엉뚱한 값 | §4.6 엔트리 재사용 시 이전 구독 미해제 |
| WBP 컴파일 에러 "required widget binding" | `BindWidget` 이름 불일치 |

## 6. 주의점

- **UI 때문에 서버 코드를 바꾸지 않는다.** 필요한 값이 복제되지 않으면 해당 기능 작업에서 CLAUDE.md §1.1 합의부터
- 남의 가방·쿨다운 같은 **소유자 전용 정보를 남의 UI 에 띄우지 않는다** — 가방은 `COND_OwnerOnly` 라 애초에 없다 (`ERInventoryComponent.h:200`)
- 이미지별 문서가 이 문서와 다른 선택을 하면(예: Retainer 사용, Tick 사용) **그 문서에 이유를 적는다**

## 7. 못 하는 검증

- 성능 수치(`stat slate`, 드로콜) 기준선 — UI 위젯이 하나도 없어서 측정 불가. **첫 HUD(`01_인게임HUD.md`) 가 붙은 뒤** 측정해 이 문서 §4 에 기록
- Epic 문서 최신판과 5.4.4 동작 차이 — 해당 기능을 쓸 때 엔진 소스로 대조

## 8. 끝나면

공통 규칙 문서이므로 체크리스트 항목을 직접 채우지 않는다. 각 이미지별 문서가 자기 기능의 `Docs/2_Checklist/` 항목을 채운다.
