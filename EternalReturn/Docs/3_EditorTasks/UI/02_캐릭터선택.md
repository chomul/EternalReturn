## 목적

코드 작업과 별도로 **선택 화면의 위젯 껍데기(레이아웃 · 카드 · 팀 슬롯)를 먼저 만들어 두는 것**이 목적이다.
끝나면 `WBP_CharacterSelect` 를 화면에 띄웠을 때 레퍼런스와 같은 배치가 나오고, 더미 데이터로 카드가 그리드에 채워진다.

### 2.2b 레이아웃 표 (1920×1080 기준)

> 레퍼런스 PNG 를 PIL 로 **픽셀 측정**한 값이다 (밝기 경계 · 색 마스크 · 열/행 평균). §1 표의 "대략값"보다 이 표가 우선이다.
> - 원본 해상도는 **1919×1079** (1920×1080 보다 가로·세로 1px 작음 — 창 모드 캡처로 추정). 배율 1.0005 라 **1:1 로 그대로 썼다**. 오른쪽·아래 기준 Offset 은 **±1px 오차**가 있다
> - 종횡비 16:9 동일 → 보정 없음. UMG 기본 DPI 커브는 짧은 변 1080 에서 배율 1.0 이므로 이 숫자가 곧 디자이너 값이다
> - 글자 크기(pt)는 글리프 높이에서 역산한 **추정**이다. 환산식: Slate 폰트 1pt = 96/72 px · 한글 글리프 ≈ 0.9em · 영문 대문자/숫자 ≈ 0.7em → **한글 pt ≈ 높이px × 0.83 · 영문/숫자 pt ≈ 높이px × 1.07**. 폰트가 바뀌면 다시 맞춘다

**앵커 · Offset 부호 규칙** — Position 은 *앵커 점 → 위젯의 Alignment 점* 까지의 거리이고 **+X = 오른쪽 · +Y = 아래**다. 그래서 오른쪽/아래 앵커(Maximum = 1)에 붙인 위젯은 Position 이 **음수**가 된다. 앵커가 한 축으로 늘어나면(Min≠Max) 그 축의 칸 이름이 Position/Size → **Left·Right / Top·Bottom 여백**(양수 = 안쪽으로)으로 바뀐다.

### 2.2c 영역별 내부 구조

> §1 의 영역(A–N)마다 **위젯 트리를 잎까지** 적고, 위젯마다 *부모 슬롯 설정* 과 *위젯 자체 설정* 을 적었다. 이 절만 보고 UMG 디자이너에서 위에서 아래로 따라 만들면 된다.
> - 수치는 레퍼런스 PNG 를 PIL 로 다시 잰 값이다 (밝기/색 마스크 bbox · 행/열 픽셀 덤프). §2.2b 와 다르면 **실측을 따르고 `⚠ 실측` 으로 표시**했다
> - **색은 픽셀에서 뽑은 sRGB Hex** 다 → 색 선택기의 **`Hex sRGB`** 칸에 넣는다 (`Hex Linear` 칸 아님). 알파는 따로 적지 않았으면 1.0
> - 글자 크기는 §2.2b 의 환산식(한글 pt ≈ 높이px × 0.83 · 영문/숫자 pt ≈ 높이px × 1.07)으로 낸 **추정**이다. 폰트는 공통원칙 기본 폰트
> - 텍스처 이름 `T_UI_CS_~` 는 **가안** (공통원칙 §1.3 `T_UI_~` 규칙 + 화면 약자 CS). 원본 조각 이미지는 아직 없다 — 레퍼런스를 잘라 임시로 쓰거나 새로 그린다 **(미확인 — 원본 소스 없음)**
> - 표시만 하는 위젯(텍스트 · 장식 이미지)은 공통원칙 §4.7 대로 Visibility = **`Not Hit-Testable (Self & All Children)`**. 아래 표에서 `NHT` 로 줄여 쓴다
> - **Bind 드롭다운은 어디에도 쓰지 않는다** (§3-③) · 이 절에서 새로 생긴 위젯도 Canvas 가 아니다 (§3-①)
> - **BindWidget 대상**(C++ 베이스가 이름으로 잡을 위젯 — §7 C-5)은 **굵게** 표시했다. 지금 C++ 베이스가 없으므로 *이름만 미리 맞춰 둔다*
> - `(추가)` = §2.2 트리에 없던 위젯을 이 절에서 보탠 것 (기존 이름은 그대로 둠)

**슬롯 칸 읽는 법** — Overlay/Box 슬롯: `HAlign · VAlign · Padding(L,T,R,B) · Size(Auto/Fill)`. 크기를 박아야 하는 곳은 그 위젯을 **SizeBox** 로 감싸 `Width Override / Height Override` 를 쓴다 (Box 슬롯에는 Size 칸이 없다).

### 2.3 그리드: TileView (가상화) 를 쓴다

| 판단 축 | 내용 |
|---|---|
| 지금 개수 | 실험체 **6명** (`Docs/3_EditorTasks/Data/DT_Character.csv` 데이터 행 6개: Katja · Magnus · Jackie · Daniel · Sissela · Leni) + Random 1칸 = 7칸. 이 숫자만 보면 `UniformGridPanel`/`WrapBox` 로 충분하다 |
| 그래도 TileView 인 이유 ① | 이미지에 **필터 · 정렬 · 검색**이 있다. 패널 방식은 필터가 바뀔 때마다 자식을 지우고 다시 넣는데, 자식 추가/삭제는 무효화 비용이 **가장 큰 등급(Child Invalidation · high)** 이다 — *"If you add or remove a child from the widget's children, it will trigger Child Invalidation"* ([Invalidation in Slate and UMG](https://dev.epicgames.com/documentation/unreal-engine/invalidation-in-slate-and-umg-for-unreal-engine)). TileView 는 `SetListItems` 로 항목 배열만 바꾸고 엔트리 위젯은 재사용한다 (`Engine/Source/Runtime/UMG/Public/Components/ListView.h:41`) |
| 그래도 TileView 인 이유 ② | 이미지에 **스크롤바**가 있다 (그리드가 화면보다 크다는 뜻). 원작 실험체 수만큼 늘면 보이는 칸만 위젯을 만드는 가상화가 필요하다. *"All children inside a widget are loaded and constructed regardless of whether they are visible."* ([Optimization Guidelines for UMG](https://dev.epicgames.com/documentation/unreal-engine/optimization-guidelines-for-umg-in-unreal-engine)) |
| 비용 | 항목이 **UObject** 여야 한다 → 카드 데이터용 작은 UObject(`UERCharacterListItem`: 캐릭터 데이터 참조 + Random 여부) 필요. 엔트리는 **재사용되므로** 상태를 반드시 `NativeOnListItemObjectSet` (`IUserObjectListEntry.h:33`) 에서 항목 값으로 전부 다시 칠한다 — 이전 카드의 "선택됨" 표시가 남는 실수가 흔하다 |
| 근거 문서 한계 | 위 Epic 3개 문서는 ListView/TileView 가상화 자체를 다루지 않는다. 가상화 동작은 엔진 코드(`ListViewBase.h`) 기준이다 |

**Random 카드**: 별도 위젯이 아니라 **목록 첫 항목**(캐릭터 참조 없음 + `bRandom=true`)으로 넣는다. 필터·검색과 무관하게 항상 첫 칸에 남길지 **(미확인)** — 이미지는 필터 없는 상태뿐이다.

## 3. 성능 결정 (Epic 문서 근거)

| # | 결정 | 근거 |

| ⑤ | 경고 띠 깜빡임 · 배경 흐름 같은 **반복 연출은 머티리얼 애니메이션**. UMG Sequencer 루프 애니로 만들지 않는다 | *"Material-only animations incur no CPU cost as these are handled by the GPU."* — [Optimization Guidelines](https://dev.epicgames.com/documentation/unreal-engine/optimization-guidelines-for-umg-in-unreal-engine). | ⑥ | Slate **Sleep 에 기대지 않는다.** 이 화면은 게임 뷰포트 위에 뜬다 | Sleep 은 *"should be utilized when working on editor UI, but not when working on UI for a game"* — [Slate Sleeping and Active Timers](https://dev.epicgames.com/documentation/unreal-engine/slate-ui-sleeping-and-active-timers-in-unreal-engine) |
| ⑦ | 카드 호버/선택 강조는 **색 · 가시성 변경만.** 크기 키우기(Render Transform Scale) 애니를 카드 전부에 걸지 않는다 | 색 = Paint(low), Render Transform 변경 = Layout(moderate) — [Invalidation](https://dev.epicgames.com/documentation/unreal-engine/invalidation-in-slate-and-umg-for-unreal-engine). *"render transform changes invalidate the layout each frame"* — [Optimization Guidelines](https://dev.epicgames.com/documentation/unreal-engine/optimization-guidelines-for-umg-in-unreal-engine) |

| ⑨ | 초상화 텍스처는 **소프트 참조**로 두고 카드가 보일 때 로드 (원작 수만큼 늘었을 때 대비). 지금 6명은 하드여도 무방 | `CLAUDE.md` §5 애셋 참조 규칙. 기존 스킨도 같은 이유로 소프트 (`ERCharacterData.h:92` 주석 "고른 스킨만 로드") |

### 4.2 제안: 무엇을 어디에 복제하나

원칙: **선택은 서버 권위** (`CLAUDE.md` §6). 클라는 "이걸 고르고 싶다"고 요청만 하고, 화면은 복제된 값이 돌아왔을 때 바뀐다.

```
[내 클라] 카드 클릭
   → AERPlayerController::ServerSelectCharacter(Id)        Server, Reliable, WithValidation
[서버] 검증: 선택 단계인가 · Id 가 로스터에 있나 · 팀원이 이미 골랐나(규칙 미확인) · 시간 안인가
   → AERPlayerState::SelectedCharacterId = Id              (서버만 씀)
[복제] PlayerState → 모든 클라  ── ReplicatedUsing=OnRep_SelectedCharacter
[각 클라] OnRep → 델리게이트 OnSelectedCharacterChanged
   → WBP_CharacterSelect: 팀 슬롯 아이콘 · 카드 "팀원이 고름" 표시 · (내 것이면) 미리보기 갱신
```

| 상태 | 위치 | 복제 | 쓰는 쪽 | 이유 |
|---|---|---|---|---|
| 지금 선택 단계인가 | `AERGameState` 새 enum (`MatchPhase`) | 전원 · `ReplicatedUsing` | 서버 GameMode | 전원이 알아야 하는 매치 상태 = GameState (`ERGameState.h:20-28` 주석). 역기획서 스키마 `EMatchPhase` 에는 **선택 단계 값이 없다** (`Docs/0_GameDesign/Systems/매치진행_게임모드_역기획서.md` §10) → 추가 필요 |
| 선택 종료 시각 | `AERGameState::SelectEndServerTime` (float) | 전원 · 단계 바뀔 때 1회 | 서버 | `PhaseEndServerTime` 과 같은 패턴 — 매 틱 복제하지 않고 클라가 서버 시각으로 계산 (`ERGameState.h:54-56` 주석) |

| 적 팀에게도 보이나 | — | **(미확인)** | — | 원작이 선택 중 적 픽을 숨기는지 확인 필요. 숨겨야 하면 PlayerState(전원 relevant) 에 두면 안 된다 → 설계가 바뀐다. **먼저 원작 규칙을 확인한다** |
| 스킨 | 기존 `AERPlayerState::SkinIndex` | 기존 그대로 | 새 Server RPC 필요 | 이미지에 스킨 UI 없음 → 지금 범위 밖 |
| 플레이어 이름 | 엔진 `APlayerState::PlayerName` | 엔진이 복제 | — | `GetPlayerName()` |
| 팀 구성 | 기존 `AERGameState::Teams` | 기존 | — | 슬롯 3개를 채우는 순서 |

- RPC 는 **PlayerController** 에 둔다 — 소유 연결이 있는 액터여야 Server RPC 가 간다 (PlayerState 도 소유는 되지만, 입력 → 요청 경로는 기존 `ServerLevelUpSkill` 처럼 PlayerState 에 둬도 된다 (`ERPlayerState.h:86-87`). **기존 관례가 PlayerState 쪽이므로 거기 맞출지 결정 필요**)
- RPC 안에서는 검증 + 값 대입만. 폰 스폰 같은 무거운 일은 선택 종료 타이머에서 (`CLAUDE.md` §6 "RPC 에 무거운 로직 금지")
- 선택 종료: 서버 `FTimerManager` 1개. 끝나면 ① 미선택자 처리 (경고문 = "로비로 이동" · 로비 레벨 ❌ 없음 · 연습 외 모드에서도 같은지 **(미확인)**) ② 고른 캐릭터로 스폰 — `GetDefaultPawnClassForController` 오버라이드 (`Engine/.../GameModeBase.h:84`) ③ 매치 시계 시작 (`StartMatchClock`)
- ⚠ 지금은 접속하자마자 폰이 스폰된다. 선택 전에는 스폰을 미뤄야 한다 — 방법(`HandleStartingNewPlayer` 오버라이드 `GameModeBase.h:366` / 별도 선택 맵 + Seamless Travel `GameModeBase.h:584` + `CopyProperties` `PlayerState.h:284`) 은 **방안이 2개 이상** → `Docs/4_Argument/` 로 비교 후 결정 (`CLAUDE.md` §1.2)

## 6. 캐릭터 프리뷰 방식

이미지의 H 영역은 **빈 상태 실루엣(2D)** 만 보인다. 고른 뒤 무엇이 나오는지 **(미확인)** → 아래 셋을 비교만 하고 결정은 원작 확인 후.

| | A. 2D 일러스트 | B. 씬 캡처 (SceneCapture2D → RenderTarget → Image) | C. 레벨 배치 (메인 카메라 앞에 캐릭터 액터 · UI 는 투명 영역) |
|---|---|---|---|
| 방식 | `PreviewImage` 에 텍스처 교체 | 화면 밖 무대에 메시 액터 + 캡처 컴포넌트, RT 를 UI 머티리얼로 표시 | 선택 화면용 무대에 카메라를 두고 캐릭터를 그 자리에 스폰 |
| 장점 | 가장 싸다 · 이미지의 실루엣 프레임과 그대로 맞는다 · 서버 무관 | 어느 맵에서든 UI 안 원하는 칸에 넣을 수 있다 · 스킨/애니 프리뷰 가능 | **추가 렌더 패스 없음** — 메인 화면 렌더에 포함 · 조명/포스트프로세스 품질 최상 |
| 단점 | 애셋(전신 일러스트) 필요 — 프로젝트에 있는지 **(미확인, `Content/` 는 읽지 않음)** · 스킨 반영 불가 | **씬을 한 번 더 그린다.** `bCaptureEveryFrame` (`Engine/Source/Runtime/Engine/Classes/Components/SceneCaptureComponent.h:83`) 이 켜져 있으면 매 프레임. RT 메모리. 투명 배경은 설정이 까다롭다 (미확인) | 선택 화면이 **어느 레벨에서 열리느냐**에 묶인다 — 매치 맵에서 열면 무대를 맵 어딘가에 숨겨야 하고, 별도 선택 맵이면 맵 전환 설계(§4.2 Argument)와 엮인다 |
| 성능 주의 | — | ① `PrimitiveRenderMode = UseShowOnlyList` (`SceneCaptureComponent.h:76`) + `ShowOnlyActorComponents` (`:165`) 로 **프리뷰 액터만** 그린다 ② 캐릭터가 움직일 때만 필요하면 `bCaptureEveryFrame` 끄고 수동 캡처 ③ RT 해상도는 표시 크기에 맞춘다 ④ `PreviewImage` 를 **Invalidation Box 밖**에 둔다 — 캐시된 그리기가 RT 갱신을 반영하는지 **(미확인 — PIE 로 확인)** | 메인 카메라가 무대를 향해야 하므로 선택 중엔 게임 카메라를 쓸 수 없다 |
| 데디 서버 | 무관 | 프리뷰 액터는 **클라 로컬 스폰 · 비복제**. 서버(`NM_DedicatedServer`)에서는 만들지 않는다 | 같음 |

**지금 단계 권고:** 위젯은 `PreviewImage` 한 칸으로만 만든다 — 셋 중 무엇이 오든 **Image 브러시만 바꾸면** 되므로(A=텍스처, B=RT 머티리얼, C=투명/Collapsed) 위젯 구조는 바뀌지 않는다. 방식 결정은 원작 확인 후 필요하면 `Docs/4_Argument/` 로.

## 주의점

- **TileView 엔트리는 재사용된다.** 카드에 "선택됨" 같은 상태를 위젯 변수로만 들고 있으면 스크롤 시 엉뚱한 카드에 남는다 — 상태는 항목(UObject)에 두고 `NativeOnListItemObjectSet` 에서 다시 칠한다
- 팀원 선택 표시를 **클라가 클릭한 순간** 바꾸지 않는다 — 서버가 거절할 수 있다. 바꾸는 시점은 OnRep (`CLAUDE.md` §6 · 예측은 요청받았을 때만)
- 카운트다운을 클라 로컬 시간으로 세지 않는다 — 접속이 늦은 클라와 숫자가 어긋난다. 서버 종료 시각 기준 (§3-④)
- 카드/슬롯 루트에 Canvas 를 쓰면 카드 수 × Layer 만큼 그리기 호출이 는다 (§3-①)
