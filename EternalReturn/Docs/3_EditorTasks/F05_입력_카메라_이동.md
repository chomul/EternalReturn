#### ⭐ Runtime Generation

- [ ] Details > **Runtime > `Runtime Generation`** = **`Static`**

⚠ **엔진 기본값은 `Dynamic`** 이고, 그러면 물체가 움직일 때마다 그 타일을 다시 굽는다.
지금 테스트 맵에서는 티가 안 나지만, **실제 맵(`ER_Level`)에서 프레임 드랍의 원인**이 된다.

#### ⭐⭐ Agent Max Step Height — 작은 둔턱에 막히는 원인

- [ ] Details > **Generation > `Agent Max Step Height`** = **`45`**

⚠⚠ **엔진 기본값이 서로 안 맞는다:**

| | 값 | 출처 |
|---|---|---|
| **CMC** `MaxStepHeight` | **45** | `CharacterMovementComponent.cpp:604` |
| **네비메시** `AgentMaxStepHeight` | **35** | `RecastNavMesh.h:648` |

⭐ **캐릭터는 45까지 올라갈 수 있는데 네비메시는 35까지만 길을 낸다.**
높이 35~45 사이의 둔턱은 **실제로는 넘을 수 있는데 네비메시가 벽으로 취급**한다.

→ 둘을 **같은 값**으로 맞춘다. CMC 쪽을 바꾸면 여기도 같이 바꾼다.

#### Agent Radius — 캐릭터 캡슐과 맞춘다

- [ ] `BP_ERCharacterBase` 의 **CapsuleComponent 반지름**을 확인한다: __________
- [ ] Details > **Generation > `Agent Radius`** 를 그 값과 **같게** 맞춘다

⚠ 네비 쪽이 더 크면 **실제로 지나갈 수 있는 틈이 막힌다.**

#### 좁은 곳에 네비메시가 안 깔릴 때

- [ ] 좁은 골목 · 작은 옥상이 초록으로 안 덮이면 아래를 조정한다

| 설정 | 하는 일 | 조정 |
|---|---|---|
| `Min Region Area` | ⭐ **이보다 작은 영역은 통째로 버린다** | **낮춘다** |
| `Merge Region Size` | 작은 영역을 큰 영역에 병합하는 기준 | 상황에 따라 |
| `Cell Size` | 복셀 해상도. 크면 가는 통로를 놓친다 | **낮춘다** |

⚠ **`Cell Size` 를 낮추면 큰 맵에서 메모리·빌드 시간이 급증한다.**
테스트 맵에서 낮춰 놓고 `ER_Level` 로 옮기면 빌드가 몇 분씩 걸린다.
→ 큰 맵 기준은 **F13** 에서 정한다: [`../1_Task/F13_맵_지역/00_개요.md`](../1_Task/F13_맵_지역/00_개요.md)

## 2-2. ⭐ 우클릭 이동

- [ ] 바닥을 우클릭하면 **캐릭터가 그쪽으로 걸어간다**
- [ ] 이동 중 다른 곳을 우클릭하면 **새 목적지로 바뀐다**
- [ ] 하늘(바닥 아닌 곳)을 클릭하면 **아무 일도 안 일어난다** (크래시 아님)
- [ ] 아주 먼 곳을 클릭하면 로그에 `목적지가 너무 멀다` 가 뜨고 무시된다

### ⭐ 장애물을 클릭했을 때

| 클릭한 곳 | 기대 |
|---|---|
| 낮은 상자 **위** | 상자 **옆 바닥**으로 이동한다 |
| 높은 벽 · 건물 | 벽 **바깥쪽 바닥**으로 이동한다 |
| 하늘 | 아무 일도 안 일어난다 |

- [ ] 상자를 클릭해도 **엉뚱한 데로 안 간다**
- [ ] ⭐ 클라와 서버가 **같은 곳으로** 간다 (`Play As Client, 2인`)

⭐ 커서 트레이스는 `ECC_Visibility` 라 **보이는 모든 것**에 맞는다. 그 좌표를
`ResolveNavigableDestination()` 이 **갈 수 있는 지점으로 스냅**한다.

### ⭐ 장애물을 **돌아서** 가는지

- [ ] 장애물 **반대편**을 클릭하면 캐릭터가 **돌아서 간다**
  ⚠ 장애물에 붙어서 멈추면 **네비메시 문제**다 — 1-5 의 `P` 키 확인으로 돌아간다

**⚠ 안 움직이면 확인 순서:**
1. 네비메시가 초록으로 덮여 있나 (`P` 키) — 1-5
2. 로그에 `[초기스탯]` 이 나왔나 — `MoveSpeed` 가 0 이면 안 움직인다
3. `ER.Damage.SetStat MoveSpeed 3.5` 로 직접 넣어 본다

## 2-3. ⭐ MoveSpeed 가 실제로 반영되는지

```
ER.Damage.SetStat MoveSpeed 8
```

- [ ] ⭐ 우클릭 이동이 **눈에 띄게 빨라진다**
- [ ] `ER.Damage.SetStat MoveSpeed 1` → 느려진다
- [ ] ⭐ **`Tick` 없이** 값이 변할 때만 갱신된다 (F02-06 델리게이트)

⚠ 속도가 전혀 안 변하면 단위 환산(m/s → cm/s)이 안 걸린 것이다.

## 2-7. ⭐⭐ 고핑 테스트 — **이게 진짜 검증이다**

로컬 PIE 는 핑이 0 에 가까워서 **서버 보정이 거의 일어나지 않는다.**
클라 예측이 걸린 이동은 여기서 100% 정상으로 보인다 —
[`E08`](../5_ErrorReport/E08_멀티에서_클릭이동_안됨.md) 이 정확히 그런 부류였다.

`Play As Client, Number of Players: 2` 로 실행한 뒤 **클라 창 콘솔**에서:

```
Net PktLag=100
Net PktLagVariance=30
Net PktLoss=2
```

⚠ 끝나면 **원래대로 되돌린다** (`Net PktLag=0` `Net PktLagVariance=0` `Net PktLoss=0`).
안 되돌리면 다음 테스트가 전부 이상해 보인다.

### 시나리오

| # | 무엇을 | 왜 보나 |
|---|---|---|
| ① | 긴 직선 이동 | 기본 동작 |
| ② | **코너 여러 개**를 도는 경로 | 보정 뒤에도 경로 갱신이 유지되나 |
| ③ | **좁은 통로** 통과 | 보정으로 경로를 벗어나면 끼는가 |
| ④ | 이동 중 **방향 급변경** (연타 클릭) | `SavedMove` 재생이 꼬이나 |
| ⑤ | ⭐ 이동 중 **CC** (`ER.CC.Block Movement 2`) | F06 의 `GetMaxSpeed()=0` 이 보정과 싸우지 않나 |
| ⑥ | 서버 correction 이 실제로 난 직후 | 경로 추종이 **복구되나** |

### 확인

- [ ] ① 직선 — 목적지까지 간다
- [ ] ② 코너 — 벽에 걸리거나 되돌아가지 않는다
- [ ] ③ 좁은 통로 — 끼지 않는다
- [ ] ④ 급변경 — 새 목적지로 즉시 바뀐다
- [ ] ⑤ ⭐ CC 중 멈추고, 풀리면 **다시 원래 목적지로 가거나 완전히 멈춘다**
      (⚠ 어느 쪽이 맞는지 **아직 안 정했다 — (미확인)**. 어떻게 동작하는지 관찰만 한다)
- [ ] ⑥ ⭐ **보정 뒤에도 경로 추종이 살아 있다**
- [ ] 전체적으로 **고무줄이 심하지 않다** (약간의 보정은 정상이다)

⚠ **⑥ 이 핵심이다.** `PathFollowingComponent` 가 서버 보정으로 위치가 튄 뒤에도
경로를 다시 잡는지는 **지금까지 확인한 적이 없다 (미확인)**.
여기서 깨지면 클라 경로 추적 방식 자체를 다시 봐야 한다
([`11_클릭이동_서버검증_수준.md`](../4_Argument/11_클릭이동_서버검증_수준.md)).

- [ ] ⚠ 끝나고 `Net PktLag=0` `Net PktLagVariance=0` `Net PktLoss=0` 으로 되돌렸다
