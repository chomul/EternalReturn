# ① 애셋 없이 먼저 확인 — 이동 차단이 되는가

⭐ **애셋을 만들기 전에 이것부터 한다.** 여기서 안 되면 애셋을 만들어도 안 된다.

**1인 PIE (`Play` 버튼)** 로 실행하고 콘솔(`~`)에서:

```

```

- [ ] ⭐ **3초 동안 우클릭해도 안 움직인다**
- [ ] ⭐ **3초 뒤 자동으로 다시 움직인다**
- [ ] 막힌 동안 캐릭터가 **제자리에서 방향도 안 돌아간다**


- [ ] 보유 태그에 `State.Block.Movement` 가 보인다
- [ ] `이동차단=O` 로 찍힌다

⚠ **`ER.CC.Block` 은 Loose 태그라 복제되지 않는다.** 2인 PIE 에서는 부른 쪽만 막힌다.

# ② CC GE 애셋 만들기

**위치:** `Content/GAS/CC/`  (⭐ 실제로 여기에 만들었다)

**만들 것 4개** — 역기획서 §3.1 · §3.3 의 1순위 CC

| 애셋 | 무엇을 막나 |
|---|---|
| `GE_CC_Stun` | 이동 · 평타 · 스킬 **전부** |
| `GE_CC_Snare` | ⭐ **이동만** (평타 · 스킬은 된다) |
| `GE_CC_Silence` | 스킬만 |
| `GE_CC_Disarm` | 평타만 |

## 만드는 순서 (`GE_CC_Stun` 기준)

**1. 애셋 생성**
`Content/GAS/CC/` 우클릭 → **Blueprint Class** → 부모 클래스 검색 `GameplayEffect` → 이름 `GE_CC_Stun`

**2. ⭐⭐ Duration Policy 를 먼저 바꾼다**

`Details` → `Duration` → **`Duration Policy` = `Has Duration`**

⚠⚠ **이걸 먼저 안 하면 다음 칸이 안 보인다.**
`Duration Magnitude` 는 `EditCondition="DurationPolicy == HasDuration"` + `EditConditionHides` 라
`Instant` 상태에서는 **칸 자체가 숨겨져 있다** (`GameplayEffect.h:2199`).

⚠⚠ 그리고 **기본값이 `Instant` 다** (`GameplayEffect.cpp:146`).
`Instant` 는 *"never gets added to ActiveGameplayEffects"* (`AbilitySystemComponent.cpp:951`) 라
**태그를 아예 부여하지 못한다.** 이 상태로 두면 CC 가 조용히 안 걸린다.

→ `ERCC::ApplyCC` 가 이걸 검사해서 에러 로그를 낸다. 그래도 **처음부터 바르게 두는 게 낫다.**

**3. 지속시간을 SetByCaller 로**

`Duration Magnitude` → `Magnitude Calculation Type` = **`Set by Caller`**
→ `Data Tag` = **`SetByCaller.CCDuration`**

⚠ **`Data Name` 이 아니라 `Data Tag` 다.** `Data Name` 은 `VisibleDefaultsOnly` 라
회색이고 `None` 에서 안 바뀐다. FName 경로는 deprecated 다 — [`E06`](../5_ErrorReport/E06_SetByCaller_DataName_편집불가.md)

**4. ⭐⭐ 태그 부여 — 여기가 UE 5.3 에서 바뀌었다**

`Details` → **`Components`** 배열 → `+` → **`Grant Tags to Target Actor`** 선택

⚠⚠ **"Granted Tags" 라는 칸을 찾지 마라. 없다.**
UE 5.3 에서 `InheritableOwnedTagsContainer` 가 deprecated 되고
`UTargetTagsGameplayEffectComponent` 로 옮겨졌다 (`GameplayEffect.h:2285`).
인터넷 예제 대부분이 5.2 이전 기준이라 없는 칸을 찾게 된다. **E06 과 같은 부류다.**

추가한 컴포넌트의 **`Add Tags`** 에 아래를 넣는다:

| 애셋 | Add Tags |
|---|---|
| `GE_CC_Stun` | `State.CC.Stun` + `State.Block.Movement` + `State.Block.BasicAttack` + `State.Block.Skill` |
| `GE_CC_Snare` | `State.CC.Snare` + `State.Block.Movement` ⭐ **이것만** |
| `GE_CC_Silence` | `State.CC.Silence` + `State.Block.Skill` |
| `GE_CC_Disarm` | `State.CC.Disarm` + `State.Block.BasicAttack` |

⭐ **두 종류를 다 넣어야 한다.**
`State.CC.*` 는 *무엇에 걸렸는지*(UI · 정화 · 저항이 본다),
`State.Block.*` 는 *무엇이 막히는지*(CMC · 어빌리티가 본다).
축 태그를 빠뜨리면 **태그는 붙는데 아무것도 안 막힌다.**

⚠ **속박(`Snare`)에 `Block.Skill` 을 넣지 않는다.** 역기획서 §3.1 이
*"이동기 스킬은 사용 가능하다"* 로 명시한다. 넣으면 설계와 어긋난다.

**5. 저장**

### 체크리스트

- [ ] `GE_CC_Stun` — Duration Policy = Has Duration
- [ ] `GE_CC_Stun` — Duration Magnitude = Set by Caller · Data **Tag** = `SetByCaller.CCDuration`
- [ ] `GE_CC_Stun` — Components 에 `Grant Tags to Target Actor` · Add Tags 4개
- [ ] `GE_CC_Snare` — 같은 설정 · Add Tags 2개 (⭐ `Block.Skill` **없이**)
- [ ] `GE_CC_Silence` — 같은 설정 · Add Tags 2개
- [ ] `GE_CC_Disarm` — 같은 설정 · Add Tags 2개

# ③ 애셋 검증 — 검사기가 잡는지도 함께 본다

**1인 PIE** 콘솔에서 (경로 끝의 **`_C`** 를 빠뜨리면 못 찾는다):

## ⚠⚠ 먼저 — 지속시간을 **길게** 준다

⚠ **짧게 주면 태그가 안 보인다.** 2초로 걸고 `ER.CC.List` 를 타이핑하는 동안
GE 가 이미 만료돼서 **"보유 태그 0개"** 가 찍힌다. 버그가 아니라 만료다.

→ 태그를 **확인할 때는 30초**, 이동 차단을 **체감할 때는 2초** 로 나눠서 본다.

## 태그 확인 (30초)

```
ER.CC.Apply /Game/GAS/CC/GE_CC_Stun.GE_CC_Stun_C 30
ER.CC.List
```

- [ ] `State.CC.Stun` + `State.Block.Movement` + `BasicAttack` + `Skill` = **4개**
- [ ] `이동차단=O  평타차단=O  스킬차단=O`

```
ER.CC.Clear
ER.CC.Apply /Game/GAS/CC/GE_CC_Snare.GE_CC_Snare_C 30
ER.CC.List
```

- [ ] `State.CC.Snare` + `State.Block.Movement` = **2개**
- [ ] ⭐ `이동차단=O  평타차단=X  스킬차단=X` — **속박은 이동만 막는다**

⚠ `ER.CC.Clear` 는 **Loose 태그만** 뗀다. GE 로 걸린 것은 만료를 기다려야 한다.
급하면 PIE 를 다시 시작한다.

## 만료 확인 (2초)

```
ER.CC.Apply /Game/GAS/CC/GE_CC_Stun.GE_CC_Stun_C 2
```

- [ ] ⭐ **2초 동안 못 움직인다**
- [ ] ⭐ **2초 뒤 자동으로 풀린다** (⚠ 해제 코드는 없다. GE 만료가 한다)

## ⭐ 검사기가 실제로 잡는지 — 일부러 틀려 본다

⚠ 이건 **애셋을 하나 복제해서** 시험한다. 원본을 망가뜨리지 않는다.

`GE_CC_Stun` 을 복제해 `GE_CC_Test_Broken` 을 만들고 **Duration Policy 를 `Instant` 로** 되돌린 뒤:

```
ER.CC.Apply /Game/GAS/CC/GE_CC_Test_Broken.GE_CC_Test_Broken_C 2
```

- [ ] ⭐ 로그에 **`Duration Policy 가 HasDuration 이 아니다`** 에러가 찍힌다
- [ ] CC 가 안 걸린다 (조용히 실패하지 않고 **이유가 보인다**)
- [ ] 확인 후 `GE_CC_Test_Broken` 을 **삭제한다**

⭐ 이게 방안 A(애셋)를 고른 대가를 갚는 부분이다. 애셋 실수가 로그로 드러나는지 확인한다.

# ④ 멀티 — 복제 확인

## ⚠⚠ `Play As Client` 로는 할 수 없다

```
Cmd: ER.CC.Apply ...
LogEternalReturn: Error: [CC] 서버가 아니다. CC 부여는 서버 권위다.
```

⭐ **이건 정상이다. 검사기가 제 일을 한 것이다.**
클라 창 콘솔은 클라의 ASC 를 잡으므로 `IsOwnerActorAuthoritative()` 가 false 다.

⚠ 그런데 `Play As Client` 는 **데디케이티드 서버**라 커맨드를 칠 서버 창이 없다.
→ 이 절차로는 복제를 확인할 방법이 없다.

## ⭐ `Play As Listen Server` 로 한다

`Net Mode` = **`Play As Listen Server`**, `Number of Players: 2`

⭐ 리슨 서버 창의 플레이어는 **서버 권위를 가지면서 로컬 조작도 된다.**
그 창에서 CC 를 걸고, **다른 클라 창에서 그 캐릭터를 본다.**

**서버 창** 콘솔에서:

```
ER.CC.Apply /Game/GAS/CC/GE_CC_Stun.GE_CC_Stun_C 10
```

- [ ] ⭐ **서버 창에서 그 캐릭터가 멈춘다**
- [ ] ⭐⭐ **다른 클라 창에서도 그 캐릭터가 멈춰 보인다** — 태그가 복제된 것이다
- [ ] ⭐ **고무줄이 안 생긴다** — 멈춘 자리에서 튀지 않는다
- [ ] 만료 시점이 양쪽에서 같다
- [ ] 클라 창에서 `showdebug abilitysystem` 으로 **태그가 보인다**

## ⏸ 데디케이티드 서버에서의 확인은 F07 로

⚠ 리슨 서버는 서버와 로컬 플레이어가 한 프로세스라 데디케이티드와 완전히 같지 않다.
**태그 복제 확인에는 충분하지만**, 진짜 데디케이티드 검증은
F07 에서 **스킬로 CC 를 걸 수 있게 되면** 자연히 된다 (스킬은 서버에서 실행된다).

→ 디버그 커맨드에 서버 RPC 를 추가하지 않는다. F07 이 곧 그 경로를 만든다 (`CLAUDE.md` §2).

# ⑤ 둔화 GE 애셋 (F06-02)

> 결정 [`12_둔화_중첩방식⭐.md`](../4_Argument/12_둔화_중첩방식⭐.md) — 방안 B + 구현 ③

## ⭐⭐ 둔화 GE 는 `MoveSpeed` 를 **직접 건드리지 않는다**

기절·속박과 만드는 법이 **다르다.** 여기가 가장 헷갈리는 지점이다.

```
둔화 GE 애셋      : State.CC.Slow 태그 + SetByCaller.SlowPercent(감소율)만
                   ❌ MoveSpeed 모디파이어를 **넣지 않는다**
                        ↓
서버가 자동으로   : 걸린 둔화들 중 **가장 큰 감소율**을 골라
                   UERSlowEffect(네이티브)를 그 값으로 적용한다
```

⚠ **왜 모디파이어를 안 넣나:** GAS 의 Multiply 는 **합산**된다.
60% 둔화 둘이면 감소율이 120% 가 되어 이동속도가 음수가 된다.
원작·LoL 모두 **가장 강한 것만** 적용하므로 서버가 최대값 하나를 골라 적용한다.

## 만들 것

**위치:** `Content/GAS/CC/` · **이름:** `GE_CC_Slow`

**1. 애셋 생성** — `GameplayEffect` 상속 블루프린트

**2. `Duration Policy` = `Has Duration`** (⚠ 기본값 `Instant` 는 태그를 못 붙인다)

**3. `Duration Magnitude`** → `Set by Caller` → `Data Tag` = **`SetByCaller.CCDuration`**

**4. `Components` → `Grant Tags to Target Actor`** → `Add Tags` 에 **`State.CC.Slow`**

⚠ **`State.Block.Movement` 를 넣지 않는다.** 둔화는 *이동 방해*이지 *이동 불가*가 아니다.
원작도 둘을 구분한다 — [아카라이브](https://arca.live/b/bser/129146888):
*"움직이긴 하는데 느리게 움직이는 둔화·춤은 **이동 방해**, 우클릭해도 안 움직이는
기절·속박·에어본 등은 **이동 불가**"*

**5. ⚠⚠ `Modifiers` 는 비워 둔다.** `MoveSpeed` 모디파이어를 넣으면
서버가 적용하는 `UERSlowEffect` 와 **이중으로 곱해진다.**

### 체크리스트

- [ ] `GE_CC_Slow` — Duration Policy = **Has Duration**
- [ ] Duration Magnitude = Set by Caller · Data Tag = `SetByCaller.CCDuration`
- [ ] Components → Grant Tags to Target Actor · Add Tags = **`State.CC.Slow` 하나만**
- [ ] ⚠ `State.Block.Movement` 를 **넣지 않았다**
- [ ] ⚠⚠ `Modifiers` 가 **비어 있다**

## 검증 — 1인 PIE (`Play` 버튼)

⚠ 둔화 전용 커맨드를 쓴다. `ER.CC.Apply` 는 지속시간만 넣어서 둔화에는 부족하다.

```
ER.CC.Slow 60 10      ← 60% 둔화 10초
ER.CC.Speed           ← 이동속도와 걸린 둔화 개수
```

### 기본 동작

- [ ] `ER.CC.Speed` 로 **평상시 값**을 먼저 적어 둔다 → `MoveSpeed` ______ m/s · CMC ______ cm/s
- [ ] `ER.CC.Slow 60 10` → ⭐ **눈에 보이게 느려진다**
- [ ] `ER.CC.Speed` → `MoveSpeed` 가 **평상시의 40%** 로 찍힌다 (3.5 → **1.40**)
- [ ] ⭐ CMC `MaxWalkSpeed` 도 **같은 비율**로 줄었다 (140 cm/s) — 어트리뷰트 반영이 동작한다
- [ ] ⭐ **10초 뒤 원래 속도로 돌아온다** (⚠ 해제 코드는 없다. GE 만료가 한다)

### ⭐⭐ 핵심 — 다중 둔화는 가장 강한 것만

```
ER.CC.Slow 30 30      ← 먼저 약한 것을 길게
ER.CC.Speed           ← 3.5 × 0.7 = 2.45 여야 한다
ER.CC.Slow 60 5       ← 강한 것을 짧게 덮는다
ER.CC.Speed           ← ⭐ 3.5 × 0.4 = 1.40 (합산이면 음수가 되어 하한 1.0 이 된다)
(5초 기다린다)
ER.CC.Speed           ← ⭐⭐ 2.45 로 **돌아온다** — 30% 가 남은 시간 동안 적용
```

- [ ] 30% 만 → **2.45**
- [ ] ⭐ 60% 를 겹침 → **1.40** (⚠ **1.0** 이 나오면 합산된 것이다 = 구현 실패)
- [ ] ⭐⭐ 60% 만료 후 → **2.45 로 복귀** (약한 둔화가 제거되지 않았다는 증거)
- [ ] `ER.CC.Speed` 의 "걸린 둔화" 개수가 2 → 1 로 줄어든다

⭐ 세 번째 항목이 이 구현의 핵심이다 — 약한 둔화를 **제거하지 않고 무시**했다는 뜻이다.

### 애셋 설정 누락을 잡는지

`ER.CC.Apply /Game/GAS/CC/GE_CC_Slow.GE_CC_Slow_C 30` (둔화율 없이 적용)

- [ ] ⚠ 로그에 **경고**가 떠야 정상이다 —
      *"State.CC.Slow 를 갖고 있는데 SetByCaller.SlowPercent 가 없다"*
- [ ] 이동속도가 **안 변한다** (조용히 0% 둔화가 되지 않고 경고가 뜬다)

## 멀티 — `Play As Listen Server` 2인

**서버 창**에서:

- [ ] `ER.CC.Slow 60 10` → ⭐ **다른 클라 창에서도 그 캐릭터가 느려 보인다**
- [ ] 고무줄이 안 생긴다
- [ ] 만료 시점이 양쪽에서 같다

# ⑥ 강제 이동 — 넉백 · 그랩 (F06-04)

> 결정 [`13_강제이동_구현방식.md`](../4_Argument/13_강제이동_구현방식.md) — 방안 B (RootMotionSource + Multicast)

⭐ **애셋이 필요 없다.** 콘솔로 바로 확인한다.

```
ER.CC.Knockback <거리m> [초=0.4] [각도=0]
ER.CC.WallCheck
```

방향은 **카메라가 보는 쪽**이다. 각도 `180` 을 주면 반대 = **그랩과 같은 방향**.

## ⭐⭐ 거리 정확도 — 이게 방안 B 를 고른 이유다

**빈 곳**(벽에서 먼 데)에 서서:

```
ER.CC.Knockback 3 0.4
```

로그가 두 줄 나온다:

```
[CC디버그] 넉백 3.0m 0.40초 시작. 시작위치 X=... Y=... Z=...
[CC디버그] 넉백 종료 — 실제 이동 3.00m (목표 3.00m)
```

- [ ] ⭐⭐ **실제 이동이 목표와 거의 같다** (오차 ~0.1m)
      ⚠ 임펄스 방식(방안 A)이었으면 여기서 어긋난다
- [ ] 넉백이 끝나고 **미끄러지지 않는다** (`FinishVelocity` 가 0)
- [ ] 넉백 중 **우클릭 이동이 먹지 않는다**

```
ER.CC.Knockback 3 0.4 180
```

- [ ] ⭐ 반대 방향으로 밀린다 — **넉백과 그랩이 같은 함수**임을 보는 것이다

## 벽 충돌 판정

**벽을 등지고** 서서:

```

```

- [ ] 벽 쪽을 보고 있을 때 `벽 판정=O`, 대상 이름이 찍힌다
- [ ] ⭐ **평지에서는 `벽 판정=X`** — ⚠ 바닥을 벽으로 세면 넉백마다 오탐이 난다

벽을 향해 넉백:

```

```

- [ ] ⚠ 로그에 **`실제 이동 …  ⚠ 벽에 막혔거나 덜 이동`** 이 뜬다
- [ ] 캐릭터가 **벽을 통과하지 않는다**

⏸ **벽 충돌 시 추가 피해 · 기절은 F07 이다.** 지금은 **판정만** 만들었다 —

# ⑦ 저항 · 면역 · 중첩 (F06-05)

> 결정 [`14_저항_적용방식.md`](../4_Argument/14_저항_적용방식.md)

## ⭐⭐ 먼저 — 두 저항은 **다른 것을 줄인다**

| 스탯 | 무엇을 | 어떤 CC 에 |
|---|---|---|
| **`CCResist`** 방해 저항 | ⭐ **지속시간** | 기절 · 속박 · **둔화** ⚠ 붙잡기 · 에어본 · 제압은 **제외** |
| **`SlowResist`** 둔화 저항 | ⭐ **강도(수치)** | **둔화만** |

⭐ **둔화는 둘 다 받는다** — 지속시간은 `CCResist`, 강도는 `SlowResist`.

⚠ **역기획서 §4 의 "이동 속도 감소 저항 = 지속시간 감소" 는 틀렸다.**
근거는 Argument 14 파트 1 에 있다.

## 애셋 수정 — CC GE 4개 + 둔화

### ① 지속시간 계산을 저항이 붙은 것으로 바꾼다

각 CC GE 애셋에서:

`Duration Magnitude` → `Magnitude Calculation Type` = **`Custom Calculation Class`**
→ `Calculation Class` = **`ERCCDurationCalc`**

⚠⚠ **`Set by Caller` 에서 바꾸는 것이다.** 지금은 `SetByCaller.CCDuration` 을
직접 쓰고 있는데, 이제 **계산 클래스가 그 값을 읽어서** 저항을 곱한다.
스킬이 넣는 값은 그대로다 — 바뀌는 건 애셋 설정뿐이다.

- [ ] `GE_CC_Stun` — Duration Magnitude = Custom Calculation Class = `ERCCDurationCalc`
- [ ] `GE_CC_Snare` — 같음
- [ ] `GE_CC_Silence` — 같음
- [ ] `GE_CC_Disarm` — 같음
- [ ] `GE_CC_Slow` — 같음 (⭐ 둔화도 **지속시간**은 `CCResist` 를 받는다)

⚠ **붙잡기 · 에어본 · 제압** GE 를 나중에 만들 때는 **이 클래스를 쓰지 않는다.**
그 셋은 방해 저항을 받지 않는다 (역기획서 §4 · 원작 확인).

### ② 면역 — `ApplicationTagRequirements`

각 CC GE 애셋에서:

`Application Tag Requirements` → `Ignore Tags` 에 **`State.CCImmune`** 추가

- [ ] `GE_CC_Stun` · `GE_CC_Snare` · `GE_CC_Silence` · `GE_CC_Disarm` · `GE_CC_Slow`

⚠ 매그너스 R 이 *"**이동 방해** 면역"* 이라 **기절까지 막는지는 (미확인)** 이다.
지금은 전부에 넣어 두고, 확인되면 조정한다.

⭐ **넉백 · 그랩은 애셋 설정이 아니다** — GE 가 아니라서 `ApplyForcedMove` 안에서
직접 검사한다. **코드에 이미 들어갔다.**

### ③ 중첩 — 같은 CC 재적용 시 갱신

각 CC GE 애셋에서:

| 설정 | 값 |
|---|---|
| `Stacking Type` | `Aggregate by Target` |
| `Stack Limit Count` | **1** |
| `Stack Duration Refresh Policy` | `Refresh on Successful Application` |

- [ ] 5개 애셋 모두

⚠ **자체 결정값이다.** 역기획서 §4 가 *"임시안: 같은 CC 재적용 시 갱신,
이종 CC 는 병렬 유지. 원작 확인값이 아니다"* 로 명시했다.

# ⑧ 피해 면역 (F06-06)

⭐ **애셋이 필요 없다.** 코드로 끝났고 콘솔로 확인한다.

## ⚠⚠ 먼저 — "무적" 과 "피해 면역" 은 다른 것이다

역기획서 §3.4 가 *"반드시 다른 플래그여야 한다"* 로 명시한다.

| 상태 | 태그 | 피해 | CC | 사례 | 지금 |
|---|---|---|---|---|---|
| **피해 면역** | `State.DamageImmune` | **0** | ⭐ **걸린다** | 시셀라 W 1.5초 | ⭐ **구현됨** |
| 무적 | `State.Invulnerable` | 0 | ⚠ **(미확인)** | 양손검 D | ⏸ 태그만 |
| 저지 불가 | `State.Unstoppable` | 정상 | ⭐ 걸리되 **억제** → 풀리면 남은 시간 | — | ⏸ 태그만 |
| 대상 지정 불가 | `State.Untargetable` | — | — | — | ⏸ 태그만 |

⚠ **무적·저지 불가·대상 지정 불가는 자리만 만들었다.** 6인 중 요구하는 캐릭터가 없고
무적은 CC 차단 여부가 (미확인) 이라, 로직을 붙이면 추측이 된다 (F06 개요의 원칙).

⭐ **저지 불가는 "면역" 이 아니다** — 원작 확인:
*"저지불가는 CC를 맞았지만 멈추지 않는 상태라서, 저불이 풀렸는데 직전 맞았던 CC
지속시간이 남아있다면 남은 시간 동안 CC기 영향을 받는다."*
→ "면역이면 무시" 로 구현하면 원작과 다른 게임이 된다 (역기획서 §4).

## 검증 — 1인 PIE

```
ER.CC.Immune 10 damage      ← ⭐ damage 를 붙이면 피해 면역
ER.Damage.Test 500 50
```

- [ ] ⭐⭐ **피해가 0 이다**
- [ ] ⚠ 로그의 **기대값 계산은 0 이 아니다** — 디버그 커맨드는 무효화 계층을
      독립적으로 계산하지 않는다. **실제 HP 가 안 줄어드는지**로 판정한다

## ⭐⭐ 가장 중요 — 피해 면역이 **CC 를 막지 않는가**

```
ER.CC.Immune 10 damage
ER.CC.Apply /Game/GAS/CC/GE_CC_Stun.GE_CC_Stun_C 3
```

- [ ] ⭐⭐ **기절이 정상으로 걸린다** (3초간 못 움직임)
- [ ] 동시에 피해는 0 이다

⚠ 여기서 기절이 안 걸리면 **피해 면역을 CC 면역처럼 만든 것**이고,
역기획서 §3.4 의 *"피해 면역은 CC를 그대로 받는다"* 와 어긋난다.

## 이동 방해 면역과 헷갈리지 않는가

```
ER.CC.Immune 10              ← 인자 없으면 이동 방해 면역
ER.CC.Knockback 3 0.4        ← 안 밀린다
ER.Damage.Test 500 50        ← ⭐ 피해는 **정상으로 들어간다**
```

- [ ] ⭐ 이동 방해 면역 중 **피해는 정상**이다 (둘은 다른 태그다)
