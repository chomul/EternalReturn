# F14 매치 진행 — 에디터 작업 · PIE 테스트

## F14-01 빈사 · 사망 · 소생 (Argument 75 · 코드 빌드 Editor · Server ✅ 2026-10-08)

> 결정 [Argument 75](../4_Argument/75_빈사_사망_소생.md): A1 GE + 태그 · H1 같은 HP 400 · R1 소생 어빌리티 (움직이거나 CC 면 끊김) · K2 빈사로 만든 사람이 처치
> 원작 규칙 [역기획서 매치진행 §4.9](../0_GameDesign/Systems/매치진행_게임모드_역기획서.md)
> ⚠ 헤더 · 태그 · 프로젝트 설정 칸이 늘었다 — **에디터 재시작** 후.

### 흐름 (서버)

```
체력 0 (피해 · 빈사 체력 감소)
 ├─ 이미 빈사 → 사망
 ├─ 서 있는 팀원 있음 → 빈사  (체력 400 · 이속 1 · 받는 피해 −(50 + 레벨×1.5)% · 초당 −1 · 스킬 · 평타 · 줍기 · 제작 막힘)
 └─ 없음 → 사망
그 뒤 팀에 서 있는 사람이 없으면 → 빈사자 전원 사망 (전멸)
사망 = 사망 GE (못 움직임 · 대상 안 됨) · 시체 · 처치 인정 (빈사로 만든 사람 · 없으면 마무리한 사람) · 사망 음성
소생 = 빈사 아군 우클릭 (2m 안) → 5초 → 체력 최대의 25% · 움직이거나 CC 면 끊김
```

### ① 에디터 작업

#### 1. `ABP_ERCharacter_Base` — Dead 상태 (실험체는 처음 · 야생동물과 같은 방법)
| 할 것 | 값 |
|---|---|
| 상태머신에 상태 **Dead** 추가 | 안에 **Sequence Player** · Sequence ← `Death Anim` (핀 · 부모 C++ 변수 — My Blueprint 톱니 › Show Inherited Variables) · **Loop Animation ✘** · `Start Position` ▼ → Expose As Pin → `Death Start Position` |
| **상태 에일리어스** `ToDead` | Aliased States: **전부 체크** — ⭐ Mode 상태들(ModeStart · ModeLoop · ModeEnd)도 포함 (빈사 자세에서 죽는다) |
| `ToDead` → Dead 화살표 | 조건 `bDead` · Blend 0.2 |
| Dead 에서 나가는 화살표 | **없음** (부활 = S5 · 나중) |
| Compile · Save | |

> **Start Position 핀이 뭔가** (사용자 질문 2026-10-08) — Sequence Player 가 애니를 **몇 초 지점부터** 틀지. 기본 0 (처음부터).
> - C++ 가 `Death Start Position` 에 넣는다: 눈앞에서 죽음 = `0` (쓰러지는 동작부터) · **늦게 보게 됨** (멀리 있다 다가와 화면에 새로 잡힘 · 나중 접속) = 애니 길이 (이미 누운 마지막 프레임부터)
> - 안 꽂으면 늦게 본 사람 화면에서 죽은 캐릭터가 그 자리에서 **다시 쓰러진다** — 야생동물 시체도 같은 이유로 꽂았다
> - 꺼내는 법: Sequence Player 클릭 → Details › Start Position 오른쪽 ▼ → **Expose As Pin** (또는 "(As pin)" 체크) → `Death Start Position` 변수 연결. **Dead 상태에만** (빈사 상태는 필요 없음)
>
> **변수를 핀에 바로 꽂아도 매 틱 낭비 아닌가** — 아니다. 멤버 변수를 **노드 없이 직접** 꽂으면 Fast Path (컴파일 때 "값 복사"로 바뀜 · 블루프린트 VM 안 돎 · 비용 ≈ 0). 낭비는 핀 앞에 함수 · Cast · AND/NOT 같은 노드를 끼울 때 — 그래서 전이 조건은 C++ 변수 하나(`bDownOutro` …)로 미리 만든다. 확인: 노드 오른쪽 위 **번개 아이콘** · Class Settings › **Warn About Blueprint Usage** 켜면 깨질 때 경고. 자세히 [7_StructCode/03](../7_StructCode/03_AnimBP_변수읽기_FastPath.md)

#### 1-2. `ABP_ERCharacter_Base` — 빈사 전용 상태 ([Argument 76](../4_Argument/76_빈사_애니_전용상태.md) — 모드와 따로)
변수는 전부 부모(C++) 것 — My Blueprint 톱니 › Show Inherited Variables.

> 애니 기준 (사용자 확인 2026-10-08): `down_wait` = 빈사 대기 · `down_run` = 빈사 이동 · **`down_start` = 빈사에서 일어날 때** · `down_dead` = 빈사에서 사망 · `death` = 빈사 없이 바로 사망 (터미네이트). **쓰러지는 애니는 없다** → 빈사가 되면 바로 대기 자세 (DownStart 상태 불필요 — C++ `bDownIntro` 는 늘 거짓)

| 상태 | 안에 넣을 것 |
|---|---|
| **DownLoop** | Blend Poses by bool (`bIsMoving`) — False = Sequence Player(`Down Idle Anim`, Loop ✔) · True = Sequence Player(`Down Run Anim`, Loop ✔) |
| **DownEnd** | Sequence Player ← `Down End Anim` (= down_start · 일어남) · Loop ✘ |

| 화살표 | 조건 |
|---|---|
| 에일리어스 **`ToDown`** (Aliased: Idle · Run · ModeStart · ModeLoop · ModeEnd — **Down 상태 · Dead 는 빼고**) → DownLoop | `bDownDirect` |
| DownLoop → DownEnd | `bDownOutro` |
| DownLoop → Idle | `bDownQuit` |
| DownEnd → Idle | Automatic Rule Based on Sequence Player ✔ |

- 1 의 `ToDead` 에일리어스에 **DownLoop · DownEnd 도 체크** (빈사에서 죽는다)
- `resurrect` = **아군을 소생하는 쪽 동작** (사용자 2026-10-08) — AnimBP 작업 없음: 소생 중(`State.Reviving` 복제 태그) 몽타주로 반복 (채집과 같은 길) · 키 `Pres.Anim.Revive`
- 소생 뒤 모드(재키 R …)가 남아 있으면 Idle 에서 기존 모드 화살표가 다시 모드로 들어간다 — 그대로 둔다

## F14-01c 빈사 스킬 — 분열 폭발 Q · 집념 W · 자가 제세동 R ([Argument 79](../4_Argument/79_빈사스킬.md) N1 · I1 · T1 · M1 변형 · 코드 빌드 Editor · Server ✅ 2026-10-12)

**목적:** 빈사 중 Q · W · R 이 빈사 스킬로 나간다 (일반 스킬은 계속 막힘). 수치 = 사용자 표 (나무위키 가이드) · Q 반경 2m · R 집중 중 출혈 계속 · 실패 잠금 없음.

| 키 | 스킬 | 소모 (현재 체력) | 쿨 | 동작 |
|---|---|---|---|---|
| Q | 분열 폭발 | 20% | 10 | 4초 뒤 반경 2m 적에게 고정 150 + 대상 현재 체력 20% → 본인 사망 (처치 = 빈사로 만든 사람) · 취소 불가 · 그 사이 죽으면 폭발 없음 |

| R | 자가 제세동 | 90% | 20 | 20초 집중 (이동 · 다른 빈사 스킬 불가 · 출혈 계속) → 체력 25% 로 소생 · 다시 R / CC = 실패 → 쿨 16초 반환 |

**선행 조건:** 에디터 재시작 — 새 C++ 클래스 · 조각 · 설정 칸 · enum 값 → 빌드 뒤 에디터 재시작.
