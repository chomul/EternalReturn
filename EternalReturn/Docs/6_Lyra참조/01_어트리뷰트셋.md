# Lyra 참조 — 어트리뷰트 세트

읽은 파일: `Source/LyraGame/AbilitySystem/Attributes/` (`LyraAttributeSet` / `LyraHealthSet` / `LyraCombatSet`)

---

## 1. 세트를 **작게 쪼갠다**

```cpp
// LyraHealthSet.h:38-41
ATTRIBUTE_ACCESSORS(ULyraHealthSet, Health);
ATTRIBUTE_ACCESSORS(ULyraHealthSet, MaxHealth);
ATTRIBUTE_ACCESSORS(ULyraHealthSet, Healing);   // 메타
ATTRIBUTE_ACCESSORS(ULyraHealthSet, Damage);    // 메타

// LyraCombatSet.h:29-30
ATTRIBUTE_ACCESSORS(ULyraCombatSet, BaseDamage);
ATTRIBUTE_ACCESSORS(ULyraCombatSet, BaseHeal);
```

**전부 6개.** 공통 베이스 `ULyraAttributeSet` 은 어트리뷰트를 하나도 안 갖고
편의 함수 두 개만 준다 (`LyraAttributeSet.h:57-60`):

```cpp
UWorld* GetWorld() const override;
ULyraAbilitySystemComponent* GetLyraAbilitySystemComponent() const;
```

### 우리는

**33개를 한 세트에** 뒀다. 근거와 재검토 조건은
[`../4_Argument/3_어트리뷰트셋_구조.md`](../4_Argument/3_어트리뷰트셋_구조.md) E-6 절.

Lyra 는 캐릭터별 스탯 차이가 없어서 6개로 끝난다. 우리는 실험체마다 다르다.
**Lyra 가 쪼갠 걸 근거로 우리도 쪼개면 안 된다** — 규모가 다르고 이유가 다르다.

⚠ 다만 `ULyraAttributeSet` 처럼 **어트리뷰트 없는 공통 베이스**를 두는 건
나중에 고유 세트(에키온 VF 등)를 붙일 때 참고할 만하다. **(지금은 미적용)**

## 2. ⭐ 사망 알림을 **한 번만** 쏜다 — `bOutOfHealth`

우리 코드에 **없어서 결함이 됐던 부분**이다. (`Docs/5_ErrorReport/E04_사망알림_중복발동.md`)

```cpp
// LyraHealthSet.cpp:172-178
if ((GetHealth() <= 0.0f) && !bOutOfHealth)
{
    OnOutOfHealth.Broadcast(Instigator, Causer, &Data.EffectSpec, ...);
}

// Check health again in case an event above changed it.
bOutOfHealth = (GetHealth() <= 0.0f);
```

빗장은 세 곳에서 관리된다:

| 위치 | 하는 일 |
|---|---|
| `LyraHealthSet.cpp:172` | 0 이하 **이고 아직 안 쐈을 때만** 쏜다 |
| `LyraHealthSet.cpp:178` | 브로드캐스트 **뒤에** 다시 읽어서 갱신 (듣는 쪽이 회복시켰을 수 있다) |
| `LyraHealthSet.cpp:214-217` | `PostAttributeChange` 에서 체력이 0 보다 커지면 **빗장을 푼다** |

⭐ **왜 필요한가:** 이미 0 인 대상에 피해가 또 들어오면 델리게이트가 다시 나간다.
같은 프레임에 투사체 여러 개가 닿거나 도트가 겹치면 바로 발생한다.
킬 로그가 두 번 찍히고 경험치가 두 번 나간다.

### 우리는 — **그대로 채택**

`ERAttributeSet` 에 `bOutOfHealth` 를 같은 방식으로 넣었다.
다만 델리게이트는 **1인자(`Instigator`)** 로 유지했다. Lyra 는 6인자다 (`LyraAttributeSet.h:41`) —
지금 우리한테 필요한 건 킬 크레딧뿐이라 늘리지 않았다 (`CLAUDE.md` §2).

⚠ Lyra 는 `OnRep_Health` 에서도 **클라 쪽으로** 쐈다 (`LyraHealthSet.cpp:50-56`).
우리는 안 쐈다 — 사망 처리가 서버 권위고, 클라 연출은 GameplayCue 로 갈 예정이라서다.
**연출을 붙일 때 다시 볼 것.** **(미확인)**

## 3. 메타 어트리뷰트 — 우리와 같은 방식

```cpp
// LyraHealthSet.cpp:146-147
SetHealth(FMath::Clamp(GetHealth() - GetDamage(), MinimumHealth, GetMaxHealth()));
SetDamage(0.0f);            // ← 쓰고 즉시 비운다
```

`Damage` / `Healing` 둘 다 `GetLifetimeReplicatedProps` 에 **없다** (`LyraHealthSet.cpp:30-36` — `Health`, `MaxHealth` 만 등록).

### 우리는

`IncomingDamage` 하나만 뒀다. 회복은 아직 경로가 없다.
비우는 방식(`SetIncomingDamage(0.f)`)과 복제 제외는 동일하다.

⚠ **Lyra 는 회복도 메타로 받는다.** 회복 GE 를 만들 때 `IncomingHealing` 을 같은 형태로 추가하는 게 맞다. **(F02 범위 밖)**

## 4. `Meta = (HideFromModifiers)` — 우리가 안 쓰는 안전장치

```cpp
// LyraHealthSet.h:71
// Health is hidden from modifiers so only executions can modify it.
UPROPERTY(..., Meta = (HideFromModifiers, AllowPrivateAccess = true))
FGameplayAttributeData Health;
```

`Damage` 에도 붙어 있다 (`:97`). 목적은 **"GE 모디파이어로 체력을 직접 못 건드리게"** 다.

### ⚠ 다만 — 런타임 강제가 아니다

엔진에서 이 메타를 쓰는 곳은 한 군데뿐이다:

```cpp
// GameplayEffect.h:534
UPROPERTY(EditDefaultsOnly, Category=GameplayModifier, meta=(FilterMetaTag="HideFromModifiers"))
```

`FGameplayModifierInfo::Attribute` 의 **에디터 드롭다운을 걸러낼 뿐**이다.
C++ 로 모디파이어를 만들면 그대로 통과한다. **실수 방지용이지 보안장치가 아니다.**

### 우리는 — **아직 안 붙였다**

붙이면 좋지만 **F02-05 와 충돌한다.** 초기화 GE 가 `HP` 를 모디파이어로 세팅하는데,
`HP` 에 `HideFromModifiers` 를 달면 **에디터 애셋에서는 `HP` 를 고를 수 없다.**

→ **F02-05 의 GE 방식을 정한 뒤에 다시 판단한다.**

## 5. 클램프 — 우리와 같다

```cpp
// LyraHealthSet.cpp:221-233
void ULyraHealthSet::ClampAttribute(const FGameplayAttribute& Attribute, float& NewValue) const
{
    if (Attribute == GetHealthAttribute())
        NewValue = FMath::Clamp(NewValue, 0.0f, GetMaxHealth());
    else if (Attribute == GetMaxHealthAttribute())
        NewValue = FMath::Max(NewValue, 1.0f);
}
```

`PreAttributeChange`(`:186`) 와 `PreAttributeBaseChange`(`:180`) 가 **둘 다 이 함수 하나를 부른다.**
우리 `ERAttributeSet::ClampAttribute` 와 완전히 같은 구조다 — 독립적으로 같은 결론에 도달했다.

## 6. 최대 체력이 줄 때 — ⚠ **방법이 다르다**

```cpp
// LyraHealthSet.cpp:204-211
if (Attribute == GetMaxHealthAttribute())
{
    if (GetHealth() > NewValue)
    {
        ULyraAbilitySystemComponent* LyraASC = GetLyraAbilitySystemComponent();
        check(LyraASC);
        LyraASC->ApplyModToAttribute(GetHealthAttribute(), EGameplayModOp::Override, NewValue);
    }
}
```

Lyra 는 `ApplyModToAttribute` 를 쓰고, **우리는 `SetHP()` 를 쓴다.** 차이는:

| | 실제로 부르는 것 | 권위 검사 |
|---|---|---|
| `SetHP(x)` | `SetNumericAttributeBase` (`AttributeSet.h:446`) | ❌ 없음 |
| `ApplyModToAttribute` | `ActiveGameplayEffects.ApplyModToAttribute` | ✅ `IsOwnerActorAuthoritative()` (`AbilitySystemComponent.cpp:439`) |

### ⭐ 확인 결과 — `PostAttributeChange` 는 **클라에서도 불린다**

Lyra 가 굳이 `ApplyModToAttribute` 를 쓴 이유가 여기 있었다. 복제 경로를 따라가면:

```
OnRep_MaxHP
  -> GAMEPLAYATTRIBUTE_REPNOTIFY            (AttributeSet.h:401-405)
  -> SetBaseAttributeValueFromReplication   (GameplayEffect.cpp:3471)
  -> OnAttributeAggregatorDirty             (:3228 이 Owner->IsNetSimulating() 을 처리한다)
  -> InternalUpdateNumericalAttribute       (:3671)
  -> SetNumericValueChecked                 (AttributeSet.cpp:102)
  -> PostAttributeChange                             ← 클라에서 여기까지 온다
```

`GameplayEffect.cpp:3491` 의 로그가 이걸 못박는다 —
`OwnerIsNetAuthority ? TEXT("Authority") : TEXT("Client")`.

그리고 두 방법의 권위 검사가 다르다:

| | 실제로 부르는 것 | 권위 검사 |
|---|---|---|
| `SetHP(x)` | `SetNumericAttributeBase` (`AttributeSet.h:446`) | ❌ **없다** |
| `ApplyModToAttribute` | `ActiveGameplayEffects.ApplyModToAttribute` | ✅ `IsOwnerActorAuthoritative()` (`AbilitySystemComponent.cpp:439`) |

→ 우리 코드는 **클라가 자기 베이스 값을 고치고 있었다.**
`IsOwnerActorAuthoritative()` 가드를 넣어 고쳤다.
기록: [`../5_ErrorReport/E05_PostAttributeChange_클라권위.md`](../5_ErrorReport/E05_PostAttributeChange_클라권위.md)

⭐ **교훈:** `Set<어트리뷰트>()` 는 권위를 안 본다. **불리는 함수가 서버 전용인지 먼저 확인한다.**
`PostGameplayEffectExecute` 는 서버 전용이라 안전하고, `PostAttributeChange` 는 아니다.

## 7. `PreGameplayEffectExecute` — 우리가 아직 안 쓰는 훅

`bool` 을 반환하고, **`false` 면 그 모디파이어가 통째로 취소된다.**

```cpp
// LyraHealthSet.cpp:80-88
if (Data.Target.HasMatchingGameplayTag(TAG_Gameplay_DamageImmunity) && !bIsDamageFromSelfDestruct)
{
    Data.EvaluatedData.Magnitude = 0.0f;
    return false;      // 피해 자체를 무효화
}
```

### 우리한테 쓸 곳

**무적(`State.Invulnerable`) 판정이 여기 들어가야 한다.** `ERGameplayTags.h` 에 태그는 이미 있다.
데미지 GE(F03) 를 만들 때 이 훅에 붙인다.

⚠ 그리고 Lyra 는 여기서 **변경 전 값을 캐싱**한다 (`LyraHealthSet.cpp:100-101`) —
`PostGameplayEffectExecute` 에서 "얼마나 변했는지"를 알려면 필요하다. 우리는 아직 안 쓴다.
