# Lyra 참조 — `ULyraAbilitySet` 으로 묶어서 부여

읽은 파일: `Source/LyraGame/AbilitySystem/LyraAbilitySet.h/.cpp`, `Source/LyraGame/Character/LyraPawnData.h`

---

## 1. 데이터 애셋 하나가 셋을 묶는다

`ULyraAbilitySet` 은 **어빌리티 + GE + 어트리뷰트셋**을 한 애셋에 담는다.

```cpp
// LyraAbilitySet.h:52-64
struct FLyraAbilitySet_GameplayEffect
{
    UPROPERTY(EditDefaultsOnly) TSubclassOf<UGameplayEffect> GameplayEffect = nullptr;
    UPROPERTY(EditDefaultsOnly) float EffectLevel = 1.0f;
};

// LyraAbilitySet.h:73-82
struct FLyraAbilitySet_AttributeSet
{
    UPROPERTY(EditDefaultsOnly) TSubclassOf<UAttributeSet> AttributeSet;
};
```

폰별 데이터 애셋이 이걸 배열로 참조한다:

```cpp
// LyraPawnData.h:37-39
UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = "Lyra|Abilities")
TArray<TObjectPtr<ULyraAbilitySet>> AbilitySets;
```

⭐ **핵심:** "이 폰은 무엇을 갖는가"가 **C++ 이 아니라 애셋**에 있다.
캐릭터를 추가할 때 코드를 안 고친다.

---

## 2. ⭐ 어트리뷰트셋을 **런타임에** 붙인다

```cpp
// LyraAbilitySet.cpp:141-142
UAttributeSet* NewSet = NewObject<UAttributeSet>(LyraASC->GetOwner(), SetToGrant.AttributeSet);
LyraASC->AddAttributeSetSubobject(NewSet);
```

생성자의 `CreateDefaultSubobject` 가 아니다. **`NewObject` + `AddAttributeSetSubobject`** 다.

### 왜 중요한가 — 우리 E-3 결정의 실물 증거

[`../4_Argument/3_어트리뷰트셋_구조.md`](../4_Argument/3_어트리뷰트셋_구조.md) E-3 에서
**"공통 세트 + 캐릭터별 고유 세트를 병렬로 추가"** 로 정했다.
그게 실제로 도는 패턴이라는 걸 Lyra 가 보여준다.

⚠ **주의:** `NewObject` 의 Outer 가 `LyraASC->GetOwner()` 다 — ASC 가 아니라 **소유 액터**다.
ASC 의 `InitializeComponent` 가 `GetObjectsWithOuter(Owner)` 로 세트를 자동 등록하기 때문이다.
Outer 를 잘못 주면 **조용히 등록이 안 된다.**

### 우리는

`ERPlayerState` 생성자에서 `CreateDefaultSubobject` 로 **공통 세트**를 만든다.
전 캐릭터가 항상 갖는 것이라 생성자가 맞다.

→ **에키온 VF 같은 고유 세트를 붙일 때 이 방식으로 간다.** (F02 범위 밖)

---

## 3. GE 는 `ApplyGameplayEffectToSelf` 로

```cpp
// LyraAbilitySet.cpp:119-120
const UGameplayEffect* GameplayEffect = EffectToGrant.GameplayEffect->GetDefaultObject<UGameplayEffect>();
const FActiveGameplayEffectHandle Handle = LyraASC->ApplyGameplayEffectToSelf(
    GameplayEffect, EffectToGrant.EffectLevel, LyraASC->MakeEffectContext());
```

⚠ **`SetByCaller` 를 쓰지 않는다.** Lyra 는 캐릭터별 스탯 차이가 없어서
GE 애셋에 값이 박혀 있어도 된다.

---

## 4. 부여한 것을 **핸들로 들고 있다가 회수**한다

`FLyraAbilitySet_GrantedHandles` 가 부여한 어빌리티·GE·세트의 핸들을 전부 모아둔다
(`LyraAbilitySet.cpp:122-125`, `:143-146`). 나중에 통째로 떼어낼 수 있다.

### 우리한테 쓸 곳

**장비 착용/해제**(F09), **부활 시 상태 초기화**(F14) 에서 같은 문제가 나온다.
"준 것을 정확히 되돌리는" 구조가 필요할 때 이걸 참고한다.

---

## 5. 유효성 검사를 **에러 로그로** 남긴다

```cpp
// LyraAbilitySet.cpp:113-117
if (!IsValid(EffectToGrant.GameplayEffect))
{
    UE_LOG(LogLyraAbilitySystem, Error, TEXT("GrantedGameplayEffects[%d] on ability set [%s] is not valid"),
        EffectIndex, *GetNameSafe(this));
    continue;
}
```

⭐ **인덱스와 애셋 이름을 둘 다 찍는다.** 애셋에서 빈 칸 하나를 찾을 때 이게 없으면 못 찾는다.

### 우리한테

GAS 는 **없는 걸 조용히 건너뛴다** (`GameplayEffect.cpp:4238`).
그래서 **애셋을 읽는 쪽이 직접 검사하고 로그를 찍어야 한다.**
F02-05 의 데이터 테이블 행을 읽을 때 같은 형태로 남긴다.
