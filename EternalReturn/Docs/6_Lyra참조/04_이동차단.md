## 무엇을 찾으러 갔나

"기절 중에 못 움직이게 한다"를 **어디에** 넣어야 클라 예측과 어긋나지 않는가.

## Lyra 가 하는 것

`ULyraCharacterMovementComponent` 가 두 함수를 오버라이드한다.

```cpp
// LyraCharacterMovementComponent.cpp:119-130
float ULyraCharacterMovementComponent::GetMaxSpeed() const
{
    if (UAbilitySystemComponent* ASC = UAbilitySystemGlobals::GetAbilitySystemComponentFromActor(GetOwner()))
    {
        if (ASC->HasMatchingGameplayTag(TAG_Gameplay_MovementStopped))
        {
            return 0;
        }
    }
    return Super::GetMaxSpeed();
}
```

```cpp
// LyraCharacterMovementComponent.cpp:106-117
FRotator ULyraCharacterMovementComponent::GetDeltaRotation(float DeltaTime) const
{
    // ... 같은 태그 검사 ...
    return FRotator(0,0,0);
}
```

태그는 하나다.

```cpp
// LyraCharacterMovementComponent.cpp:13
UE_DEFINE_GAMEPLAY_TAG(TAG_Gameplay_MovementStopped, "Gameplay.MovementStopped");
```

---

## ⭐ 배운 것 1 — 왜 이 자리인가 (우리에게도 그대로 성립한다)

`GetMaxSpeed()` 는 속도 계산 안에서 호출된다.

```
CalcVelocity()                          CharacterMovementComponent.cpp:3641
   └─ float MaxSpeed = GetMaxSpeed();   :3651
```

⭐ **이 경로는 클라 예측 · 서버 재생 · 서버 보정 후 리플레이가 전부 같이 탄다.**
(`ClientUpdatePositionAfterServerUpdate` → `MoveAutonomous` → 같은 `PerformMovement`,
`CharacterMovementComponent.cpp:8230`, `:8302`)

태그는 ASC 가 복제하므로 클라와 서버가 **같은 값을 보고 같은 결과**를 낸다.
→ **이동 차단용 RPC 가 필요 없다.** 만들면 오히려 두 경로가 어긋난다.

⚠ 반대로 **`AddLooseGameplayTag` 는 못 쓴다.** 복제되지 않으므로 서버만 막히고
클라는 계속 움직인다 → 서버가 되돌린다 → **고무줄.**

## ⭐ 배운 것 2 — 회전도 막아야 한다

`GetMaxSpeed` 만 막으면 **제자리에서 방향은 계속 돌아간다.**
Lyra 가 `GetDeltaRotation` 을 함께 막는 이유다. 우리도 그대로 가져왔다.

---

## ⚠ Lyra 를 그대로 쓰지 않은 것 — 태그 개수

| | Lyra | 우리 |
|---|---|---|
| 이동을 막는 상황 | **1종** | ⭐ **기절 · 수면 · 제압 · 에어본 · 경직 · 붙잡기 …** |
| 차단 축 | 이동만 | ⭐ **이동 · 평타 · 스킬 3축** |
| 태그 | `Gameplay.MovementStopped` 1개 | `State.Block.Movement` / `BasicAttack` / `Skill` |

⭐ **Lyra 는 팀 슈터여서 CC 시스템이 없다.** 이동을 막는 상황이 한 종류뿐이라
태그 1개로 충분했다. 그 *이유*가 우리에게는 성립하지 않는다 (`CLAUDE.md` §11).

우리는 역기획서 §3.1·§3.3 이 **3축 × 10종 이상**을 요구하고,
**속박**처럼 축이 갈리는 CC(이동은 막고 스킬은 허용)가 있다.

→ **패턴은 그대로, 태그만 1개에서 축 3개로.**
전문: [`../4_Argument/10_CC_차단축_태그설계.md`](../4_Argument/10_CC_차단축_태그설계.md)

## ⚠ Lyra 가 하지 않아서 우리가 정해야 했던 것

| 항목 | Lyra | 우리 결정 |
|---|---|---|
| 태그를 **누가** 부여하나 | 어빌리티가 직접 | ⭐ **CC GE 애셋의 `GrantedTags`** (문서 9 방안 A) |
| 지속시간 | 어빌리티가 관리 | ⭐ **GE Duration + `SetByCaller`** — 스킬마다 다르다 |
| 축 태그 누락 검사 | 없음 (태그 1개라 불필요) | ⭐ **`ERCCLibrary` 가 검사 + 로그** |

⚠ 마지막 항목이 A 를 고른 대가다. 축 태그를 빠뜨리면 조용히 안 막히므로
**부여 경로를 한 곳으로 모아 거기서 검사**한다.

## ⚠ 성능 — 지금 손대지 않은 것

`IsMovementBlocked()` 가 **매 프레임 여러 번** ASC 를 조회한다. Lyra 도 같다.

⚠ **캐시하지 않았다.** 24명 + 야생동물 규모에서 실제로 문제인지 측정 전에는 알 수 없고,
추측으로 넣은 캐시는 태그 변화를 놓친다. 필요해지면
`ASC->RegisterGameplayTagEvent` 로 bool 을 유지하는 것이 올바른 방향이다
(태그가 바뀔 때만 갱신된다). **측정 후에 판단한다.**
