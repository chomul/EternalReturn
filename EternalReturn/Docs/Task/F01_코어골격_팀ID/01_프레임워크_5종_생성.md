# F01-01 — 프레임워크 5종 생성

> 기능 [F01 코어 골격 · 팀 ID](00_개요.md) · 선행 없음
> 체크리스트 [`01_프레임워크_5종_생성.md`](../../Checklist/F01_코어골격_팀ID/01_프레임워크_5종_생성.md)

## 할 일

프레임워크 클래스 5종을 **빈 상태로** 만들고, `AERGameMode` 가 나머지를 쓰도록 연결한다.

| 클래스 | 부모 | 어디에 존재하나 |
|---|---|---|
| `AERGameMode` | `AGameModeBase` | ⭐ **서버에만.** 클라에는 복제되지 않는다 |
| `AERGameState` | `AGameStateBase` | 모두에게 복제 |
| `AERPlayerState` | `APlayerState` | 모두에게 복제 |
| `AERPlayerController` | `APlayerController` | 소유 클라 + 서버 |
| `AERCharacterBase` | `ACharacter` | 릴리번시에 따라 |

`AERGameMode` 생성자에서 기본 클래스를 지정한다.

```cpp
// AERGameMode 생성자
DefaultPawnClass      = AERCharacterBase::StaticClass();
PlayerStateClass      = AERPlayerState::StaticClass();
PlayerControllerClass = AERPlayerController::StaticClass();
GameStateClass        = AERGameState::StaticClass();
```

## 왜 이렇게 하나

- **빈 껍데기부터 만드는 이유:** 지금 스탯·인벤토리 멤버를 넣으면 F02·F08이 이 파일을 다시 고쳐야 한다. 상향식에서는 **각 기능이 자기 컴포넌트를 들고 와서 붙는다.**
- 역할 분담 근거: [네트워크 문서](../../GameDesign/Systems/네트워크_서버아키텍처_역기획서.md) §2 — *"어떤 데이터가 어느 클래스에 가야 하는지"* 판단 기준 Q1~Q3.

## 검증

- **빌드 통과** — `EternalReturnEditor` **와** `EternalReturnServer` 둘 다.
- PIE 실행 시 `AERCharacterBase` 가 스폰된다 (`UE_LOG` 로 클래스명 확인).

## 주의점

- 헤더에서는 **전방 선언**을 쓰고 include는 `.cpp` 로 내린다. `.generated.h` 는 include 목록의 **맨 마지막** (`CLAUDE.md` §3).
- 생성자에서 **게임 로직·월드 접근 금지.** `CreateDefaultSubobject` 만 (`CLAUDE.md` §5).
- ⚠ **에디터가 열려 있으면 링크가 실패한다.** `Cannot open ... UnrealEditor-EternalReturn.dll` 이 나오면 에디터를 닫고 재빌드한다.
- ⚠ 기존 애셋 `BP_RGameMode` / `BP_ERCharacter` 가 **삭제된 클래스를 부모로 참조**하고 있다. 클래스 이름을 이전과 같게 만들면 애셋이 다시 붙을 수 있지만, **애셋 조작은 `Content/` 라 직접 하지 않는다** — 에디터 작업이 필요하면 `Docs/EditorTasks/` 로 넘긴다 (`CLAUDE.md` §9).
