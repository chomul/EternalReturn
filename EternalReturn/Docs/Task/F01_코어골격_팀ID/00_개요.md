# F01 — 코어 골격 · 팀 ID

> 체크리스트 [`../../Checklist/F01_코어골격_팀ID/`](../../Checklist/F01_코어골격_팀ID/00_기능_완료판정.md)

## 목표

게임플레이 클래스가 하나도 없는 상태에서 **프레임워크 5종의 빈 골격과 팀 개념**을 세운다.
끝나면 데디케이티드 서버에 접속한 인원이 팀으로 나뉜 채 서 있을 수 있다.

## 왜 이게 첫 번째인가

- 소스 트리에 모듈 진입점밖에 없다. **다른 기능이 붙을 자리가 없다.**
- ⚠ **팀 개념이 프로젝트에 전혀 없다.** [팀시야 문서](../../GameDesign/Systems/팀시야_포그오브워_역기획서.md) 구현 우선순위 1순위가 *"팀 ID 인프라 … 시야보다 먼저다"* 라고 지적했다. 팀은 시야만이 아니라 아군 오사 판정·부활·UI가 전부 쓴다.

## 독립 구현 전략

- **빈 껍데기만 만든다.** 스탯·스킬·인벤토리 멤버를 지금 넣지 않는다. 각 기능이 자기 컴포넌트를 들고 온다.
- 팀 ID는 `AERPlayerState` 에 두되, **접근은 공용 함수로만** 한다(Task 04). 그래야 나중에 배치를 바꿔도 호출부가 안 깨진다.

## ⚠ F00(GAS 기반 세팅)과 겹치는 부분

**`AERPlayerState` 를 양쪽이 건드린다.**

| 파일 | F01이 넣는 것 | F00이 넣는 것 |
|---|---|---|
| `ERPlayerState.h/.cpp` | `TeamId` + 복제 | ASC + `IAbilitySystemInterface` (F00-03) |

**어느 쪽을 먼저 해도 된다.** 다만 나중에 하는 쪽이 **기존 내용을 지우지 않게** 주의한다.

⭐ **F01은 GAS를 모른다.** 팀 ID는 GAS 어트리뷰트가 아니라 일반 복제 프로퍼티다.
팀은 어트리뷰트(수치)가 아니라 **소속**이므로 `UAttributeSet` 에 넣지 않는다.
