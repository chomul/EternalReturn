## 할 일

**하나의 판정이 두 개의 결과 집합**을 돌려준다.

```cpp
static FTargetResult QueryDualRadius(const UWorld* World, const FTargetQuery& Q);
// 결과: InnerHitActors (RadiusInner 안) + HitActors (RadiusOuter 안, 중앙 제외)
```

요구 사례: ⭐ **레니 W — 중앙 1.25m / 외곽 2.25m**, 두 구간의 **효과가 다르다.**
활 D(곡사)도 *"중앙 2배 피해"* 로 같은 구조다.

## 왜 판정 계층에서 갈라야 하나

호출자(스킬)가 하나의 배열을 받아서 다시 거리로 나누면:

- **거리를 두 번 계산**한다 (판정에서 한 번, 스킬에서 한 번)
- 두 계산 사이에 **대상이 움직이면** 경계에 있던 대상의 판정이 흔들린다
- 이중 반경을 쓰는 스킬마다 **같은 분류 코드가 복사**된다

F04-01에서 `InnerHitActors` 를 따로 만들어 둔 이유가 이것이다.

## 경계 처리를 정해야 한다

```
대상이 정확히 1.25m 지점에 있으면 → 중앙인가 외곽인가?
```

**중앙 우선**으로 정하고 주석에 남긴다 (`거리 <= RadiusInner` 면 중앙).
**(미확인)** 이므로 자체 결정값임을 표기한다.

⭐ **한 대상이 양쪽 배열에 모두 들어가면 안 된다.** 피해가 두 번 들어간다.

## 검증

- **빌드 통과**
- ⭐ 중앙 1.25m 안 액터 → `InnerHitActors` 에만
- ⭐ 1.25~2.25m 액터 → `HitActors` 에만
- ⭐ **어떤 액터도 양쪽에 동시에 들어가지 않는다**
- 2.25m 밖 액터 → 양쪽 다 없음
- 정확히 1.25m 지점 → 정한 규칙대로 (중앙)
- 두 배열이 각각 **가까운 순 정렬**

## 주의점

- ⭐ **중복 포함이 가장 위험하다.** 피해가 2회 들어가면 레니 W가 설계보다 2배 강해진다. 검증 항목에 반드시 넣는다.
- `RadiusInner > RadiusOuter` 로 잘못 들어올 수 있다 — **스왑하거나 경고 로그**를 남긴다. 조용히 잘못된 결과를 내지 않는다.
- `RadiusInner == 0` 이면 중앙이 없는 일반 원형으로 동작해야 한다 (안전한 기본값).
- 레니 W는 **아군에게도 효과가 있다** (아군 = 회복·이속·보호막). 팀 필터와 조합되므로 **F04-06과 함께 검증**한다.
