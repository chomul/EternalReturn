# F03-04 — 치명타 · 채널 분기 ⭐

> 기능 [F03 데미지 ExecutionCalculation](00_개요.md) · 선행 [03 방어 관통](03_방어관통.md)
> 체크리스트 [`04_치명타_채널분기.md`](../../Checklist/F03_데미지_ExecutionCalc/04_치명타_채널분기.md)

## 할 일

피해 채널을 **GameplayTag로 판별**하고, 치명타를 **기본 공격에서만** 발생시킨다.

```cpp
const FGameplayTagContainer& SourceTags = *Spec.CapturedSourceTags.GetAggregatedTags();

// ⭐ 채널 검사가 먼저
if (SourceTags.HasTag(ERTags::Damage_Type_BasicAttack))
{
    if (FMath::FRand() < CritChance)          // 서버에서만 실행되는 자리
        Damage *= (1.f + CritDamage);         // 기본 175% = 0.75 추가
}
```

## 채널 → 태그 대응

F00-05에서 정한 태그를 쓴다.

| 채널 | 태그 | 방어력 | 치명타 |
|---|---|---|---|
| 기본 공격 | `Damage.Type.BasicAttack` | O | **O** |
| 스킬 | `Damage.Type.Skill` | O | **X** |
| 고정 피해 | `Damage.Type.True` | **X** | X |

## ⭐ 왜 스킬에는 치명타가 없나

[스탯 문서 §7 4순위](../../GameDesign/Systems/스탯_데미지공식_역기획서.md) 검증 기준이 이것 하나다 —
***"스킬 채널에서는 어떤 경우에도 치명타가 발생하지 않음"***.

밸런스의 뼈대다. 스킬에 치명타가 붙으면 **스킬 딜러가 치명타를 쌓아** 설계 의도가 무너진다.

## GAS에서 이게 더 위험해지는 이유

자체 구현에서는 `EDamageChannel` 열거형이라 **값을 안 넣으면 컴파일이 걸렸다.**
GAS에서는 **태그를 안 붙이면 아무 일도 안 일어난다** — 조용히 어느 분기에도 안 들어간다.

⭐ **태그가 없는 GE를 만나면 경고 로그를 남긴다.** 조용히 통과시키지 않는다.

## 난수와 예측

`FMath::FRand()` 는 Execution 안에서 실행되고, **Execution은 서버에서만 돈다.**
클라가 난수를 굴려 다시 뽑는 경로가 구조적으로 없다.

⚠ 다만 **GAS 예측을 켜면 이야기가 달라진다.** 지금은 예측을 켜지 않는다 (`CLAUDE.md` §8).

## 검증

| 입력 | 기대 |
|---|---|
| ⭐ **스킬 태그** + 치명타 확률 100% | **치명타 발생 안 함** |
| ⭐ **고정 피해 태그** + 확률 100% | **치명타 발생 안 함** |
| 기본 공격 태그 + 확률 100% + 175% | 원시 피해의 **1.75배** |
| 기본 공격 태그 + 확률 0% | 항상 기본 피해 |
| ⭐ **태그 없음** | **경고 로그**가 남는다 |

- **빌드 통과** (Editor + Server)

## 주의점

- ⭐ **채널 검사를 조건문 맨 앞에** 둔다. 확률을 먼저 계산하고 나중에 채널을 보면, 리팩터링 중 순서가 뒤집혀 스킬에 치명타가 붙는다.
- ⭐ **태그 누락을 조용히 넘기지 않는다.**
- 치명타 발생을 UI에 알려야 한다 (데미지 텍스트) — **`GameplayCue`** 로 처리한다. Execution 안에서 이펙트를 재생하지 않는다.
- 치명타 적용 시점(방어력 전/후)을 정하고 주석에 남긴다.
- 태그를 문자열로 박지 않는다 (F00-05).
