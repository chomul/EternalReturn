## 목표

**이 프로젝트의 모든 피해가 예외 없이 통과하는 `UGameplayEffectExecutionCalculation` 하나.**

```cpp
class UERDamageExecution : public UGameplayEffectExecutionCalculation
{
    virtual void Execute_Implementation(const FGameplayEffectCustomExecutionParameters& ExecParams,
                                        FGameplayEffectCustomExecutionOutput& OutExecutionOutput) const override;
};
```
기반 클래스: `GameplayEffectExecutionCalculation.h:258`

## ⭐ 왜 이게 가장 중요한가 — GAS로 바뀌어도 그대로다

[스탯 문서 §7](../../GameDesign/Systems/스탯_데미지공식_역기획서.md) 주석:
*"**2순위가 이 문서의 전부다.** 나머지는 전부 2순위 함수에 인자를 더하는 작업이다.
순서를 바꿔 캐릭터 스킬을 먼저 만들면 계산식이 캐릭터마다 복제되고 …"*

GAS에서 계산식이 흩어지는 방식은 두 가지다 — **어빌리티 안에서 직접 계산**하거나, **ExecutionCalculation을 여러 개** 만들거나.
둘 다 하지 않는다. **Execution은 하나다.**

## ⚠ 이전 계획과 달라진 점

| 이전 (자체 구현) | GAS |
|---|---|
| `CalculateDamage(FDamageContext&)` 정적 함수 | `UERDamageExecution::Execute_Implementation()` |
| 호출자가 `FDamageContext` 를 손으로 채움 | ⭐ **`FGameplayEffectAttributeCaptureDefinition` 이 자동 캡처** |
| 결과를 반환 → 호출자가 체력 차감 | ⭐ **`IncomingDamage` Meta 어트리뷰트에 출력** → F02-04가 처리 |
| 흡혈을 별도 함수로 분리 | GE + `GameplayCue` 또는 별도 Execution |
| 쿨다운 환산 함수 | ⭐ **Cooldown GE의 Duration** — 여기서 안 한다 |
