## 할 일

`Execute_Implementation()` 을 구현한다. **이 프로젝트에서 피해를 계산하는 유일한 자리다.**

```cpp
void UERDamageExecution::Execute_Implementation(
    const FGameplayEffectCustomExecutionParameters& ExecParams,
    FGameplayEffectCustomExecutionOutput& OutExecutionOutput) const
{
    // 1. 캡처값 읽기
    float Defense = 0.f;
    ExecParams.AttemptCalculateCapturedAttributeMagnitude(
        FERDamageStatics::Get().DefenseDef, EvalParams, Defense);

    // 2. 스킬이 넘긴 원시 피해 (SetByCaller)
    const float RawDamage = Spec.GetSetByCallerMagnitude(ERTags::Data_Damage, false, 0.f);

    // 3. 방어력 적용:  100 / (100 + DEF)
    const float Mitigated = RawDamage * (100.f / (100.f + FMath::Max(Defense, 0.f)));

    // 4. IncomingDamage 에 출력  ← F02-04 가 받아서 체력에서 뺀다
    OutExecutionOutput.AddOutputModifier(FGameplayModifierEvaluatedData(
        FERDamageStatics::Get().IncomingDamageProperty, EGameplayModOp::Additive, Mitigated));
}
```

## 왜 `100 / (100 + DEF)` 인가

[스탯 문서 §6.2](../../GameDesign/Systems/스탯_데미지공식_역기획서.md) (공식 고객센터 원문 기반) · §6.3 방어력 감소 곡선.
원본 §12.5 M1 최소 사양도 *"데미지 공식(방어력 100/(100+DEF) 모델 + 고정 피해 채널)"* 로 못 박았다.

방어력이 올라갈수록 효율이 떨어지지만 0이 되지 않는다 — **무한 방어가 안 나온다.**

## ⭐ 원시 피해는 SetByCaller로 받는다

스킬마다 계수가 다르다. 그 값을 **어빌리티가 GE Spec에 넣어** 넘긴다.

```cpp
// 어빌리티 쪽 (F07)
Spec->SetSetByCallerMagnitude(ERTags::Data_Damage, ComputedRawDamage);
```

⭐ **어빌리티는 "얼마"만 넘기고, "어떻게 깎이는지"는 전혀 모른다.** 이게 계산식을 한 곳에 묶는 방법이다.

## 고정 피해 채널

`True` 채널은 방어력을 적용하지 않는다. **GameplayTag로 판별**한다 (F00-05).

```cpp
if (Spec.CapturedSourceTags.GetSpecTags().HasTag(ERTags::Damage_Type_True))
    Mitigated = RawDamage;   // 방어력 무시
```

## 주의점

- ⭐ **체력을 직접 건드리지 않는다.** `IncomingDamage` 에 출력만 한다. 체력 차감은 F02-04다. 이 분리를 깨면 클램프·사망 알림이 우회된다.
- ⭐ **여기서 클램프하지 않는다.** F02-03의 `PreAttributeChange` 가 한다.
- 분모가 0 이하가 되지 않게 `FMath::Max(Defense, 0.f)`. 음수 방어력은 F03-03(관통)에서 생긴다.
- Execution은 **서버에서만** 실행된다. 별도 가드는 불필요하다.
- ⭐ **이 파일에 로그·이펙트·사운드를 섞지 않는다.** 연출은 `GameplayCue` 다 (`CLAUDE.md` §8).
- 「최종 피해 추가(%)」는 **적용하지 않고 보류**한다. `(1+x)` 인지 `x` 인지 모른 채 넣으면 피해량이 배 단위로 틀린다.
