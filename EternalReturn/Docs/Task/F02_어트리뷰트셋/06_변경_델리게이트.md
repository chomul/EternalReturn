# F02-06 — 변경 델리게이트

> 기능 [F02 어트리뷰트셋](00_개요.md) · 선행 [05 초기값 데이터 테이블](05_초기값_데이터테이블.md)
> 체크리스트 [`06_변경_델리게이트.md`](../../Checklist/F02_어트리뷰트셋/06_변경_델리게이트.md)

## 할 일

UI(F17)와 다른 시스템이 어트리뷰트 변화를 **듣는 통로**를 만든다.

⭐ **자체 델리게이트를 새로 만들지 않는다.** ASC가 이미 제공한다.

```cpp
ASC->GetGameplayAttributeValueChangeDelegate(UERAttributeSet::GetHealthAttribute())
   .AddUObject(this, &UMyWidget::OnHealthChanged);
```

## 왜 자체 델리게이트를 안 만드나

이전 계획은 `FOnStatChanged` 자체 멀티캐스트였다. **GAS에 이미 있다** (`CLAUDE.md` §8 — GAS가 제공하는 것을 다시 만들지 않는다).

ASC 델리게이트는 추가로 이걸 해준다.
- 어트리뷰트 **단위로** 구독한다 — 체력만 듣는 위젯이 공격력 변화에 깨어나지 않는다
- 서버·클라 양쪽에서 일관되게 발동한다
- 예측 롤백도 변화로 잡힌다

## ⭐ UMG Property Binding을 쓰지 않는다

[UI 문서](../../GameDesign/Systems/UI_HUD_역기획서.md)가 못 박았다 — **UMG Property Binding은 매 프레임 호출된다.**
체력바를 바인딩으로 만들면 24명분 위젯이 매 프레임 돈다.

**값이 변할 때만 델리게이트로 갱신한다.**

## ⭐ AttributeSet은 UI를 몰라야 한다

이 Task에서 만드는 것은 **"들을 수 있는 통로"** 뿐이다.
`ERAttributeSet.cpp` 에 위젯을 아는 코드가 한 줄도 없어야 한다. **구독은 듣는 쪽이 한다.**

그래야 F17 없이 F02가 완성된다.

## 할 일 정리

1. 사망 알림 델리게이트를 노출한다 (F02-04에서 만든 것)
2. 구독 방법을 **문서화**한다 — 나중에 F17이 이걸 보고 붙인다
3. 테스트용 구독 코드로 동작을 확인한다 (임시, 나중에 제거)

## 만질 파일

```
Source/EternalReturn/GAS/ERAttributeSet.h / .cpp
```

## 검증 — `Play As Client, Number of Players: 2`

- **빌드 통과** (Editor + Server)
- ⭐ 서버에서 GE로 체력을 바꾸면 **클라에서 델리게이트가 발동**한다
- 체력만 구독한 리스너가 공격력 변화에는 **안 깨어난다**
- 체력 0 시 사망 델리게이트가 발동한다
- ⭐ `Tick` 없이 동작한다

## 주의점

- ⭐ **구독 시점.** ASC 초기화(F00-03) 이후여야 한다. 클라에서는 `OnRep_PlayerState` 이후다.
- ⭐ **구독 해제를 반드시 한다.** 위젯이 파괴될 때 해제하지 않으면 dangling 델리게이트가 남는다.
- 구독은 **약한 참조**로 건다 (`AddUObject` 는 UObject 수명을 따른다).
- 테스트용 임시 구독 코드는 **작업이 끝나면 지운다** (`CLAUDE.md` §3 — 내가 만든 쓰레기만 치운다).
- 이 델리게이트는 **값 변화**를 알린다. "누가 때렸나" 같은 맥락은 없다 — 그건 F03의 `GameplayCue` 나 이펙트 컨텍스트가 다룬다.
