# F02-03 — 클램프 · 상한

> 기능 [F02 어트리뷰트셋](00_개요.md) · 선행 [02 복제 · OnRep](02_복제_OnRep.md)
> 체크리스트 [`03_클램프_상한.md`](../../Checklist/F02_어트리뷰트셋/03_클램프_상한.md)

## 할 일

어트리뷰트 값의 범위를 강제한다. **엔진이 정해둔 자리가 따로 있다.**

```cpp
void UERAttributeSet::PreAttributeChange(const FGameplayAttribute& Attribute, float& NewValue)
{
    Super::PreAttributeChange(Attribute, NewValue);
    if (Attribute == GetHealthAttribute())
        NewValue = FMath::Clamp(NewValue, 0.f, GetMaxHealth());
    // 쿨다운 감소·치명타 확률 등 상한
}

void UERAttributeSet::PreAttributeBaseChange(const FGameplayAttribute& Attribute, float& NewValue) const
{
    Super::PreAttributeBaseChange(Attribute, NewValue);
    // Base 값까지 자르려면 여기서도 같은 클램프
}
```

## ⭐ 엔진 주석이 이 자리를 지정한다

`AttributeSet.h:208-212` (`PreAttributeChange`):

> *"Called just before any modification happens to an attribute. … This function is meant to enforce things like **"Health = Clamp(Health, 0, MaxHealth)"** and **NOT** things like "trigger this extra thing if damage is applied, etc"."*

`AttributeSet.h:222-225` (`PreAttributeBaseChange`):

> *"This function should enforce clamping (presuming you wish to clamp the base value along with the final value in PreAttributeChange). This function should **NOT invoke gameplay related events or callbacks.** Do those in PreAttributeChange()…"*

⭐ **즉 클램프는 여기, 게임플레이 반응은 다른 곳.** 이 자리에 사망 처리나 이펙트를 넣지 않는다.

## Current만 자를지 Base까지 자를지

| | 자르는 것 | 필요한 때 |
|---|---|---|
| `PreAttributeChange` | Current (최종값) | 항상 |
| `PreAttributeBaseChange` | Base (영구값) | Base를 직접 바꾸는 GE가 있을 때 |

체력은 Base가 바뀐다(피해). **둘 다 건다.**

## 어떤 상한이 필요한가

[스탯 문서 §7 6순위](../../GameDesign/Systems/스탯_데미지공식_역기획서.md) 검증 기준이 이유를 보여준다 —
**"피해 감소 150%를 넣어도 회복이 발생하지 않는다."**

상한이 없으면:
- 피해 감소 100% 초과 → 맞을 때마다 체력이 **차오른다**
- 쿨다운 감소 100% → 쿨다운 **0초**, 무한 연사
- 이동속도 무제한 → 맵을 한 프레임에 횡단

**밸런스 문제가 아니라 게임이 깨지는 문제다.**

## ⚠ 상한값은 전부 자체 결정값이다

[스탯 문서 §6.5 「확인하지 못한 상한값」](../../GameDesign/Systems/스탯_데미지공식_역기획서.md) — 원본에서 확인되지 않았다.
**추측한 값을 원작 확인값처럼 적지 않는다.** 주석에 명시한다.

## 검증

- **빌드 통과** (Editor + Server)
- 체력이 **0 미만·MaxHealth 초과로 가지 않는다**
- ⭐ 피해 감소 150%를 넣어도 **회복이 발생하지 않는다**
- 쿨다운 감소가 상한에서 멈춘다
- MaxHealth가 줄면 Health가 따라 줄어든다

## 주의점

- ⭐ **`Super::` 를 먼저 호출한다.**
- ⭐ **클램프를 여러 곳에서 하지 않는다.** ExecutionCalculation(F03)에서도 자르면 어디서 잘렸는지 추적이 안 된다.
- `PreAttributeChange` 에 **사망 처리·이펙트를 넣지 않는다** — 엔진 주석이 금지한다. 그건 F02-04다.
- MaxHealth가 줄 때 Health를 따라 줄이는 것은 **클램프가 아니라 반응**이다. `PostAttributeChange` 또는 F02-04에서 처리한다.
- 상한 테이블을 `Config` 나 데이터 애셋으로 뺄지 정한다 — 애셋 생성은 **에디터 작업**이므로 `Docs/EditorTasks/` 로 넘긴다.
