# 기능 목록 · 의존성 그래프

> 갱신 2026-09-02 — **GAS 기반으로 전환** (`CLAUDE.md` §8 · [`../Argument/1. 스킬 시스템 구조 선택.md`](../Argument/1.%20스킬%20시스템%20구조%20선택.md) 결정)
> 방식: **상향식(bottom-up)** — 기능을 최대한 독립적으로 만든 뒤 연결한다.

## 이 문서의 사용법

1. **레이어 순서대로 내려간다.** 앞 레이어가 끝나기 전에 뒤를 시작하지 않는다.
2. 같은 레이어 안의 기능들은 **서로 독립**이다. 순서를 바꿔도 되고 동시에 해도 된다.
3. 각 기능은 `Task/FNN_*/00_개요.md` 를 읽고 시작해서, `Checklist/FNN_*/` 를 채우며 끝낸다.
4. **1차 검증은 언제나 빌드 통과다** (`CLAUDE.md` §4).

## GAS 전환으로 바뀐 것

| 이전 (자체 구현) | 지금 (GAS) |
|---|---|
| `UERStatComponent` 4레이어 | ⭐ **`UAttributeSet`** + `UGameplayEffect` |
| `CalculateDamage()` 정적 함수 | ⭐ **`UGameplayEffectExecutionCalculation`** |
| `UERSkillBase` / `UERSkillComponent` | ⭐ **`UGameplayAbility`** / `UAbilitySystemComponent` |
| 쿨다운 `FTimerManager` | Cooldown `UGameplayEffect` |
| 자체 CC enum + 차단 플래그 | `GameplayTag` + `ActivationBlockedTags` |
| 채널링 자체 타이머 | `UAbilityTask` |
| 이펙트 직접 재생 | `GameplayCue` |

**F01(코어 골격)과 F04(판정)는 거의 영향이 없다.** GAS는 팀 개념도, 판정 형상 계산도 제공하지 않는다.

## 상향식을 성립시키는 3가지 원칙

### 1. 데이터를 구조체·태그로 받는다 — 상대를 조회하지 않는다

**F03(데미지)이 대표 사례다.** Execution은 `Cast<ABossActor>` 로 대상을 검사하지 않는다.
보스 감쇠는 **태그 또는 어트리뷰트**로 판별한다. 그래야 F12(야생동물)가 없어도 F03이 완성된다.

같은 이유로 F04(판정)는 팀 판정을 **인자로 받고**, 흡혈 감쇠 조건은 **스킬이 태그로 알려준다.**

### 2. 위쪽 기능은 아래쪽에 **델리게이트로** 알린다

F02(어트리뷰트)는 F17(UI)의 존재를 몰라야 한다.
ASC의 `GetGameplayAttributeValueChangeDelegate()` 를 쓰고, **듣는 쪽이 구독**한다.
UMG Property Binding은 매 프레임 호출되므로 쓰지 않는다.

### 3. 아직 없는 기능은 **스텁**으로 대체한다

F07(스킬)을 만들 때 F11(무기)은 아직 없다. D 슬롯은 빈 채로 두고 나중에 바인딩한다.
각 Task의 **「독립 구현 전략」** 절에 무엇을 스텁으로 둘지 적혀 있다.

## 통합(조립) 순서

```
0. F00 → 전부       ASC가 서 있어야 아무것도 못 붙는다
1. F02 → F03        어트리뷰트 캡처 정의 (F03-01)
2. F03 → F02        IncomingDamage → 체력 차감 (F02-04)   ⭐ 양방향이다
3. F04 → F07        판정 결과 → FGameplayAbilityTargetData 변환
4. F06 → F07        CC 태그 → ActivationBlockedTags
5. F06 → F05        CC 차단 플래그 ↔ 입력 게이트 (이중 게이트)
6. F03 → F10        데미지 파이프라인 종단에 경험치·숙련도 분배
7. F07 → F11        D 슬롯 런타임 바인딩  ⭐ 이 게임의 정체성
8. F08 → F09        인벤토리 ↔ 제작 재귀 탐색
9. F13 → F14        지역 판정 ↔ 금지구역 타임라인
10. F01 → F16       팀 ID ↔ 시야 릴리번시  ⭐ 여기까지 해야 맵핵이 아니다
11. 전체 → F17      HUD 바인딩
```

> ⚠ **10번(팀 시야)을 미루면 그때까지 만든 모든 것이 맵핵 상태다.**
> [팀시야 문서](../GameDesign/Systems/팀시야_포그오브워_역기획서.md) 구현 우선순위 3순위 주석: *"여기까지가 '맵핵이 아닌 상태'의 최소선이다."*
