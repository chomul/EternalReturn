# E08 — 멀티에서 클릭 이동이 안 된다 (싱글은 정상)

> 발견 **2026-09-10** · F05-02 · ⭐ **사용자 보고**
> 관련 [`E07`](E07_클릭이동_서버구동_충돌.md)

## 증상

사용자 보고: *"싱글에서는 문제 없었는데 멀티에서 캐릭터가 이동을 안 해"*

| | 결과 |
|---|---|
| 1인 PIE (Standalone) | ⭐ 정상 이동 |
| `Play As Client` 2인 — 클라 창 | ❌ **거의 제자리** |

⚠ 완전 정지가 아니라 **속도는 붙는데 위치가 안 변한다.** 이게 원인을 가리키는 단서였다.

---

## ⭐ 측정 — 추정하지 않고 로그로 확정했다

임시 진단(`ER.Move.Diag 1`)을 넣어 클라 창에서 우클릭한 결과:

```
[이동진단:요청직후] NetMode=3 Role=2 | PF=있음 상태=3 | 속도=112.1 가속=0.0 요청속도=41580.8 MaxSpeed=350.0
[이동진단:0.2초]   NetMode=3 Role=2 | PF=있음 상태=3 | 속도=121.1 가속=0.0 요청속도=37170.3 MaxSpeed=350.0
[이동진단:1.0초]   NetMode=3 Role=2 | PF=있음 상태=3 | 속도=45.7  가속=0.0 요청속도=43965.9 MaxSpeed=350.0
```

읽은 것:

| 값 | 의미 |
|---|---|
| `NetMode=3` `Role=2` | 클라이언트 · `AutonomousProxy` ✅ 정상 |
| `상태=3` | `EPathFollowingStatus::Moving` — ⭐ **경로 추적은 정상 작동한다** |
| `MaxSpeed=350` | ⭐ CC 차단(F06)이 원인이 **아니다** |
| ⭐⭐ **`가속=0.0`** | **이동 입력이 `Acceleration` 에 없다** |
| `요청속도` 큰 값 | `RequestedVelocity` 경로로 움직이고 있다 |
| `속도` 112 → 121 → **45.7** | ⭐ 붙었다가 줄어든다 — **서버가 계속 되돌린다** |

⭐ **`가속=0` 인데 `요청속도`가 있다** = 이동이 `Acceleration` 이 아니라 `RequestedVelocity` 로 구동된다.

---

## ⭐⭐ 원인

```
SimpleMoveToLocation
  → UPathFollowingComponent
  → CMC::RequestDirectMove
        RequestedVelocity = MoveVelocity      CharacterMovementComponent.cpp:3804
        bHasRequestedVelocity = true          :3805
        ⚠ Acceleration 은 건드리지 않는다
```

그런데 **클라가 서버에 보내는 이동 입력은 `Acceleration` 뿐이다.**

```cpp
// FSavedMove_Character::SetMoveFor — CharacterMovementComponent.cpp:12157
Acceleration = Character->GetCharacterMovement()->RoundAcceleration(NewAccel);
```

`FSavedMove_Character` 의 멤버 목록(`CharacterMovementComponent.h:2858~`)에
**`RequestedVelocity` 가 없다.**

→ `RequestedVelocity` 는 `ServerMove` 에 **실려 가지 않는다**
→ 서버는 가속 0 으로 재생 → 서버에서 캐릭터가 안 움직인다
→ 서버가 클라를 원위치로 보정 → **클라도 제자리**

⚠ **Standalone 에서는 서버=클라라 이 검증 자체가 없다.** 그래서 싱글에서만 정상으로 보였다.

## ⭐ 수정 — 엔진이 이미 스위치를 제공한다

`Source/EternalReturn/Character/ERCharacterMovementComponent.cpp` 생성자:

```cpp
bUseAccelerationForPaths = true;
```

기본값은 `false` 다 (`NavMovementComponent.cpp:16`).

`true` 로 두면 경로 추적이 **Acceleration 경로**를 탄다:

```

PawnMovementComponent.cpp:91      PawnOwner->Internal_AddMovementInput(MoveInput)
CharacterMovementComponent.cpp:1518   InputVector = ConsumeInputVector()  -> Acceleration
CharacterMovementComponent.cpp:12157  SavedMove 가 Acceleration 을 저장
                                  -> ServerMove 로 전송 -> 서버가 같은 입력을 재생
```

## ⭐ E07 판단은 뒤집히지 않았다

한때 *"서버도 경로를 돌려야 하나"* 를 다시 검토해야 하나 싶었지만 **아니다.**

E07 의 결론(**서버는 목적지를 검증만 하고 이동을 구동하지 않는다**)이 오히려 맞았다.
클라의 입력이 `ServerMove` 로 정상 전달되면 **서버는 그것을 재생하기만 하면 된다.**
서버가 따로 `PathFollowing` 을 돌리면 그 재생과 충돌한다 — E07 이 지적한 그대로다.

→ 문제는 "누가 이동을 구동하나" 가 아니라 **"클라의 이동이 서버에 전달되는 형식"** 이었다.

---

## ⚠ 배운 것

**Standalone 통과는 멀티 검증이 아니다.**

`Play` 버튼으로 되는 것을 "이동 구현 완료" 로 판정하면 이 부류의 버그가 통째로 숨는다.
클라 예측(`SavedMove`)을 타지 않는 이동은 **싱글에서 100% 정상으로 보인다.**

→ 이동·입력을 건드리는 작업은 **`Play As Client` 2인이 검증 조건**이다.
F05 체크리스트에 그렇게 적혀 있었는데 **아직 안 돌려본 상태에서 F06 으로 넘어갔다.**

⚠ 그리고 이 값은 **CMC 를 교체하지 않았으면 설정할 자리도 없었다.**
F06 에서 `UERCharacterMovementComponent` 를 만든 것이 우연히 자리를 마련해 줬다.

## ✅ 검증 완료 — 2026-09-10

수정 후 같은 진단을 다시 돌린 결과, **값이 정확히 뒤바뀌었다.**

```
[이동진단:요청직후] ... 속도=0.0   가속=0.0    요청속도=0.0 MaxSpeed=350.0
[이동진단:0.2초]   ... 속도=350.0 가속=2048.0 요청속도=0.0 MaxSpeed=350.0
[이동진단:1.0초]   ... 속도=350.0 가속=2048.0 요청속도=0.0 MaxSpeed=350.0
```

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| `가속` | **0.0** ❌ | ⭐ **2048** (= `MaxAcceleration` 기본값) |
| `요청속도` | 41580 | ⭐ **0** — `RequestDirectMove` 경로를 안 탄다 |
| `속도` | 112 → 121 → **45** (줄어듦) | ⭐ **350 유지** (= `MaxSpeed`) |

⭐ **`속도`가 줄지 않는다**는 것이 핵심이다 — 서버가 되돌리지 않는다는 뜻이다.
