# E15 — 익명 네임스페이스의 같은 이름 헬퍼가 **유니티 빌드**에서 충돌한다

> 발견 **2026-09-18** · F09-01 (파일을 추가하자 F10 디버그 파일이 깨졌다)

## 증상

`Item/ERCraftLibrary.cpp` · `ERCraftDebug.cpp` 를 **추가**만 했는데 손대지 않은 `Growth/ERGrowthDebug.cpp` 가 실패:
```
ERGrowthDebug.cpp(22): error C2995: 'void `anonymous-namespace'::ForEachServerPlayer(UWorld *,TFunc)': 함수 템플릿이 이미 정의되었습니다.
```

## 원인

UBT 유니티 빌드는 여러 `.cpp` 를 하나의 번역 단위로 묶는다. 묶음은 **파일 목록 순서·개수**로 정해져서, 파일을 추가하면 경계가 밀린다.
`ERSkillDebug.cpp` 와 `ERGrowthDebug.cpp` 가 각각 익명 네임스페이스에 `ForEachServerPlayer` 템플릿을 갖고 있었는데, 이번에 같은 묶음에 들어가면서 **익명 네임스페이스가 하나로 합쳐져** 재정의가 됐다.
(익명 네임스페이스는 번역 단위 단위로 고유하다 — 유니티 빌드에서는 "번역 단위" 가 내 파일 하나가 아니다.)

## 수정

`ERGrowthDebug.cpp` 쪽을 `ForEachServerPlayerGrowth` 로 개명. 빌드 통과.

## ⚠ 재발 방지

- 익명 네임스페이스 헬퍼 이름에 **파일 접두어**를 붙인다 (`ForEachServerPlayerGrowth`, `GetLocalSkillASC` 처럼). 특히 임시 디버그 파일 — 비슷한 헬퍼가 반복된다
- "손대지 않은 파일이 갑자기 재정의 에러" 면 유니티 묶음 경계 이동을 의심한다
- 근본 해결(공용 헬퍼 헤더)은 디버그 파일들이 F17 때 전부 삭제될 예정이라 하지 않는다
