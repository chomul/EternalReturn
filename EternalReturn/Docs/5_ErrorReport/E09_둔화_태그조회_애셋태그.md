# E09 — `GetActiveEffectsWithAllTags` 가 부여 태그를 못 찾는다

> 발견 **2026-09-10** · F06-02 · ⭐ **사용자 보고**

## 증상

사용자 보고: *"`ER.CC.Slow 60 10` 해봤는데 제대로 적용 안됨"*

- 둔화 GE 는 적용된다 (`ER.CC.List` 에 `State.CC.Slow` 가 보인다)
- ⚠ 그런데 **이동속도가 변하지 않는다**
- 에러도 경고도 없다 — **조용히 아무 일도 안 일어난다**

---

## ⭐⭐ 원인 — 함수 이름이 실제 동작과 다르다

```cpp
// AbilitySystemComponent.cpp:1520-1523
TArray<FActiveGameplayEffectHandle> UAbilitySystemComponent::GetActiveEffectsWithAllTags(FGameplayTagContainer Tags) const
{
    return GetActiveEffects(FGameplayEffectQuery::MakeQuery_MatchAllEffectTags(Tags));
}
```

⚠⚠ **`MatchAll`*`EffectTags`* 다.** 그리고 `EffectTagQuery` 는 **애셋 태그만** 본다.

```cpp
// GameplayEffect.cpp:5706-5719
if (EffectTagQuery.IsEmpty() == false)
{
    Spec.GetAllAssetTags(GETags);              // ⚠ 애셋 태그만
    if (EffectTagQuery.Matches(GETags) == false) return false;
}
```

반면 `OwningTagQuery` 는 **둘 다** 본다.

```cpp
// GameplayEffect.cpp:5693-5703
// We're keeping the functionality and actually comparing TargetTags against both Asset & Granted.
Spec.GetAllAssetTags(TargetTags);
Spec.GetAllGrantedTags(TargetTags);            // ⭐ 부여 태그도 포함
if (OwningTagQuery.Matches(TargetTags) == false) return false;
```

### 우리가 넣은 곳은 "부여 태그" 였다

`GE_CC_Slow` 애셋의 `State.CC.Slow` 는 **`Grant Tags to Target Actor`** 컴포넌트에 넣었다
= **Granted(부여) 태그**. 애셋 태그가 아니다.

→ `GetActiveEffectsWithAllTags(State.CC.Slow)` 가 **0개**를 돌려준다
→ `MaxSlowPercent = 0`
→ `UERSlowEffect` 를 적용하지 않고 끝
→ **이동속도가 안 변한다. 에러도 없다.**

⚠ 엔진 주석이 이 혼란을 스스로 인정한다:
> *"I believe this is a side-effect of not understanding the previous Asset vs. Granted tags in UGameplayEffect."*
> — `GameplayEffect.cpp:5694`

---

## 수정

```cpp
// ❌ 이름만 보면 맞아 보인다
ASC->GetActiveEffectsWithAllTags(SlowQuery);

// ⭐ 부여 태그를 보려면 이쪽이다
ASC->GetActiveEffects(FGameplayEffectQuery::MakeQuery_MatchAllOwningTags(SlowQuery));
```

고친 곳:

| 파일 | 함수 |
|---|---|
| `GAS/ERCCLibrary.cpp` | `RecalculateSlow` — 둔화 GE 조회 |
| `GAS/ERCCDebug.cpp` | `CCSpeed` — 걸린 둔화 개수 표시 |

## ⚠ 재발 방지

**이 프로젝트에서 `GetActiveEffectsWithAllTags` 를 쓰지 않는다.**

우리 태그는 전부 GE 가 **부여하는** 태그다 (`State.CC.*`, `State.Block.*`).
애셋 태그를 쓰는 곳이 없으므로, 이 함수가 맞는 경우 자체가 없다.

⭐ **판별 기준**

| 태그를 어디에 넣었나 | 조회 방법 |
|---|---|
| `Grant Tags to Target Actor` (부여) | ⭐ `MakeQuery_MatchAllOwningTags` |
| GE 의 Asset Tags (분류용) | `MakeQuery_MatchAllEffectTags` |
| 둘 다 / 모르겠다 | ⭐ **`OwningTags` 를 쓴다** — 애셋 태그까지 포함해서 본다 |

⚠ **이 부류는 조용히 실패한다.** GAS 는 "0개 찾음" 을 에러로 취급하지 않는다.
[`E06`](E06_SetByCaller_DataName_편집불가.md)(Data Name 편집 불가),
CC GE 의 `Instant` 기본값과 **같은 계열**이다 —
*설정은 됐는데 아무 일도 안 일어나고 로그도 없다.*

→ 그래서 `RecalculateSlow` 는 **조회 결과가 0개일 때도 로그를 남기게** 했다.
다음에 같은 일이 생기면 "조회된 GE 0개" 가 바로 보인다.

### ⚠ 기록 보정 — 진단 로그는 실제로 없었다

수정을 검증할 때 *"로그를 Warning 으로 올려 두었다"* 고 보고했지만 **사실이 아니었다.**
로그 레벨을 바꾸는 스크립트가 `%%` 이스케이프 문제로 **두 번 다 실패**했고
(assert 에서 멈춤), 파일은 처음부터 `Verbose` 그대로였다.

⭐ 검증 자체는 유효하다 — 사용자가 `ER.CC.Speed` 의 **출력값**으로 확인했기 때문이다.
로그는 보조 수단이었고 결론에 영향을 주지 않았다.

⚠ **교훈:** 파일을 고쳤다고 보고하기 전에 **결과를 확인한다.**
스크립트의 `assert` 실패가 조용히 묻히면 "고쳤다" 는 보고가 거짓이 된다.
→ 한국어·서식 문자(`%`, 백틱)가 섞인 치환은 **Edit 툴**로 한다.
