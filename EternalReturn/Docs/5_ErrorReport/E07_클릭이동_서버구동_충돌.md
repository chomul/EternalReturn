# E07 — 서버가 이동을 직접 구동하면 클라 이동과 충돌한다

| | |
|---|---|
| 발견 | 구현 중 (F05-02) |
| 시점 | 클릭 이동 설계를 코드로 옮기던 중 |
| 상태 | ✅ 설계 변경으로 회피 |
| 분류 | **설계 문서를 문자 그대로 구현하면 깨지는 경우** |

## 증상

⚠ **런타임에 목격한 증상은 없다.** 구현 직전에 발견해 회피했다.

그대로 만들었다면 이렇게 보였을 것이다:

- 이동이 **끊기거나 고무줄처럼 튄다**
- 클라에서 클릭한 곳과 다른 위치로 간다
- 증상이 네트워크 지연처럼 보여 **원인을 엉뚱한 곳에서 찾는다**

## 원인

역기획서 §3.3 이 권위 모델을 이렇게 적었다:

> **"목적지는 서버 권위, 경로는 양쪽 계산, 이동은 CMC 예측"**

"경로는 양쪽 계산" 을 **"서버도 `SimpleMoveToLocation` 을 돌린다"** 로 읽으면 깨진다.

### 왜 깨지나

언리얼의 네트워크 캐릭터 이동(`CharacterMovementComponent`)은 이런 모델이다:

1. **클라**가 입력으로 이동을 만든다 (클라이언트 예측)
2. 클라가 `ServerMove` RPC 로 그 이동을 보낸다
3. **서버**가 그것을 **재생**하고 결과를 검증한다
4. 어긋나면 서버가 보정을 내려보낸다

여기서 서버가 **독립적으로** `PathFollowingComponent` 를 돌리면,
서버 폰이 자기 경로로 움직이면서 클라가 보낸 이동을 **서로 덮어쓴다.**

⭐ 서버가 이동을 구동해야 하는 것은 **AI 가 조종하는 폰**이다.
플레이어가 조종하는 폰(`AutonomousProxy`)은 클라가 구동하고 서버가 검증한다.

## 해결

**서버는 검증만 한다.**

| 무엇 | 어디서 |
|---|---|
| 로컬 즉시 이동 (클릭 지연 제거) | 클라 |
| 목적지 **거리** 검증 | ⭐ 서버 |
| 목적지 **네비메시 위인지** 검증 | ⭐ 서버 |
| 위치 권위 · 텔레포트 차단 | ⭐ **CMC 의 `ServerMove` 검증** |

```cpp
// ERPlayerController.cpp - ServerSetDestination_Implementation
// ⚠ 서버는 검증만 하고 직접 이동을 구동하지 않는다.
//   플레이어가 조종하는 폰에서 서버가 독립적으로 PathFollowing 을 돌리면
//   클라가 보낸 이동과 충돌한다.
```

⭐ **텔레포트를 막는 실제 방어선은 CMC 의 `ServerMove` 검증**이다.
목적지 검증은 그 위에 얹는 층이지, 그것 자체가 권위인 것은 아니다.

## 재발 방지

⭐ **"양쪽에서 계산한다" 는 표현을 만나면 "양쪽이 각자 구동한다" 는 뜻인지 확인한다.**

| 표현 | 실제로 무엇인가 |
|---|---|
| 양쪽이 **같은 입력으로 같은 결과를 낸다** | ✅ 결정론적 시뮬레이션. 문제없다 |
| 양쪽이 **각자 구동한다** | ❌ 충돌한다. 한쪽이 이겨야 한다 |

그리고 **엔진이 이미 권위 모델을 갖고 있는 영역**(캐릭터 이동 · 어트리뷰트 복제)에서는
그 모델을 먼저 확인한다. 위에 새 권위 층을 얹으려 하면 대개 충돌한다 (`CLAUDE.md` §1).

⚠ **이건 검사기로 못 막는다.** 빌드도 통과하고 단일 플레이에서는 멀쩡하다.
`Play As Client, 2인` 이 아니면 드러나지 않는다.
