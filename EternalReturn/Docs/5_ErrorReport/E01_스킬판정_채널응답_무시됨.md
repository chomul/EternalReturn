# E01 — 스킬 판정 채널 응답이 무시됨

> 발견 2026-09-06 · 관련 [F04 판정·타게팅](../1_Task/F04_판정_타게팅/00_개요.md) · [Argument 2](../4_Argument/2_판정콜리전_설계.md)
> 상태: ✅ **해결**

## 증상

`AERCharacterBase` 생성자에서 캡슐의 `SkillTarget` 채널 응답을 `Overlap` 으로 켰는데,
에디터에서 `BP_ERCharacterBase` 의 캡슐을 열어보면 **`Ignore` 로 보인다.**

```cpp
// 이렇게 했는데 반영이 안 됐다
GetCapsuleComponent()->SetCollisionResponseToChannel(ERCollisionChannel::SkillTarget, ECR_Overlap);
```

빌드는 통과했고 컴파일 경고도 없었다. **조용히 안 먹는 종류의 문제다.**

⚠ 이대로 뒀으면 **모든 스킬 판정이 아무도 못 맞히는데 원인 표시가 없는** 상태가 됐다.

## 원인

`FBodyInstance::SetResponseToChannel()` 이 응답을 바꾸면서
**`InvalidateCollisionProfileName()` 을 호출한다.**

```cpp
// Engine/Source/Runtime/Engine/Private/PhysicsEngine/BodyInstance.cpp:544-548
bool FBodyInstance::SetResponseToChannel(ECollisionChannel Channel, ECollisionResponse NewResponse)
{
    if (CollisionResponses.SetResponse(Channel, NewResponse))
    {
        InvalidateCollisionProfileName();   // ← 여기
        UpdatePhysicsFilterData();
        return true;
    }
    return false;
}
```

`InvalidateCollisionProfileName()` 은 프로파일 이름을 **`Custom`** 으로 바꾼다.

```cpp
// BodyInstance.cpp:534-542
void FBodyInstance::InvalidateCollisionProfileName()
{
    CollisionProfileName = UCollisionProfile::CustomCollisionProfileName;
    ...
}
```

즉 내 코드는 캡슐을 **`Pawn` 프로파일에서 떼어내 `Custom` 으로 만들었다.**
그런데 `BP_ERCharacterBase` 는 캡슐의 콜리전 설정을 **애셋에 저장하고 있어서**,
BP 를 로드할 때 저장된 `Pawn` 프로파일이 복원되며 내 변경이 덮인다.

그리고 **새로 판 채널은 기존 프로파일에서 `DefaultResponse` 를 따른다.**
`SkillTarget` 의 `DefaultResponse` 가 `ECR_Ignore` 이므로 `Pawn` 프로파일은 `Ignore` 로 응답한다.

> **한 줄 요약: 프로파일 시스템과 싸웠다.** 개별 응답을 코드로 덮는 방식은
> 프로파일을 쓰는 컴포넌트에서 안정적으로 유지되지 않는다.

## 해결

엔진에 정확히 이걸 위한 설정이 있다.

```cpp
// Engine/Source/Runtime/Engine/Classes/Engine/CollisionProfile.h:175-176
/** Game-specific overrides to engine profiles */
UPROPERTY(globalconfig)
TArray<FCustomProfile>  EditProfiles;
```

**1. `Config/DefaultEngine.ini` — `Pawn` 프로파일 자체를 고친다**

```ini
+EditProfiles=(Name="Pawn",CustomResponses=((Channel=SkillTarget,Response=ECR_Overlap)))
```

**2. `ERCharacterBase.cpp` — `SetCollisionResponseToChannel` 호출을 삭제**

미사용이 된 include 2개(`ERCollisionChannels.h`, `Components/CapsuleComponent.h`)도 같이 제거했다.

### 결과

- 캡슐이 **`Pawn` 프로파일을 유지**한다 (`Custom` 으로 안 바뀜)
- BP 저장값과 싸우지 않는다
- Project Settings > Collision 에서 **눈으로 확인 가능**하다
- `Pawn` 프로파일을 쓰는 액터(야생동물·보스 등)가 **자동으로 판정 대상**이 된다

## 재발 방지

- ⭐ **프로파일을 쓰는 컴포넌트의 채널 응답을 C++ 에서 개별로 바꾸지 않는다.**
  프로파일을 고치거나(`EditProfiles`), 전용 프로파일을 새로 정의한다.
- 이 사실을 `ERCharacterBase.cpp` 생성자 주석에 남겼다 — 나중에 누군가 다시
  `SetCollisionResponseToChannel` 을 넣으려 할 때 이유를 보게 된다.
- ⚠ **완전히 막지는 못한다.** 새 판정 대상 액터가 `Pawn` 이 아닌 프로파일을 쓰면
  여전히 응답을 켜야 하고, 빠뜨리면 조용히 안 맞는다.
  → `ERTargetingDebug.cpp` 가 **판정 결과 0개일 때 경고 로그**를 남기게 해 뒀다.
  그게 유일한 단서다.

## 배운 것

**"빌드 통과 = 동작"이 아니다.** 이건 컴파일도 되고 런타임 에러도 없는데
**아무 일도 안 일어나는** 종류였다. 에디터에서 눈으로 확인하지 않았으면
F07(스킬)까지 가서야 "왜 아무도 안 맞지"로 발견했을 것이다.

사용자가 EditorTasks 문서의 확인 절차(1-2)를 실제로 밟아서 잡혔다.
**에디터 확인 항목을 문서로 남기는 것이 실제로 값을 했다.**
