# E04 — 사망 알림(`OnOutOfHealth`)이 여러 번 발동

| | |
|---|---|
| 발견 | Lyra 소스 대조 중 (사용자 지적 아님) |
| 시점 | F02-04 구현 직후, PIE 검증 전 |
| 상태 | ✅ 구현 단계에서 수정 |

## 증상

⚠ **런타임에 실제로 목격한 증상은 없다.** 빌드는 통과했고 PIE 검증 전이었다.
Lyra 의 같은 기능과 대조하다가 **우리 코드에만 없는 가드**를 발견했다.

증상이 났다면 이렇게 보였을 것이다:

- 킬 로그가 **두 번 이상** 찍힌다
- 경험치·크레딧이 **여러 번** 지급된다
- 사망 연출이 겹쳐서 재생된다

## 원인

`ERAttributeSet::PostGameplayEffectExecute` 가 **체력이 0 이하이기만 하면 매번** 브로드캐스트했다.

```cpp
// 고치기 전
if (GetHP() <= 0.f)
{
    AActor* Instigator = Data.EffectSpec.GetEffectContext().GetOriginalInstigator();
    OnOutOfHealth.Broadcast(Instigator);
}
```

**체력이 이미 0 인 대상에 피해가 또 들어오면 다시 쏜다.** 클램프가 0 에서 잘라내므로
체력은 계속 0 이고, 조건은 계속 참이다.

### 언제 실제로 터지나

이건 드문 상황이 아니다:

| 상황 | 왜 |
|---|---|
| 같은 프레임에 투사체 여러 개가 닿음 | 각각이 별도 GE |
| 도트(장판·화상)가 도는 중에 사망 | 주기 실행마다 `PostGameplayEffectExecute` |
| 광역기와 평타가 동시에 들어감 | GE 두 개가 연달아 실행 |

### 근거 — Lyra 는 빗장을 둔다

```cpp
// LyraHealthSet.cpp:172-178
if ((GetHealth() <= 0.0f) && !bOutOfHealth)
{
    OnOutOfHealth.Broadcast(Instigator, Causer, &Data.EffectSpec, ...);
}

// Check health again in case an event above changed it.
bOutOfHealth = (GetHealth() <= 0.0f);
```

그리고 부활하면 `PostAttributeChange` 에서 푼다:

```cpp
// LyraHealthSet.cpp:214-217
if (bOutOfHealth && (GetHealth() > 0.0f))
{
    bOutOfHealth = false;
}
```

## 해결

같은 방식으로 `bOutOfHealth` 빗장을 넣었다.

```cpp
// ERAttributeSet.cpp - PostGameplayEffectExecute
if (GetHP() <= 0.f && !bOutOfHealth)
{
    AActor* Instigator = Data.EffectSpec.GetEffectContext().GetOriginalInstigator();
    OnOutOfHealth.Broadcast(Instigator);
}

// 듣는 쪽이 회복시켰을 수 있으므로 브로드캐스트 뒤에 다시 읽는다.
bOutOfHealth = (GetHP() <= 0.f);
```

```cpp
// ERAttributeSet.cpp - PostAttributeChange
// 부활·회복으로 체력이 다시 0 보다 커지면 빗장을 푼다.
if (bOutOfHealth && GetHP() > 0.f)
{
    bOutOfHealth = false;
}
```

⭐ **브로드캐스트 뒤에 값을 다시 읽는 것**이 중요하다.
델리게이트를 듣는 쪽이 "죽으면 즉시 부활" 같은 처리를 하면 체력이 그 자리에서 올라간다.
브로드캐스트 전에 `bOutOfHealth = true` 로 박아두면 그 부활을 놓친다.

## 재발 방지

⚠ **자동으로 막을 방법은 없다.** 대신 규칙으로 남긴다.

**"상태 진입"을 알리는 델리게이트는 조건이 아니라 전이(transition)로 판단한다.**

```
❌  if (조건)              → 조건이 참인 동안 계속 쏜다
✅  if (조건 && !이미쏨)   → 조건이 거짓→참으로 바뀔 때만 쏜다
```

체력 0, 기절 진입, 전투 진입/이탈 등 **"~가 되었다"류 알림이 전부 해당**된다.

그리고 **빗장을 푸는 곳을 같이 만든다.** 거는 것만 만들고 푸는 걸 빠뜨리면
두 번째 죽음이 영영 안 알려진다 — 이쪽이 더 찾기 어렵다.
