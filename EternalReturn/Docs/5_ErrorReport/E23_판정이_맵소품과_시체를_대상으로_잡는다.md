# E23 — 평타가 맵 소품과 시체를 대상으로 잡는다

> 발견: 2026-09-23 F12-02 검증 로그 (사용자 "테스트 다 했어")
> 관련 [`Argument 33`](../4_Argument/33_야생동물_충돌_클릭_판정_분리.md) (Select 채널) · `Combat/ERTargeting.cpp::PassesFilter`

## 증상

닭을 죽인 **뒤에도** 평타가 계속 성립했다.

```
06:55:16  [야생동물] … 사망 — 처치 ERPlayerState_0
06:55:29  DA_BasicAttack 판정 SingleTarget: 적중 1 → 피해 1명 (기본 50 · 평타)   ← 죽은 뒤
06:55:35  SingleTarget 빗나감 — 대상 StaticMeshActor_34 · 거리 2407cm · 적대 O   ← 맵 소품이 대상
```

두 가지가 겹쳐 있었다.
1. **맵 소품 · 지형이 대상이 된다** — `StaticMeshActor` 는 `BlockAll` 프로파일이라 커서 트레이스 채널(`Select`, 이전에는 `Pawn`)을 막는다. 팀 필터는 *무소속끼리는 적* 이라 통과시킨다 (`ERTeamStatics::IsHostile` — 야생동물을 때리려면 그래야 한다)
2. **시체가 대상이 된다** — F12-02 에서 시체의 콜리전(`SkillTarget`)을 껐는데도 맞았다

## 원인

`QuerySingleTarget` 은 **오버랩이 아니라 "커서가 짚은 액터"(`DesignatedTarget`)** 를 그대로 쓴다. 필터와 거리만 본다.
→ 콜리전 채널을 꺼도 **아무 효과가 없다.** 걸러야 할 자격이 콜리전이 아니라 "대상이 될 수 있는 액터인가" 인데 그 검사가 없었다.

## 고침 (2026-09-23)

`ERTargeting::PassesFilter` 에 자격 검사 2줄을 넣었다.

```cpp
const UAbilitySystemComponent* ASC = UAbilitySystemGlobals::GetAbilitySystemComponentFromActor(Candidate);
if (!ASC) { return false; }                                           // 맵 소품 · 지형
if (ASC->HasMatchingGameplayTag(ERTags::State_Untargetable)) { return false; }   // 시체 · 무적 연출
```

- **ASC 가 없으면 대상이 아니다** — 피해 · CC 를 받을 수 없는 액터를 때릴 이유가 없다. 파괴 가능한 설치물을 넣을 때는 그 액터가 ASC 를 갖게 된다 (F13)
- `State.Untargetable` 은 선언만 되어 있고 아무도 안 쓰던 태그다 (`ERGameplayTags.h:68`). 여기서 첫 소비자가 생겼다
- `AERWildlifeCharacter::EnterCorpseState` 가 죽을 때 이 태그를 붙인다 (loose + replicated) — **클릭(Select)은 살아 있어 루팅은 된다**

## 이 필터가 닿는 범위

`PassesFilter` 는 SingleTarget · 반경 · 부채꼴 · 직선 · 이중 반경 **전부**가 쓴다. 즉 맵 소품이 범위기에 "적중" 으로 세지던 것도 같이 사라진다.

## 검증

```
닭 처치 → 시체를 평타         → 적중 0 (빗나감 로그도 안 뜬다 — 대상 자격 없음)
시체를 클릭 → ER.Item.Pickup  → 여전히 열리고 가져갈 수 있다
빈 바닥 · 벽을 클릭하고 평타   → 적중 0 (이전에는 적중 1 · 피해 1명)
살아 있는 닭 · 실험체         → 이전과 같이 적중 1
```
