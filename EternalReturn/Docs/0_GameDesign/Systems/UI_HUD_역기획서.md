# UI · HUD 시스템 — 개발자용 역기획서

> 기준: **시즌 12 · 패치 12.2 (2026-08-20)** / 조사일 2026-08-30
> 상위 문서: [`../이터널리턴_역기획서.md`](../이터널리턴_역기획서.md) §11 (보조 근거: §12.3, §12.5)
> 연관 문서: [`장비_아이템_역기획서.md`](장비_아이템_역기획서.md) §6.2 · [`몬스터_야생동물_역기획서.md`](몬스터_야생동물_역기획서.md) §5.2

## 0. 이 시스템의 정체

**이 게임에서 UI는 편의 기능이 아니라 게임 시스템의 일부다.**
상위 문서 §12.3이 진단한 것처럼 신규 유저는 **12개 시스템(실험체 90 · 무기 23 · 재료 35 · 지역 21 · 특성 48 …)을 동시에 학습**해야 첫 승리가 가능하다.
개발팀이 이 학습량을 줄인 방법은 시스템을 삭제한 게 아니라 **UI에 암기 부담을 떠넘긴 것**이다.
`Alt + M` 파밍 위치 오버레이는 "목표 아이템 → 필요 재료 → 재료가 있는 지역"이라는 3단 역추적을 UI가 대신 수행하며, 상위 문서는 이를 **"의도적 치트시트 내장"** 이라고 명시한다.

> ⚠ **클론 개발 시 가장 중요한 경고 (상위 문서 §12.5 · 장비 문서 서두와 동일):**
> **제작 시스템과 확장맵 파밍 위치 오버레이는 반드시 동시에 구현해야 한다.**
> 이 문서는 그 경고를 UI 관점에서 구체화한 것이다 — §5의 **재귀 요구사항 분해**가 없으면 오버레이는 만들 수 없고,
> 오버레이가 없으면 크래프팅은 `35종 재료 × 21지역` 암기 지옥이 된다. **둘은 하나의 기능이다.**

## 1. 대원칙 — UI는 게임 상태를 바꾸지 않는다

이 프로젝트는 **데디케이티드 서버 타겟**이 있다. UI 코드에는 예외 없이 아래가 적용된다.

| 방향 | 규칙 |
|---|---|
| **읽기** | 위젯은 **복제된 값을 읽기만 한다.** `GameState` / `PlayerState` / 복제 컴포넌트가 유일한 진실 원천 |
| **쓰기** | 위젯의 모든 입력(제작 버튼, 아이템 요청, 핑, 자동습득 토글)은 **`Server` RPC(`WithValidation`)로 넘긴다** |
| **금지** | 위젯이 어트리뷰트·인벤토리·크레딧 값을 직접 수정하는 코드는 존재해서는 안 된다 |
| **표시용 선판정** | "제작 가능"·"크레딧 부족" 같은 버튼 활성화 판정은 클라에서 미리 계산해도 되지만, **서버가 반드시 다시 검증**한다. 클라 판정은 어디까지나 표시다 |
| **로컬 전용 상태** | 확장맵 열림 여부, `F8` 오버레이 토글, 설정값, 정렬 순서는 **복제하지 않는다.** 순수 클라 로컬 상태 |

> **구현 메모 (C++/BP 경계 — 전 섹션 공통):**
> - **C++**: 위젯 베이스 클래스(`UERUserWidget` 계열), 데이터 조회·계산·정렬·재귀 탐색, 델리게이트 구독/해제, Server RPC 호출, 좌표 변환.
> - **위젯 BP**: 레이아웃, 이미지·폰트·색, 애니메이션, `BindWidget`으로 노출된 텍스트/프로그레스바에 값 꽂기, 사운드.
> - C++는 **"무엇을 표시할지"(구조체 하나)** 를 만들어 BP에 넘기고, BP는 **"어떻게 보일지"** 만 담당한다.
> - BP에 노출하는 것은 전부 `BlueprintCallable` / `BlueprintPure` / **`BlueprintReadOnly`**. `BlueprintReadWrite`는 쓰지 않는다(위젯이 상태를 바꾸게 되므로).

## 3. ⭐ 핵심 산출물 1 — HUD 요소 전수 표

> **갱신 주기 열이 이 표의 핵심이다.** 언리얼에서 위젯을 `NativeTick`으로 돌릴지 델리게이트에 바인딩할지가 여기서 갈린다.
> **결론부터: 매 프레임이 정당한 요소는 미니맵 아이콘 위치 하나뿐이다.** 나머지는 전부 이벤트 기반으로 만든다.
> 데이터 출처 열은 **이 프로젝트의 구현 권장안**이며 원작 확인값이 아니다(원작 내부 구조는 알 수 없다).

| # | 요소 | 화면 위치 | 표시 정보 | 갱신 주기 | 데이터 출처 (권장) | 클론 초기 필수 |
|---|---|---|---|---|---|---|
| 1 | **체력 / 기력 바** | 하단 중앙 | 현재/최대 수치, 비율 | **이벤트** — `OnRep_Health` 델리게이트 | `UCharacterStatComponent` (복제) | ✅ 필수 |
| 2 | **스킬 바** | 하단 중앙 | P/Q/W/E/R **+ D(무기) + F(전술)**, 쿨다운, 스킬 레벨(12.0에서 무기/전술 레벨 표시 통일) | **이벤트**(쿨다운 시작·종료) + 숫자 카운트다운만 로컬 0.1초 타이머 | 스킬 컴포넌트(복제) | ✅ 필수 (**D/F 슬롯은 컷** — §9) |
| 3 | **실험체 초상 · 레벨** | 하단 좌측 | 초상, 레벨, 경험치 진행도 | **이벤트**(레벨업·경험치 변동) | `AERPlayerState` | ✅ 필수 |

| 7 | **미니맵** | 우하단 | §4.1 표 참조 | **자기·팀원 아이콘만 매 프레임**(보간). 마커·상자·오브젝트는 **이벤트** | 로컬 폰 트랜스폼 + `AERGameState` 마커 배열 | ✅ 필수 |

| 12 | **핑 / 신호** | 미니맵 + 월드 | 위험 / 주의 / 지원 요청 / 가고 있음. **12.2 도배 제한 남은 시간 표시** | **이벤트** — `NetMulticast`(팀 한정) | 서버 브로드캐스트 | ⬜ 권장 (3인 팀에선 사실상 필수) |
| 13 | **교전 로그 UI** | 관전 · 리플레이 | 12.0 신규, e스포츠 중계 대응 | **이벤트** | (미확인) | ❌ 컷 |
| 14 | **크로노 스피어 범위** | 미니맵 · 확장맵 | 12.0에서 **범위 시각 강조** 추가 | **이벤트**(스폰/소멸) | `AERGameState` 오브젝트 목록 | ❌ 컷 |

> **구현 메모:**
> - **`NativeTick`을 켜는 위젯은 미니맵 하나로 제한한다.** 나머지는 위젯 Tick을 끄고 델리게이트를 구독한다. HUD 위젯 10여 개가 각자 Tick을 돌면 그것만으로 프레임을 갉아먹는다.
> - 복제 값 → UI 갱신은 **전부 `UPROPERTY(ReplicatedUsing = OnRep_XXX)`** 로 잡고, `OnRep_` 안에서 멀티캐스트 델리게이트를 브로드캐스트한다. 위젯은 그 델리게이트만 구독한다. **UMG의 Property Binding(BP 바인딩 함수)은 내부적으로 매 프레임 호출되므로 쓰지 않는다.**
> - 팀원 포트레이트(#5)는 팀원 `PlayerState`가 **늦게 복제될 수 있다.** `PlayerArray` 순회 결과가 비어 있어도 정상이므로, 플레이어 추가/제거 이벤트에 재구독하는 경로가 필요하다. `BeginPlay`에서 한 번 훑고 끝내면 팀원 칸이 빈 채로 남는다.
> - 남은 시간(#8)을 매 프레임 복제하면 대역폭 낭비다. **종료 서버시각 1개만 복제**하고 클라가 `GetServerWorldTimeSeconds()` 기준으로 뺄셈한다.
> - 인벤토리(#6)는 **소유자 전용 복제**(`COND_OwnerOnly`)로 둔다. 남의 인벤토리를 클라가 받으면 그대로 정보 유출이다. #5의 "팀원 보유 재료 아이콘"만 예외적으로 팀 범위 복제가 필요하다 — **재료 아이콘용 축약 배열을 따로 두는 편이 안전하다.**
> - **C++**: 델리게이트 구독/해제, 표시용 구조체 생성. **위젯 BP**: 프로그레스바 색·아이콘·애니메이션(피격 시 붉은 플래시 등).

### 4.3 확장맵 (`M`) + 파밍 위치 오버레이 (`Alt + M` / `F8` 토글)

```
+----------------------- 확장맵 (M) ------------------------+
|  [F8] 파밍 오버레이 ON     목표 빌드: 천근추 · 창파오 ...   |
|                                                           |
|   +--------+  +--------+  +--------+                      |
|   | 숲      |  | 절      |  | 병원    |   o     상자(파란 점)|
|   | *유리병 |  | *꽃     |  |        |   ooooo 우선 상자    |
|   +--------+  +--------+  +--------+   *  필요 재료(오버레이)|
|   +--------+  +--------+  +--------+   ^  오브젝트/보스     |
|   | 골목길  |  | 연못    |  | 공장    |   +  팀원            |
|   | *고무   |  | *꽃     |  | *배터리 |   :  금지 예정(노랑) |
|   +--------+  +--------+  +--------+   #  금지 구역(빨강)   |
|                                                           |
|  +-- 부족 재료 ---------------------------------------+   |
|  | 고무 x1 -> 골목길   유리병 x1 -> 숲   (여분: 파랑)   |   |
|  | 트럼프 카드 x1 -> 호텔                              |   |
|  +-----------------------------------------------------+  |
+-----------------------------------------------------------+
```

> **정보 설계 의도 (상위 문서 원문):** `Alt + M`은 이 게임 UI 설계의 가장 중요한 결정이다.
> **"목표 아이템 → 필요 재료 → 재료가 있는 지역"** 3단계 역추적을 **UI가 대신해 준다.**
> 이것이 없으면 `90명 × 23무기 × 35재료`의 조합을 전부 암기해야 한다.
> **검증 기준(§12.5):** 신규 유저가 튜토리얼 없이 오버레이만 보고 **"내가 지금 어디로 가야 하는지"를 5초 안에** 판단할 수 있는가.

> **구현 메모:**
> - **미니맵을 `SceneCaptureComponent2D`로 만들지 말 것.** 탑다운 21지역을 실시간 렌더하면 비용이 크고, 상자·재료 마커는 어차피 데이터에서 그린다. **지역 경계는 미리 만든 텍스처 1장 + 마커는 UMG 위젯**이 싸다.
> - **미니맵과 확장맵은 같은 위젯 클래스에 스케일·표시 필터만 다르게** 둔다. 두 개를 따로 만들면 마커가 서로 어긋난다.
> - **월드 좌표 → 맵 UV 변환은 C++ 함수 하나로 고정한다** (`FVector2D WorldToMapUV(const FVector&)`). 미니맵·확장맵·핑·오버레이가 전부 이 함수를 공유해야 좌표가 일치한다.
> - 마커 수가 수백 개다. **위젯을 매번 생성/파괴하지 말고 오브젝트 풀링**한다.
> - 핑은 **`Server` RPC → 서버가 쿨타임·도배 제한 검증 → `NetMulticast`(팀 한정)**. 클라가 팀원에게 직접 쏘지 않는다. 남은 시간은 서버 값 기준 로컬 카운트다운.
> - `F8` 토글과 `M` 열림 상태는 **복제하지 않는다.** 순수 로컬.
> - **C++**: 좌표 변환, 마커 목록 구성·필터링, 오버레이 하이라이트 대상 계산, 핑 RPC. **위젯 BP**: 마커 아이콘·색·깜빡임 애니메이션·툴팁 레이아웃.

## 5. ⭐ 핵심 산출물 2 — 제작 UI의 요구사항 분해

**이 게임에서 가장 복잡한 UI다.** 그리고 §4.3의 오버레이는 **이 계산 결과를 지도에 칠하는 것뿐**이다. 그래서 둘은 분리할 수 없다.

### 5.1 원작이 제작 UI에 요구하는 것 (상위 문서 §11.3)

| 항목 | 내용 |
|---|---|
| 기본 표시 | 목표 아이템 → **하위 재료 트리** → 보유/미보유 표시 |
| **동적 대체 아이템 추천** | 현재 보유 재료로 만들 수 있는 **대안 아이템을 자동 추천** |
| **12.2 신규** | 후반 아이템 제작에 필요한 **여분 재료를 파란색으로 강조 표기** |
| 제작 우선순위 | 설정에서 순위 지정. 고수는 **다리 방어구를 최상단**(초반 이동속도 확보) |
| 팀 요청 | 크레딧 부족 시 `Alt + 클릭`으로 팀원에게 아이템 요청 → 팀원은 **말풍선 우클릭**으로 응답 |

### 5.2 "이 아이템을 만들려면 무엇이 필요한가" — 재귀 탐색

장비 문서 §6.2가 확정한 규칙 하나가 이 UI 전체를 가능하게 만든다: **제작은 항상 아이템 2개 조합(`A + B → C`)이다. 3개 이상은 없다.**
따라서 `FItemRow`의 `CraftMaterialA` / `CraftMaterialB` 두 필드만으로 **이진 트리 재귀 탐색**이 성립한다.

```
[목표] 천근추 (영웅)
 +- 운명의 망치 (희귀)          <- 미보유 -> 계속 내려감
 |   +- 사슴 망치 (고급)        <- 미보유
 |   |   +- 망치 (일반)     [보유] -> 잎, 탐색 종료 (하위로 안 내려감)
 |   |   +- 고무 (일반)     [없음] -> 잎, 수집 대상
 |   +- 트럼프 카드 (일반)  [없음] -> 잎, 수집 대상
 +- 유리병 (일반)           [없음] -> 잎, 수집 대상

  결과: 부족 재료 = { 고무, 트럼프 카드, 유리병 }
        |
        v  재료 -> 지역 매핑 테이블 조회 (결정론적 스폰. 확률 아님)
        고무 = 골목길 / 트럼프 카드 = 호텔 / 유리병 = 숲
        |
        v
  >> 확장맵 오버레이: 해당 지역에 하이라이트
  >> 부족 재료 패널: 재료명 · 개수 · 지역명
  >> 루트 제안: 현재 위치에서 가까운 순서로 지역 정렬
```

> **여기서 읽어야 할 것:** 오버레이는 별도 기능이 아니다. **제작 트리 재귀의 마지막 출력 단계**다.
> 제작 UI를 만들면 오버레이는 "지역 하이라이트 코드 몇 줄"이고, 제작 UI 없이 오버레이만 만들면 **하이라이트할 대상을 계산할 방법이 없다.**

### 5.3 계산 단계 분해 (그대로 구현 순서다)

| 단계 | 입력 | 처리 | 출력 | 어디서 |
|---|---|---|---|---|
| ① 트리 펼치기 | 목표 아이템 ID | `CraftMaterialA/B`를 잎(`NAME_None`)까지 재귀 | 트리 구조 | **C++ · 매치 시작 시 1회 캐시** (정적 데이터) |
| ② 보유 판정 | 인벤토리 스냅샷 | 트리 순회하며 보유 플래그. **보유한 노드는 하위로 내려가지 않는다** | 부족 잎 재료 목록 | **C++ · 인벤토리 변경 이벤트에서만 재계산** |
| ③ 지역 매핑 | 부족 재료 목록 | 재료 → 지역 테이블 조회 | `{재료, 개수, 지역[]}` | **C++** |
| ④ 오버레이 | ③ 결과 | 지역 하이라이트 + 마커 배치 | 확장맵 표시 | **C++ 계산 / 위젯 BP 표현** |
| ⑤ 대체 추천 | 인벤토리 | **역방향 인덱스**(재료 → 그 재료를 쓰는 아이템) 조회 후 "부족 1개"인 아이템 우선 정렬 | 추천 목록 | **C++ · 역인덱스는 시작 시 1회 빌드** |
| ⑥ 여분 강조 (12.2) | 목표 빌드 전체(5슬롯) | 둘 이상의 목표에 쓰이는 재료를 마킹 | 파란색 태그 | **C++ 판정 / BP 색상** |
| ⑦ 정렬 | 유저 설정 우선순위 | 제작 가능 목록을 유저 지정 순으로 정렬 (다리 방어구 최상단 등) | 표시 순서 | **C++ · 설정은 로컬 저장** |

> **⑤ 대체 추천이 왜 "편의 기능"이 아닌가:** 상위 문서 §12.3은 이것을 **"루트 실패 시의 회복 경로"** 로 분류한다.
> 파밍이 꼬였을 때 유저가 스스로 대안을 찾으려면 트리 전체를 암기해야 한다. UI가 대신하지 않으면 꼬인 유저는 그 판을 포기한다.

### 5.4 서버 권위 경계

| 동작 | 클라(UI) | 서버 |
|---|---|---|
| 트리 표시 · 부족 재료 계산 | ✅ 로컬 계산 (정적 데이터 + 내 인벤토리) | 관여 안 함 |
| "제작" 버튼 활성화 | ✅ 로컬 선판정 (**표시용일 뿐**) | — |
| **실제 제작 실행** | `ServerCraftItem(FName TargetItemId)` 호출만 | **재료 보유·크레딧 재검증 → 인벤토리 변경 → 복제** |
| 팀원에게 아이템 요청 (`Alt+클릭`) | `ServerRequestItem(...)` 호출만 | 검증 후 해당 팀원에게 `Client` RPC로 말풍선 |
| 말풍선 우클릭 응답 | `ServerRespondItemRequest(...)` | 아이템 이동 실행 |
| 오버레이 On/Off, 정렬 설정 | ✅ 완전 로컬 (복제 금지) | 관여 안 함 |

> **구현 메모:**
> - **재귀 탐색을 위젯 Tick이나 BP에서 돌리지 말 것.** 트리는 데이터 테이블 기반의 **정적 구조**다. `UGameInstanceSubsystem`에서 **한 번 펼쳐 캐시**하고, 인벤토리 변경 델리게이트에서 **보유 플래그만** 갱신한다.
> - **순환 참조 방어 필수.** 데이터 입력 실수로 `A → B → A`가 생기면 무한 재귀로 크래시한다. `TSet<FName> Visited` + 깊이 상한(등급 단수 + 여유)을 두고, 걸리면 `ensure()` + 조기 반환 + `UE_LOG(Warning)`.
> - 제작 트리 노드는 **재귀 위젯**이다. BP에서 자기 자신을 자식으로 배치하면 순환 참조 경고가 나기 쉽다. **C++ 베이스 위젯이 자식 노드를 `CreateWidget`으로 생성**하고, BP는 노드 한 칸의 외형만 담당한다.
> - 트리 계산은 **위젯이 아니라 서브시스템에 둔다.** 인게임 제작 UI와 로비 루트 플래너(§7)가 같은 코드를 써야 하기 때문이다.
> - **C++**: ①~⑦ 전부 + RPC. **위젯 BP**: 노드 아이콘·등급 색·보유/미보유 시각 차이·파란색 여분 태그·펼침 애니메이션.

## 6. 루팅 UI (상위 문서 §11.4)

| 항목 | 내용 | 갱신 / 출처 |
|---|---|---|
| 상자 | 미니맵에 **점 개수로 등급·수량 암시**. **점 5개 상자 우선 오픈** | 이벤트 / `AERGameState` 상자 목록 |
| 자동 획득 | 우선순위 아이템 자동 습득 (설정 기반) | 설정은 로컬, **획득 판정은 서버** |
| 인벤토리 소비 우선순위 | 설정에서 **내림차순 지정** → 높은 번호 슬롯의 음식부터 소비 | 설정 로컬 → 소비 실행은 Server RPC |
| 상자 오픈 중 제작 | 오픈 대기 시간 동안 **제작을 병행하는 것이 최적화** | — |

> **"상자 오픈 중 제작 병행"은 그냥 팁이 아니라 UI 요구사항이다.** 오픈 진행 바가 떠 있는 동안에도 **제작 UI가 입력을 받아야 한다.**
> 오픈 중 다른 UI를 잠그는 구현을 하면 원작의 최적 플레이가 불가능해진다. **모달 UI로 만들지 말 것.**

> **구현 메모:** 자동 획득·소비 우선순위는 매 획득마다 RPC를 보내는 대신 **접속 시 1회 `ServerSetLootPriority(TArray<FName>)`로 서버에 동기화**하고, 이후 판정은 서버가 자기 사본으로 수행한다. 오픈 진행 바는 서버가 복제한 시작 시각 기준으로 클라가 로컬 보간한다(진행률을 매 프레임 복제하지 않는다).

> ⚠ **상위 문서 §12.5 안에서 서술이 충돌한다.** 「2순위 크래프팅의 최소 구현 사양」은 **【필수】 로비 루트 플래너**라고 적고,
> 「권장 개발 순서」는 로비 루트 플래너를 **M5**에 둔다.
> **이 문서의 판단: 매치 중 확장맵 오버레이(§4.3·§5)가 먼저다.** 로비 플래너는 같은 계산을 매치 밖에서 미리 하는 것뿐이므로,
> 오버레이가 동작하면 플래너는 **UI 껍데기 추가**로 끝난다. 순서를 뒤집으면 계산 코드를 두 번 짜게 된다.

> **구현 메모:** 로비는 별도 레벨 + 별도 `GameMode`이고 매치 HUD 위젯과 코드를 공유하지 않는다. **단 제작 트리 계산(§5.3 ①⑤)만은 반드시 공유한다** — 로비 플래너와 인게임 제작 UI가 서로 다른 트리를 보여주면 즉시 신뢰를 잃는다. 이것이 트리 계산을 위젯이 아니라 서브시스템에 두어야 하는 이유다.

## 8. 접근성 / 편의 설정 (상위 문서 §11.6)

| 설정 | 권장값 | 이유 | 저장 위치 |
|---|---|---|---|
| 인벤토리 아이템 소비 우선순위 | 내림차순 | 높은 슬롯 음식부터 소비 | 로컬 (+ 접속 시 서버 1회 동기화) |
| CCTV 감지 범위 표시 | 항상 표시 | 적에게 내 정보가 노출되는 것을 방지 | 순수 로컬 |
| 제작 아이템 순위 | **다리 방어구 최상단** | 초반 이동속도 확보 | 순수 로컬 |
| 연습 모드 (12.2) | `Ctrl+Alt+우클릭` 즉시 이동 | 콤보 연습 효율 | 연습 모드 전용 |
| 파밍 오버레이 토글 | `F8` | On/Off | 순수 로컬 |

> **이 표는 "옵션 화면"이 아니라 진입장벽 완화 장치 목록이다.** 상위 문서는 이를 **커뮤니티가 필수로 꼽는 항목**으로 기술한다.
> 그리고 §12.3의 교훈이 그대로 적용된다 — 12.0 휴식 개편은 **"초보자가 쉽게 파악하도록"** 이 명시된 의도였으나 숙련자의 조작 리듬을 파괴해 **커뮤니티 투표 87%가 롤백을 요구**했고, 12.1에서 **병존** 방식으로 봉합됐다.
> → **온보딩 장치는 기존 시스템을 대체하는 게 아니라 병렬로 추가한다.** 따라서 **오버레이·자동습득·대체 추천은 전부 끌 수 있어야 한다.**

> **구현 메모:** 설정은 `UGameUserSettings` 파생 또는 `USaveGame`에 저장. **설정값을 복제하지 않는다.** 예외는 서버가 대신 판정해야 하는 자동 획득·소비 우선순위뿐이며 §6대로 접속 시 1회만 동기화한다.

## 9. 클론 초기 버전 — 필수 UI vs 잘라도 되는 UI

| 판정 | 요소 | 근거 |
|---|---|---|
| ✅ **필수** | 체력/기력 바, 스킬 바(P/Q/W/E/R), 인벤토리·장비 5칸, 미니맵, 매치 정보 바, 금지구역 표시, 버프/상태이상 바, **제작 UI 전체**, **⭐확장맵 파밍 오버레이** | 오버레이는 §12.5 2순위의 **【필수】** 항목. 제작과 세트 |
| ✅ **필수 (3인 팀 유지 시)** | 팀원 3인 포트레이트 + 보유 재료 아이콘, 핑 4종 | 재료 트레이드를 **UI 레벨에서 유도**하는 장치. 팀 플레이의 전제 |
| ⬜ **저비용 · 권장** | 킬 어나운스, 실험체 초상·레벨 | 구현 비용 대비 체감이 큼 |
| ❌ **컷** | **F(전술) 슬롯** | §12.5: "D와 역할이 겹치고 슬롯 2개는 초심자에게 과하다 → **초기 버전에서 완전 삭제. D만 운영**" |
| ❌ **컷** | **숙련도 6종 표시 → 무기 숙련도 1종만** | §12.5: 나머지 5종은 2~10%의 미미한 스탯. 인지 부하 대비 재미 기여도가 낮다 |
| ❌ **컷** | 교전 로그 UI, 이스포츠 스케쥴러, 아카이브, 상점, 크로노 스피어 범위 강조 | 중계·메타 콘텐츠. 코어 루프 이후 |
| ❌ **컷 (조건부)** | 로비 전략 탭(루트 플래너) | M5. **단 인게임 오버레이는 컷 불가** (§7의 충돌 주의) |

> **잘라서는 안 되는 것을 한 줄로: 제작 UI + 확장맵 파밍 오버레이.**
> §12.5 「클론 개발 시 반드시 피해야 할 함정」이 명시한다 — *"크래프팅을 UI 지원 없이 출시하기: Alt+M 오버레이가 없었다면 35종 재료 × 21지역 암기 강요."*

## 구현 우선순위

```
1순위. HUD 위젯 C++ 베이스 + 체력/기력 바 + 스킬 바(P/Q/W/E/R)
       → 검증: 서버에서 체력을 바꾸면 클라 위젯이 Tick 없이 OnRep 델리게이트로 갱신됨
2순위. 매치 정보 바(일차/낮밤/남은 시간/생존 팀 수) + 금지구역 예고
       → 검증: Play As Client, Number of Players 2 에서 두 클라의 남은 시간이 ±0.5초 내 일치
3순위. 인벤토리 / 장비 5칸 위젯
       → 검증: 서버가 아이템을 지급하면 소유 클라에만 슬롯이 갱신되고 타 클라에는 안 보임
4순위. 미니맵 (WorldToMapUV 공용 함수 + 마커 오브젝트 풀링)
       → 검증: 팀원 아이콘이 실제 월드 위치와 일치, 마커 200개에서 프레임 저하 없음
5순위. ⭐ 제작 UI — 재귀 트리 탐색 + 보유 판정 + 부족 재료 목록
       → 검증: 망치 계열 17종 중 임의 1종을 목표로 지정하면 부족 잎 재료가 정확히 산출됨
              (순환 참조 데이터를 일부러 넣어도 크래시 없이 경고 로그만)
6순위. ⭐ 확장맵 + 파밍 위치 오버레이 (M / Alt+M / F8 토글)   ← 5순위와 세트. 분리 금지
       → 검증: 튜토리얼 없이 오버레이만 보고 "다음에 갈 지역"을 5초 안에 판단 가능한가 (§12.5 기준)
7순위. 제작 실행 Server RPC + 서버 재검증
       → 검증: 클라가 재료 없이 제작을 호출해도 서버가 거부하고 인벤토리가 변하지 않음
8순위. 팀원 포트레이트 + 보유 재료 아이콘 + 핑 4종
       → 검증: 핑이 같은 팀에만 표시되고, 도배 제한 시 남은 시간이 표시됨
9순위. 동적 대체 아이템 추천 (역방향 인덱스)
       → 검증: 재료를 임의로 지급하면 "부족 1개" 아이템이 추천 목록 상단에 올라옴
10순위. 버프/상태이상 바, 킬 어나운스, 자동 획득·소비 우선순위 설정
       → 검증: 상태이상 부여 시 아이콘·중첩 수·남은 시간이 표시됨
```
