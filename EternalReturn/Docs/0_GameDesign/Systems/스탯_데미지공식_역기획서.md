## 0. 이 시스템의 정체

**스탯은 "빌드로 조립하는 계산기"이고, 피해 공식은 그 계산기의 유일한 출력 함수다.** 장비가 스탯을, 스킬이 계수를 공급하고, 둘이 만나는 지점은 여기 하나뿐이다. 설계 핵심 셋:
① **방어력은 체감 감소처럼 보이지만 체력과 곱해지면 선형 가치**를 가진다 → "체력 vs 방어력" 트레이드오프가 성립한다.
② **고정 피해는 모든 보정을 우회**한다 → 탱커 무한 스케일링을 끊는 유일한 안전장치.
③ **스킬 가속은 상한 없는 선형 모델**이다 → 구 % 쿨감의 비선형 폭발을 의도적으로 제거한 결과.

> **결론:** 스탯 목록을 늘리는 건 쉽다. 어려운 건 **연산 순서를 한 곳에 고정하는 것**이다. §2 의사코드가 그 "한 곳"의 명세다.

> **네트워크 전제 (CLAUDE.md §6)** — 데디케이티드 서버 타겟이다. **피해 계산은 서버에서만 수행되고 클라이언트에는 결과(체력·상태)만 복제된다.** 클라이언트는 어떤 경우에도 피해량을 스스로 계산해 체력을 깎지 않는다. 피격 이펙트·데미지 넘버는 서버 판정 후 `NetMulticast`/`Client` RPC로 내려보내는 **표시용**이다.

## 1. 스탯 전수 목록

### 1.1 기초 스탯 (실험체 고유 + 레벨 성장)

| 스탯 | 의미 | 단위 | 상한 | 비고 |
|---|---|---|---|---|
| **최대 체력 (HP)** | 생명력 | 정수 | 없음 | 레벨당 고정 증가 (재키 +95 / 아야 +76) |
| **체력 재생** | 초당 체력 회복 | 실수 | 없음 | 재키 1.28 → 2.743 |
| **최대 기력 (VP/SP)** | 스킬 자원 | 정수 | 없음 | 레벨 성장 수치 **(미확인)** |
| **기력 재생** | 초당 기력 회복 | 실수 | 없음 | **(미확인)** |
| **공격력 (AP)** | 기본 공격 피해 + 스킬 공격력 계수의 기준값 | 정수 | 없음 | 재키 36 → 125 |
| **방어력 (DEF)** | 기본 공격·스킬 피해 감소 | 정수 | 없음 | 재키 50 → 107 |
| **공격 속도 (AS)** | 초당 기본 공격 횟수 | 실수 | **2.5** | ⚠ 돌격소총 "과열"은 상한 무시 |
| **이동 속도 (MS)** | 초당 이동 거리 | 실수 | **(미확인)** | 기본 3.5~3.6대 |
| **시야 (Sight)** | 시야 반경 | 실수 | 없음 | 탐색 숙련도 레벨당 +0.01 |
| **기본 공격 사거리** | 기본 공격 최대 거리 | 실수 | — | 무기 계열이 결정 |

> **구현 메모** — `AS`는 클램프 지점이 명확한 유일한 스탯이다. 단, "상한 무시" 플래그(과열)가 존재하므로 `ClampAttackSpeed(Value, bIgnoreCap)` 형태로 **플래그를 받는 함수**로 만든다. 상수 `2.5f`를 코드에 흩뿌리지 않는다. `MS`는 상한 미확인이나 **둔화 하한과 함께 반드시 클램프가 필요**하다(무한 감속 방지). 값은 팀이 정하고 자체 결정값임을 기록한다.

### 1.2 공격 계열 파생 스탯

| 스탯 | 의미 | 단위 | 상한 | 비고 |
|---|---|---|---|---|
| **치명타 확률** | 기본 공격의 치명타 발생 확률 | % | **(미확인)** 100% 추정 | 공식 문서 미확보 |
| **치명타 피해 증가** | 치명타 배율 가산 | % | 없음 | 공식상 `0.75 + 치명타 피해 증가` |
| **스킬 증폭 (스증)** | 스킬 피해 계수 기준값 | 실수 | 없음 | 스킬 피해 산출에만 관여 |
| **기본 공격 증폭 (%)** | 기본 공격 한정 피해 증폭 | % | 없음 | 무기 숙련도·아이템 |
| **방어 관통 (%)** | 대상 방어력 비율 무시 | % | **(미확인)** | **고정 관통보다 먼저 적용** |
| **방어 관통 (고정)** | 대상 방어력 정수 무시 | 정수 | 없음 | % 적용 후 감산 |
| **피해 증가 (%)** | 모든 피해 증가 | % | 없음 | 대상의 피해 감소(%)와 **상쇄(가감산)** |
| **최종 피해 추가 (%)** | 마지막 단계 곱연산 | % | 없음 | 연산 위치가 가장 마지막 |
| **최종 피해 추가 (고정)** | 마지막 단계 합연산 | 정수 | 없음 | % 적용 **이후** 가산 |
| **쿨다운 감소 / 스킬 가속** | 스킬 재사용 대기시간 감소 | 수치 | **없음(선형)** | §4 참조 |

> **치명타 배율은 175%다** (구 200%에서 하향). 공식상 `1 + (0.75 + 치명타 피해 증가%)`로 계산된다. **스킬은 치명타가 발생하지 않는다.** 이건 밸런스 옵션이 아니라 공식 규칙이므로 파이프라인에서 타입으로 강제한다.

> **구현 메모** — `피해 증가(%)`와 대상의 `피해 감소(%)`는 **곱이 아니라 뺄셈으로 상쇄**된다(`1 + 증가 − 감소`). 이를 각각 곱연산으로 구현하면 수치가 어긋난다. 반면 `스킬 피해 감소(%)`는 `(1 − 감소)` **독립 곱**이다. 두 규칙이 다르다는 점에 주의.

### 1.3 방어 계열 파생 스탯

| 스탯 | 의미 | 단위 | 상한 | 비고 |
|---|---|---|---|---|
| **피해 감소 (%)** | 기본 공격·치명타·스킬·함정 피해 전반 감소 | % | **(미확인)** | 공격자의 피해 증가(%)와 상쇄 |
| **기본 공격 피해 감소 (%)** | 기본 공격 한정 | % | **(미확인)** | 기본 공격 증폭 단계에서 상쇄 |
| **스킬 피해 감소 (%)** | 스킬 한정 | % | **(미확인)** | 독립 곱 `(1 − x)` |
| **이동 속도 감소 저항 (%)** | 둔화 **지속시간** 감소 | % | **(미확인)** | 세기가 아니라 **지속시간**이다 |
| **방해 저항 (%)** | 방해(기절·둔화·속박 등) **지속시간** 감소 | % | **(미확인)** | ⚠ **붙잡기·에어본·제압은 제외** |

> **구현 메모** — 저항 계열 2종은 **피해 계산에 전혀 관여하지 않는다.** CC 지속시간 산출 함수에만 들어간다. 상세는 [`전투판정_상태이상_역기획서.md`](전투판정_상태이상_역기획서.md) 담당. 여기서는 스탯 목록에만 존재하고 `CalculateDamage()`에서는 참조하지 않는다.

### 1.4 유지력 계열

| 스탯 | 의미 | 단위 | 상한 | 감쇠 규칙 |
|---|---|---|---|---|
| **생명력 흡수 (흡혈)** | **기본 공격** 피해의 일정 비율 회복 | % | **(미확인)** | 광역 피해 **50%**, 야생동물 대상 **60%** |
| **모든 피해 흡혈** | **모든 유형**의 피해에 대해 회복 | % | **(미확인)** | 동일 감쇠 규칙 |
| **회복량 증가 (%)** | 받는 회복 효과 증폭 | % | **(미확인)** | 치유 감소(치감) 효과와 상쇄 여부 **(미확인)** |
| **비전투 체력 재생** | 비전투 시 회복 | % | **+200%** | 제작 숙련도 레벨당 +10% |

> **구현 메모** — 흡혈은 **피해 계산의 일부가 아니라 피해 적용 이후의 후처리**다. `CalculateDamage()`가 반환한 최종 피해량과 `bIsAoE` / `bTargetIsWildlife` 플래그를 받아 별도 함수 `ApplyLifesteal()`이 처리한다. 두 감쇠(50% / 60%)의 **중복 적용 규칙은 (미확인)**.

### 1.5 모드/전용 보정 스탯

| 스탯 | 의미 | 비고 |
|---|---|---|
| **모드 피해 증가 (%)** | 모드별 실험체·무기 조합 보정 | 12.2 기준 대부분 ±1~3% |
| **모드 피해 감소 (%)** | 동일 | 코발트 프로토콜 등 |

> **구현 메모** — 모드 보정은 **고정 피해에도 적용되는 유일한 보정**이다. 따라서 파이프라인의 **가장 바깥 단계**에 모든 피해 타입이 공통으로 통과하는 지점을 두어야 한다. 정규 매치만 만들 계획이라면 계수를 1.0으로 두되 **단계 자체는 남긴다.**

## 2. 데미지 계산 파이프라인 (핵심 산출물)

원본 §6.2의 4개 공식(적용 방어력 / 기본 공격 / 스킬 / 고정)을 **하나의 함수**로 합친 것이다.
CLAUDE.md §8 — 데미지 계산은 반드시 한 곳에 모은다. 캐릭터·스킬·무기 코드는 이 함수를 **호출만** 하고 자체 계산하지 않는다.

### 2.1 입력 구조체

```cpp
// 피해 1회에 필요한 전부. 스킬/기본공격/함정/야생동물이 모두 이걸 채워서 넘긴다.
struct FDamageContext
{
    AActor*        Attacker;  AActor* Target;
    EDamageChannel Channel;        // BasicAttack / Skill / True(고정) — 연산 분기를 결정
    float BaseDamage;              // 스킬 기본 피해 (기본 공격이면 0)
    float APRatio, BonusAPRatio;   // 공격력 계수 / 추가 공격력 계수(기본 공격력 제외분)
    float SkillAmpRatio;           // 스킬 증폭 계수
    float CharLevelRatio;          // 캐릭터 레벨 계수 (레니 전용 경로)
    float MaxHPRatio, CurHPRatio;  // 대상 최대/현재 체력 비례
    float LostHPRatio;             // 시전자 잃은 체력 비례
    bool  bCanCrit;                // Skill 채널이면 항상 false (공식 규칙)
    bool  bIsAoE;                  // 흡혈 감쇠 판정용
};
```

### 2.2 계산 함수 (의사코드)

```cpp
// [서버 전용] 이 프로젝트의 모든 피해는 예외 없이 이 함수 하나를 통과한다.
float CalculateDamage(const FDamageContext& Ctx)
{
    // 0. 권위 검사 — 클라이언트는 절대 계산하지 않는다
    if (!HasAuthority() || !Ctx.Attacker || !Ctx.Target) return 0.f;
    const FStats& A = GetStats(Ctx.Attacker);
    const FStats& T = GetStats(Ctx.Target);

    // 1. 모드 보정 계수 (모든 채널이 마지막에 공유)
    const float ModeMul = 1.f + A.ModeDamageUp - T.ModeDamageDown;

    // 2. 고정 피해 채널 → 즉시 종료. 방어력·피해감소·증폭·치명타 어느 것도 받지 않는다
    if (Ctx.Channel == EDamageChannel::True)
        return Max(0.f, Ctx.BaseDamage * ModeMul);

    // 3. 계수 적용 → 방어력 적용 전 원시 피해
    float Raw;
    if (Ctx.Channel == EDamageChannel::Skill)
    {   // 원본 §6.2 ③: "스킬 피해 = 기본 피해 + 공격력 계수 + 스킬 증폭 계수"의 합
        Raw  = Ctx.BaseDamage;
        Raw += A.AttackPower * Ctx.APRatio;
        Raw += A.BonusAP     * Ctx.BonusAPRatio;              // 기본 공격력 제외분
        Raw += A.SkillAmp    * Ctx.SkillAmpRatio;
        Raw += GetLevel(Ctx.Attacker) * Ctx.CharLevelRatio;   // 레니 전용 경로
    }
    else Raw = A.AttackPower;                                 // BasicAttack: 계수 없이 공격력 그대로

    // 3-b. 체력 비례 성분 (원본에 연산 위치 명시 없음 → 자체 결정)
    //      대상별 감쇠: 위클라인 등 보스는 0.5 (몬스터 문서 §5.1)
    float Prop = T.MaxHP * Ctx.MaxHPRatio + GetCurHP(T) * Ctx.CurHPRatio
               + GetLostHP(A) * Ctx.LostHPRatio;
    Raw += Prop * T.ProportionalDamageTakenMul;               // 기본 1.0

    // 4. 적용 방어력 (§6.2 ①) — 순서 고정: % 관통 먼저, 고정 관통 나중
    float EffDef = (T.Defense * (1.f - A.DefPenPercent)) - A.DefPenFlat;
    EffDef = Max(0.f, EffDef);                     // 음수 방어력은 추가 피해가 아니다 (자체 결정)

    // 5. 방어력 감산
    float Dmg = Raw * (100.f / (100.f + EffDef));

    // 6. 치명타 — 기본 공격 채널 전용. 스킬은 절대 치명타가 발생하지 않는다
    if (Ctx.Channel == EDamageChannel::BasicAttack && Ctx.bCanCrit)
        if (ServerRandom() < A.CritChance)          // 난수는 반드시 서버에서만
            Dmg *= (1.f + (0.75f + A.CritDamageUp));// 기본 175%

    // 7. 공통 피해 증감 (가감산 상쇄)
    Dmg *= (1.f + A.DamageUp - T.DamageDown);

    // 8. 채널별 증감 — 기본공격은 가감산 상쇄, 스킬은 독립 곱. 규칙이 다르다
    Dmg *= (Ctx.Channel == EDamageChannel::BasicAttack)
         ? (1.f + A.BasicAtkAmp - T.BasicAtkDamageDown)
         : (1.f - T.SkillDamageDown);

    // 9. 최종 피해 추가 — ⚠ 원본 표기는 `× 최종 피해 추가(%)`. (1+x)로 해석했다. §8 참조
    Dmg = (Dmg * (1.f + A.FinalDamageUpPercent)) + A.FinalDamageUpFlat;

    // 10. 모드 보정
    Dmg *= ModeMul;

    // 11. 무효화 계층 (시셀라 W 등) — CC는 막지 않는다. 피해만 0
    if (T.bDamageImmune) return 0.f;

    return Max(0.f, Dmg);
}
```

### 2.3 함수 밖에서 처리하는 것

| 항목 | 이유 | 처리 위치 |
|---|---|---|
| 보호막 소모 | 피해량이 아니라 **적용 방식**의 문제 | `ApplyDamage()` — 계산 결과를 체력에 반영하는 지점 |
| 흡혈 회복 | 최종 피해량이 확정된 **뒤** 계산 | `ApplyLifesteal(FinalDmg, bIsAoE, bTargetIsWildlife)` |
| CC 지속시간 감소 | 피해가 아님 | CC 시스템 ([`전투판정_상태이상_역기획서.md`](전투판정_상태이상_역기획서.md)) |
| 도트(출혈) 틱 | 틱마다 이 함수를 **재호출**한다 | 도트 컴포넌트가 주기적으로 `CalculateDamage()` 호출 |

> **구현 메모** — 함수는 **부작용이 없어야 한다(pure)**. 체력을 깎거나 이펙트를 재생하지 않고 **숫자만 반환**한다. 그래야 ① 툴팁의 "예상 피해량"에 같은 함수를 재사용할 수 있고, ② GAS `ExecutionCalculation`으로 그대로 이식된다. 난수(치명타)가 유일한 비순수 요소이므로 `bForceCrit`/`bForceNoCrit`로 결정론적 호출을 허용한다.

## 3. 방어력 감소 곡선

```
피해 감소율 = 1 − (100 / (100 + 적용 방어력))
유효 체력   = 최대 체력 × (1 + 적용 방어력 / 100)
```

| 적용 방어력 | 피해 감소율 | 유효 체력 배율 |
|---|---|---|
| 0 | 0% | ×1.00 |
| 50 | 33.3% | ×1.50 |
| **100** | **50.0%** | **×2.00** |
| 150 | 60.0% | ×2.50 |
| 200 | 66.7% | ×3.00 |
| **300** | **75.0%** | **×4.00** |
| 400 | 80.0% | ×5.00 |

> **설계적 함의:** 방어력 100당 유효 체력이 **선형으로 +1배씩** 증가한다. "수익 체감"은 피해 감소율 표기에서만 보이는 착시이고, **체력과 곱해질 때 방어력의 가치는 선형**이다. 그래서 탱커 빌드에서 체력과 방어력이 균형을 이루고 **고정 피해가 유일한 카운터**가 된다.

> **구현 메모** — 이 곡선은 커브 애셋이 아니라 §2 5단계의 `100/(100+DEF)` 한 줄이 전부다. `UCurveFloat`를 만들지 않는다. 밸런스 조정이 필요하면 상수 `100.f`를 프로젝트 설정값 하나로 뺀다. **음수 적용 방어력은 0 클램프** — 관통 초과분이 추가 피해가 되는지는 원본 미확인이므로 보수적으로 간다.

## 4. 쿨다운 감소 / 스킬 가속

```
최종 쿨다운 = 기본 쿨다운 × 100 / (100 + 스킬 가속)
```

| 스킬 가속 | 0 | 25 | 50 | 100 | 200 |
|---|---|---|---|---|---|
| **환산 쿨감** | 0% | 20.0% | 33.3% | 50.0% | 66.7% |
| **시전 횟수 배율** | ×1.00 | ×1.25 | ×1.50 | ×2.00 | ×3.00 |

| 항목 | 내용 |
|---|---|
| 도입 시점 / 이유 | **시즌 8** — 아이템 빌드 다양성 확대 + 쿨감 격차 해소 |
| 구조 | **상한 없는 선형 DPS 증가** 모델. 구 `%` 쿨감의 80~90% 구간 비선형 폭발을 제거 |
| 개발팀 자평 | "초기 수치를 너무 보수적으로 잡은 것은 나쁜 판단", "무리하게 진행할 만큼 큰 변화는 아니었다" |

> ⚠ **출처 불일치:** "쿨감은 30%까지만 적용되며 최대 쿨다운 감소 능력치로 상한을 늘릴 수 있다"는 **구버전 서술**이 위키에 남아 있다. **현행 모델에는 상한이 없다.** 구 서술을 따라 30% 캡을 구현하면 안 된다.

> **구현 메모** — 방어력 공식과 **수학적으로 동일한 형태**(`100/(100+X)`)다. 공용 헬퍼 `DiminishingFactor(X)` 하나로 양쪽을 처리한다. ⚠ 단 **쿨감이 적용되지 않는 고정 쿨다운이 존재하므로**(아야 패시브 등 — 공통 규약 §2.1) 스킬 데이터에 `bIgnoreCooldownReduction` 플래그가 필요하다.

## 5. 스탯 상한(캡) 문제

원본이 **명시적으로 "클론 구현 시 자체 결정 필요"**라고 남긴 영역이다. 확인된 것은 두 개뿐이다.

| 스탯 | 원본 상태 | 미설정 시 발생하는 사고 | 권장 처리 |
|---|---|---|---|
| **공격 속도** | **2.5 (확인됨)** | — | 상수화 + `bIgnoreCap` 플래그 |
| **스킬 가속** | **상한 없음 (확인됨)** | — | 클램프하지 않는다 |
| 치명타 확률 | (미확인, 100% 추정) | 100% 초과분이 낭비되거나 오버플로 | **1.0 클램프**는 최소한 필요 |
| 이동 속도 | (미확인) | 이동 스탯 스택 시 서버 이동 검증·충돌 판정 파탄 | 상·하한 모두 클램프 필요 |
| 둔화 하한 | "일정 수준 이하로 안 내려감"만 확인 | 이동 속도 0 → **영구 행동 불능** | **하한 필수** |
| 방해 저항 / 이속 감소 저항 | (미확인) | 100% 도달 시 CC 완전 면역 | 상한 필요 |
| 방어 관통(%) | (미확인) | 100% 도달 시 방어력 스탯 자체가 무의미해짐 | 상한 필요 |
| 피해 감소(%) 계열 | (미확인) | 100% 도달 시 **무적** | 상한 필수 |

> **구현 메모** — 캡은 코드에 흩뿌리지 말고 **한 곳(`UStatCapSettings` 또는 데이터 테이블 1행)** 에 모으고, 각 캡에 **"원작 확인값 / 자체 결정값"** 구분 컬럼을 둔다. 나중에 원작 값을 확인했을 때 무엇을 고쳐야 하는지 즉시 알아야 한다. **"100%에 도달하면 게임이 깨지는 스탯"(피해 감소, 방어 관통%, 저항, 치확)에는 지금 당장 임시 캡을 넣는다.**

## 6. 데이터 스키마 제안

`CLAUDE.md` §8 — 이 프로젝트는 **GAS 기반**이다. 아래 목록은 그대로 `UERAttributeSet` 의 어트리뷰트가 된다.

### 6.1 `EStatType` 후보 목록

```cpp
UENUM(BlueprintType)
enum class EStatType : uint8
{
    // 기초 — 각각 FGameplayAttributeData 1개가 된다
    MaxHP, HPRegen, MaxVP, VPRegen,
    AttackPower, Defense, AttackSpeed, MoveSpeed, Sight, AttackRange,

    // 공격 파생
    CritChance, CritDamageUp, SkillAmp, BasicAtkAmp,
    DefPenPercent, DefPenFlat,
    DamageUp, FinalDamageUpPercent, FinalDamageUpFlat,
    SkillHaste,

    // 방어 파생
    DamageDown, BasicAtkDamageDown, SkillDamageDown,
    SlowResist, CCResist,

    // 유지력
    Lifesteal, OmniLifesteal, HealAmp, OutOfCombatRegen,

    // 모드 보정
    ModeDamageUp, ModeDamageDown,
};
```

> **명명 규칙:** 이 이름이 그대로 GAS `Attribute` 이름이 된다. 구현 시 `ATTRIBUTE_ACCESSORS(UERAttributeSet, AttackPower)` 형태로 기계적 치환이 가능하다. **한 번 확정한 뒤 이름을 바꾸지 않는다** — 데이터 테이블·블루프린트 참조가 끊긴다 (CLAUDE.md §3).

### 6.2 스탯 컨테이너

```cpp
// 스탯 1개의 4개 레이어. GAS의 Base/Current 이원 구조를 미리 흉내낸 것이다.
struct FStatValue
{
    float Base;          // 실험체 고유 + 레벨 성장 (= GAS BaseValue)
    float Additive;      // 장비·특성의 합연산 보너스
    float Multiplier;    // 곱연산 보너스 (기본 1.0)
    float TempModifier;  // 버프/디버프 — 만료 시 복구되어야 함
    float Final() const { return (Base + Additive) * Multiplier + TempModifier; }
};

// ⚠ 위 4레이어는 **개념 설명이다. 이 컨테이너를 직접 만들지 않는다.**
// GAS 에서는 UAttributeSet + UGameplayEffect 가 그대로 이 역할을 한다:
//   Base       → FGameplayAttributeData::BaseValue
//   Additive   → GE Modifier (Additive)
//   Multiplier → GE Modifier (Multiplicitive)
//   Temp       → Duration GE — 만료 시 자동 복구된다
UCLASS()
class UERAttributeSet : public UAttributeSet
{
    UPROPERTY(BlueprintReadOnly, ReplicatedUsing=OnRep_AttackPower)
    FGameplayAttributeData AttackPower;
    ATTRIBUTE_ACCESSORS(UERAttributeSet, AttackPower)
    // ... §6.1 목록이 각각 하나씩
};
```

**GAS 구현 대응 관계**

| 이 문서의 개념 | GAS 구현 |
|---|---|
| `EStatType` 1개 | `FGameplayAttributeData` 1개 (`UERAttributeSet` 멤버) |
| 스탯의 영구값 | `AttributeData.**BaseValue**` |
| 장비·버프가 얹힌 값 | `AttributeData.**CurrentValue**` |
| 4레이어(기본/성장/장비/버프) | ⭐ **`UGameplayEffect` 가 대신한다** — 장비 착용 = Infinite GE 적용, 벗기 = GE 제거 |
| 수정자 추가/제거 + 출처 추적 | `UGameplayEffect` 적용/제거 + `FActiveGameplayEffectHandle` |
| 데미지 계산 함수 | ⭐ **`UGameplayEffectExecutionCalculation` 하나** |
| 데미지 입력 파라미터 | `FGameplayEffectSpec` + `SetByCaller` + 어트리뷰트 캡처 정의 |
| 상태 플래그 (`bDamageImmune` 등) | `GameplayTag` |
| 스탯 상한 클램프 | `PreAttributeChange` / `PreAttributeBaseChange` |
| "받은 피해" 전달 | **Meta 어트리뷰트**(`IncomingDamage`) — 복제하지 않는다 |

> **구현 메모 — 지금 지켜야 할 세 가지.**
> ① ⭐ **`UERStatComponent` 를 만들지 않는다.** 4레이어 자체 구현도 하지 않는다 — GE가 이미 그 일을 한다 (`CLAUDE.md` §8).
> ② **어트리뷰트를 코드에서 직접 `SetXXX()` 하지 않는다.** 초기화도 GE로 한다. 직접 세팅하면 클램프와 `PostGameplayEffectExecute` 를 우회한다.
> ③ **어트리뷰트 이름을 한 번 확정한 뒤 바꾸지 않는다** — GameplayEffect 애셋 참조가 끊긴다 (`CLAUDE.md` §3).

## 7. 구현 우선순위

```
1순위. UERAttributeSet(§6.1 목록) + 복제(GAMEPLAYATTRIBUTE_REPNOTIFY) + PreAttributeChange 클램프
       → 검증: 서버에서 GE 적용 시 클라 UI 값이 갱신됨
2순위. UGameplayEffectExecutionCalculation 하나 (고정/기본공격/스킬 3채널, 태그로 분기)
       → 검증: 방어력 100인 대상에게 원시 피해 200 → 정확히 100
3순위. 방어 관통(% → 고정) 순서 + 적용 방어력 0 클램프
       → 검증: 방어력 100 + 관통 50% + 고정 30 → 적용 방어력 20
4순위. 치명타 (기본공격 전용, 서버 난수, 175% 기본 배율)
       → 검증: 스킬 채널에서는 어떤 경우에도 치명타가 발생하지 않음
5순위. 스킬 가속 → Cooldown GE 의 Duration 환산 (스킬 문서 소관, 여기서는 환산식만)
       → 검증: 가속 100에서 쿨다운이 정확히 절반
6순위. 스탯 캡 테이블 (임시값 + "자체 결정" 표기)
       → 검증: 피해 감소 150%를 넣어도 회복이 발생하지 않음
7순위. 흡혈 후처리 (광역 50% / 야생동물 60% 감쇠)
       → 검증: 광역 스킬 적중 시 회복량이 절반
8순위. 체력 비례 피해 + 대상별 감쇠 계수 (보스 0.5)
       → 검증: 위클라인에게 최대체력 8% 피해 → 실제 4%
```

> **2순위가 이 문서의 전부다.** 나머지는 전부 2순위 Execution에 인자를 더하는 작업이다.
> 순서를 바꿔 캐릭터 스킬을 먼저 만들면 **계산식이 어빌리티마다 복제되고**, ExecutionCalculation 을 한 곳에 두는 의미가 사라진다.

## 8. 미확인 항목

| 항목 | 영향 | 확인 방법 |
|---|---|---|
| **최종 피해 추가(%)의 정확한 해석** | 원본 표기가 `× 최종 피해 추가(%)`인데 `(1 + x)`인지 `x` 자체인지 불명. **해석에 따라 피해량이 배 단위로 달라진다** | 인게임 계측 (해당 옵션 아이템 착용 전후 비교) |
| **치명타 확률 상한** | 100% 초과 스택의 낭비 여부 | 공식 문서 / 인게임 계측 |
| **이동 속도 상한** | 이동 스탯 스택 밸런스 | 인게임 계측 |
| **둔화 하한값** | 영구 행동 불능 방지 — **미설정 시 치명적** | 인게임 계측 |
| **방해 저항 / 이속 감소 저항 상한** | 100% 도달 시 CC 면역 | 인게임 계측 |
| **방어 관통(%) 상한** | 100% 도달 시 방어력 무의미화 | 인게임 계측 |
| **피해 감소(%) 계열 상한** | 100% 도달 시 무적 — **미설정 시 치명적** | 인게임 계측 |
| 적용 방어력이 음수일 때의 처리 | 관통 초과분이 추가 피해가 되는지 | 인게임 계측 (관통 아이템 vs 저방어 대상) |
| 체력 비례 피해의 연산 위치 | 방어력 적용 전/후에 따라 탱커 상대 피해가 달라짐 | 인게임 계측 |
| 흡혈 감쇠 중복 규칙 | 광역 50% × 야생동물 60% 동시 성립 시 | 인게임 계측 |
| 기력(VP) 레벨 성장 · 재생 수치 | 스킬 코스트 체계 전반 | 인게임 계측 |
| 회복량 증가(%)와 치유 감소의 상쇄 방식 | 가감산인지 독립 곱인지 | 인게임 계측 |
| 도트(출혈) 피해의 채널 분류 | 스킬 피해 감소가 적용되는지 | 인게임 계측 |

> **추측값을 넣지 않았다.** 위 항목은 팀이 값을 정해 채우되, 채울 때 **"원작 확인값이 아니라 자체 결정값"** 임을 캡 테이블에 반드시 기록한다. 특히 **볼드 표시된 4개(둔화 하한 · 피해 감소 상한 · 방어 관통 상한 · 치확 상한)** 는 값이 없으면 게임이 성립하지 않으므로, 미확인 상태여도 **임시값을 즉시 넣는다.**
