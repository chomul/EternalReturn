## 0. 이 시스템의 정체

**이 게임의 스킬 슬롯은 "캐릭터가 가진 5개의 스킬"이 아니라, 소유 주체가 서로 다른 7개의 슬롯이다.**
실험체가 P/Q/W/E/R을 소유하고, **무기가 D를**, 로비 선택이 F를 소유한다.

`이터널리턴_역기획서.md` §5.2 [S5]가 이를 명시한다 — **"D는 실험체가 아니라 무기가 소유한다. 같은 실험체라도 무기를 바꾸면 스킬 1개가 통째로 교체된다."**
LoL의 소환사 주문은 로비에서 고정되지만, 여기서는 **슬롯 하나가 인벤토리 상태에 종속된 런타임 가변 슬롯**이다. 이것이 결정적 차이다.

> **구현 관점의 결론 — 스킬을 캐릭터 클래스의 멤버 변수로 만들면 반드시 무너진다.**
> 슬롯은 **`슬롯 → 스킬 인스턴스` 매핑 테이블**이어야 하고, D 슬롯은 **무기 장착/해제 이벤트에 바인딩되어 런타임에 갈아끼워져야** 한다.
> 또한 D는 **무기 숙련도 5레벨에 해금**되고 10/15레벨에서 강화되므로(§5.2 [S5], `성장_레벨_숙련도_특성_역기획서.md`:102–103),
> **"슬롯이 비어 있는 상태"와 "슬롯이 잠긴 상태"를 프레임워크가 1급 개념으로 다뤄야 한다.**

M1 최우선인 이유는 `00_공통_구현규약.md` §2.1이 스킬 프레임워크를 **"최우선"**으로, §5가 M1을 **"스킬 프레임워크 + 데미지 파이프라인 + 기본 CC"**로 지정했기 때문이다.
**6인 중 누구도 이 프레임워크 없이는 스킬을 한 개도 붙일 수 없다.**

## 1. 슬롯 구조

### 1.1 슬롯 정의 (원본 §5.2 [S5] 기준)

| 슬롯 | 정체 | 소유 | 최대 레벨 | 레벨 상승 방식 |
|---|---|---|---|---|
| **P** | 실험체 고유 패시브 | 실험체 | **3단계** | **실험체 레벨에 따라 자동 강화. 포인트 소모 없음** |
| **Q / W / E** | 기본 스킬 3종 | 실험체 | **5** | 스킬 포인트 배분 |
| **R** | 궁극기 | 실험체 | **3** | 스킬 포인트 배분 |
| **D** | **무기 스킬** | **장착 무기 계열** | **3단계**(숙련도 5/10/15) | **무기 숙련도** |
| **F** | 전술 스킬 | 로비 선택 | **2** | **전술 강화 모듈**(영웅 등급 재료) 소비 |

- **F는 D키와 스왑 가능**하다(§5.2 [S5]). 즉 UI상 두 슬롯의 위치가 사용자 설정으로 바뀐다 → **슬롯 인덱스와 입력 키를 분리**해야 한다.
- F 목록은 공용 11종 + 루미아 섬 전용 3종이 확인된다(§5.4 [S9]). 점멸(3m 즉시 이동, **벽 통과**), 아티팩트(2.5초 무적), 해방(디버프 제거) 등
  **기존 CC·이동·정화 시스템을 전부 재사용**하는 형태다. 새 판정 타입을 요구하지 않는다.

### 1.2 D 슬롯 — 런타임 교체가 프레임워크에 강제하는 것

| 요구사항 | 이유 |
|---|---|
| 슬롯 상태 3종: `비어있음 / 잠김(숙련도 미달) / 사용가능` | 숙련도 5 이전에는 무기가 있어도 못 쓴다 |
| 무기 교체 시 **쿨다운 처리 규칙** | 무기를 바꿨다가 되돌리면 쿨이 초기화되는가? **(미확인)** |
| D스킬의 데이터 출처가 **실험체 테이블이 아니다** | `FWeaponProficiencyRow::DSkillClass` (`성장_레벨_숙련도_특성_역기획서.md`:335) |
| 숙련도 10/15 강화 = **같은 스킬의 다른 레벨** | 별도 스킬이 아니라 레벨 인덱스로 처리 |

> ⚠ 6인 중 **재키 4종 / 매그너스 2종 / 시셀라 2종**의 무기를 쓴다(`00_공통_구현규약.md` §2.5). 초기 구현은 **캐릭터당 무기 1종**으로 시작할 것을 같은 절이 권장한다.
> 그래도 **슬롯 교체 경로 자체는 M1에 넣어야 한다.** 나중에 붙이면 스킬 소유권 모델을 다시 짜야 한다.

## 2. 스킬 레벨

### 2.1 포인트 배분 규칙

| 항목 | 값 | 출처 |
|---|---|---|
| 실험체 최대 레벨 | **20** | 원본 §5.1 [S16][S17][S18] |
| 레벨당 스킬 포인트 | **1** (Lv.1에 1포인트 지급) | `성장_레벨_숙련도_특성_역기획서.md`:46 |
| Q/W/E 상한 | **5** | 원본 §5.2 |
| R 상한 | **3** | 원본 §5.2 |
| 슬롯별 습득 가능 레벨 제한(R 해금 시점 등) | **(미확인)** | `성장_레벨_숙련도_특성_역기획서.md`:50 |

> ⚠ **포인트 수지가 맞지 않는다.** 최대 소비 `5+5+5+3 = 18`인데 Lv.20까지 20포인트가 지급된다.
> 2포인트가 남는다 → 별도 규칙 존재 가능성 **(미확인)** (`성장_레벨_숙련도_특성_역기획서.md`:53).
> **프레임워크는 "잔여 포인트 > 0인데 모든 슬롯이 만렙"인 상태를 정상 상태로 받아들여야 한다.** 여기서 assert를 걸면 20레벨에 크래시한다.

### 2.2 레벨이 올라가면 무엇이 변하는가 — 6인 실측

**레벨은 단일 배율이 아니다. 항목마다 독립 배열이다.**

| 변하는 항목 | 실증 |
|---|---|
| **기본 피해** | 전 스킬 공통 (예: 카티야 Q `[40/80/120/160/200]`) |
| **계수(공격력/스증)** | 재키 W `20~60%`, 카티야 P `30/45/60%` — **기본 피해와 별개로 오른다** |
| **쿨다운 감소** | 카티야 Q `[7/6/5/4/3]`초, 시셀라 E `[11/10.5/10/9.5/9]`초 ⚠ **0.5초 단위 → 정수 타입 금지** |
| **쿨다운 불변** | ⭐ **레니 E는 9초 고정** (`06_레니.md` E 절) — "레벨업하면 쿨이 준다"고 가정한 코드는 틀린다 |
| **CC 강도·지속** | 매그너스 E 벽충돌 기절 `0.7→1.3초`, 카티야 E 둔화 `[50/55/60/65/70]%` |
| **부가 효과 수치** | 매그너스 P 방어력 `2/2.5/3%`, 레니 P 쿨감 `[0.5/0.75/1]`초 |
| **코스트** | 시셀라 W 체력 소모 `[50/60/70/80/90]` — ⭐ **레벨업하면 코스트가 늘어난다** |
| **레벨업해도 안 변하는 것** | 사거리·반경·투사체 속도 — 6인 전 스킬에서 레벨별 값이 확인되지 않음 |

> **결론: `FSkillRow`의 수치는 전부 `TArray<float>`(길이 5 또는 3)여야 하고, 사거리·반경·속도만 스칼라다.**
> 단일 `float BaseDamage + float PerLevel` 구조로 만들면 레니 E(쿨 고정)와 시셀라 E(0.5초 단위)에서 즉시 깨진다.

### 2.3 P(패시브)의 3단계 자동 강화

원본 §5.2 [S5]: **"레벨업으로 자동 강화(대개 3단계)"**. 포인트를 소비하지 않는다.

- **강화가 발생하는 실험체 레벨이 (미확인)이다.** 6개 캐릭터 문서 어디에도 "몇 레벨에 P가 2단계가 되는가"가 없다.
- 처리: P는 **스킬 포인트 배분 대상에서 제외**하고, `실험체 레벨 → P 단계` 매핑을 **데이터 테이블 한 곳**(`FSkillRow.PassiveTierLevels : TArray<int32>`)에 둔다. 하드코딩 금지.
- ⭐ **"패시브 = 쿨다운 없음"으로 특수 처리하지 말 것.** 카티야 P·다니엘 P는 쿨이 없지만 **아야 P는 25초 쿨 + "기본 공격마다 −1초(고정값, 쿨감 미적용)"** 을 가진다(원본 §5.7.2 [S17]).
  → P도 쿨다운 필드와 `bIgnoreCooldownReduction`이 필요하다 (`00_공통_구현규약.md` §2.1).

## 3. 자원(코스트)

**결론부터: 이 게임에 마나는 없다. 스킬 자원의 정식 명칭은 "기력(VP/SP)"이다.**

| 항목 | 확인 내용 | 출처 |
|---|---|---|
| **기력 (VP/SP)** | 스탯 목록에 **"스킬 자원"으로 명시** | 원본 §6.1 스탯표 (`이터널리턴_역기획서.md`:749) |
| 기력 재생 | 스탯으로 존재 | 원본 §6.1 (`:750`) — 수치 **(미확인)** |
| 기력 회복 수단 | 비전투 시 **0.5초당 최대 기력 2%**, 휴식(X) 3단계로 **20/25/30%** | 원본 §3.2.7 (`:317`–`:321`) |
| **스태미나** | ⭐ **시즌 9에서 완전 삭제됨. 만들지 말 것** | `경제_크레딧_소비아이템_역기획서.md` §2.4 |
| **기력 소모량 체계** | **(미확인)** — 부록 A가 명시적으로 미확인으로 남김 | 원본 부록 A (`:1867`) |
| **체력 코스트** | ⭐ **시셀라만 체력을 소모한다** (Q 40 고정 / W `[50~90]` / E 없음) | `05_시셀라.md`, `00_공통_구현규약.md` §2.1 |

> **6인 중 기력 소모량이 확인된 스킬이 단 하나도 없다.** 6개 캐릭터 문서 전체에 기력 수치가 나오지 않는다.
> 따라서 **M1에서는 기력 소모를 0으로 두되, 코스트 시스템 자체는 넣는다** — 시셀라가 체력을 소모하므로 "검증 → 차감" 경로는 어차피 필요하다.
> `ESkillCostType { None, VP, Health }` + `TArray<float> CostAmount` 구조면 나중에 기력 수치를 계측해 **데이터만 채우면 끝난다.**

**코스트 규칙 (프레임워크가 정해야 할 것)**

| 항목 | 처리 | 근거 |
|---|---|---|
| 차감 시점 | **발동 직전(§4의 [4])**, 선딜 시작 시점이 아님 | 선딜 중 CC로 끊겼을 때 코스트를 먹으면 안 된다 — §5 참조 |
| 체력 코스트로 사망 가능? | ⭐ **불가.** 시셀라 R은 **체력 하한 100 클램프**가 명시돼 있다 | `05_시셀라.md` R 절 |
| 체력 코스트에 방어력 적용? | **적용 안 함.** 데미지 파이프라인을 타지 않는 순수 차감 | 자체 결정값 — 원작 **(미확인)** |
| 코스트 부족 시 | 시전 거부 + `Client` RPC로 본인에게만 피드백 | `00_공통_구현규약.md` §3 |

## 4. 스킬 실행 파이프라인

### 4.1 단계 정의

```
[0] 입력          : 클라 로컬. 큐잉 판정(§6) → Server RPC 전송
[1] 사용 가능 판정 : 슬롯 잠금 / 스킬 레벨>0 / 쿨다운 / 코스트 / CC(침묵·기절) / 사거리
[2] 선딜(캐스팅)   : 몽타주 재생 + 시전 상태 진입. 이 구간에서 CC로 취소 가능(§5)
[3] 방향·위치 확정 : ⭐ 클라가 보낸 조준 파라미터를 서버가 클램프(사거리 상·하한)
[4] 코스트 차감 + 발동 : 판정 실행 → 데미지 파이프라인 호출(전투판정 문서 §2)
[5] 후딜           : 다음 행동 입력 차단 구간. 큐잉 윈도우가 열리는 구간(§6)
[6] 쿨다운 시작    : 서버 타이머. 스킬 가속 적용(§4.4)
[7] 연출 브로드캐스트 : NetMulticast (몽타주·나이아가라·사운드)
```

- **[1]의 CC 검사는 전투판정 문서에 위임한다.** `CanUseSkill()`이 CC 플래그 OR 캐시를 본다(`전투판정_상태이상_역기획서.md` §3). 프레임워크가 CC 종류를 알 필요는 없다.
- **[3]을 [2] 뒤에 둔 이유**: 카티야 R은 0.8초 채널링 **뒤에** 가까운 순 3명을 선정한다(`01_카티야.md` R 절). **대상 선정은 선딜 종료 시점의 월드 상태로** 해야 한다.
- **예외 ① 시전 시점 확정:** 매그너스 W는 **시전 시점**의 `11 + floor(추가방어력/35)`로 타격 수를 고정한다 → `bResolveParamsAtCastStart` 플래그 필요.
- **예외 ② 캐싱 금지:** 시셀라는 **현재 체력에 따라 스킬 증폭이 실시간으로 변한다**(`05_시셀라.md` P) → 피해 계산은 **[4] 시점의 스탯**을 읽는다.

### 4.2 단계별 권한 — 누가 무엇을 판정하는가

| 단계 | 클라이언트 | 서버 | 비고 |
|---|---|---|---|
| [0] 입력 | 키 입력 수집, **로컬 예측 UI**(쿨다운 회색 처리) | — | 예측은 **UI 한정.** 게임플레이 예측 없음 (`CLAUDE.md` §6) |

## 6. 스킬 큐잉 / 선입력

**원본 역기획서에 큐잉·선입력에 대한 서술이 전혀 없다. 아래는 전부 이 프로젝트가 정해야 할 값이다.**

왜 필요한가: 탑다운 MOBA는 **후딜 구간에 다음 입력이 씹히면 콤보가 성립하지 않는다.**
6인 중 **재키 Q(적중 시 3초 내 재사용) · 재키 R→학살 · 매그너스 R→W 콤보 · 레니 R→W 콤보**가 직접적으로 큐잉을 요구한다.

| 항목 | 권장값 | 근거 |
|---|---|---|
| **큐 깊이** | **1개** | 2개 이상 쌓으면 플레이어 의도와 어긋난다. 최신 입력이 이전 큐를 덮어쓴다 |
| **큐 윈도우** | **행동 종료 전 0.25초** | 아래 산출 근거 참조 — **자체 결정값** |
| **큐 유효 시간** | 큐 등록 후 **0.5초 내 미발동 시 폐기** | 오래된 입력이 뒤늦게 터지면 사고가 난다 |
| **큐잉 대상** | 스킬 / 기본 공격 / 아이템 | 이동 명령은 큐잉하지 않고 즉시 덮어쓴다 |
| **CC 진입 시** | ⭐ **큐를 비운다** | 기절 풀리자마자 의도치 않은 스킬이 나가면 안 된다 |

**0.25초 산출 근거 (측정값 아님 — 설계 추정)**
서버 틱 30Hz = 1틱 33ms, 왕복 RTT 60~120ms를 가정하면 입력→서버 도달에 30~60ms가 든다. 여기에 사람의 입력 오차(통상 100ms 단위)를 더하면 **150~250ms 구간**이 나온다.
더 크게 잡으면 "안 눌렀는데 나갔다"가, 작게 잡으면 원거리 유저의 콤보 실패가 발생한다.
⚠ **RTT·틱레이트 모두 이 프로젝트에서 아직 측정되지 않았다 (미확인).** PIE 2인 테스트로 실측 후 재조정할 것.

**⭐ 큐는 클라이언트에만 존재한다.** 서버에 큐를 두면 24명 × 큐 상태를 복제해야 하고 입력 지연이 두 배가 된다.
클라가 큐를 들고 있다가 소진 시점에 평소와 같은 `Server` RPC를 보내며, **서버는 큐의 존재를 모른 채** 도착 시점 기준으로 §4 [1]을 재검증한다.

> **엔진 메모:** Enhanced Input은 입력 버퍼링을 제공하지 않는다(`Triggered/Started/Completed` 이벤트만).
> ⭐ **GAS도 스킬 큐를 제공하지 않는다.** 입력 어댑터의 **로컬 상태 하나**(`FQueuedSkillInput { ESkillSlot, FVector AimPoint, float QueuedTime }`)로 충분하다. 별도 시스템을 만들지 말 것.
> 큐는 **복제하지 않는다** — 클라 조작감을 위한 것이지 게임 상태가 아니다.

## 7. 인디케이터 (조준 UI)

> 조작 방식(마우스 커서 / 키 홀드 / 릴리즈 캐스트)은 [`입력_카메라_조작_역기획서.md`](입력_카메라_조작_역기획서.md) 담당.
> **이 절은 "판정 타입별로 무엇을 그려야 하는가"만 정의한다.**

`00_공통_구현규약.md` §2.2의 판정 타입이 그대로 인디케이터 종류가 된다. **인디케이터는 판정과 1:1이어야 한다.**

| 판정 타입 | 그려야 할 것 | 실증 (수치는 캐릭터 문서 참조) |
|---|---|---|
| **방향 지정 투사체** | 사거리 길이 + **폭** 직선 | 레니 Q `7.5m × 1.5m`, 시셀라 E `5.5m × 1.1m` |
| **위치 지정(착탄)** | 사거리 링 + 착탄 원. ⭐ **최소 사거리 링** | 시셀라 Q **1 ~ 7.5m** — 하한 링이 없으면 조준 불가 |
| **이중 반경** | **중앙 원 + 외곽 원 두 겹** | 레니 W `1.25m / 2.25m`, 다니엘 Q 강화 판정 |
| **부채꼴** | 각도 + 사거리 부채 | 다니엘 Q `3.5m × 65°`, 레니 E `4.5m × 60°` |
| **자기 중심 원형** | 자기 중심 원 (조준 없음) | 매그너스 W `2.5m`, 시셀라 R **`20m`** |
| **대상 지정** | 사거리 링 + **커서 아래 대상 하이라이트** | 매그너스 E `3m`, 다니엘 W `7m` |
| **자기 이동(대시)** | ⭐ **도착 지점 고스트** | 카티야 E는 **조준 방향의 반대로 4m 이동** — 화살표만 그리면 반대로 간다 |
| **설치물** | 설치 위치 + 유효/무효 표시 | 레니 R `7m` |
| **자동 대상 선정** | ⭐ **선정될 대상들을 미리 강조** | 카티야 R(가까운 순 3명), 다니엘 R(최근 4초 내 피해 준 적) |
| **아군 대상 분기** | ⭐ **아군/적에 다른 색** | 레니 Q·W·E는 하나의 판정이 팀으로 갈린다 |

**스마트캐스트 — 원작 지원 여부 (미확인).** 원본 역기획서 전체에 "스마트캐스트 / 퀵캐스트" 서술이 없다(grep 0건).
**M1 판단:** 인디케이터 표시 후 재클릭하는 **일반 캐스트만** 구현한다. 스마트캐스트는 **입력 계층의 옵션**이지 스킬 프레임워크의 기능이 아니다.
다만 프레임워크는 **"조준 파라미터를 언제 확정하는가"를 입력 방식과 분리**해 두어야 한다 → §4 [3]이 그 분리점이다.
인디케이터는 **전적으로 로컬 시각 요소**이므로 복제하지 않는다. 적에게 내 조준선이 보이면 안 된다.

| **아군 대상 / 팀 분기 판정** | ⭐ **레니 Q·W·E 전부** — 하나의 판정이 적=피해 / 아군=회복·이속·보호막으로 갈린다 | **2** |
| **표식 상태 머신** | **다니엘 W**(부여 → 4초 대기 → 2.5초 폭발 윈도우 → 소멸) · **레니 P**(아군 표식 5초, **제3자 발동**) | **2** |
| **중첩(스택)** | 매그너스 P(최대 10, 평타 1 / 스킬 2) · 재키 P(출혈 5중첩 6초) | **2** |
| **런타임 스탯 의존 시전 파라미터** | ⭐ **매그너스 W** — 타격 횟수 `11 + floor(추가방어력/35)` (시전 시점 확정) | **2** |
| **피해 0 유틸리티 스킬** | ⭐ **카티야 W** — 데미지 파이프라인을 타지 않는 유일한 스킬 | **2** |
| **자기 자신 대상 피해** | 시셀라 R (체력 하한 100 클램프) | **2** |
| **거리 비례 보간** | 카티야 Q — 기본 피해와 계수를 **각각** 보간, **적중 시점 계산** | **2** |
| **체력 코스트** | 시셀라 Q(40 고정) · W(`[50~90]`) | **2** |
| **쿨다운 이벤트 훅** | 재키 E(처치 시 초기화) · 매그너스 W · 레니 P · 아야 E(**다른 슬롯의 쿨 감소**) | **2** |
| **충전형 (차지 스택)** | ⭐ **6인 중 요구 없음** — 재키 Q의 "3초 내 재사용"은 스택이 아니라 윈도우다 | **미구현** |
| **진짜 토글 (on/off 유지)** | ⭐ **6인 중 요구 없음** — 매그너스 R·재키 R은 **지속시간 버프**이지 토글이 아니다 | **미구현** |
| **지속 장판 (지면 고정 AoE)** | 시셀라 암기 D(마름쇠) · 시셀라 투척 D(연막 2.5초) — **D스킬에만 존재, 기본 스킬에는 없다** | **3** |
| **채널링 중 이동** | **(미확인)** — 매그너스 W 4초에서 조작감이 갈린다 | 확인 후 결정 |

> ⭐ **가장 중요한 발견 두 가지.**
> **① "충전형"과 "토글"은 6인 중 아무도 요구하지 않는다.** 지금 만들면 검증할 방법이 없는 죽은 코드다 (`CLAUDE.md` §2).
> **② "다음 기본 공격 강화" 구조는 4곳(카티야 P · 재키 W · 시셀라 Q · 권총 D)이 공유한다.**
> 캐릭터별로 따로 짜면 4벌이 되고, 무장 해제 CC 하나 추가할 때 4곳을 고쳐야 한다
> (`전투판정_상태이상_역기획서.md` §3.3 — 무장 해제는 "기본 공격 판정 스킬"도 막아야 한다).

## 9. 네트워크 설계

**매치 규모: 3인 × 8팀 = 최대 24명** (원본 §4 `이터널리턴_역기획서.md`:207). 데디케이티드 서버 타겟 존재.

| 대상 | 권위 | 전달 방식 | 비고 |
|---|---|---|---|
| 스킬 사용 요청 | 클라 요청 → **서버 검증** | **`Server` RPC (`WithValidation`)** | 슬롯·조준 파라미터 전달. `Validate`에서 슬롯 인덱스 범위만 검사, 게임 로직은 `Implementation`에서 |
| 스킬 포인트 배분 | 클라 요청 → **서버 검증** | **`Server` RPC (`WithValidation`)** | 잔여 포인트·상한 5/5/5/3 서버 검증 (`성장_레벨_숙련도_특성_역기획서.md`:288) |
| 스킬 레벨 배열 | **서버 전용** | `Replicated` (`COND_OwnerOnly` 검토) | 적의 스킬 레벨 노출 = 정보 우위. 원작 처리 **(미확인)** |
| 쿨다운 만료 시각 | **서버 (`FTimerManager`)** | `Replicated` + `OnRep_` | ⭐ **남은 시간이 아니라 "만료 서버 시각"을 복제**한다. 매 틱 복제 금지 |
| 시전 상태(선딜/채널링) | **서버** | `ReplicatedUsing = OnRep_CastState` | 클라는 몽타주 재생·캐스팅바 갱신만 |
| 조준 방향·목표 위치 | 클라 전송 → **서버 클램프** | Server RPC 파라미터 | ⭐ 클램프 없으면 사거리 핵 |
| 코스트 차감(기력·체력) | **서버 전용** | `Replicated` + `OnRep_` (UI) | 클라에서 차감하지 않는다 |
| D 슬롯 교체(무기 장착) | **서버** | 장착 상태 복제 → 슬롯 재바인딩 | 숙련도 해금은 `COND_OwnerOnly` 권고 (`성장_레벨_숙련도_특성_역기획서.md`:163) |
| 투사체 | **서버 스폰 + 이동 권위** | 액터 복제 | 속도가 스킬마다 다르다(15~40 m/s). 클라 스폰 금지 |
| 설치물·소환물 | **서버 스폰** | 액터 복제 + 소유권 | 레니 발판 · 카티야 드론 · 시셀라 윌슨 |
| 몽타주·나이아가라·사운드 | 서버 판정 후 | **`NetMulticast`** | 로직 금지 (`CLAUDE.md` §7) |
| 본인 전용 피드백(쿨 미완료·코스트 부족·적중 표시) | 서버 판정 후 | **`Client` RPC** | 24명에게 뿌리지 않는다 |
| 스킬 큐(선입력) | **클라 로컬 전용** | ⭐ **복제하지 않음** | §6 참조 |
| 인디케이터 | **클라 로컬 전용** | ⭐ **복제하지 않음** | 적에게 조준선이 보이면 안 된다 |

**24명 규모에서 주의할 것**
- 스킬 하나가 터질 때 `NetMulticast`가 24명 전원에게 가면 안 된다. **관련성(relevancy) 밖의 클라에는 보내지 않는다.**
- 은신(다니엘 E·단검 D)은 **서버가 가시성을 판정하고 적 클라에 위치를 복제하지 않아야 한다**
  (`00_공통_구현규약.md` §3). 클라에서 숨기기만 하면 핵에 뚫린다.
- **클라이언트 예측은 이번 범위에서 구현하지 않는다** (`CLAUDE.md` §6). 먼저 서버 권위로 정확히 동작시킨다.

## 데이터 스키마 제안

**설계 전제:** 이 프레임워크는 **GAS로 만든다** (`CLAUDE.md` §8). 아래 스키마는 `UGameplayAbility` 가 읽는 **데이터 소스**다.
따라서 **로직은 어빌리티에, 수치는 데이터 테이블에.** 아래 필드는 GAS 위에서 그대로 쓰인다.

```cpp
UENUM(BlueprintType)
enum class ESkillSlot : uint8 { P, Q, W, E, R, D, F };

UENUM(BlueprintType)
enum class ESkillCostType : uint8 { None, VP, Health };  // ⭐ 마나 없음. 기력(VP) 또는 체력

UENUM(BlueprintType)          // §8 표에서 6인이 실제로 요구하는 것만. 토글·충전형은 넣지 않는다
enum class ESkillCastForm : uint8
{
    Instant,        // 즉발 — 대다수
    Channeled,      // 채널링, CC로 중단 (카티야 R / 다니엘 R / 매그너스 W)
    MultiHit,       // 다단 히트 (매그너스 W 11타 / 카티야 R 3발)
    ChargedMove,    // 자기 이동 동반 (돌진·도약·대시)
    NextAttackBuff, // 다음 기본 공격 강화 대기 (카티야 P / 재키 W / 시셀라 Q / 권총 D)
    Placeable,      // 설치물·소환물 (레니 R / 카티야 W / 윌슨)
};
```

```cpp
USTRUCT(BlueprintType)
struct FSkillRow : public FTableRowBase   // RowName = "Katja_Q" 형태
{
    GENERATED_BODY()
    // 슬롯
    UPROPERTY(EditDefaultsOnly, Category="Slot") ESkillSlot      Slot     = ESkillSlot::Q;
    UPROPERTY(EditDefaultsOnly, Category="Slot") int32           MaxLevel = 5;   // 5 또는 3
    UPROPERTY(EditDefaultsOnly, Category="Slot") ESkillCastForm  CastForm = ESkillCastForm::Instant;
    UPROPERTY(EditDefaultsOnly, Category="Slot") ESkillTargeting TargetType;     // 00_공통 §2.2

    // ⭐ 레벨 가변값은 전부 배열. 레니 E(9초 고정)·시셀라 E(0.5초 단위) 때문에 스칼라 금지
    UPROPERTY(EditDefaultsOnly, Category="Level") TArray<float>  Cooldown;
    UPROPERTY(EditDefaultsOnly, Category="Level") TArray<float>  CostAmount;  // 시셀라 W [50~90]
    UPROPERTY(EditDefaultsOnly, Category="Level") ESkillCostType CostType = ESkillCostType::None;

    // 타이밍 — ⚠ 전 항목 원작 (미확인). 몽타주 길이가 아니라 이 값이 진실이다
    UPROPERTY(EditDefaultsOnly, Category="Timing") float CastTime = 0.f, RecoveryTime = 0.f;
    UPROPERTY(EditDefaultsOnly, Category="Timing") float RecastWindow = 0.f;   // 재키 Q = 3.0

    // 형상 — 레벨 불변 (6인 전 스킬에서 레벨별 값 확인 안 됨). 단위 m
    UPROPERTY(EditDefaultsOnly, Category="Shape") float RangeMax = 0.f, RangeMin = 0.f;  // ⭐ 시셀라 Q 하한 1.0
    UPROPERTY(EditDefaultsOnly, Category="Shape") float RadiusInner = 0.f, RadiusOuter = 0.f; // 레니 W 1.25 / 2.25
    UPROPERTY(EditDefaultsOnly, Category="Shape") float Angle = 0.f, ProjectileSpeed = 0.f;   // 다니엘 Q 65° / 0=투사체 아님

    UPROPERTY(EditDefaultsOnly, Category="Rule") bool bIgnoreCooldownReduction = false; // 아야 P
    UPROPERTY(EditDefaultsOnly, Category="Rule") bool bCancelableByMove         = false; // ⚠ 자체 결정값
    UPROPERTY(EditDefaultsOnly, Category="Rule") bool bResolveParamsAtCastStart = false; // 매그너스 W
    UPROPERTY(EditDefaultsOnly, Category="Rule") bool bAffectsAllies            = false; // 레니 Q·W·E

    // 피해·CC 수치는 여기 두지 않는다 — 담당 문서가 따로 있다
    UPROPERTY(EditDefaultsOnly, Category="Link") FDataTableRowHandle DamageRow, StatusEffectRow;
    // 연출 훅만. 로직 분기는 BP로 넘기지 않는다 (CLAUDE.md §7)
    UPROPERTY(EditDefaultsOnly, Category="FX")   TSoftObjectPtr<UAnimMontage> CastMontage;
};
```

**클래스 구조**

| 무엇 | 어디 |
|---|---|
| 슬롯 7개 · 쿨다운 · 시전 상태 · 복제 | ⭐ **`UAbilitySystemComponent`** — 자체 컴포넌트를 만들지 않는다 |
| 스킬 1개의 실행 로직 | **`UGameplayAbility` 파생 클래스 1개** |
| 판정 형상 → 히트 배열 | `ERTargeting` **정적 함수** (직접 만든다. GAS가 제공하지 않는다) |
| 스킬 큐(클라 로컬 선입력) | 얇은 입력 어댑터의 로컬 상태 (직접 만든다) |

> - 스킬 로직을 `AERCharacterBase` 에 직접 박지 않는다 (`CLAUDE.md` §8).
> - **야생동물·보스도 ASC를 갖는다** — 곰의 기절기가 어빌리티로 붙는다. 단 야생동물은 **Pawn에 ASC**, 플레이어는 **PlayerState에 ASC** 다.

**GAS 구현 대응표** — 이 문서가 요구하는 것을 GAS의 무엇으로 만드는가.

| 이 게임의 요구 | GAS 구현 | 비고 |
|---|---|---|
| 스킬 수치·형상 데이터 (`FSkillRow`) | `UGameplayAbility` 의 데이터 소스 / `UGameplayEffect` 파라미터 | ✅ 위 스키마 그대로 |
| 스킬 1개의 실행 로직 | ⭐ **`UGameplayAbility` 파생 클래스 1개** | §8의 83%가 전용 로직을 요구한다 |
| 슬롯 7개(P/Q/W/E/R/D/F) 관리 | `UAbilitySystemComponent` + `FGameplayAbilitySpec` 의 `InputID` | 자체 컴포넌트를 만들지 않는다 |
| 쿨다운 | **Cooldown `UGameplayEffect`** (Duration 정책) | `FTimerManager` 직접 사용 금지 |
| 코스트(체력·기력) | **Cost `UGameplayEffect`** + `UAttributeSet` | 수동 차감 금지 |
| 채널링 · 선딜 · 후딜 대기 | ⭐ **`UAbilityTask`** (`WaitDelay` / `PlayMontageAndWait` / `WaitGameplayEvent`) | 자체 타이머 상태 머신 금지 |
| CC로 인한 시전 차단·중단 | `ActivationBlockedTags` + `CancelAbilitiesWithTag` | |
| 시전 형태(`ESkillCastForm`) · 판정 타입 | `GameplayTag` (`Ability.Form.Channeled` 등) | 태그는 코드에 문자열로 박지 않는다 |
| 조준 파라미터 전송 | `FGameplayAbilityTargetData` + `UAbilityTask_WaitTargetData` | ⭐ **판정 형상 계산 자체는 직접 만든다** |
| 이펙트 · 몽타주 · 사운드 | `GameplayCue` | 어빌리티 안에서 직접 재생하지 않는다 |
| 스킬 큐(클라 로컬 선입력) | ⭐ **GAS에 없다 — 직접 만든다** | §6 참조 |

> ⭐ **어빌리티는 스킬마다 클래스 하나다.** `NonInstanced` 정책으로 데이터 구동하려는 시도는 하지 않는다 —
> 엔진 주석: *"a NonInstanced Ability **cannot have state**"* (`GameplayAbilityTypes.h:40`).
> 이 게임의 스킬은 표식·스택·리캐스트 윈도우·채널링 진행도 같은 **상태를 가진다**.
> 근거: [`../../Argument/1_스킬시스템_구조선택.md`](../../4_Argument/1_스킬시스템_구조선택.md) §1.2
>
> ⭐ **GAS가 제공하지 않아 직접 만드는 것 둘** — **판정 형상 계산**(부채꼴·이중 반경·관통)과 **스킬 큐**.
> 나머지는 GAS가 이미 갖고 있으므로 다시 만들지 않는다 (`CLAUDE.md` §8).
