## 0. 이 게임에서 몬스터가 하는 일

**야생동물은 "몹"이 아니라 경제 시스템의 입력단이다.** 세 가지를 동시에 공급한다.

| 공급물 | 용도 |
|---|---|
| **경험치** | 캐릭터 레벨 = 스탯 성장. 매치 내 유일한 안정적 성장 경로 |
| **제작 재료** | 장비 제작의 하위 재료. 상자 파밍만으로는 부족하다 |
| **무기 숙련도** | 무기를 휘두른 만큼 오르는 두 번째 성장축 |

> **구현 관점의 결론:** 야생동물은 **AI가 중요한 게 아니라 스폰·리젠·드랍 테이블이 중요하다.**
> 전투 AI를 정교하게 만드는 것보다 **"어느 지역에 몇 마리가, 언제 다시 차는가"** 를 데이터로 다루는 게 우선이다.

## 2. 능력치 (12.0 하향 확정값)

**12.0 패치에서 공식적으로 조정된 값** — 게임에서 확인 가능한 유일한 수치 데이터다.
표기는 `기본 공격력 / 레벨당 증가`.

| 동물 | 변경 전 | **변경 후 (현재)** |
|---|---|---|
| 닭 | 20 / 21 | **18 / 19** |
| 박쥐 | 34 / 22 | **30 / 20** |
| 멧돼지 | 30 / 23 | **27 / 21** |
| 곰 | 100 / 17 | **90 / 16** |
| 변이 곰 | 170 / 21 | **155 / 19** |

**중요한 구조 정보 두 가지:**

1. **야생동물도 레벨을 가진다.** "레벨당 증가"가 존재한다.
   ⚠ **2026-09-23 정정** — 이 문서는 레벨이 **매치 시간에 따라** 오른다고 추정했으나, 야생동물 가이드(fmkorea, 사용자 제공)는
   *"동물 레벨의 경우 섬의 가장 높은 실험체 레벨에 따라 변화"* 라고 적는다. **기준은 시간이 아니라 섬 최고 실험체 레벨**이다.
   (배율 · 공식은 그 문서에도 없다 **(미확인)** — 예: 최고 레벨 그대로인지, −1 인지)
   → 구현: 레벨 갱신 주체가 "타이머" 가 아니라 **"섬 최고 실험체 레벨 변화 이벤트"** 다 (F12-03). 종별 **기초 레벨**(§1.2)이 하한이다.
2. **곰의 기본 공격력 90은 캐릭터(32~44)의 2~3배다.** 초반에 곰을 잡으면 죽는다 — 이건 버그가 아니라 **의도된 진입 장벽**이다.

> ⚠ **체력·제공 경험치·방어력은 (미확인).** 공격력만 패치노트로 확인됐다.

## 3. 스폰 / 리스폰

### 3.1 시간에 따른 등장

| 시점 | 사건 |
|---|---|
| **1일차 낮 1분** | **늑대 등장 시작** |
| **1일차 밤** | **곰 등장 시작** |

> **즉 강한 동물은 처음부터 있는 게 아니라 시간에 따라 추가된다.**
> 초반 파밍 난이도를 시간축으로 통제하는 장치이며, 클론 시 **스폰 스케줄러**가 필요하다.
> (캐릭터 문서 §공통에서 말한 "오브젝트 스케줄러"와 같은 시스템을 공유한다)

### 3.2 지역당 개체 수 — 12.0 조정 확정값

| 조정 | 내용 |
|---|---|
| 변이 닭 | 7마리 → **6마리** |
| 항구 | 멧돼지 **−1**, 곰 **+1** |
| 경찰서 / 양궁장 / 호텔 / 주유소 | 각 **곰 +1** |

### 5.1 구현상 가장 중요한 규칙

**보스는 체력 비례 피해를 줄여 받는다 — 알파 70% · 오메가 60% · 위클라인 50%.** (보스마다 다르다 → 대상 어트리뷰트 `ProportionalDamageResist` · Argument 38 B)

이 한 줄이 없으면 게임이 무너진다. 이유:
- 매그너스 W(대상 최대 체력 2.5% × 11타 이상), E(8%), 레니 R(8%) 등 **최대 체력 비례 피해**를 가진 캐릭터가 많다.
- 보스는 체력이 압도적으로 높으므로, 비례 피해에 감쇠가 없으면 **탱커 한 명이 보스를 혼자 녹인다.**

> **클론 구현 시 반드시 데미지 파이프라인에 "대상별 비례 피해 감쇠 계수"를 넣을 것.**
> 캐릭터 문서 §공통 2.3의 데미지 파이프라인에 이 분기가 들어가야 한다.

### 5.2 보스 = 타임라인 이벤트

세 보스는 **전부 정해진 시각에 등장하고, 정해진 영웅 재료를 확정 드랍**한다.

```
2일차 밤 → 알파   → 미스릴
3일차 밤 → 오메가 → 포스코어
4일차 밤 → 위클라인 → VF 혈액 샘플
```

**이건 몬스터 시스템이 아니라 아이템 공급 스케줄이다.**
전설·초월 장비의 재료가 여기서만 나오므로, **보스 등장 시각 = 파워 스파이크 시각**이 된다.
(상위 역기획서 §12.1이 지적한 "오브젝트 등장 시각 = 파워 스파이크 시각 동기화"의 실체)

> **클론 개발 시:** 보스를 "강한 몬스터"로 만들지 말고 **"재료 배급기"** 로 설계할 것. 전투 난이도보다 **등장 시각과 드랍 확정성**이 훨씬 중요하다.

## 6. 구현 우선순위 제안

```
1순위. 스폰 테이블 (지역 × 동물종 × 마리수) + 시간 기반 스폰 스케줄러
       → 검증: 1일차 낮 1분에 늑대가, 1일차 밤에 곰이 서버에서 스폰
2순위. 야생동물 레벨 + 스탯 테이블 (레벨당 증가 포함)
       → 검증: 시간 경과에 따라 동물 스탯이 상승
3순위. 드랍 테이블 (확정/확률 구분)
       → 검증: 가죽 확정, 깃털 확률
4순위. 변이체 배율 (체력1.5 / 공격1.4 / 경험치2.0)
5순위. 기본 전투 AI (선공/비선공, 어그로, 귀환)
6순위. 보스 3종 + 타임라인 연동 + 체력 비례 피해 감쇠
```

> **AI는 마지막이다.** 순서를 바꾸면 "잘 싸우지만 아무도 사냥할 이유가 없는 몬스터"가 만들어진다.

- 구현 귀결: 어그로는 **사람이 아니라 팀**에 붙는다 → 매 판단마다 "그 팀에서 가장 가까운 생존자" 를 다시 고른다
- (미확인) 까마귀 경로의 실제 형태 · 까마귀 어그로 한계 거리

## 7. 네트워크 설계

> **이 문서에 이 절이 필요한 이유:** 야생동물은 **매치에서 동시 생존 액터 수가 가장 많은 종류**다.
> [`네트워크_서버아키텍처_역기획서.md`](네트워크_서버아키텍처_역기획서.md) §5.2 는 야생동물을 **120~200마리(추정)** 로 잡았고,
> 이는 전체 추산 200~300개의 절반 이상이다. **복제 비용을 여기서 못 잡으면 다른 데서 아낀 것이 의미가 없다.**

매치 규모는 **3인 × 8팀 = 최대 24명**이다 (`../이터널리턴_역기획서.md` §3.1).

### 7.1 서버 권위 · 복제 대상

| 항목 | 권위 | 복제 | 이유 |
|---|---|---|---|
| 스폰 · 리스폰 스케줄 (§3) | **서버 전용** | 스폰된 액터 자체 | 늑대 1일차 낮 1분 / 곰 1일차 밤은 **매치 타임라인 이벤트**다 (§3.1) |
| 레벨 · 스탯 (§2) | **서버 전용** | 결과값만 | "레벨당 증가"가 있으므로 시간 경과에 따라 서버가 재계산한다 (§2) |
| 현재 체력 | **서버 전용** | `ReplicatedUsing = OnRep_` | 체력바 연출용. **값 변경은 절대 클라에서 하지 않는다** |
| 피해 수신 · 사망 판정 | **서버 전용** | 사망 연출만 `NetMulticast` | |
| **드랍 확률 롤 (§4)** | **서버 전용** | 스폰된 아이템 액터 | ⚠ **깃털·루프 카드키-γ는 확률 드랍이다. 클라가 굴리면 그대로 조작된다** |
| 어그로 · 타겟 선택 | **서버 전용** | — | §7.2 참조 |
| 변이 플래그 · 배율 (§1.2) | **서버 전용** | **스폰 시 1회** | 매치 중 변하지 않으므로 초기 복제로 충분하다 |
| 위클라인 비례 피해 50% 감쇠 (§5.1) | **서버 전용** | — | 데미지 파이프라인 내부. [`스탯_데미지공식_역기획서.md`](스탯_데미지공식_역기획서.md) 소관 |

### 7.2 AI는 클라이언트에 존재하지 않는다

`AController` 생성자가 `bOnlyRelevantToOwner = true` 로 시작한다
(`Engine/Source/Runtime/Engine/Private/Controller.cpp:51`).
`AAIController` 에는 소유 클라이언트가 없으므로 **어떤 클라에도 복제되지 않는다.**

따라서 **AI 로직 전체가 서버에만 존재**하고, 클라는 결과(위치·애니메이션)만 받는다. 구현상 두 가지가 따라온다.

- 비헤이비어 트리 · 블랙보드 · `AIPerception` 을 클라에서 돌릴 필요가 없다. **서버에서만 Tick 한다.**
- 클라에 보이는 야생동물의 움직임은 **복제된 위치의 보간**이다. 갱신 빈도를 낮추면 그만큼 끊겨 보인다 — §7.3의 값은 대역폭만이 아니라 **연출 품질과 직결**된다.

### 7.3 권장 설정 — 도먼시(dormancy)가 핵심이다

야생동물 120~200마리 문제의 해법은 빈도를 낮추는 것이 아니라 **대부분을 재우는 것**이다.
대다수의 야생동물은 **아무도 안 건드리는 동안 아무 값도 변하지 않는다.**

| 상태 | `NetUpdateFrequency` | 도먼시 | 근거 |
|---|---|---|---|
| **야생동물 — 비전투(대기)** | 5 | **`DORM_DormantAll`** | 값이 변하지 않는다. 재워두면 복제 대상에서 빠진다 |
| **야생동물 — 전투 중** | 20 | `DORM_Awake` | 어그로 진입 시 `FlushNetDormancy()` 로 깨운다 |
| **보스 (알파 / 오메가 / 위클라인)** | 30 | `DORM_Never` | 개체가 0~2기뿐이고 한타의 중심이다. 아낄 대상이 아니다 |

- 엔진 기본값은 `NetUpdateFrequency = 100.0f` (`Engine/Private/Actor.cpp:158`), `MinNetUpdateFrequency = 2.0f` (`:159`), `NetDormancy = DORM_Awake` (`:177`) 다. **야생동물에 기본값을 그대로 쓰면 안 된다.**
- 도먼시 열거형: `DORM_Never` / `DORM_Awake` / `DORM_DormantAll` / `DORM_DormantPartial` / `DORM_Initial` (`Engine/Classes/Engine/EngineTypes.h:3075-3083`). 주석상 `DORM_Awake` 는 *"can go dormant, but is not currently dormant. Game code will tell it when to go dormant"* — **재우는 시점을 게임 코드가 직접 지정해야 한다.**
- API: `SetNetDormancy()` (`Engine/Classes/GameFramework/Actor.h:2989`), `FlushNetDormancy()` (`:2993`).

> **전환 지점을 어디에 둘 것인가:** 어그로 진입 = `FlushNetDormancy()`, 어그로 해제 + 귀환 완료 = `SetNetDormancy(DORM_DormantAll)`.
> §6의 구현 우선순위에서 **5순위(기본 전투 AI)에 이 전환을 함께 넣는다.** AI와 복제 상태가 같은 이벤트를 공유하기 때문이다.

> ⚠ **위 숫자는 전부 자체 결정 초기값이며 측정하지 않았다.** 측정 방법은 [`네트워크_서버아키텍처_역기획서.md`](네트워크_서버아키텍처_역기획서.md) §5.2 의 절차(봇 24명 + `NET ACTIVE` + `stat unit`)를 따른다.

### 7.4 팀 시야와의 관계 — **미결**

야생동물이 **포그 오브 워의 대상인지**가 정해지지 않았다.

| 안 | 결과 |
|---|---|
| 시야 대상이다 | 안 보이는 지역의 야생동물은 복제되지 않는다 → 복제 비용이 크게 준다. 대신 "저 지역에 곰이 남아 있나"를 적이 알 수 없다 |
| 시야 대상이 아니다 | 거리 컬링만 적용된다. 구현이 단순하지만 위 120~200마리를 그대로 떠안는다 |

**(미확인)** — 원작이 어느 쪽인지 확인되지 않았다. 이 결정은 [`팀시야_포그오브워_역기획서.md`](팀시야_포그오브워_역기획서.md) 소관이며, **이 문서는 결정하지 않는다.**
다만 §7.3의 도먼시 설계는 **어느 쪽을 고르든 유효**하다.
