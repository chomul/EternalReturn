## 0. 이 시스템의 정체

**루미아 섬은 "전장"이 아니라 "제작 트리를 공간에 펼쳐 놓은 것"이다.**
장비 문서의 제작 트리가 세로축(등급)이라면, 맵은 그 트리를 가로축(위치)으로 투영한 결과다.
지역이 21개나 되는 이유는 지형을 다양하게 만들기 위해서가 아니라, **재료 35종을 서로 다른 좌표에 흩뿌려 "이동 자체를 비용으로 만들기"** 위해서다.

여기서 이 게임의 세 축이 하나로 묶인다.

| 맵 요소 | 실제로 통제하는 것 |
|---|---|
| **지역 = 재료 분포** | 파밍 루트 = 매치 전 세운 계획. 루트가 곧 빌드다 |
| **금지구역 = 지역 삭제** | 시간이 갈수록 선택지가 물리적으로 줄어든다 |
| **이동 수단 = 지역 간 비용** | 하이퍼루프/VLS가 열려 있는 동안만 "루트 수정"이 가능하다 |

> **구현 관점의 결론:** 맵 작업의 본체는 지형 아트가 아니라 **`지역(Region)`이라는 논리 단위**다.
> 스폰·금지구역·이동·CCTV·미니맵 오버레이가 전부 "이 좌표가 어느 지역인가"에 의존한다.
> **지역 판정은 서버 권위여야 하고, 가장 먼저 만들어져야 한다.**

## 1. 맵 개요

| 항목 | 값 |
|---|---|
| 맵 이름 | 루미아 섬 (Lumia Island) |
| 지역 수 | **총 21개**. 이 중 **연구소 / 오래된 선창을 제외한 19개가 통상 탐색 가능** ⚠ 판본 간 19~23으로 상이 |
| 구조 | 중앙 **연구소**(다이아몬드형, 시작부터 금지구역) + 주변 지역이 **링 형태**로 연결 |
| 물리적 크기 | **(미확인)** — 공개 자료에 실측값 없음 |
| 별도 공간 | **전투 실험실(차원의 틈)** — 본맵과 분리된 서브 공간 |
| 동시 인원 | 3인 × 8팀 = 최대 24명 (론울프는 솔로 18명) |
| 매치 길이 | 약 25~26분 (8일 × 낮/밤) |

**크기 추정의 유일한 단서**: 원작은 거리를 **미터 단위**로 명시한다(크로노 스피어 반경 30m → 10m → 5m).
즉 게임 내부 단위가 미터에 대응하며, 언리얼 기준 **1m = 100uu**로 그대로 매핑하면 된다.
다만 **섬 전체의 가로세로 길이는 확인되지 않았다.** 아래는 역산 절차이지 확정값이 아니다.

> **역산 메모(추정임을 명시):** 캐릭터 기본 이동 속도와 지역 간 도보 이동 체감 시간이 있으면
> `섬 한 변 ≈ 이동속도 × 횡단 시간`으로 역산할 수 있다. **두 값 모두 미확인이라 지금은 계산하지 않는다.**
> 프로토타입에서는 **한 변 200~300m(20,000~30,000uu)** 정도로 두고 도보 횡단 시간을 계측해 조정하기를 제안한다.
> — **이 값은 팀 자체 결정값이며 원작 확인값이 아니다.**

**구현 메모**
- 맵은 단일 퍼시스턴트 레벨 + **지역 단위 서브레벨(월드 파티션 또는 레벨 스트리밍)** 로 나눈다. 스트리밍 단위 = 지역 단위로 맞추면 나중에 "지역 하나 추가"가 데이터 작업이 된다.
- **데디케이티드 서버는 모든 지역을 항상 로드해야 한다.** 클라이언트만 거리 기반 언로드한다. 서버가 언로드하면 그 지역의 스폰·상자·야생동물이 죽는다.
- 네비메시는 지역 단위로 잘라 굽지 말고 **섬 전체를 하나의 NavMesh**로 둔다. 지역 경계에서 경로 탐색이 끊기면 안 된다.
- 지역 경계는 콜리전이 아니라 **판정용 볼륨(`AERRegionVolume`)** 으로 만든다. 이동을 막는 벽이 아니다.

### 2.3 지역이 실제로 가지는 속성 축 (구현 관점)

지역은 자유 서술이 아니라 **정형 데이터 6축**으로 환원된다. 위 표는 이 6축의 실제 사례일 뿐이다.

| 축 | 내용 | 소비처 |
|---|---|---|
| **채집 오브젝트** | 종류 × 수량 (결정론적, 확률 아님) | 파밍 루트, Alt+M 오버레이 |
| **상자 스폰** | 위치 + 우선도(미니맵 점 5개 = 우선 상자) | 파밍 |
| **야생동물 구성** | 종 × 마리수 → [몬스터 문서](몬스터_야생동물_역기획서.md) | 경험치·재료 |
| **시설** | 하이퍼루프 / 키오스크 / 모닥불 / CCTV | 이동·경제·조리·시야 |
| **인접 지역** | 그래프 간선 (도보 연결, 점프대 포함) | 이동, 금지구역 순서 |
| **특수 스폰 슬롯** | 생명의 나무 / 운석 / 보스 / 균열 후보지 | 타임라인 이벤트 |

> **핵심 설계 해석:** 채집 재료가 **확률이 아니라 고정 수량**인 것이 이 게임의 정체성이다.
> "개울에 나뭇가지 7개"는 밸런싱 숫자가 아니라 **유저가 외우고 계획하는 약속**이다.
> 클론에서 이걸 랜덤으로 바꾸면 파밍 루트 설계라는 IP 자체가 사라진다.

**구현 메모**
- 지역은 액터가 아니라 **데이터 테이블 행 + 레벨에 배치된 볼륨/스폰 포인트**의 조합으로 만든다.
- 지역 판정(`GetRegionAtLocation`)은 **서버 권위**. 금지구역 폭사, 부활 지점, CCTV 시야, 크레딧 정산이 전부 여기에 의존한다. 클라는 UI 표시용 로컬 캐시만 갖는다.
- 인접 관계는 **런타임 그래프**로 들고 있어야 한다. 금지구역 순서 결정과 "잔존 2개 지역" 판정이 그래프 탐색이다.
- 채집 오브젝트는 개별 액터로 두되 **리스폰 타이머를 서버에서만** 돌린다. 클라 예측 금지.

## 3. 시작 지역 선택

| 항목 | 값 |
|---|---|
| 시점 | 매치 시작 전 |
| 주체 | **팀 3인 협의**로 1개 지역 지정 |
| 정석 | "내 파밍 루트의 1번 지역 = 시작 지역" |
| 리스크 | 상대 팀과 겹치면 초반 교전 + **루트 전면 재설계** |
| 정보 | 상대 팀 선택은 **비공개** (정보 비대칭 도박) |
| 선택 가능 지역 | **(미확인)** — 19개 전부인지, 별도 시작 가능 목록이 있는지 |
| 중복 허용 여부 | **(미확인)** — 여러 팀이 같은 지역을 고를 수 있는지 |

**구현 메모**
- 선택 UI는 클라, **확정은 서버**. 팀 3인 중 누가 확정 권한을 갖는지 규칙이 필요하다(미확인 → 팀장 확정 / 마지막 입력 우선 중 자체 결정).
- 매치 시작 스폰은 **지역 내 랜덤 시작 지점**(하이퍼루프 도착 지점과 같은 개념)에 배치한다. 지역당 시작 지점을 3개 이상 두고 팀 단위로 묶는다.
- **초기 버전 판단: 반드시 필요.** 이게 없으면 파밍 루트 시스템이 시작점을 갖지 못한다. UI는 단순한 맵 클릭으로 충분하다.

| 4일차 밤 | **위클라인** | VF 혈액 샘플 + 아글라이아의 선물-희귀 확정 / 생명의 나무·운석·미사일 중 1종 랜덤. **버프 4분** | **연구소** (계단 아래) |
| 4일차 밤 | 전투 실험실 **폐쇄** | 위클라인 등장과 동시 | — |
| 5일차 | 키오스크 부활 종료 | 이후 루미 부활만 | — |
| 6일차 밤 | **임시 안전지대 지정** | 잔존 2개 지역 | 그래프상 남은 지역 |
| 7일차 낮 | 임시 안전지대 활성화 | **하이퍼루프/VLS 비활성** | — |
| 7일차 밤 | **크로노 스피어 발동** | 반경 30m / 5초 | 최종 지점 |
| 8일차 | 최종 축소 | 30m → 10m → 5m → 0m | — |

> **설계 해석:** 이 표에는 **공간 이벤트와 규칙 전환이 섞여 있다.**
> "운석이 떨어진다"(공간)와 "부활이 200 크레딧이 된다"(규칙)가 같은 시각표에 있는 이유는,
> **유저가 시계를 하나만 보게 하기 위해서**다. 일차/낮밤이 유일한 시간 표현이고 모든 시스템이 여기에 붙는다.

**구현 메모**
- 이 표는 **오브젝트 스케줄러 하나**로 구현한다. 상위 문서 §12.5 【1순위】와 같은 시스템이며, [몬스터 문서](몬스터_야생동물_역기획서.md) §3의 스폰 스케줄러도 이것을 공유한다. **세 곳에 타이머를 흩뿌리면 반드시 어긋난다.**
- `AERGameState`에 `CurrentDay` / `EMatchPhase(Day|Night)` / `PhaseRemainingTime`을 **Replicated**로 둔다. 서버가 유일한 시계다.
- 이벤트 큐는 `(Day, Phase, EventId)` 데이터 테이블로. 코드에 시각을 하드코딩하지 않는다.
- 페이즈 전환은 `OnRep_Phase`로 클라 연출(조명·UI·사운드)을 트리거한다. 로직은 전부 서버.
- **초기 버전 판단: 스케줄러 자체는 반드시 필요.** 개별 오브젝트(분실물 상자·영웅 보급 상자·조명탄총 호출)는 잘라도 된다. **필수는 "일차/낮밤 상태 머신 + 보스 3종 + 금지구역 확장 + 부활 규칙 전환"** 네 가지다.

## 5. 금지구역 — 지역을 시간으로 삭제하는 장치

| 항목 | 값 |
|---|---|
| 맵 표기 | **노랑 = 다음 차례 금지 예정 / 빨강 = 금지됨** |
| 진입 시 폭사 타이머 | **20초** |
| 실험체 처치 시 연장 | **+7초** |
| 알파/오메가 처치 시 연장 | **+2초** |
| 타이머 상한 | **30초** |
| 부활 직후 타이머 | 10초 |
| 7일차 회복량 | 15초 (상한 무시) |
| 시작부터 금지 | **연구소** |
| 금지 순서 규칙 | **(미확인)** — 완전 랜덤인지 인접 그래프 기반인지 |

**12.0 신규 — 금지구역 복원**: 20 크레딧 / 3~5일차 낮 / 페이즈 시작 20초 전 / **페이즈당 1팀만** / 구매 팀은 CCTV 시야 획득 + 복원 구역 첫 리스폰 야생동물의 변이체 확률 +10%.

**구현 메모**
- 금지구역은 데미지 볼륨이 아니라 **지역 상태 플래그(`ERegionState: Normal / Warning / Forbidden / Restored`)** 다. 폭사 타이머는 캐릭터가 들고 있고 서버가 갱신한다.
- 타이머 연장(+7 / +2)이 있으므로 **킬 처리 코드가 금지구역 타이머를 알아야 한다.** 데미지 파이프라인 종단에서 이벤트로 흘려보낸다.
- **경계 판정은 서버만.** 클라가 "나는 아직 안전지대에 있다"고 주장하게 두면 안 된다. 클라는 잔여 시간 HUD만 표시한다.
- **초기 버전 판단:** 금지구역 확장은 **필수**, **금지구역 복원 시스템은 잘라도 된다**(상위 문서 §12.5와 동일 판단). 코어 루프 안정화 후 얹는다.

## 6. 이동 시스템

### 6.1 하이퍼루프 (1~2일차)

| 항목 | 값 |
|---|---|
| 시전 시간 | **3초** |
| 도착 지점 | 목적지 지역의 **랜덤 시작 지점** |
| 이동 중 | **군중제어 면역** |
| 쿨다운 | 2일차부터 **8초** |
| 리스크 | 도착 시 근처 적에게 **핑(소리/표식) 노출** |
| 상급 테크닉 | **이동 중 제작** (도착 무적 프레임 동안 제작) |
| 확인된 보유 지역 | 절 · 주유소 · 개울 · 병원 · 학교 · 성당 (나머지 미확인) |

### 6.2 VLS (3일차 이후, Vertical Launching System)

| 항목 | 값 |
|---|---|
| 방식 | 상호작용으로 충전 후 발사 |
| 탑승 인원 | 최대 **3인** |
| 비행 시간 | **7초** |
| 조작 | 최초 상호작용자(호스트)가 발사 시점·방향 결정. 게스트는 낙하 각도만 조정 |
| 착지 | 사용자 **1초 기절**, 착지 지점 대상 **0.5초 기절** |
| 제한 | **7일차부터 사용 불가** |
| 충전 시간 | **(미확인)** |
| 사거리 제한 | **(미확인)** — 임의 좌표 지정인지 지역 단위인지 |

> **설계 해석:** 두 수단은 성격이 정반대다. 하이퍼루프는 **안전한 재배치**(CC 면역, 목적지 랜덤),
> VLS는 **위험한 진입**(3인 동시, 착지 기절, 임의 지점). 3일차에 이동의 의미가 "도주"에서 "습격"으로 바뀐다.
> 이것이 3일차부터 교전 밀도가 올라가는 구조적 원인이다.

**구현 메모**
- **모든 텔레포트는 서버 권위다.** 클라 요청 → `Server RPC(WithValidation)` → 서버가 조건 검사(쿨다운·일차·금지구역·전투 상태) → `SetActorLocation` → 클라 보정. **클라에서 위치를 먼저 옮기지 않는다.**
- 도착 지점은 서버가 골라 `NetMulticast`로 연출(파티클·사운드·적 노출 핑)을 뿌린다. 도착 지점을 클라가 결정하면 곧바로 텔레포트 핵이 된다.
- 도착 전 **네비메시 위 유효 위치인지 `ProjectPointToNavigation`으로 검증**한다. 실패 시 대체 지점.
- 하이퍼루프 3초 시전은 **캐스팅 상태**다. 피격·이동으로 취소되는지 여부는 **(미확인)** — 자체 결정 필요.
- VLS 3인 탑승은 **소유권 문제**가 있다. 호스트가 중간에 사망/접속 종료하면 게스트를 어떻게 처리할지 규칙이 필요하다(미확인 → 자체 결정).
- 착지 기절은 **범위 CC**다. 데미지 파이프라인이 아니라 상태이상 시스템을 타야 한다(GAS 전환 시 GameplayEffect에 대응되도록).
- **초기 버전 판단: 하이퍼루프만 만든다.** 상위 문서 §12.5도 "하이퍼루프+VLS 이원화"를 잘라내기 목록에 넣었다. 3일차에 이동 수단이 통째로 교체되는 것은 학습 부담이고, VLS는 3인 탑승·호스트 권한·낙하 조작까지 **구현량이 하이퍼루프의 3배 이상**이다.

## 8. CCTV / 감시 시스템

| 항목 | 값 |
|---|---|
| 배치 | 지역별로 존재 |
| 활성화 효과 | 해당 구역 **시야 확보** + **소량의 크레딧** 획득 |
| 미니맵 표시 | CCTV 범위가 미니맵에 표시됨 |
| 적 시점 | 적의 CCTV 감지 범위는 **항상 표시**(내 노출 방지) |
| 12.0 변경 | 병원·성당·양궁장·절·숲·고급주택가·창고·호텔 등 **감시 범위 재조정** — 사각지대 제거 |
| 12.2 수정 | **금지 구역 내 CCTV 시야가 유지되던 버그 수정** |
| 크레딧 획득량 | **(미확인)** |
| 활성화 지속 시간 | **(미확인)** — 영구인지 시한부인지 |
| 팀 단위 공유 여부 | **(미확인)** (금지구역 복원 구매 팀이 CCTV 시야를 얻는 것으로 보아 팀 단위로 추정) |

> **설계 해석:** CCTV는 "정찰 도구"라기보다 **파밍 중 잉여 행동에 보상을 붙이는 장치**다.
> 활성화에 크레딧이 걸려 있어서, 지나가는 김에 누르는 행동이 경제에 연결된다.
> 12.2에서 "금지구역 CCTV가 살아 있던 버그"를 고친 것은, **시야가 금지구역 규칙을 우회하면 안 된다**는 의도가 명확하다는 뜻이다.

**구현 메모**
- 시야는 **팀 단위 가시성**이다. 언리얼 기본 relevancy가 아니라 **별도의 팀 시야 시스템**(MOBA식 fog of war)이 필요하다. 이건 맵 시스템이 아니라 독립 과제이고, **규모가 크다.**
- 서버가 "이 액터가 이 팀에게 보이는가"를 판정해 **`IsNetRelevantFor` 또는 커스텀 리플리케이션 그래프**로 거른다. 클라에 위치를 다 보내고 클라에서 숨기면 그대로 맵핵이 된다.
- 금지구역 상태 변경 시 **해당 지역 CCTV를 반드시 비활성화**한다(12.2 버그의 원인).
- **초기 버전 판단: CCTV 자체는 잘라도 되지만, 팀 시야(fog of war)는 잘라낼 수 없다.** 탑다운 MOBA에서 시야는 전투 그 자체다. CCTV는 그 시야 시스템 위에 얹는 작은 기능이므로, **시야 시스템을 먼저 만들고 CCTV는 나중에 추가**하는 순서가 맞다.

## 구현 우선순위

```
1순위. 지역 시스템 (RegionVolume + FRegionRow + GetRegionAtLocation)
       → 검증: 서버에서 캐릭터 위치로 지역명이 정확히 반환되고,
               경계를 넘을 때 OnRegionChanged가 서버에서 1회만 발생

2순위. 매치 타임라인 상태 머신 (Day / Phase / 남은 시간, Replicated)
       → 검증: 서버 시계로 일차·낮밤이 진행되고 클라 HUD가 OnRep으로 동기화.
               PIE `Play As Client, Number of Players: 2`에서 두 클라의 표시가 일치

3순위. 금지구역 확장 + 폭사 타이머 (+7 / +2 연장, 상한 30초)
       → 검증: 금지 지역 진입 20초 후 서버가 사망 처리. 킬 발생 시 타이머 +7초.
               클라에서 위치를 조작해도 폭사를 회피할 수 없음

4순위. 채집 오브젝트 + 지역별 상자 배치 (결정론적 고정 수량)
       → 검증: 같은 지역을 10판 돌았을 때 채집 재료 종류·수량이 항상 동일

5순위. 하이퍼루프 (Server RPC 텔레포트 + 3초 캐스팅 + CC 면역 + 8초 쿨다운)
       → 검증: 클라 요청이 서버 검증을 거쳐서만 이동. 쿨다운 중 재요청은 서버가 거부.
               도착 지점이 네비메시 위 유효 좌표

6순위. 시작 지역 선택 (로비 UI + 서버 확정 + 지역 내 랜덤 스폰)
       → 검증: 3인 팀이 고른 지역에 함께 스폰. 최종 지역 결정은 서버 로그로 확인

7순위. 특수 오브젝트 스폰 (생명의 나무 / 운석 / 보스 3종)
       → 검증: 타임라인 이벤트 시각에 지정 지역에서 서버 스폰.
               보스 자체는 [몬스터 문서] 담당 — 여기서는 "언제 어디서"만 검증

8순위. 임시 안전지대 + 크로노 스피어 (30m → 10m → 5m → 0m)
       → 검증: 잔존 2개 지역이 인접 그래프에서 올바르게 선택되고,
               스피어 외부 캐릭터가 서버에서 폭사

9순위. 팀 시야(fog of war) → 그 위에 CCTV
       → 검증: 적 위치가 클라 메모리·패킷에 존재하지 않음.
               금지구역 전환 시 해당 지역 CCTV가 즉시 꺼짐

--- 이하는 후속 업데이트 ---
10순위. VLS (3인 탑승 / 호스트 권한 / 착지 기절)
11순위. 금지구역 복원 시스템 (20 크레딧)
12순위. 전투 실험실 (차원의 틈)
```

> **순서의 근거:** 1~3순위가 없으면 나머지가 붙을 곳이 없다.
> 반대로 **지형 아트는 이 목록 어디에도 없다.** 회색 박스 지역 8개로 1~5순위를 전부 검증할 수 있고,
> 그게 끝난 뒤에 지역을 21개로 늘리는 것이 옳다. (상위 문서 §12.5의 M2가 "지역 8개"로 시작하는 것과 동일)

## 미확인 항목

| 항목 | 영향 | 확인 방법 |
|---|---|---|
| **맵 물리적 크기(한 변 길이)** | 이동 속도 · 매치 템포 · 레벨 스트리밍 설계 전부 | 인게임 계측 (도보 횡단 시간 × 이동 속도) |
| **지역별 경계 좌표** | 지역 판정 볼륨, 금지구역 볼륨 | 인게임 확장맵 캡처 후 수작업 배치 |
| **지역 인접 그래프 전체** | 금지구역 순서, 경로 계산, 잔존 2개 지역 판정 | 인게임 맵 |
| 금지구역 확장 순서 규칙 | 랜덤인지 그래프 기반인지에 따라 구현이 달라짐 | 다회 플레이 관찰 |
| 하이퍼루프 보유 지역 전체 목록 | 이동망 설계 | 인게임 |
| 하이퍼루프 3초 캐스팅의 취소 조건 | 전투 중 도주 가능 여부 = 밸런스 핵심 | 인게임 |
| VLS 충전 시간 / 사거리 제한 | VLS 구현 (후순위) | 인게임 |
| VLS 호스트 이탈 시 게스트 처리 | 예외 케이스 | 인게임 |
| 시작 지역 선택 가능 목록 / 팀 간 중복 허용 | 로비 UI 규칙 | 인게임 |
| CCTV 크레딧 획득량 / 지속 시간 / 공유 범위 | 경제 밸런스, 시야 시스템 | 인게임 계측 |
| 알파 · 오메가의 스폰 지역 | 타임라인 이벤트 배치 | 인게임 |

| 전투 실험실 내부 맵 구조 | 후순위 | 인게임 |
| 지역 수 19 / 21 / 23 판본 불일치 | 데이터 테이블 행 수 | 최신 인게임 확인 |

> **추측값을 넣지 않았다.** §1의 "한 변 200~300m"만이 예외이며, 이는 **원작 확인값이 아니라 프로토타입용 자체 결정 제안**임을 본문에 명시했다.
> 위 항목을 채울 때도 원작 확인값인지 자체 결정값인지 반드시 기록할 것.
