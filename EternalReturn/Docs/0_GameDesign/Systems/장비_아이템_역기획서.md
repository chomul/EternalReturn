## 0. 이 시스템의 정체

**이 게임의 아이템은 "주워서 입는 것"이 아니라 "만드는 것"이다.**
배틀로얄의 무작위 루팅과 정반대로, **무엇을 만들지 미리 정하고 재료를 모으러 다닌다.**

```
[일반 재료 2개] → [고급] → [희귀] → [영웅] → [전설] → [초월]
```

이 구조가 만드는 것:
- **파밍 루트 사전 계획** — 어떤 지역을 어떤 순서로 돌지가 매치 전에 결정된다
- **결정론적 성장** — 운이 아니라 계획과 실행력이 파워를 결정한다
- **높은 진입장벽** — 신규 유저는 무엇을 만들어야 할지 모른다

> ⚠ **클론 개발 시 가장 중요한 경고 (상위 문서 §12.5와 동일):**
> **제작 시스템과 "확장맵 파밍 위치 오버레이"는 반드시 동시에 구현해야 한다.**
> 제작만 있고 재료 위치를 알려주는 UI가 없으면, 유저는 무엇을 어디서 모아야 할지 몰라 게임이 성립하지 않는다.

### 3.1 여기서 읽어야 할 설계 규칙 4가지

**① 제작은 항상 "아이템 2개 조합"이다.**
`A + B → C`. 3개 이상 조합은 없다. 구현이 매우 단순해진다 — **조합 테이블 하나**면 끝난다.

**② 상위 등급이 반드시 더 센 게 아니다. 방향이 갈린다.**
같은 영웅 등급인데 낭아봉(공격력 34 / 스증 75)과 토르의 망치(공격력 95 / 공속 30%)는 **완전히 다른 물건**이다.
→ **등급 = 파워가 아니라 "투자한 재료의 희소성"**이다. 스탯 배분은 별개 축이다.

**③ 전설·초월은 전부 보스 드랍 재료를 요구한다.**
운석 · 미스릴 · 생명의 나무 · VF 혈액 샘플 → 전부 **타임라인 오브젝트/보스에서만 나온다**([`몬스터_야생동물_역기획서.md`](몬스터_야생동물_역기획서.md) §5).
→ **최종 장비 완성 시각이 보스 등장 시각에 묶여 있다.** 파밍만 열심히 해서는 전설을 못 만든다.

**④ 초월은 "일반 아이템 + 최고급 재료"로 건너뛴다.**
피스브링어 = **망치(일반)** + VF 혈액 샘플. 중간 단계를 안 거친다.
→ 후반에 재료를 얻으면 **트리를 처음부터 다시 타지 않고 즉시 최종템**을 만들 수 있다. **역전 장치**다.

> **클론 구현 제안:** 무기군 23종 전부는 과하다. 6인이 쓰는 **6종(망치·도끼·단검·암기·저격총·권총)** 만
> 위 구조로 만들면 시스템 검증은 끝난다. 나머지는 데이터 추가 작업일 뿐이다.

## 5. 6인 캐릭터별 자주 쓰는 장비

> ⚠ **아래 빌드는 커뮤니티 위키 기준이며, 12.2 시점의 실시간 픽률 데이터가 아니다.**
> dak.gg의 실시간 통계는 자동 수집이 불가능해(JS 렌더링) 아이템명을 확보하지 못했다.
> **메타는 패치마다 바뀌므로, 실제 구현 시점에 dak.gg에서 재확인할 것.**
> 여기서 중요한 건 개별 아이템명이 아니라 **"이 캐릭터는 어떤 스탯을 원하는가"** 다.

### 5.1 카티야 — 원거리 딜러 / 저격총

| 부위 | 초반 | 후반 |
|---|---|---|
| 무기 | 폴라리스 | **현자총통** |
| 옷 | 창파오 | 선녀강림 |
| 머리 | 여우 가면 | 쿼드 아이 |
| 팔/장식 | 미닛맨의 표식 | 운명의 주사위 |
| 다리 | 부케팔로스 | 알렉산드로스 |

**스탯 우선순위:** 공격력 → **방어 관통** → 공격 속도 → 치명타(후반)
**특성:** 아드레날린 (주) / 액셀러레이터 (사거리 우위 시) / 속사·늑대 탈·열세극복
**전술 스킬:** 붉은 폭풍 (진입 회피)

> **설계 해석:** 스킬 증폭이 하나도 없다. 카티야는 스킬 계수가 전부 **공격력 기준**이기 때문
> ([`../Characters/01_카티야.md`](../Characters/01_카티야.md) 참조). **계수 종류가 아이템 빌드를 결정한다** — 이 대응 관계가 구현의 핵심이다.

### 5.2 매그너스 — 탱커·전사 / 방망이·망치

**빌드가 무기에 따라 완전히 갈린다.** 같은 캐릭터가 아니라고 봐도 된다.

| | **방망이 (극딜)** | **망치 (딜탱)** |
|---|---|---|
| 무기 | 여의봉 | **천근추 / 다그다의 망치** (초반 낭아봉·아는 것이 힘) |
| 옷 | 창파오 | 창파오 |
| 머리 | 수정 티아라 | 수정 티아라 |
| 팔 | 미닛맨의 표식 | 미닛맨의 표식 |
| 다리 | 부케팔로스 | 부케팔로스 |
| **스탯 순위** | **공격력 → 치명타 → 공격 속도** | **방어력 → 체력 → 스킬 증폭 → 공격력** |
| 주력기 | 기본 공격 | **W (17대 1)** |

**특성(공통):** 액셀러레이터, 상흔, 늑대 탈, 위압감 / **전술:** 블링크

> **설계 해석:** 망치 빌드가 **방어력을 1순위로 올리는 이유가 "W 타격 횟수 +1 / 추가 방어력 35"** 다.
> 방어 아이템이 곧 딜 아이템이 되는 구조 — 이 규칙 하나가 아이템 빌드 전체를 바꾼다.
> 커뮤니티 가이드에서 **EOD 부츠**(방어력·체력·체젠·격동)를 추천하는 것도 같은 이유다.
> 후반 코어로는 **개밥바라기, 가디언 슈트, 우주비행사의 헬멧, 틴달로스의 군주, 헤르메스의 신발**이 언급된다.

> **계수 타입 → 아이템 선택**의 대응이 가장 뚜렷한 캐릭터다.

**특성:** 벽력, 상처 악화, 오버워치, 열세극복, 곰 탈

> **설계 해석 — 이 캐릭터만 특이하다:**
> - **스킬 증폭 1순위**: 패시브 + 궁 기준 추가 스증을 크게 얻으므로 곱연산이 커진다 (위키는 최대 **74**로 기술, [캐릭터 문서](../Characters/05_시셀라.md) §6의 충돌 항목 참조)
> - **체력 2순위**: 체력이 **자원이자 패시브 스케일링 기준**이다. 다른 캐릭터의 "체력 = 생존력"과 의미가 다르다
> - **쿨감 3순위**: Q 쿨다운이 최종 4초까지 내려가므로 회전율이 곧 딜이다
>
> 무기 선택도 갈린다 — **투척**은 성장 스증이 높아 후반형, **암기**는 초반 조합이 빨라 초반형.

### 5.6 레니 — 지원가 / 권총

| 부위 | 초반 | 후반 |
|---|---|---|
| 무기 | 엘레강스 | **알타이르** |
| 머리 | 스포츠 선글라스 | **천룡잠** (1코어) |
| 옷 | EOD 슈트 | 배틀 슈트 |
| 팔 | 슈뢰딩거의 상자 | 요술램프 |
| 다리 | 타키온 브레이스 | 와일드 워커 |

**스탯:** 스킬 증폭 + 체력 + 방어력 + **치유 효과 증가** + 쿨감을 **골고루**
**특성:** 치유의 바람·초재생 (주) / 가시 덤불, 불굴·견고, 서큘러 시스템·오버워치 (부)
**전술 스킬:** 치유의 바람, 강한 결속, 프로토콜 위반

> **설계 해석:** 레니만 **"골고루"** 다. 한 스탯에 몰빵하지 않는다.
> 이유는 스킬 계수가 **캐릭터 레벨**을 따라가기 때문이다([캐릭터 문서](../Characters/06_레니.md) §3).
> **스킬 증폭 아이템을 몰아줘도 딜이 비례해서 늘지 않으므로**, 생존·유틸 스탯을 챙기는 게 이득이다.
> → **계수 설계가 아이템 빌드를 강제한 사례.** 클론에서 레벨 계수를 빼면 이 캐릭터의 빌드 정체성도 사라진다.

## 6. 6인 빌드에서 도출되는 구현 요구사항

### 6.1 필요한 아이템 옵션(스탯) 종류

빌드에 등장한 옵션을 전부 모으면 **구현해야 할 스탯 목록**이 나온다.

| 분류 | 옵션 |
|---|---|
| 공격 | 공격력, **추가 공격력**, 공격 속도, 치명타 확률, 치명타 피해, **방어 관통**, 기본 공격 증폭 |
| 스킬 | **스킬 증폭**, 쿨다운 감소(쿨감), 스킬 가속 |
| 생존 | 체력, 체력 재생, 방어력, 피해 감소, 흡혈, **치유 효과 증가**, 보호막 |
| 이동 | 이동 속도, 둔화 저항 |
| 특수(고유 효과) | 격동, 처형, 파열, 크리티컬 블로우, 가벼운 발걸음, 치감(치유 감소) |

> **기존 `FCharStatRow`에 있던 19개 스탯이 대부분 여기 대응된다.** 삭제했지만 스탯 목록 자체는 재사용 가치가 있다.
> 다만 **"고유 효과"(격동/처형/파열 등)는 단순 수치가 아니라 트리거형 효과**다. 별도 시스템이 필요하다.

### 6.2 데이터 스키마 제안

```
FItemRow : FTableRowBase
  ItemName / Grade(ESItemGrade) / SlotType(EEquipSlot)
  WeaponType      : EWeaponType     // 무기일 때만. 장착 제한 검사용
  BaseAttackPower : int32
  StatModifiers   : TMap<EStatType, float>   // 위 6.1 목록
  UniqueEffectId  : FName           // 고유 효과 (없으면 NAME_None)
  CraftMaterialA  : FName           // 조합 재료 1
  CraftMaterialB  : FName           // 조합 재료 2  ← 항상 2개다
```

> **제작은 항상 2개 조합**이므로 재귀적으로 트리를 만들 수 있다.
> `CraftMaterialA/B`만 있으면 "이 아이템을 만들려면 무엇이 필요한가"를 **재귀 탐색으로 자동 계산**할 수 있다.
> 파밍 루트 UI도 이 데이터에서 자동 생성 가능하다.

### 6.3 구현 우선순위

```
1순위. 아이템 데이터 테이블 + 등급 + 슬롯 + 장착 제한(무기군)
       → 검증: 카티야가 망치를 못 들고, 저격총만 장착됨
2순위. 장비 스탯을 **Infinite UGameplayEffect** 로 적용 / 해제 시 GE 제거
       → 검증: 장착 시 서버에서 어트리뷰트가 변하고 클라에 복제. 벗으면 정확히 원복
3순위. 2개 조합 제작 시스템 + 재귀 트리 탐색
       → 검증: 망치 계열 17종이 데이터만으로 전부 제작 가능
4순위. 재료 획득 (상자 · 채집 · 야생동물 드랍)
5순위. ⭐ 확장맵 파밍 위치 오버레이 UI  ← 3순위와 세트다. 빼면 안 된다
6순위. 고유 효과 (격동/처형/파열 등 트리거형)
7순위. 원격 전송 드론 (크레딧 구매)
```

## 7. 사망 시 드롭 · 습득 권한

> **이 절이 이 문서에 필요한 이유:** [`네트워크_서버아키텍처_역기획서.md`](네트워크_서버아키텍처_역기획서.md) §11 색인이
> 이 문서의 네트워크 서술이 1건뿐(`:289`)이고 **사망 시 드롭·습득 규칙이 비어 있다**고 지적했다.
> 그 공백 때문에 인벤토리를 Pawn에 둘지 PlayerState에 둘지가 막혀 있다.

### 7.1 사망 시 드롭은 **확인된 사실**이다

원본 역기획서 두 곳이 명시한다.

- `../이터널리턴_역기획서.md:151` (§2.1 단계별 행동) — *"장비 격차 벌리기 / **상대 재료 강탈(사망 시 아이템 드롭)**"*
- `../이터널리턴_역기획서.md:1140` (§12.2) — *"교전 동기를 만든다. **사망 시 아이템 드롭** → 상대를 죽이면 내 제작 트리를 건너뛸 수 있다. 즉 **크래프팅이 PvP의 보상 구조 자체**다."*

> **이건 편의 기능이 아니라 이 게임의 코어 루프를 닫는 고리다.**
> §3의 제작 트리가 "재료를 모아 올라가는 길"이라면, 드롭은 **"남의 진행도를 빼앗는 두 번째 길"** 이다.
> 드롭이 없으면 교전할 이유가 사라지고, 파밍만 하다 자기장에서 만나는 게임이 된다.

### 7.2 부활 3단계와의 상호작용 — 일부 미확인

부활 규칙은 매치 시점에 따라 3단으로 바뀐다 (`../이터널리턴_역기획서.md` §3.2.3).

| 시점 | 부활 | 드롭은? |
|---|---|---|
| 1일차 ~ 2일차 낮 | 팀원 생존 시 **자동 부활** | **(미확인)** — 자동 부활인데도 장비를 떨구면 초반 페널티가 과도해진다 |
| 2일차(주입) ~ | 자동 부활 종료. 팀 전멸 = 게임 오버 | **(미확인)** |
| 3일차 ~ 5일차 | **크레딧 200 수동 부활**(키오스크) | **(미확인)** — 부활해도 장비가 없으면 200 크레딧의 가치가 애매해진다 |
| 5일차 밤 이후 | 부활 종료 | 사망 확정이므로 전량 드롭이 자연스럽다 |

> ⚠ **"사망 시 드롭한다"는 확인됐지만, "부활 시 되찾는가 / 자동 부활에도 떨구는가"는 확인되지 않았다.**
> 추측해서 채우지 않는다. 이 값이 초반 사망 페널티 전체를 좌우하므로 **인게임 계측 대상**이다.

### 7.3 드롭 액터 — 서버 권위

| 항목 | 규칙 |
|---|---|
| 드롭 액터 스폰 | **서버 전용.** 클라는 복제로 받는다 |
| 스폰 시점 | 사망 확정 시. 부활 대기 30초(`../이터널리턴_역기획서.md` §3.2.3) 중에 떨구는지는 **(미확인)** |
| 액터 구조 | 아이템 1개당 액터 1개 vs **시체 컨테이너 1개**(안에 목록) — 후자를 권장. 5슬롯 + 소비아이템이 한 번에 떨어지므로 개당 액터면 사망 1회에 액터가 여러 개 생긴다 |
| 릴리번시 | 지상 아이템은 **`DORM_DormantAll`** 로 재운다. 스폰 후 값이 변하지 않는다 (`Engine/Classes/Engine/EngineTypes.h:3079`) |
| 소멸 | 일정 시간 후 정리 여부 **(미확인)**. 정리하지 않으면 매치 후반에 액터가 단조 증가한다 |

### 7.4 습득 권한 — 경쟁을 서버가 단독 판정한다

**한 아이템을 두 명이 동시에 주우려는 상황이 이 게임에서는 흔하다.** 한타 직후 시체 위에서 벌어진다.

| 항목 | 규칙 | 이유 |
|---|---|---|
| 습득 요청 | `Server` RPC + **`WithValidation`** | CLAUDE.md §6. 거리·소유권·인벤토리 여유를 서버가 검증 |
| 경쟁 판정 | **서버가 먼저 도착한 요청 1건만 승인**, 나머지는 거절 | |
| 클라 UI | ⚠ **낙관적 표시 금지.** 요청 즉시 내 인벤토리에 넣어 보여주면, 거절됐을 때 아이템이 사라지는 것처럼 보인다 | 서버 승인 후 복제된 결과로만 갱신한다 |
| 자동 획득 | 원본 §11.4에 *"우선순위 아이템 자동 습득(설정 기반)"* 이 있다 (`../이터널리턴_역기획서.md:1426`) | **자동 습득도 예외 없이 같은 Server RPC를 탄다.** 클라 자동화가 서버를 우회하면 안 된다 |
| 습득 거리 | **(미확인)** | 인게임 계측 |

### 7.5 인벤토리를 어디에 둘 것인가 — **이 문서는 결정하지 않는다**

[`네트워크_서버아키텍처_역기획서.md`](네트워크_서버아키텍처_역기획서.md) §2.3 이 두 안(Pawn / PlayerState)을 제시하고 **잠정 권장만** 해 둔 상태다.
§7.1에서 "사망 시 드롭"이 확인됐으므로 그 판단의 전제 하나는 채워졌지만, §7.2의 **부활 시 인벤토리 유지 여부가 여전히 미확인**이라 결론이 나지 않는다.

확정된 것 하나는 유지된다 — **인벤토리 복제는 `COND_OwnerOnly`** 다.
[`UI_HUD_역기획서.md`](UI_HUD_역기획서.md)`:101` 이 *"남의 인벤토리를 클라가 받으면 그대로 정보 유출"* 이라고 못 박았다.
이건 성능 문제가 아니라 **정보 유출** 문제이므로 배치 안과 무관하게 적용된다.

> **다음 작업:** 이 결정은 선택지가 2개이고 되돌리기 비용이 크므로, CLAUDE.md §1.2 에 따라
> `Docs/4_Argument/` 비교 문서로 다뤄야 한다. **§7.2의 미확인 2건을 먼저 계측하는 편이 낫다** — 그게 채워지면 선택지가 하나로 줄어들 수도 있다.
