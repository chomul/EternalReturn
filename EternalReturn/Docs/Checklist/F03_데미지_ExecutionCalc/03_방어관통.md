# ✅ F03-03 — 방어 관통

## 선행

- [ ] [02 핵심 계산 · 방어력 공식](02_핵심계산_방어력공식.md) 완료

## 구현

- [ ] ⭐ **퍼센트 관통 먼저**, 고정 관통 나중
- [ ] ⭐ **`max(0, ...)` 클램프**
- [ ] ⭐ **Execution 안에서 지역 변수로 계산** — Target 어트리뷰트를 수정하지 않는다
- [ ] 관통%의 단위를 어트리뷰트 주석에 명시
- [ ] 계산 순서를 코드 주석으로 남겼다

## 빌드

- [ ] `EternalReturnEditor` 빌드 통과
- [ ] `EternalReturnServer` 빌드 통과

## 수치 검증

- [ ] ⭐ 방어력 100, 관통 50%, 고정 30 → **20** (문서 §7 3순위 기준)
- [ ] 방어력 100, 관통 0%, 고정 0 → 100
- [ ] 방어력 100, 관통 100%, 고정 0 → 0
- [ ] ⭐ 방어력 100, 관통 50%, 고정 999 → **0** (음수 아님)
- [ ] 방어력 0, 관통 50%, 고정 30 → **0**
- [ ] 관통 과다에서 **피해가 폭증하지 않는다**
- [ ] 고정 피해 태그에서는 관통이 무의미하다

## ⭐ GAS 특유의 실수 — 가장 위험

- [ ] **관통을 GE 수정자로 Target 방어력에 걸지 않았다**
  걸면 **다른 공격자의 피해까지** 방어력이 깎인 상태로 계산된다
- [ ] 관통 공격 후 **Target의 실제 `Defense` 어트리뷰트가 안 변한다**
  (PIE에서 공격 전후 Defense 값을 로그로 확인)

## 흔한 실수 — 걸렸는지 확인

- [ ] ⭐ **0 클램프 누락이 없다**
- [ ] 고정 관통을 먼저 적용하지 않았다 (35가 나오면 순서가 틀렸다)
- [ ] 관통% 단위를 섞지 않았다 (`0.5` vs `50` — 100배 차이)

## 판단 기록

- [ ] 관통 여러 소스의 합산이 **GE 수정자 op로 결정됨**을 주석에 남겼다
- [ ] 관통 상한 처리를 정하거나 **(미확인)** 으로 남겼다
