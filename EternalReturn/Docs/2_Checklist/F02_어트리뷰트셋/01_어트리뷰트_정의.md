## 실행 기록 (2026-09-07)

### 만든 것

```
Source/EternalReturn/GAS/ERAttributeSet.h / .cpp     어트리뷰트 33개
Source/EternalReturn/Core/ERPlayerState.h / .cpp     (수정) AttributeSet 생성
```

**어트리뷰트 33개** = 역기획서 §6.1 목록 30개 + 현재값 `HP` `VP` + Meta `IncomingDamage`

> §6.1 은 `MaxHP` / `MaxVP` 만 나열하고 **현재값을 안 적었다.**
> 최대치만으로는 체력이 성립하지 않아 `HP` / `VP` 를 추가했다. 이름은 §6.1 규칙을 따랐다.

### 이름을 `Health` 가 아니라 `HP` 로 한 이유

§6.1 이 *"이 이름이 그대로 GAS Attribute 이름이 된다"* 고 못 박았다.
GAS 예제 관례는 `Health` 지만, **역기획서와 코드가 다른 이름을 쓰면 대조가 안 된다.**

⚠ 한 번 확정했으므로 바꾸지 않는다 — GE 애셋이 이름으로 참조한다 (`CLAUDE.md` §3).

### 반복 선언을 매크로로 묶었다

어트리뷰트가 33개라 `DOREPLIFETIME_CONDITION_NOTIFY` 와 `OnRep_` 정의가 각각 33벌이다.
`ER_REP` / `ER_ONREP` 매크로로 묶어 **한 줄씩**으로 줄였다.

목적은 짧게 쓰는 게 아니라 **빠뜨림을 줄이는 것**이다 — 목록이 세로로 정렬되어 눈으로 대조할 수 있다.
`GAMEPLAYATTRIBUTE_REPNOTIFY` 를 한 곳에만 쓰므로 그걸 빠뜨릴 수도 없다.

### 고유 리소스 구조를 주석으로 못 박았다

`ERAttributeSet.h` 클래스 주석과 `ERPlayerState.h` 멤버 주석 양쪽에:

- 캐릭터 고유 리소스(VF 게이지 등)는 **여기 넣지 않는다**
- **이 클래스를 상속하지 마라** — ASC 조회가 `IsA()` 라 같은 계층 둘을 등록하면 조용히 틀린 세트를 쓴다
- 별도 세트를 만들어 **병렬 추가**한다
