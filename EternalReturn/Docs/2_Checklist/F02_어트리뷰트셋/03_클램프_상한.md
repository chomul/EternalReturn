### 캡을 `UDeveloperSettings` 로 모은 이유

역기획서 §5 가 *"캡은 코드에 흩뿌리지 말고 한 곳(`UStatCapSettings` 또는 데이터 테이블 1행)에 모으고,
각 캡에 '원작 확인값 / 자체 결정값' 구분 컬럼을 둔다"* 고 지시했다.

데이터 테이블이 아니라 DeveloperSettings 를 고른 이유:

- 캡은 실험체별이 아니라 **프로젝트 전역** 값이다 → 행이 하나뿐인 테이블이 된다
- **애셋을 만들지 않아도 된다** (에디터 작업이 줄어든다)
- config(ini) 로 저장되어 **텍스트로 diff** 가 된다
- Project Settings > Game > **ER Stat Caps** 에 그대로 보인다

⚠ `UPROPERTY` 카테고리를 **`확인값` / `자체 결정값 (미확인)`** 두 개로 나눴다.
에디터에서 열면 어느 값이 근거 있는 값인지 바로 보인다.

### 클램프를 두 곳에 건 이유

`PreAttributeChange`(Current) 와 `PreAttributeBaseChange`(Base) 둘 다 오버라이드하고,
**규칙은 `ClampAttribute()` 한 함수**에 뒀다.

Current 만 자르면 Base 에 상한을 넘긴 값이 남아, **버프가 빠질 때 그 값이 튀어나온다.**
두 곳에서 규칙을 따로 쓰면 언젠가 어긋나므로 함수 하나를 공유한다.

⚠ 엔진 주석이 이 자리를 지정한다 — *"meant to enforce things like Health = Clamp(...)
and NOT things like trigger this extra thing"*. 사망 처리·이펙트는 여기 넣지 않았다.

### ⭐ 체력 하한은 넣지 않았다

`HP` 의 하한은 **언제나 0** 이다. 시셀라 R 의 "100 아래로 안 떨어짐"을 여기 넣지 않았다.
그런 하한이 데미지 경로에 섞이면 **실수로 하나 남았을 때 죽어야 할 때 안 죽는다.**
하한이 필요한 스킬이 스스로 피해량을 깎아서 넘긴다.
