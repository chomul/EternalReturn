| | 개수 | 스냅샷 |
|---|---|---|
| Source (공격자) | 15 | `true` |

목록은 추측이 아니라 [스탯 문서 §2.2](../../0_GameDesign/Systems/스탯_데미지공식_역기획서.md) 의사코드에서
쓰이는 어트리뷰트를 그대로 뽑았다. 각 항목 주석에 **몇 단계에서 쓰는지**를 적었다.

### ⭐ 등록 누락을 구조적으로 막았다

`RelevantAttributesToCapture` 누락은 **값이 경고 없이 0 이 되는** 실수다.
정의와 등록을 매크로 하나로 묶어 따로 쓸 수 없게 했다.

```cpp
#define ER_CAPTURE(PropertyName, CaptureSource, bSnapshot)     {         DEFINE_ATTRIBUTE_CAPTUREDEF(UERAttributeSet, PropertyName, CaptureSource, bSnapshot);         AllDefs.Add(PropertyName##Def);     }
```

F03-02 는 `ERDamageStatics().AllDefs` 를 통째로 붙이면 된다.

### ⚠ HP / MaxHP 만 매크로를 못 썼다

`DECLARE_ATTRIBUTE_CAPTUREDEF(HP)` 는 멤버 이름이 `HPDef` 로 고정이라
**같은 어트리뷰트를 Source·Target 두 번 선언할 수 없다.**
그 넷만 `SourceHPDef` / `TargetHPDef` 식으로 손으로 만들었다 (Lyra 방식, `LyraDamageExecution.cpp:19`).

### 매크로를 쓸 수 있었던 이유

`DEFINE_ATTRIBUTE_CAPTUREDEF` 는 `GET_MEMBER_NAME_CHECKED` 로 멤버에 접근한다
(`GameplayEffectExecutionCalculation.h:327`). 우리 어트리뷰트는 `public`(`ERAttributeSet.h:108`) 이라 통한다.

⚠ **Lyra 는 이 매크로를 못 쓴다** — 어트리뷰트가 `private` + `AllowPrivateAccess` 라서다.
Lyra 가 다른 방식을 쓴 건 취향이 아니라 제약이었다.
