- [x] 방어력 100, 관통 0%, 고정 0 → 100
- [x] ~~방어력 100, 관통 100%, 고정 0 → 0~~ → ⚠ **이 케이스는 나올 수 없다**
  `DefPenPercent` 는 F02-03 이 **상한 0.8** 로 자른다 (`ERStatCapSettings::MaxDefPenPercent`).
  1.0 을 넣어도 0.8 로 클램프되어 적용 방어력은 100×0.2 = **20** 이 된다.
  상한 이유: *"1.0 이면 방어력 스탯 자체가 무의미해진다"* (자체 결정값).
  → 대신 아래 항목으로 검증한다
- [x] 방어력 100, 관통 100%(→0.8 로 클램프), 고정 0 → 적용 방어력 **20**
- [x] ⭐ 방어력 100, 관통 50%, 고정 999 → **0** (음수 아님)
- [x] 방어력 0, 관통 50%, 고정 30 → **0**
- [x] 관통 과다에서 **피해가 폭증하지 않는다**

## ⭐ GAS 특유의 실수 — 가장 위험

- [x] **관통을 GE 수정자로 Target 방어력에 걸지 않았다**
  걸면 **다른 공격자의 피해까지** 방어력이 깎인 상태로 계산된다
- [x] 관통 공격 후 **Target 의 실제 `Defense` 어트리뷰트가 안 변한다**
  ⭐ 디버그 커맨드가 자동으로 검사한다 — 변했으면 `Error` 로 찍는다.
  정상이면 `대상 방어력 100.00 그대로 (관통이 어트리뷰트를 안 건드렸다)`

## 흔한 실수 — 걸렸는지 확인

- [x] ⭐ **0 클램프 누락이 없다**
- [x] 고정 관통을 먼저 적용하지 않았다 (35가 나오면 순서가 틀렸다)
- [x] 관통% 단위를 섞지 않았다 (`0.5` vs `50` — 100배 차이)

## 판단 기록

- [x] 관통 여러 소스의 합산이 **GE 수정자 op 로 결정됨**
  Execution 은 최종 합산값 하나만 읽는다. 장비 2개의 관통을 더할지 곱할지는
  각 장비 GE 의 `ModifierOp` 가 정한다 — Execution 이 관여하지 않는다
- [x] 관통 상한 처리를 정했다 — **`MaxDefPenPercent = 0.8`** (F02-03, 자체 결정값)
  ⚠ 고정 관통(`DefPenFlat`)에는 상한이 없다. 0 클램프만 있다 **(미확인)** —
  아이템 수치가 정해지면 필요 여부를 다시 본다
