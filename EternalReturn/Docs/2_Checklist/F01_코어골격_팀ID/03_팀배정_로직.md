## 검증 — `Play As Client, Number of Players: 4`, `TeamSize = 2`

- [ ] 4명이 **2팀으로 나뉜다**
- [ ] 각 팀에 정확히 2명씩 들어간다
- [ ] 서버 로그에 배정 결과가 찍힌다
- [ ] 각 클라가 자기 팀 ID를 올바로 읽는다
- [ ] `TeamSize = 1` 로 바꾸면 4팀이 된다 (데이터값이 실제로 동작)

## 흔한 실수 — 걸렸는지 확인

- [x] 3 × 8 = 24를 상수로 박지 않았다 — **박으면 PIE 테스트가 불가능해진다**
- [x] 배정 로직이 `AERGameMode` 에 있다 (클라에 존재하지 않는 클래스)
- [x] 클라가 자기 팀을 정하는 경로가 없다
- [x] `AGameStateBase` 팀 배열에 인벤토리 같은 큰 데이터를 넣지 않았다
- [x] `PostLogin` 시점에 `PlayerState` 가 `nullptr` 일 수 있음을 감안했다

## 막혔을 때

| 증상 | 확인할 것 |
|---|---|
| 전원이 같은 팀 | 배정 인덱스가 증가하지 않는다. 접속 카운터를 확인 |
| `PostLogin` 에서 크래시 | `PlayerState` 가 아직 없다. 더 늦은 시점(예: `OnPostLogin` 이후)으로 옮긴다 |
| 클라마다 팀 구성이 다르게 보임 | GameState 배열 복제 누락 (`DOREPLIFETIME`) |

## 실행 기록 (2026-09-06)

**`AERGameState`** — 팀 구성을 들고 복제한다.

```cpp
USTRUCT() struct FERTeamRoster { TArray<TObjectPtr<APlayerState>> Members; };
UPROPERTY(Replicated) TArray<FERTeamRoster> Teams;
```

⚠ **`TArray<TArray<>>` 는 복제되지 않는다.** 그래서 `FERTeamRoster` 로 한 겹 감쌌다.
함수 3개(`InitTeams` / `AssignToFirstOpenTeam` / `RemoveFromTeams`)는 전부 `HasAuthority()` 가드 뒤에 있다.

**`AERGameMode`** — 배정 시점을 셋으로 나눴다.

| 시점 | 하는 일 |
|---|---|
| `InitGameState()` | `Teams` 를 `TeamCount` 크기로 준비 |
| `PostLogin()` | 빈 자리를 찾아 `TeamId` 배정 + 로그 |
| `Logout()` | 팀에서 제거 (`Super::` **호출 전에** 뺀다 — 그 뒤엔 PlayerState 가 정리된다) |

**자체 결정값 2건** (주석에 표기)
- 정원 초과 시 → **미배정(`INDEX_NONE`)으로 두고 접속은 막지 않는다.** 관전 처리로 바꿀지는 F14 에서 정한다
- 배정 순서 → **접속 순서.** 파티 우선은 매치메이킹 이후 **(미확인)**

⬜ 4인 2팀 분할 확인은 F01 통합 검증에서 한다.
