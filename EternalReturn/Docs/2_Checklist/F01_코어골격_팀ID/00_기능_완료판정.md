### 설계 판단 2건 — Task 문서를 고쳤다

**1. `GetController()` 를 경유하지 않는다.**
Task 원문은 `Pawn -> Controller -> PlayerState` 경로였는데, `AController` 는
`bOnlyRelevantToOwner = true`(`Controller.cpp:51`)라 **클라에는 남의 컨트롤러가 없다.**
그 경로면 클라에서 적의 팀을 못 읽어 아군/적군 구분이 통째로 깨진다.
`APawn::GetPlayerState()` 로 복제된 PlayerState 를 직접 읽도록 구현하고 Task 문서를 수정했다.

**2. `IsHostile()` 을 추가했다.**
`!IsSameTeam` 으로 적을 판정하면 **곰과 늑대(둘 다 무소속)가 적이 아니게** 되고,
같은 방식으로 `Ally` 필터를 짜면 **야생동물이 아군으로 잡힌다.**
판정 규칙을 부정 연산에 맡기지 않고 함수로 못 박았다. F04 의 팀 필터가 이걸 쓴다.

### 자체 결정값 (주석에 표기)

- 정원 초과 시 → 미배정(`INDEX_NONE`)으로 두고 접속은 막지 않는다. 관전 처리 여부는 F14
- 배정 순서 → 접속 순서. 파티 우선은 매치메이킹 이후 **(미확인)**

### 남은 것

통합 검증 5건은 **PIE 실행이 필요**하다.
절차와 판정 기준은 [`../../EditorTasks/F01_코어골격_팀ID.md`](../../3_EditorTasks/F01_코어골격_팀ID.md) 에 있다.

## ⏸ 3건의 후속 (2026-09-07) — F04 에서 2건 해결

[F04 판정·타게팅](../F04_판정_타게팅/00_기능_완료판정.md) 의 팀 필터 테스트가
`ERTeamStatics` 의 첫 호출자가 되면서 **클라 월드에서 팀 읽기가 실증됐다.**

`Play As Client / Players 4 / Team Size 2`, 클라 월드 실행 결과:

| 필터 | 결과 |
|---|---|
| `ally` | Team 0 하나만. **무소속(Team -1) 없음** |
| `enemy` | Team 1 둘 + **무소속 다섯**. 아군은 빠짐 |

⭐ **`GetController()` 를 버리고 `APawn::GetPlayerState()` 를 쓴 판단이 증명됐다**
([E03](../../5_ErrorReport/E03_팀조회_컨트롤러경유.md)). 컨트롤러 경유였다면
클라에서 적의 팀 번호가 전부 `INDEX_NONE` 으로 나왔을 것이다.

### 남은 1건

- **클라에서 `TeamId` 를 조작해도 서버 값이 안 변한다** — 여전히 확인 못 함.
  클라가 값을 바꾸는 코드 경로가 없어서(치트 콘솔도 없음) 시험할 수단이 없다.
  `TeamId` 에 `Replicated` 만 붙어 있고 클라 쓰기 RPC 가 없다는 **코드상 사실로 대신한다.**
