## 구현

- [x] `MoveSpeed` 를 **퍼센트로** 깎는다  → `UERSlowEffect` 의 Multiply 모디파이어
- [x] ⭐ 둔화 GE 애셋이 **`HasDuration`** 이다 — `Instant` 가 아니다
      ⚠ 단 `UERSlowEffect` 는 **Infinite** 다. 의도적이다 — 지속시간은 둔화 GE 들이 갖고,
      그것들이 모두 사라지면 `RecalculateSlow` 가 이 GE 를 제거한다
- [x] ⭐ **여기서 클램프하지 않는다** — `RecalculateSlow` 에 `MoveSpeed` 클램프가 없다.
      감소율 클램프(`0~0.99`)는 있지만 그건 **다른 값**이다 (음수 배수 방지)
- [x] ⭐⭐ **가장 강한 둔화 하나만 적용한다** (방안 B)
- [x] ⭐⭐ **약한 둔화를 제거하지 않는다** — 계산에서만 뺀다.
      강한 것이 만료되면 남은 것 중 최대가 자동 적용된다
- [x] ⚠ **재진입을 막았다** — `UERSlowEffect` 자신의 추가·제거는 콜백에서 무시한다
      (클래스로 판별. 태그로는 못 거른다)
- [x] ⚠ 델리게이트를 **PlayerState 의 `BeginPlay`** 에서 한 번만 건다
      (폰의 `InitAbilityActorInfo` 는 여러 번 불려 중복 등록된다)

## 빌드

- [x] `EternalReturnEditor` 빌드 통과
- [x] `EternalReturnServer` 빌드 통과

## 검증 — ⏸ **애셋 필요** ([3_EditorTasks/F06_상태이상.md](../../3_EditorTasks/F06_상태이상.md) ⑤절)

### 1인 PIE — `ER.CC.Slow` / `ER.CC.Speed`

- [x] ⭐ 실제로 캐릭터가 **느리게 움직인다**
- [x] 60% 둔화 → `MoveSpeed` 가 **1.40** (3.5 × 0.4)
- [x] ⭐ CMC `MaxWalkSpeed` 도 같은 비율로 줄었다 (F05-02 반영 지점이 동작한다)
- [x] ⭐ **만료되면 원래 속도로 돌아온다**

### ⭐⭐ 다중 둔화 — 이 구현의 핵심

- [x] 30% 만 → **2.45**
- [x] ⭐ 60% 를 겹침 → **1.40** (⚠ **1.0** 이면 합산된 것 = 구현 실패)
- [x] ⭐⭐ 60% 만료 후 → **2.45 로 복귀** (약한 둔화가 살아 있었다는 증거)

### 애셋 실수를 잡는지

- [ ] 둔화율 없이 적용 → *"SetByCaller.SlowPercent 가 없다"* 경고가 뜬다  → ⚠ **미확인** (기능 판정과 무관한 검사기 시험)

### 멀티 — `Play As Listen Server` 2인

- [x] ⭐ 다른 클라 창에서도 **느려 보인다** (`MoveSpeed` 복제)
- [x] 고무줄이 안 생긴다

## ⭐ 가장 위험한 실수

- [x] ⭐ **`Instant` 로 만들지 않았다** — 그러면 기본 이동속도가 영구히 깎인다
- [x] ⭐ 클램프를 두 곳에서 하지 않았다
- [x] ⚠ `SlowResist` 는 F06-05 소관이다 — 여기서 미리 넣지 않았다
