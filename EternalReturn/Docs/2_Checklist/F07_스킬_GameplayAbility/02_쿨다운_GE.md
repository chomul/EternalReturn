## 검증 — `Play As Client, Number of Players: 2`

> 절차: [`../../3_EditorTasks/F07_스킬.md`](../../3_EditorTasks/F07_스킬.md) "F07-02 — 쿨다운" · ⚠ 에디터 재시작 필요 (UPROPERTY 추가)

- [x] ⭐ 쿨다운 중 같은 스킬이 **발동하지 않는다** — 2026-09-13 로그: 연타해도 발동이 5.03 · 6.36 · 5.25초 간격으로만 통과
- [ ] ⭐ 클라 쿨다운 표시가 서버와 **±0.1초 이내** → ⚠ **부분 확인** (2026-09-13, 2인 PIE 4샘플)
  - ✅ 클라가 계산한 `만료서버시각` 과 서버의 `서버시각+5.00` 차이 **≤ 0.01초** (4/4) — GE 복제·시작시각 복원(`GameplayEffect.cpp:2776`)은 정확하고 드리프트 없음
  - ⚠ 다만 이 비교는 클라의 **서버시각 추정**(`AGameStateBase::ServerWorldTimeSecondsDelta`)을 양쪽 다 거치므로 추정 자체의 오차는 못 잰다. 로그 타임스탬프(벽시계)로 재려 했더니 PIE 는 월드마다 다른 시점에 ~1초씩 시간을 잃어(`MaxUndilatedFrameTime` 클램프, 히치) 공통 기준시계가 없다 — 첫 측정의 0.6~0.8초 오차 2건도 이것과 구분이 안 된다
  - → 절대 오차는 **쿨다운 UI 작업 때** 재측정: 클라 `ER.Skill.Cooldown` 이 Server RPC 로 같은 순간의 서버 잔여시간을 받아 비교 (또는 Standalone 서버+클라)
- [x] `SkillHaste` 가 오르면 쿨다운이 줄어든다 — 로그: 가속 100 → `2.50초`, 300 → `1.25초` (30% 캡 없음 확인)
- [x] `bIgnoreCooldownReduction` 스킬은 가속을 안 받는다 — 로그: 가속 300 상태에서 `5.00초 (가속 무시)`
- [x] ⭐ **채널링이 취소돼도 쿨다운이 남는다** (F06-03 완결) — F07-04 에서 확인 (2026-09-13). 구조상은 보장됨 — `CommitExecute → ApplyCooldown` 이 시작 시점이고 취소는 GE 를 안 지운다 (`GameplayAbility.cpp:557-561`)
