# 2026-09-06 — GAS 기반 세팅 · 애셋 복구

> 관련 작업 [`../Task/F00_GAS기반세팅/00_개요.md`](../Task/F00_GAS기반세팅/00_개요.md)
> 선행 빌드: `EternalReturnEditor` **통과** (2026-09-06)

## 1. 목적

C++ 쪽 F00(GAS 기반 세팅)은 끝났다. 그런데 **애셋이 삭제된 옛 C++ 클래스를 부모로 참조**하고 있어서
PIE 를 켜도 새로 만든 `AERGameMode` / `AERPlayerState` / `AERCharacterBase` 가 쓰이지 않는다.

이 문서를 끝내면 **PIE 에서 ASC 가 서버·클라 양쪽에 붙는 것을 로그로 확인**할 수 있고,
F00 체크리스트의 남은 검증 항목이 채워진다.

## 2. 선행 조건

- [ ] `EternalReturnEditor` 빌드가 통과해 있다 (2026-09-06 완료)
- [ ] 에디터를 **새로 실행**한다. 이번에 `UPROPERTY` / 새 클래스가 추가됐으므로 이전 세션이 떠 있으면 안 보인다
- [ ] 첫 실행은 GAS 플러그인 모듈·셰이더 컴파일로 **느리다.** 정상이다

## 3. 단계별 절차

### 3-1. GAS 플러그인이 켜져 있는지 확인

1. 메뉴 **Edit > Plugins**
2. 검색창에 `Gameplay Abilities`
3. **Gameplay Abilities** 항목의 체크박스가 **켜져 있는지** 확인
   - 이미 `EternalReturn.uproject` 에 넣어뒀으므로 켜져 있어야 정상이다. **직접 켜거나 끄지 않는다**

### 3-2. 게임플레이 태그가 로드됐는지 확인

1. 메뉴 **Edit > Project Settings**
2. 좌측 **Project > GameplayTags**
3. **Manage Gameplay Tags** 버튼 클릭
4. 아래 태그가 목록에 보이는지 확인 (C++ 에서 선언한 네이티브 태그다)

| 확인할 태그 |
|---|
| `State.CC.Stun` |
| `State.Stealth` |
| `Ability.Slot.Q` |
| `Damage.Type.BasicAttack` |

> 안 보이면 빌드가 반영되지 않은 것이다. 에디터를 닫고 재빌드한다.
> ⚠ 여기서 **태그를 직접 추가하지 않는다.** 이 태그들은 C++ 소유이고, 에디터에서 만들면 이름이 두 곳에 생긴다.

### 3-3. `BP_RGameMode` 의 부모 클래스를 `AERGameMode` 로 재지정

애셋: **`/Game/Core/BP_RGameMode`**

1. 콘텐츠 브라우저에서 위 애셋을 **더블클릭**해 연다
2. 툴바 **File > Reparent Blueprint**
3. 목록에서 **`ERGameMode`** 선택
4. **Compile** → **Save**

> ⚠ 부모가 없어져서 열 때 경고가 뜰 수 있다. 그래도 Reparent 는 가능하다.
> ⚠ 열리지 않으면 3-3′ 로 간다.

**3-3′ (대안) — BP 를 쓰지 않고 C++ 게임모드를 직접 지정**

`BP_RGameMode` 가 복구 불가능하면 이렇게 한다.

1. **Edit > Project Settings > Project > Maps & Modes**
2. **Default Modes** 카테고리
3. **Default GameMode** 를 **`ERGameMode`** 로 변경
4. 에디터가 `Config/DefaultEngine.ini` 의 `GlobalDefaultGameMode` 를 자동으로 바꾼다

> 지금 값: `GlobalDefaultGameMode=/Game/Core/BP_RGameMode.BP_RGameMode_C`
> 3-3′ 를 택하면 `/Script/EternalReturn.ERGameMode` 로 바뀐다.

### 3-4. `BP_ERCharacterBase` 의 부모 클래스를 `AERCharacterBase` 로 재지정

애셋: **`/Game/ERCharacter/Blueprints/BP_ERCharacterBase`**

1. 애셋을 연다
2. **File > Reparent Blueprint** → **`ERCharacterBase`** 선택
3. **Compile** → **Save**

> ⚠ 이전 부모에 있던 변수·이벤트를 참조하던 노드가 **끊어진다.** 컴파일 에러가 뜨면
> 끊어진 노드를 지운다 — 그 로직은 어차피 GAS 로 다시 만든다.

### 3-5. 게임모드가 새 클래스를 쓰게 배선

`BP_RGameMode` 를 살렸다면(3-3), 그 BP 의 **Class Defaults** 에서:

| 프로퍼티 (에디터 표시 이름) | 넣을 값 |
|---|---|
| **Default Pawn Class** | `BP_ERCharacterBase` (3-4 를 했으면) 또는 `ERCharacterBase` |
| **Player State Class** | `ERPlayerState` |

> `AERGameMode` 생성자가 이미 `ERCharacterBase` / `ERPlayerState` 를 기본값으로 넣어두므로,
> **BP 에서 덮어쓰지 않았다면 비워둬도 된다.** BP 에 옛 값이 남아 있으면 그게 우선하므로 확인이 필요하다.

## 5. 검증 방법

맵: **`/Game/ERCharacter/Maps/TopDownMap`**

1. 툴바 **Play** 옆 드롭다운 → **Advanced Settings**
2. 아래대로 설정

| 설정 | 값 |
|---|---|
| **Net Mode** | **Play As Client** |
| **Number of Players** | **2** |

3. **Play** 실행
4. **Output Log** (메뉴 **Window > Output Log**) 를 열고 `LogEternalReturn` 으로 필터

**성공 판정** — 아래 두 줄이 **모두** 보여야 한다.

```
LogEternalReturn: [GAS] InitAbilityActorInfo — Server / Owner=... / Avatar=...
LogEternalReturn: [GAS] InitAbilityActorInfo — Client / Owner=... / Avatar=...
```

| 보이는 것 | 뜻 |
|---|---|
| Server + Client 둘 다 | ✅ 정상. F00-03 검증 통과 |
| **Server 만** | ❌ 클라 경로가 안 탄다. `OnRep_PlayerState` 문제 |
| **Client 만** | ❌ 서버 경로가 안 탄다. `PossessedBy` 문제 |
| **아무것도 없음** | ❌ 게임모드가 `AERGameMode` 가 아니다. 3-3 / 3-3′ 를 다시 확인 |

- `Owner=` 에 **PlayerState** 이름이, `Avatar=` 에 **캐릭터** 이름이 찍혀야 한다. 반대면 인자 순서가 틀린 것이다.

## 6. 주의점

- ⚠ **부모 클래스를 재지정하면 그 BP 의 기존 노드가 끊어질 수 있다.** 끊어진 노드는 지운다 — 옛 로직은 GAS 로 다시 만든다.
- ⚠ **데이터 테이블 4개는 이번에 건드리지 않는다.** 지금 행 구조체를 바꾸면 입력해둔 값이 날아간다.
- ⚠ **게임플레이 태그를 에디터에서 추가하지 않는다.** 코드가 소유한다.
- ⚠ 에디터가 열려 있으면 다음 빌드의 링크가 실패한다. 빌드가 필요하면 **에디터를 먼저 닫는다.**
- 3-3 과 3-3′ 는 **둘 중 하나만** 한다. 둘 다 하면 어느 쪽이 쓰이는지 헷갈린다.
