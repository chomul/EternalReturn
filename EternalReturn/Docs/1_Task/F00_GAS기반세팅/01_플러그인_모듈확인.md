# F00-01 — 플러그인 · 모듈 확인

> 체크리스트 [`01_플러그인_모듈확인.md`](../../2_Checklist/F00_GAS기반세팅/01_플러그인_모듈확인.md)

## ⚠ 이 Task는 "적용"이 아니라 "확인"이다

**변경은 이미 적용됐다.** 다시 추가하면 중복된다.

## 적용된 변경

### 1. `EternalReturn.uproject`

```json
"Plugins": [
    { "Name": "ModelingToolsEditorMode", "Enabled": true, "TargetAllowList": ["Editor"] },
    { "Name": "GameplayAbilities", "Enabled": true }        ← 추가됨
]
```

**왜 필요한가:** 플러그인이 엔진에 있지만 기본 비활성이다 — `GameplayAbilities.uplugin:13` `"EnabledByDefault": false`.
프로젝트에서 명시적으로 켜야 한다.

### 2. `Source/EternalReturn/EternalReturn.Build.cs`

```csharp
PublicDependencyModuleNames.AddRange(new string[] {
    "Core", "CoreUObject", "Engine", "InputCore", "NavigationSystem",
    "AIModule", "Niagara", "EnhancedInput",
    "GameplayAbilities", "GameplayTags", "GameplayTasks"     // ← 추가됨
});
```

**왜 3개인가:** `GameplayAbilities.Build.cs:18-19` 가 `GameplayTags` 와 `GameplayTasks` 를 공개 의존성으로 갖는다.
어빌리티가 태그와 `UAbilityTask` 를 쓰므로 우리 모듈도 직접 참조하게 된다.

## 할 일 — 확인만

1. 두 파일에 위 내용이 있는지 확인
2. **빌드** — 이게 진짜 검증이다
3. 에디터에서 플러그인이 켜져 있는지 확인

## 검증

- [ ] `EternalReturnEditor` 빌드 통과
- [ ] `EternalReturnServer` 빌드 통과
- [ ] 아무 `.cpp` 에서 `#include "AbilitySystemComponent.h"` 가 컴파일된다

## ⚠ 주의점

- ⭐ **빌드 액션 수가 수천 개면 엔진 전체 재빌드 중이다.** 플러그인을 처음 켜면 GAS 모듈을 컴파일하므로 평소보다 오래 걸리는 건 정상이지만, **수천 개는 다르다.** UBT 로그 앞부분의 `UnrealHeaderTool needs to run because ...` 를 확인하고, 몇 시간 걸릴 상황이면 사용자에게 알린다.
- 에디터가 열려 있으면 링크가 실패한다. 닫고 재빌드한다.
- ⭐ **플러그인을 켠 뒤 첫 에디터 실행은 셰이더·모듈 컴파일로 느리다.** 정상이다.
- `.uproject` / `Build.cs` 변경은 `CLAUDE.md` §9의 **보고 대상**이다 — 이미 보고했다.

## 되돌리려면

GAS를 쓰지 않기로 되돌릴 경우, 위 두 파일에서 항목을 빼고 `CLAUDE.md` §8을 복원한다.
**단 코드가 GAS에 의존하기 시작한 뒤에는 되돌리기 비용이 급격히 커진다.**
