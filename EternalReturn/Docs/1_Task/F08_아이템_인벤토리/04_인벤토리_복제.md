## ⚠ 역기획서가 결정하지 않은 것

> *"인벤토리를 어디에 둘 것인가 — **이 문서는 결정하지 않는다**"* — §7.5

⭐ **이걸 먼저 정해야 한다.** `Docs/4_Argument/` 문서 대상이다 (`CLAUDE.md` §1.2).

| | 후보 | |
|---|---|---|
| A | **PlayerState** | ⭐ 부활해도 남는다. ASC 와 같은 자리 |
| B | **Pawn** | 사망 시 드롭과 자연스럽게 엮인다. ⚠ 부활 시 사라진다 |
| C | **PlayerController** | 관전 중에도 남는다. ⚠ 서버 전용 액터라 다른 클라가 못 본다 |

⚠ **F02 에서 ASC 를 PlayerState 에 둔 이유**(*"부활이 코어 루프"*)가 여기도 적용될 가능성이 높다.
다만 사망 시 **드롭**(§7.1)과의 관계를 같이 봐야 한다.

## 복제

인벤토리는 **본인만** 알면 된다 — 남의 인벤토리는 안 보인다.
→ `COND_OwnerOnly` 를 검토한다. ⚠ 다만 **장착 중인 무기는 남에게도 보여야** 한다 (메시 표시).

⭐ **"보이는 장비"와 "인벤토리 내용"의 복제 조건이 다르다.** 나누어 설계한다.

## 검증 — `Play As Client, Number of Players: 2`

- **빌드 통과** (Editor + Server)
- 아이템을 넣고 뺄 수 있다
- ⭐ **본인 클라에만** 인벤토리 내용이 복제된다
- ⭐ 장착한 무기는 **다른 클라에도** 보인다
- 서버 권위 — 클라가 아이템을 직접 추가할 수 없다
- 인벤토리가 가득 찼을 때 규칙대로 처리된다

## 주의점

- ⭐ 인벤토리 **소유 주체를 먼저 정한다** (Argument)
- ⚠ 남의 인벤토리를 복제하면 **정보 노출**이다
- 슬롯 수 · 스택 규칙을 하드코딩하지 않는다
