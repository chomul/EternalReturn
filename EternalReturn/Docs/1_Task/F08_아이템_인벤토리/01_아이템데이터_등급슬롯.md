## 할 일

아이템 하나를 정의하는 **데이터 구조**와 **등급 · 슬롯**을 만든다.

## ⭐ 데이터 애셋인가 데이터 테이블인가

F02 에서 스탯을 **실험체별 데이터 애셋**으로 정했다
([`../../4_Argument/4_스탯데이터_저장방식.md`](../../4_Argument/4_스탯데이터_저장방식.md)).

⚠ **아이템은 사정이 다르다.** 아이템은 수백 개고, 하나하나가 가벼우며(스탯 몇 개),
**제작 트리 탐색(F09)** 이 전체를 훑어야 한다.

| | 아이템 | 실험체 |
|---|---|---|
| 개수 | 수백 | ~80 |
| 개당 무게 | 가볍다 (스탯 + 아이콘) | ⭐ 무겁다 (메시 · 애님 · 스킬) |
| 전체 순회 | ⭐ **필요** (제작 트리) | 불필요 |

→ ⚠ **결론이 F02 와 다를 수 있다.** `Docs/4_Argument/` 문서를 먼저 쓴다 (`CLAUDE.md` §1.2).

## 등급 · 슬롯

역기획서 §1 등급 체계, §2 장비 슬롯을 그대로 옮긴다.
⚠ 등급이 **제작 트리와 스탯 배율 양쪽**에 쓰인다 — 열거형 순서를 바꾸면 둘 다 깨진다.

## 검증

- **빌드 통과** (Editor + Server)
- 아이템 하나를 정의하고 로그로 읽을 수 있다
- 등급 · 슬롯이 §1 §2 표와 일치한다
- ⭐ 아이템 개수가 늘어도 조회가 느려지지 않는다 (제작 트리가 이걸 쓴다)

## 주의점

- ⚠ **열거형 순서를 나중에 바꾸지 않는다** — 애셋에 저장된 값이 어긋난다 (`CLAUDE.md` §3)
- 아이콘 · 메시는 **소프트 참조**로 둔다 (`TSoftObjectPtr`) — 수백 개가 한꺼번에 로드되면 안 된다
- 스탯 옵션 종류는 §6.1 표를 따른다
