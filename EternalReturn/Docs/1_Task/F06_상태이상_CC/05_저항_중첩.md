> 체크리스트 [`../../2_Checklist/F06_상태이상_CC/05_저항_중첩.md`](../../2_Checklist/F06_상태이상_CC/05_저항_중첩.md)

## 할 일

**방해 저항**으로 CC 지속시간을 줄이고, **면역**으로 무시하고, 중첩 규칙을 정한다.

```
매그너스 W — 방해 저항 40% → 기절 지속시간이 60%로 감소
매그너스 R — 이동 방해 면역 → 넉백이 무시됨
```

## 어트리뷰트는 이미 있다

`CCResist` / `SlowResist` 가 F02 에 있고, F02-03 이 상한 0.8 로 자른다.

## ⭐ 저항을 어디서 적용하나

CC GE 의 **Duration 을 계산할 때** 대상의 `CCResist` 를 읽어야 한다.

| | 방법 | |
|---|---|---|
| A | `UGameplayModMagnitudeCalculation` 으로 Duration 계산 | GAS 정석. Target 어트리뷰트 캡처 가능 |
| B | 어빌리티가 미리 계산해 SetByCaller 로 넘김 | ⚠ 어빌리티가 대상 저항을 알아야 한다 |

⚠ **A 가 유력하다** (F03 에서 어빌리티가 대상 스탯을 모르게 한 것과 같은 이유).
방안이 2개이므로 `Docs/4_Argument/` 대상이다.

## 면역 — `State.CCImmune`

면역은 저항과 다르다. **지속시간을 줄이는 게 아니라 아예 안 걸린다.**
GE 의 `ApplicationTagRequirements` 로 막는다 — 대상이 그 태그를 가지면 적용되지 않는다.

## 검증 — `Play As Client, Number of Players: 2`

- **빌드 통과** (Editor + Server)
- ⭐ 저항 40% 에서 기절 지속시간이 **60%** 가 된다
- ⭐ `State.CCImmune` 중 넉백이 **무시된다**
- 저항 상한(0.8)이 걸린다
- 같은 CC 가 겹칠 때 규칙대로 처리된다 (갱신 / 중첩 / 무시)

## 주의점

- ⭐ 저항 상한을 여기서 또 자르지 않는다 — F02-03 소관
- ⚠ `SlowResist` 와 `CCResist` 는 **다른 스탯**이다. 둔화는 전자, 기절은 후자
- 중첩 규칙(`StackingType`)을 정하고 주석에 남긴다
