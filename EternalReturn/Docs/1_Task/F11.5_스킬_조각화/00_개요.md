## 목표

**새 스킬 기능 = 새 조각 클래스 파일 1개.** `UERSkillData` 와 `UERGameplayAbility` 를 건드리지 않는다. 애셋에는 그 스킬이 쓰는 조각만 보이고, 조각 순서는 배열 순서다.
**동작은 바뀌지 않는다** — F11-05 8종 · F07 Q/P/R 의 검증 로그가 이관 전후 같아야 한다 (03).

## 1. 구조

```
UERSkillFragment (UObject · DefaultToInstanced · EditInlineNew · Abstract)          GAS/Fragment/ERSkillFragment.h
 ├ CanExecute(Ctx, OutReason) : bool     커밋 **전** — 실패면 발동 자체를 없던 일로 (단검 블링크 "리캐스트 보류")
 ├ OnExecute(Ctx)                        [서버] 판정 전 — 자기 이동 · 자기 버프 · 장판 스폰(판정 대체) · 모드 진입
 ├ OnTargetsResolved(Ctx, Targets)       [서버] 판정 뒤 — 피해 · 적중 효과 · 넉백 · 2차 판정 예약 · 리캐스트 창
 ├ OnLocalExecute(Ctx)                   [소유 클라 · 리슨 호스트] 연출성 — 모드 카메라
 └ OnEnd(Ctx, bCancelled)                [서버] EndAbility — 모드 정리 · 쿨 반환

FERSkillContext (구조체 · 어빌리티가 만들어 넘김)                                        GAS/Fragment/ERSkillContext.h
   Ability* · ASC* · Avatar* · PlayerState* · Skill(실행 데이터) · Level · AimPoint · AimDirection · AimActor
   · bActivatedByRecast · bHitAnything(피해 조각이 세팅) · bSkipTargeting(장판이 세팅) · DamageScale(장판 감쇠)
   · ExecuteOther(const UERSkillData*, Scale)  — 다른 데이터로 파이프라인 재진입 (2차 판정 · 리캐스트 · 벽 충돌) → ExecOverride 제거

UERSkillData (핵심만 평면)
   SlotTag · AbilityClass · Cooldowns · bIgnoreCooldownReduction · CooldownTagOverride · CostType · Costs · Shape
   · CastTime · RecoveryTime · bMoveCancelsCast · InitialLevel · MaxLevel · bUsesSkillPoints · MinCharacterLevel
   + UPROPERTY(Instanced) TArray<TObjectPtr<UERSkillFragment>> Fragments
   + template<T> const T* FindFragment() const

UERGameplayAbility (파이프라인만)
   ActivateAbility → ResolveAim → 리캐스트 판정 → [조각.CanExecute] → 선딜 → Commit → 리캐스트 소비
   → [조각.OnExecute] → (bSkipTargeting 아니면) ERTargeting::Query → [조각.OnTargetsResolved] → K2 훅 · [조각.OnLocalExecute]
   → 후딜 / EndAbility → [조각.OnEnd]
```

조각 12개 (`GAS/Fragment/ERSkillFragment_*.h/.cpp` — 지금 필드에서 1:1로 옮김):

| 조각 | 옮겨 오는 필드 | 훅 | 지금 코드 |
|---|---|---|---|
| `_Damage` | DamageType · Base · APRatio · BonusAPRatio · SkillAmpRatio · MaxHPRatio · FixedCurHPRatio · TargetLostHPScaleMax · HealFromDamageRatio | OnTargetsResolved (Ctx.bHitAnything 세팅) | `ApplySkillDamage` → `ERSkillDamage::Apply(Ctx, Frag, Targets, Scale)` 라이브러리 |
| `_OnHitEffect` | OnHitEffect · Duration · SlowPercent · Magnitude | OnTargetsResolved | `ApplySkillDamage` 앞부분 (ERCC::ApplyCC) |
| `_SelfMove` | SelfMove · Distance · Duration | CanExecute(블링크 전제) · OnExecute | `ApplySelfMove` · `GetBlinkFailReason` |
| `_SelfBuff` | SelfEffects[] | OnExecute | `ApplySelfEffects` |
| `_Knockback` | Distance · Duration · WallImpactSkill | OnTargetsResolved | `ApplyKnockback` (벽 충돌은 `Ctx.ExecuteOther(Wall)`) |
| `_FollowUp` | FollowUpSkill · Delay | OnTargetsResolved (타이머 → ExecuteOther) | `ExecuteFollowUp` (E19 람다 그대로) |
| `_Recast` | bRecastOnHit · bRecastAlways · Window · RecastSkill | OnTargetsResolved (창 열기) | `GrantOnHitStates` 리캐스트 부분 · ActivateAbility 의 RecastSkill 분기는 어빌리티가 `FindFragment<_Recast>()` 로 |
| `_NextAttackBuff` | bGrantsNextAttackBuff · Duration | OnTargetsResolved | `GrantOnHitStates` 강화 부분 · 평타 소비는 `UERBasicAttackAbility` 그대로 (`FindFragment<_Damage>` 로 강화 피해) |
| `_Area` | AreaDuration · Radius · TickInterval · DamageDecay | OnExecute (스폰 · bSkipTargeting) | `ExecuteSkill` 장판 분기 · `AERSkillAreaActor` 는 `Ctx.ExecuteOther(Skill, Scale)` 대신 `ERSkillDamage::Apply` |
| `_Mode` | FERSkillMode 전부 | OnExecute(진입 · 활성 유지 요청) · OnLocalExecute(카메라) · OnEnd(정리 · 반환) | `EnterMode/CleanupMode/OnAnyAbilityEnded` · PS 의 `SetModeAttack/SetModeAimLimit` 는 그대로 |
| `_ArmorBreak`? | — 없음 | — | 망치는 `_OnHitEffect(GE_ArmorBreak, Magnitude)` 로 충분 — 조각 없음 |
| (형상 `Shape`) | 그대로 핵심 | — | 조준 보조 · 모드 조준 제한은 `ResolveAim` 그대로 |

**어빌리티가 계속 드는 것**: 조준(ResolveAim · 사거리 클램프 · 모드 ±각) · 선딜/후딜 · 커밋(쿨 · 코스트) · 리캐스트 **소비**(CheckCooldown 우회) · 판정 · 몸 회전 · 연출 훅. 조각이 필요한 어빌리티 상태는 Ctx 로만 본다.

## 2. 네트워크

바뀌지 않는다. 조각 훅은 **서버**에서만 돈다 (`OnLocalExecute` 만 소유 클라). 복제되는 것은 지금과 같이 ASC 스펙 · GE · 어트리뷰트 · 이동뿐. 조각 객체 자체는 애셋의 서브오브젝트라 복제 대상이 아니다 (클라도 같은 애셋을 가진다).

## 3. 세부 — 3단계 · 빌드 3번

| 단계 | 내용 | 검증 |
|---|---|---|
| **01 조각 기반** | `UERSkillFragment` · `FERSkillContext` · `Fragments` 배열 · 어빌리티 파이프라인이 조각 훅을 부름. **옛 필드와 공존** — 조각이 없으면 옛 경로 그대로 | 빌드 통과 · 기존 애셋 그대로 PIE 1회 (동작 변화 0) |
| **02 조각 12 + 이관 명령** | 조각 클래스 12 · `ERSkillDamage` 라이브러리 · `ER.Skill.MigrateFragments` (WITH_EDITOR, 옛 필드 → 조각 → 옛 필드 초기화 → 저장 · 로그) | 빌드 통과 · 사용자가 명령 실행 → `[이관]` 로그 18줄 대조 · PIE 8종 + Q/P/R **로그 동일** (03 표) |
| **03 옛 필드 · 명령 삭제** | `UERSkillData` 에서 옛 필드 ~35개 · `ApplySkillDamage` 류 · `ExecOverride` · 이관 명령 삭제 | 빌드 통과 · 애셋 로드 경고 0 · PIE 재확인 |

⚠ 순서 규칙(문서화): 같은 훅 안에서는 **배열 순서**. 기본 권장: `_SelfMove → _SelfBuff → _Area/_Mode` (OnExecute) · `_Damage → _OnHitEffect → _Knockback → _FollowUp → _Recast/_NextAttackBuff` (OnTargetsResolved). `_Recast(bRecastOnHit)` 가 `_Damage` 보다 앞이면 `Validate` 가 Warning (bHitAnything 을 못 본다).

## 4. 검증 — 동작 불변

`Docs/3_EditorTasks/F11_무기.md` 의 8종 명령을 그대로 다시 돌려 **아래 로그 줄이 이관 전과 같은지** 본다 (03 체크리스트에 표):
망치 `Defense 45.00` · 도끼 `회복 49.7` · 권총 `2회 · 1.0초 뒤` → `간격 0.59초` · 방망이 `넉백 3.0m` → `벽 충돌` · 암기 `7번째 (x0.03)` · 투척 `2차 판정 … 기본 60` · 단검 `보류 → 블링크 150cm → +8.4 · +49.7` · 저격 `1/3 → Deadeye → 3/3 · 쿨 반환` · Q 리캐스트 · 평타 강화.

## ⚠ 이 기능이 하지 않는 것

- 새 스킬 기능 추가 없음 (진짜 투사체 · 시야 · 은신은 그대로 미구현)
- BP 조각 없음 — 조각은 C++ 만 (§7). `EditInlineNew` 는 데이터 입력용
- 실험체 스킬(F12 뒤) 은 이관 뒤 새 구조로만 만든다
