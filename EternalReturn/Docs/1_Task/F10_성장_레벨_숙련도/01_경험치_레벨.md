## 할 일

**서버가 경험치를 쌓고, 필요 경험치 테이블에 따라 레벨을 올린다.** 레벨은 전원에게, 경험치는 본인에게만 복제한다.

## ⭐ 어디에 두나 — PlayerState

부활이 코어 루프라 폰이 죽어도 남아야 한다 (Argument 3 · 21 과 같은 이유). 스킬 포인트(`AERPlayerState.SkillPoints`)가 이미 거기 있다.
→ **`UERGrowthComponent`** 를 PlayerState 에 붙인다 (인벤토리와 같은 자리). 레벨 · 경험치 · 숙련도가 한 컴포넌트에.

⚠ 레벨을 **어트리뷰트**로 둘지는 [`Docs/4_Argument/`](../../4_Argument/) 대상이다 — 어트리뷰트면 MMC 가 캡처할 수 있지만(레벨 비례 계산), 지금 그런 계산이 없다.
방안이 둘이므로 구현 시작 전에 비교 문서를 쓴다 (`CLAUDE.md` §1.2).

## 필요 경험치 — 테이블, 거의 전부 `[자체]`

```
FLevelExpRow : FTableRowBase   // RowName = "Lv1" … "Lv19"  (Lv N → N+1 에 필요한 경험치)
  RequiredExp        : int32   // 800 [확인] · 2500 (Lv5) [확인] · 나머지 [자체]
  SkillPointGranted  : int32   // 기본 1. §2.1 "2포인트 남는다" 가 여기 예외로 들어갈 수 있다
```

⚠ **출처 태그를 행에 남긴다** (`[확인]` / `[역산]` / `[자체]`) — 역기획서 §11 권고. 나중에 원작 값을 구했을 때 갈아끼울 행을 알아야 한다.
⚠ 최대 레벨 20 을 하드코딩하지 않는다 — 테이블 행 수 + 1 이 최대 레벨이다.

## 경험치 획득원 (§2.3) — 값은 전부 (미확인)

| 출처 | 이번 단계 |
|---|---|
| 야생동물 처치 | F12 가 값을 준다. 여기서는 **입구 함수** `AddExp(Amount, Source)` 만 |
| 실험체 처치 · 관여 | F02-04 `OnOutOfHealth(Instigator)` 에서 처치자에게. 관여(어시스트) 분배는 (미확인) → 처치자만 `[자체]` |
| 시간 경과 | 존재 자체 (미확인) → 만들지 않는다 |

## 검증 — `Play As Listen Server, 2명`

- **빌드 통과** (Editor + Server)
- ⭐ 서버 `ER.Growth.AddExp 800` → Lv.2, 경험치 0 · 클라 창에서 상대 레벨이 보인다 (전원 복제)
- ⭐ 클라 창에서 **남의 경험치는 안 보인다** (`COND_OwnerOnly`)
- 한 번에 큰 경험치(`AddExp 5000`) → 여러 레벨을 **연속으로** 오르고 남은 경험치가 정확하다
- 최대 레벨에서 경험치가 더 쌓이지 않는다 (또는 쌓이되 레벨은 안 오른다 — 어느 쪽인지 `[자체]` 로 정하고 기록)
- 클라가 `AddExp` 를 치면 거부된다

## 주의점

- ⭐ 레벨업 판정은 **서버 전용**. 클라는 `OnRep_Level` 로 UI 만 (§7)
- ⚠ `Replicated` 를 추가하면 `GetLifetimeReplicatedProps` 등록 — 빠뜨리면 조용히 안 온다
- ⚠ 레벨업 한 번에 여러 레벨이 오를 수 있다 — `while` 로 처리하고 각 레벨마다 02 · 03 의 훅을 순서대로 부른다
- 부활 시 레벨 · 경험치는 **유지** (인벤토리와 같은 결정, F14 에서 확인)
