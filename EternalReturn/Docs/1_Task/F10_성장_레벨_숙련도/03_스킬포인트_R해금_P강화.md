## 할 일

F07-03 이 비워 둔 세 자리를 채운다. **배분 · 검증은 이미 있다** (`AERPlayerState::ServerLevelUpSkill` → `ERSkill::LevelUpSkill`). 여기서는 **지급과 해금 조건**만.

| 자리 | 지금 | F10-03 |
|---|---|---|
| 포인트 지급 | 디버그 `ER.Skill.Points` | 레벨업 훅 → `AddSkillPoints(FLevelExpRow.SkillPointGranted)`. Lv.1 시작 포인트 1 도 여기 |
| R 해금 레벨 | 없음 — 1레벨에도 R 을 찍을 수 있다 | `UERSkillData.MinCharacterLevel : TArray<int32>` (스킬 레벨별 요구 실험체 레벨). **원작 (미확인)** — 인터넷 조사 실패(F07-03 기록) → `[자체]` 로 LoL 관례(6/11/16)를 출발값, 기록 |
| P 자동 강화 | 없음 — P 는 Lv.1 고정 | `UERSkillData.AutoLevelAtCharacterLevels : TArray<int32>` — 실험체 레벨이 그 값에 닿으면 서버가 스펙 레벨 +1. **강화 시점 (미확인)** (스킬 역기획서 §2.3) → `[자체]` |

⭐ 세 필드 모두 **스킬 데이터**에 붙는다 — F07-03 의 사용자 결정("레벨 규칙은 슬롯이 아니라 스킬이 든다")의 연장. 코드에 "R 이면 6레벨" 분기가 없다.

## ⚠ 2포인트 문제 (§2.1)

Lv.20 까지 20포인트 · 최대 소비 18. 원작 규칙 (미확인). 프레임워크는 **"포인트가 남았는데 전부 만렙"** 을 정상으로 받는다 — F07-03 에서 이미 assert 없이 만들었다. 여기서 `SkillPointGranted` 를 특정 레벨에 0 으로 두는 것으로 조정 가능하게만 해 둔다.

## 검증 — `Play As Listen Server, 2명`

- **빌드 통과**
- ⭐ `AddExp` 로 Lv.2 → 포인트 +1 (로그 `포인트 +1 -> N`) · 클라 `ER.Skill.Levels` 에 반영
- ⭐ `MinCharacterLevel = [6, 11, 16]` 인 R: Lv.5 에서 `LevelUp R` → 거부 "실험체 레벨 6 필요" · Lv.6 → 성공 · Lv.6 에서 두 번째 → 거부(11 필요)
- ⭐ `AutoLevelAtCharacterLevels = [1, 7, 13]` 인 P: Lv.7 도달 순간 P 가 Lv.2 (포인트 안 씀, 로그)
- 클라가 조건을 우회해 요청해도 서버가 거부

## 주의점

- ⭐ 지급 · 해금 판정은 **서버** — `ERSkill::LevelUpSkill` 에 실험체 레벨 인자가 하나 늘어난다
- ⚠ 세 필드 값은 전부 `[자체]` 로 표기하고, 원작 값이 확인되면 애셋만 바꾼다
