## 할 일 — 전부 **자체 결정값** (원작 미확인)

### ① 쿨다운 정책 — 역기획서 제안 **B(무기별 개별 보존)** + 스왑 락

| 정책 | 우리 구조에서 |
|---|---|
| A 리셋 | ❌ 익스플로잇 |
| **B 무기별 보존** | ⚠ 지금 쿨다운 태그는 **슬롯 단위**(`Cooldown.Slot.D`, F07-02) — 무기를 바꾸면 이전 D 의 쿨다운 GE 가 ASC 에 남아 **새 D 도 막는다** = 사실상 C |
| C 슬롯 승계 | 지금 구조의 기본 동작 |

→ B 를 하려면 "계열별 쿨다운 태그" 또는 "교체 시 남은 시간을 계열별로 저장했다가 복귀 시 재적용" 이 필요하다. **방안이 둘이므로 `Docs/4_Argument/`** — C(현재 동작) 를 그대로 둘지도 포함해 비교. 역기획서 제안은 B 지만 원작 (미확인)이므로 **C 유지가 가장 싸고 익스플로잇도 없다**는 점을 같이 놓는다.

### ② 스왑 락 — 교체 직후 D 를 N초 못 쓴다
`UERWeaponSettings.SwapLockSeconds` `[자체]`. 구현은 F07-04 페이즈 GE 와 같은 꼴 — Infinite 가 아니라 HasDuration 으로 `State.Block.Skill` 대신 **D 슬롯만 막는 태그** 하나 (`State.WeaponSwapLock` → D 어빌리티 `ActivationBlockedTags`).

### ③ 시전 중 교체 거부 (§8.3)
`Equip(Weapon)` 서버 검증에 한 줄: D 어빌리티가 **활성**이면 거부 (`IsActive`). 저격 모드 · 패링 무적이 여기에 걸린다. D 가 남긴 지속 효과(연막 · 은신)는 GE/액터 소유라 그대로 유지 — 별도 처리 없음.

## 검증 — `Play As Listen Server, 2명`

- **빌드 통과**
- ⭐ 망치 D 사용(쿨 25초) → 방망이로 교체 → D 시도 → **정책대로**(Argument 결과) · 다시 망치 → 남은 쿨 그대로
- 교체 직후 N초간 D 거부 (`State.WeaponSwapLock`) · N초 뒤 됨
- D 선딜 중 교체 요청 → 서버 거부 로그, 무기 그대로
- 연막(투척 D) 설치 후 교체 → 연막 유지

## 주의점

- ⭐ 셋 다 `[자체]`. 원작 값이 나오면 설정값 · Argument 재검토
- ⚠ 락은 D 만 막는다 — Q/W/E/R · 평타는 그대로
