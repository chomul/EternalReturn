# F02-05 — 초기값 데이터 테이블

> 기능 [F02 어트리뷰트셋](00_개요.md) · 선행 [04 체력 처리 · 사망 알림](04_체력처리_사망알림.md)
> 체크리스트 [`05_초기값_데이터테이블.md`](../../2_Checklist/F02_어트리뷰트셋/05_초기값_데이터테이블.md)

> ⚠ **저장 방식이 바뀌었다 (2026-09-07).** 데이터 테이블이 아니라 **실험체별 데이터 애셋**을 쓴다.
> 아래 본문의 `FCharStatRow` / 데이터 테이블 서술은 **전환 전 기록**이다.
> 결정과 이유: [`../../4_Argument/4_스탯데이터_저장방식.md`](../../4_Argument/4_스탯데이터_저장방식.md)
>
> 최종 형태: `FERCharStats`(구조체) → `UERCharacterData`(데이터 애셋) → Instant GE + SetByCaller
> **GE 주입 방식은 그대로다.**

## 할 일

실험체별 기본 스탯을 실험체 데이터 애셋에 두고, **초기화 GE로 적용**한다.

```cpp
USTRUCT(BlueprintType)
struct FCharStatRow : public FTableRowBase   // RowName = 실험체 이름
{
    GENERATED_BODY()
    UPROPERTY(EditDefaultsOnly) float MaxHealth   = 0.f;
    UPROPERTY(EditDefaultsOnly) float AttackPower = 0.f;
    UPROPERTY(EditDefaultsOnly) float Defense     = 0.f;
    // ... §6.1 목록
};
```

## ⭐ 왜 GE로 적용하나 — 직접 `SetHealth()` 하지 않는 이유

어트리뷰트를 코드에서 직접 세팅하면 **GAS의 계산 경로를 우회**한다.
클램프(F02-03)와 `PostGameplayEffectExecute`(F02-04)가 안 돌고, 예측·복제 타이밍이 어긋난다.

**초기화도 GE로 한다.** `Instant` GE 하나가 Base 값을 세팅한다.

두 가지 방식이 있다.

### ⭐ 조사 결과 — 엔진 내장 경로는 쓸 수 없다 (2026-09-07)

`UAttributeSet::InitFromMetaDataTable()` (`AttributeSet.h:238`) 과 행 구조체 `FAttributeMetaData`
(`BaseValue/MinValue/MaxValue`, `:268`) 가 있어 딱 맞아 보이지만, **행 이름이 고정이다.**

```cpp
// AttributeSet.cpp - InitFromMetaDataTable
FString RowNameStr = FString::Printf(TEXT("%s.%s"),
    *Property->GetOwnerVariant().GetName(), *Property->GetName());
//  -> "ERAttributeSet.MaxHealth"
```

행 이름이 **어트리뷰트 이름**이라 테이블 하나에 그 행이 딱 하나다.
**카티야용과 매그너스용을 같이 둘 수 없다.** 실험체마다 테이블을 따로 만들어야 하고,
`SetBaseValue` 를 직접 불러 **클램프도 우회**한다.

→ **Instant GE + SetByCaller 로 간다.** 실험체별 값을 테이블 하나에서 읽고, GE 경로를 타서 클램프가 걸린다.

상세: [`../../4_Argument/3_어트리뷰트셋_구조.md`](../../4_Argument/3_어트리뷰트셋_구조.md) C절

## 레벨 성장과의 관계

레벨업 시 스탯 증가는 **F10(성장)** 이 담당한다. 여기서는 **Lv.1 초기값만** 다룬다.
F10도 같은 방식(GE)으로 Base를 올린다 — 그래야 경로가 하나로 유지된다.

## 만들 파일

```

```

⚠ **GE 애셋과 데이터 테이블 애셋 생성은 `Content/` 라 직접 하지 않는다.** `Docs/3_EditorTasks/` 문서로 넘긴다 (`CLAUDE.md` §9).

## 검증

- **빌드 통과** (Editor + Server)
- 캐릭터 스폰 시 어트리뷰트가 테이블 값으로 초기화된다
- Health == MaxHealth 로 시작한다
- ⭐ 클라에서도 초기값이 보인다 (복제 확인)
- 테이블 값을 바꾸면 반영된다 (하드코딩 아님)

## 주의점

- ⭐ **초기화 시점.** ASC의 `InitAbilityActorInfo`(F00-03) 이후여야 한다. 그 전에 GE를 걸면 조용히 실패한다.
- ⭐ **서버에서만 초기화한다.** 클라는 복제로 받는다.
- ⭐ **`FCharStatRow` 필드 이름을 나중에 바꾸지 않는다** — 데이터 테이블 애셋의 값이 날아간다 (`CLAUDE.md` §3).
- Health를 MaxHealth로 채울 때 **MaxHealth가 먼저 세팅**되어야 한다. 순서가 뒤집히면 체력이 0으로 클램프된다.
- 부활 시 재초기화가 필요한지는 F14(매치 진행)와 함께 정한다.
