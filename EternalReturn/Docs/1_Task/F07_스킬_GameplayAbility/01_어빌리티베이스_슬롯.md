## 할 일

`UGameplayAbility` 파생 **베이스 하나**와 **슬롯 배선**, **스킬 데이터**를 만든다.

## 슬롯 (§1.1)

`Ability.Slot.P / Q / W / E / R / D` — 태그는 `ERGameplayTags.h` 에 **이미 있다** (F00-05).

⚠ **D 슬롯은 무기가 소유한다.** 런타임 교체는 F11 이다. 여기서는 **자리만** 만든다.

## ⭐ 어빌리티를 어떻게 부여하나

Lyra 의 `ULyraAbilitySet` 형태를 참고한다 —
데이터 애셋 하나가 **어빌리티 + GE + 어트리뷰트셋**을 묶어 부여하고, **핸들로 회수**한다
(`LyraAbilitySet.cpp:109-147`). 근거: [`../../6_Lyra참조/02_어빌리티셋_부여.md`](../../6_Lyra참조/02_어빌리티셋_부여.md)

⭐ **부여는 서버 권위**다 (`CLAUDE.md` §8).

## 스킬 데이터

```cpp
USTRUCT(BlueprintType)
struct FERSkillRow
{
    UPROPERTY(EditDefaultsOnly) FGameplayTag SlotTag;
    UPROPERTY(EditDefaultsOnly) TSubclassOf<UERGameplayAbility> AbilityClass;
    UPROPERTY(EditDefaultsOnly) float BaseDamage;
    UPROPERTY(EditDefaultsOnly) float APRatio;
    // ... F03 의 Data.Damage.* 계수들
};
```

⚠ **어디에 둘지는 Argument 대상**이다 — [`4_스탯데이터_저장방식⭐.md`](../../4_Argument/4_스탯데이터_저장방식⭐.md) 에서
스탯을 데이터 애셋으로 정한 것과 같은 논점이다. **실험체 데이터 애셋에 스킬을 넣는 게 유력**하다.

## 검증 — `Play As Client, Number of Players: 2`

- **빌드 통과** (Editor + Server)
- ⭐ 클라가 Q 를 누르면 **서버에서 어빌리티가 발동**한다
- 슬롯 태그로 어빌리티를 찾을 수 있다
- 부여가 서버에서만 일어난다
- 부여한 것을 **핸들로 회수**할 수 있다

## 주의점

- ⭐ **어빌리티 부여 · 발동은 서버 권위** (`CLAUDE.md` §8)
- ⭐ 계산식을 어빌리티에 넣지 않는다 — **계수만** F03 에 넘긴다
- ⚠ 어빌리티가 대상 스탯을 읽지 않는다 (F03 이 읽는다)
- 슬롯 태그를 문자열로 박지 않는다
