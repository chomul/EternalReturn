## 할 일

§4.1 의 실행 단계 [1]~[6] 을 구현하고, **채널링**과 **취소**를 붙인다.

## 단계별 권한 (§4.2)

⭐ **누가 무엇을 판정하는지**가 이 Task 의 핵심이다.

| 단계 | 권한 |
|---|---|
| 입력 수신 | 클라 |
| 발동 가능 검사 | ⭐ **서버** (`CanActivateAbility`) |
| 코스트 · 쿨다운 커밋 | ⭐ **서버** (`CommitAbility`) |
| 조준 데이터 전송 | 클라 → 서버 (`FGameplayAbilityTargetData`) |
| 판정 · 피해 | ⭐ **서버** |
| 연출 | 클라 (`GameplayCue`) |

## 채널링

`UAbilityTask` 로 대기한다. ⭐ **자체 타이머 상태 머신을 만들지 않는다** (`CLAUDE.md` §8).

CC 로 인한 취소는 F06-03 의 `CancelAbilitiesWithTag` 가 처리한다 —
어빌리티가 `Ability.Form.Channeled` 태그를 **갖기만** 하면 된다.

## 취소 규칙 (§5.1)

⚠ 역기획서가 **자체 결정값 — 원작 확인값 아님**이라고 명시했다.
표를 그대로 쓰되 **(미확인)** 을 주석에 남긴다.

## 검증 — `Play As Client, Number of Players: 2`

- **빌드 통과** (Editor + Server)
- ⭐ 카티야 R(0.8초) 채널링 중 기절 → **시전 취소, 쿨다운은 남음**
- 시전 상태가 클라에 복제된다 (다른 플레이어도 시전 중인 것을 본다)
- ⭐ 클라가 발동 조건을 우회해도 **서버가 거부**한다
- 이동으로 취소되는 스킬과 안 되는 스킬이 표대로다

## 주의점

- ⭐ **자체 타이머 상태 머신을 만들지 않는다** — `UAbilityTask`
- ⭐ 발동 가능 검사·커밋이 **서버**다
- ⚠ 취소 규칙이 **자체 결정값**임을 주석에 남긴다
