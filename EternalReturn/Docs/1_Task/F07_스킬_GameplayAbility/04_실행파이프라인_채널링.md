## 단계별 권한 (§4.2)

⭐ **누가 무엇을 판정하는지**가 이 Task 의 핵심이다.

| 단계 | 권한 |
|---|---|
| 입력 수신 | 클라 |
| 발동 가능 검사 | ⭐ **서버** (`CanActivateAbility`) |

| 연출 | 클라 (`GameplayCue`) |

## 채널링

`UAbilityTask` 로 대기한다. ⭐ **자체 타이머 상태 머신을 만들지 않는다** (`CLAUDE.md` §8).

~~CC 로 인한 취소는 F06-03 의 `CancelAbilitiesWithTag` 가 처리한다~~ → ⚠ **정정 (2026-09-13): GE 에 그런 기능이 없다.**
GE 는 `BlockAbilitiesWithTags` 로 **새 발동을 막을 뿐** 진행 중인 어빌리티를 끊지 않는다 (`GameplayEffect.cpp:4279`).
→ `UERGameplayAbility::BeginCast` 가 `UAbilityTask_WaitGameplayTagAdded(State.Block.Skill)` 로 **스스로** 끊는다.
`Ability.Form.Channeled` 태그는 필요 없다 — `CastTime > 0` 이면 자동. 근거 [`../../4_Argument/17_시전상태_표현과_취소경로.md`](../../4_Argument/17_시전상태_표현과_취소경로.md)

⭐ 시전·후딜 상태는 `UERSkillPhaseEffect`(HasDuration) + 동적 부여 태그 `State.Casting` / `State.Recovering` — 전원 복제.
이동 입력은 `ERPlayerController::ServerSetDestination` 이 수락한 뒤 `Event.Input.Move` 게임플레이 이벤트로 어빌리티에 전달한다.
⚠ 큐잉(§6)은 F07 어느 Task 에도 없다 — 별도 Task 로 뺀다.

## 취소 규칙 (§5.1)

⚠ 역기획서가 **자체 결정값 — 원작 확인값 아님**이라고 명시했다.
표를 그대로 쓰되 **(미확인)** 을 주석에 남긴다.

## 검증 — `Play As Client, Number of Players: 2`

- **빌드 통과** (Editor + Server)
- ⭐ 카티야 R(0.8초) 채널링 중 기절 → **시전 취소, 쿨다운은 남음**
- 시전 상태가 클라에 복제된다 (다른 플레이어도 시전 중인 것을 본다)
- ⭐ 클라가 발동 조건을 우회해도 **서버가 거부**한다
- 이동으로 취소되는 스킬과 안 되는 스킬이 표대로다

## 주의점

- ⭐ **자체 타이머 상태 머신을 만들지 않는다** — `UAbilityTask`
- ⭐ 발동 가능 검사·커밋이 **서버**다
- ⚠ 취소 규칙이 **자체 결정값**임을 주석에 남긴다
