> 기능 [F03 데미지 ExecutionCalculation](00_개요.md) · 선행 [04 치명타 · 채널 분기](04_치명타_채널분기.md)
> 체크리스트 [`05_흡혈.md`](../../2_Checklist/F03_데미지_ExecutionCalc/05_흡혈.md)

## 할 일

확정된 피해량으로 공격자를 회복시킨다. 치유 감소 규칙 ([스탯 문서 §7 7순위](../../0_GameDesign/Systems/스탯_데미지공식_역기획서.md)):

| 조건 | 치유 감소 |
|---|---|
| 광역(AoE) 스킬 | **50%** |
| 야생동물 대상 | **60%** |

## ⭐ 어디에 넣을 것인가 — GAS에서는 자체 구현과 답이 다르다

자체 구현 계획에서는 *"`CalculateDamage()` 밖의 별도 함수"* 였다. 이유는 **회복 대상(공격자)을 알아야 해서 액터를 받게 되고, 함수의 순수성이 깨지기 때문**이었다.

**GAS에서는 그 문제가 없다.** Execution은 이미 Source(공격자)와 Target(피격자)을 **둘 다 알고 있다.**
`OutExecutionOutput` 에 Source 어트리뷰트 수정자를 추가하면 된다.

```cpp
// 같은 Execution 안에서 Source 의 Health 를 올린다
OutExecutionOutput.AddOutputModifier(FGameplayModifierEvaluatedData(
    FERDamageStatics::Get().IncomingHealProperty, EGameplayModOp::Additive, HealAmount));
```

> ⚠ 단 **Execution의 출력이 Target에 적용되는 것이 기본**이다. Source를 회복시키려면
> **별도 GE를 Source에 적용**하거나 Meta 어트리뷰트를 하나 더 두는 방식이 필요하다.
> 어느 쪽인지 **구현하면서 확인하고 결정을 주석에 남긴다** — 현재 **(미확인)**.

## 치유 감소 조건을 어떻게 아는가

| 조건 | GAS에서 |
|---|---|
| 광역인가 | ⭐ **스킬이 GE Spec에 태그로 붙인다** (`Damage.Shape.AoE`) — 판정 형상을 Execution이 추측하지 않는다 |
| 야생동물인가 | ⭐ **Target의 태그로 판별** (`Actor.Type.Wildlife`) — `Cast<>` 로 클래스를 검사하지 않는다 |

**태그로 판별하는 이유는 이전 계획과 같다.** Execution이 `Cast<ABossActor>` 를 하면 F03이 F12에 의존한다.
태그면 야생동물이 나중에 생겨도 Execution을 안 고친다.

## 검증

| 입력 | 기대 |
|---|---|
| 피해 100, 흡혈 20%, 단일 대상, 캐릭터 | **20 회복** |
| ⭐ 피해 100, 흡혈 20%, **AoE 태그** | **10 회복** |
| 피해 100, 흡혈 20%, **야생동물 태그** | **8 회복** |
| AoE + 야생동물 동시 | **8 회복** — 더 높은 60% 하나만 적용 |
| 피해 0 | 0 회복 |

- **빌드 통과** (Editor + Server)
- ⭐ 회복이 **공격자에게** 간다 (피격자 아님)
- 최대 체력을 넘지 않는다 (F02-03 클램프가 처리)

## 주의점

- ⭐ **최대 체력 클램프를 여기서 또 하지 않는다.** F02-03의 `PreAttributeChange` 가 이미 한다.
- ⭐ **회복 대상이 Source인지 반드시 확인한다.** Target에 가면 때린 상대를 회복시킨다.
- 치유 감소는 **가장 높은 것 하나만** 적용한다 (겹쳐도 곱하지 않는다 — 2026-09-08 결정).
- 흡혈이 **고정 피해에도 적용되는지** **(미확인)** — 자체 결정 후 주석.
- 연출(회복 이펙트)은 `GameplayCue` 다. Execution 안에서 재생하지 않는다.
