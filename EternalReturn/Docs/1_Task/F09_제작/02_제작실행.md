## 할 일

클라가 "C 를 만들겠다" 고 요청하면 **서버가** 재료 2개를 인벤토리(가방 + **장착 중**)에서 확인 · 소비하고 C 를 넣는다.

## ⭐ 서버 권위 — F08 과 같은 자리

`UERInventoryComponent::ServerCraft(FName ResultId)` `WithValidation`:
1. `ResultId` 행이 있고 재료 2개가 있다 (01 인덱스)
2. 인벤토리에 A · B 가 **각 1개 이상** (같은 재료 2개면 2개) — ⭐ **장착 중인 무기도 재료다** (원작: 망치를 든 채로 사슴 망치를 만든다 — 장착 무기가 소비되고 결과가 **바로 장착**되는가? (미확인) → `[자체]`: 장착 중 재료를 쓰면 결과가 장비면 그 슬롯에 장착, 아니면 가방)
3. 결과가 들어갈 자리 — 재료 2개가 빠지면 최소 1칸은 빈다. 스택은 `HasSpaceFor`
4. 소비 → 추가 → **F10-04 에 제작 경험치** (`OnItemCrafted(Grade, bFirstTime)`: 100 / 200 / 350 / 550 / 800, 최초 +25%). F10 이 없으면 델리게이트만

⚠ 실패는 **아무것도 바꾸지 않는다** — 재료를 빼고 나서 결과가 안 들어가는 상황이 없어야 한다 (검사를 전부 먼저).

## 자동 제작 · 연쇄 제작

원작은 "제작 버튼" 과 재료가 모이면 알려 주는 UI 가 있다. **연쇄**(잎 재료만 있으면 중간 단계를 자동으로 여러 번 제작) 여부 (미확인).
이 단계는 **한 번에 한 조합**만. 연쇄는 01 의 트리로 UI/F17 이 여러 번 요청하면 된다 — 서버 API 는 그대로.

## 검증 — `Play As Listen Server, 2명`

- **빌드 통과**
- ⭐ 클라 가방에 `망치 + 고무` → `ER.Craft.Make 사슴망치` → 서버 로그 `제작: 망치 + 고무 -> 사슴 망치` · 가방에 재료 사라지고 결과 등장 (복제)
- ⭐ 재료 하나 없이 요청 → 서버 거부, 가방 변화 없음
- 장착 중인 망치 + 가방의 고무 → 사슴 망치가 **장착 슬롯**에 (자체 결정값대로) · 스탯이 망치분 → 사슴 망치분으로 바뀐다
- 가방 10/10 인데 결과가 스택 불가 → 거부 (재료 2개가 빠져 1칸 비므로 실제로는 거의 안 일어남 — 재료 하나가 장착 중이고 가방이 가득일 때만)
- 클라가 인덱스를 우회해 없는 조합을 보내면 거부
- 제작 경험치 델리게이트 로그 (등급별 값)

## 주의점

- ⭐ 검사 전부 → 그 다음 변경. 부분 실패 없음
- ⚠ 장착 중 재료 소비 규칙은 `[자체]` — 원작 확인되면 한 곳만 바꾼다
- ⚠ 낙관적 UI 금지 (F08-05 와 같음) — 복제된 결과로만
