# F09-03 — 재료 획득 — 채집 · 상자

> 기능 [F09](00_개요.md) · 근거 [`장비_아이템_역기획서.md`](../../0_GameDesign/Systems/장비_아이템_역기획서.md) §4 · §4.1 · 우선순위 4
> 체크리스트 [`../../2_Checklist/F09_제작/03_재료획득_채집상자.md`](../../2_Checklist/F09_제작/03_재료획득_채집상자.md)

## 할 일

맵에 놓인 **상자 · 채집물**에서 재료를 얻는다. 습득은 F08-05 의 `ServerPickup` 을 그대로 쓴다 — 상자는 **"미리 채워진 시체"** 다.

## ⭐ 재사용 — 새 습득 경로를 만들지 않는다

| | F08-05 시체 | 상자 | 채집물 |
|---|---|---|---|
| 액터 | `AERItemDropActor` | **같은 클래스** (내용을 루트 테이블로 채움) | 같은 클래스 + **재생성**(채집 후 N초 뒤 다시) |
| 내용 | 사망자 인벤토리 복사 | 루트 테이블에서 뽑음 (열 때 · 스폰 때 — (미확인) → `[자체]` 스폰 때) | 고정 1종 (나뭇가지 · 돌멩이 · 꽃) |
| 습득 | `ServerPickup` (거리 · 경쟁 서버 판정) | 동일 | 동일 |
| 비면 | Destroy | Destroy (또는 빈 상자 유지 (미확인)) | **Destroy 안 함**, 타이머 후 재충전 |

→ `AERItemDropActor` 에 "내용을 루트 테이블로 채우는 초기화" 와 "재충전" 만 붙는다. 드롭 · 상자 · 채집이 **한 액터 클래스 · 한 습득 RPC**.

## 루트 테이블

```
FERLootRow : FTableRowBase        // RowName = 상자/채집물 종류 ("Box_Pond", "Gather_Branch" …). 지역별 종류 차이는 행이 다른 것
  Entries : TArray<FERLootEntry { FName ItemId; int32 Weight; int32 MinCount; int32 MaxCount; }>
  RollCount : int32               // 상자 하나에서 몇 종 뽑나 (미확인 → [자체])
  RespawnSeconds : float          // 채집물만. 0 = 재충전 없음 (상자)
```

- 꽃은 **연못 · 개울 · 고급주택가 · 절 · 묘지 · 숲**에만 (§4.1) — 행 이름과 **F13 배치**로 표현. 코드에 지역 분기 없음
- 확률 · 수량 전부 (미확인) → `[자체]` 표기. F12 야생동물 드랍(가죽 확정 · 깃털 확률)이 같은 행 형식을 쓴다

## ⚠ 파밍 위치 데이터 = F17 오버레이의 원천

"어느 재료가 어느 지역에서 나오나" 는 **루트 테이블 행 ↔ F13 지역 배치**에서 역산된다. 역기획서가 "3순위와 세트" 라고 한 오버레이의 데이터는 여기서 나오고, 그림은 F17.

## 검증 — `Play As Listen Server, 2명`

- **빌드 통과**
- 맵에 상자 액터를 놓고 루트 행 지정 → PIE 시작 시 내용이 채워진다 (`ER.Item.Drops` 에 보임) · 클라 `ER.Item.Pickup` 으로 줍는다 (F08-05 경로)
- ⭐ 두 명이 같은 상자 칸을 노리면 한 명만 (F08-05 검증 재확인)
- 채집물: 줍고 나서 N초 뒤 다시 채워진다 · 그 사이엔 비어 있다
- 루트 테이블 가중치가 0 인 항목은 안 나온다 · `RollCount` 만큼만
- 없는 아이템 ID 를 루트에 넣으면 에러 로그

## 주의점

- ⭐ 습득 RPC 를 새로 만들지 않는다 — `ServerPickup`
- ⚠ 확률 · 수량 · 재충전 시간은 전부 `[자체]`
- ⚠ 지역 분기를 코드에 넣지 않는다 — 배치(F13)와 행 이름
