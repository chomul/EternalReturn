## 할 일

우클릭한 지점으로 캐릭터를 이동시킨다.

## ⭐⭐ 이 문서 최대의 논점 — 권위 모델

역기획서 §3.3 의 결론:

> **"목적지는 서버 권위, 경로는 양쪽 계산, 이동은 CMC 예측"**

| 무엇 | 어디서 |
|---|---|
| 클릭 지점 → 목적지 확정 | ⭐ **서버** (`Server` RPC + `WithValidation`) |
| 목적지 → 경로 계산 | 서버·클라 **각자** (`UNavigationSystemV1`) |
| 실제 이동 | `CharacterMovementComponent` 의 **기존 예측** 그대로 |

⭐ **CMC 의 이동 예측을 건드리지 않는다.** 언리얼이 이미 검증된 예측·보정을 갖고 있고,
그걸 대체하면 순간이동·고무줄이 생긴다.

## ⚠ 하지 말아야 할 것 (§3.4)

- ❌ **매 프레임 목적지를 RPC 로 보내기** — 대역폭이 터진다
- ❌ **클라가 계산한 위치를 서버에 통보** — 텔레포트 치트가 된다
- ❌ **CMC 를 끄고 직접 보간** — 예측·보정을 전부 다시 만들게 된다

## 엔진이 이미 주는 것

> *"`SimpleMoveToLocation` 은 `AIController` 를 요구하지 않는다."* — §2.1

`UAIBlueprintHelperLibrary::SimpleMoveToLocation` 으로 시작한다.
**직접 경로 추적을 만들지 않는다** (`CLAUDE.md` §1).

## 만들 파일

```
Source/EternalReturn/Core/ERPlayerController.h/.cpp
```

## 검증 — `Play As Client, Number of Players: 2`

- **빌드 통과** (Editor + Server)
- 우클릭한 지점으로 이동한다
- ⭐ **클라에서 클릭해도 서버가 목적지를 확정**한다 (서버 로그로 확인)
- ⭐ 다른 클라 화면에서도 **같은 위치로** 이동한다
- 이동 중 다시 클릭하면 **새 목적지로 바뀐다**
- 갈 수 없는 곳(네비 밖)을 클릭하면 **아무 일도 안 일어난다** (크래시 아님)

## 주의점

- ⭐ **`Server` RPC 에 `WithValidation` 을 붙인다.** 목적지가 터무니없으면 거부한다
- ⚠ 네비메시가 없는 레벨에서는 이동이 안 된다 — EditorTasks 에 네비 빌드를 넣는다
- 클릭 판정 트레이스 채널은 `SkillTarget`(F04) 과 **다른 것**을 쓴다
- `MoveSpeed` 어트리뷰트(F02)를 CMC 에 반영해야 한다 — **연결 지점을 주석에 남긴다**

## 미확인

| 항목 | 상태 |
|---|---|
| 이동 입력이 우클릭인지 | **(미확인)** — §1.2 는 〔제안〕 |
| `MoveSpeed`(m/s) → CMC(cm/s) 환산 위치 | ✅ 확정 — `AERCharacterBase::ApplyMoveSpeed` |
| ⭐ 서버 보정 뒤 경로 추종이 유지되나 | **(미확인)** — 고핑 테스트 필요 (EditorTasks 2-7) |

## ⏸ 등록된 과제 — 네비메시 이탈 감지 (방안 D)

> 결정 [`../../4_Argument/11_클릭이동_서버검증_수준.md`](../../4_Argument/11_클릭이동_서버검증_수준.md) · **F13 이후**

### 문제

⚠⚠ **CMC 는 네비메시를 모른다. 콜리전만 본다.**

→ **콜리전은 있는데 네비메시가 없는 곳**(맵 경계 경사면, 의도적으로 네비를 뺀 지역)으로
클라가 걸어가면 **서버도 그대로 재생한다.**

`ProjectPointToNavigation` 은 **클릭 지점만** 검사한다. **이동 경로 중간은 아무도 안 본다.**

⭐ 속도 핵 · 텔레포트 · 벽 통과는 CMC 가 이미 막는다. **이것만 안 막힌다.**

### 할 일 (F13 에서 네비 설정을 확정한 뒤)

- [ ] 서버가 주기적으로(예: 1초) 폰 위치를 `ProjectPointToNavigation` 으로 검사
- [ ] N회 연속 실패 → ⭐ **먼저 로그·텔레메트리만.** 되돌리기는 그 다음이다
- [ ] 24명 규모에서 쿼리 비용 **측정**
- [ ] 오탐률 확인 후에 되돌리기 도입 여부 결정
- [ ] 되돌릴 위치로 `AERPlayerController::ServerDestination` 또는 마지막 정상 위치를 쓴다

### ⚠ 왜 지금 안 하나

**오탐의 원인이 네비메시 설정에 있다.** `ER_Level` 에서 네비를 확정하기 전에 켜면
**결백한 플레이어를 잡는다.** `AgentMaxStepHeight` 35 vs 45 불일치가 정확히 그런 사례였다
([F13 개요](../F13_맵_지역/00_개요.md)).

⭐ **전제는 이미 만들어 뒀다** — `ServerDestination` 에 서버가 승인한 목적지가 남는다.
