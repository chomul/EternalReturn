# F01-03 — 팀 배정 로직

> 기능 [F01 코어 골격 · 팀 ID](00_개요.md) · 선행 [02 팀 ID 복제](02_팀ID_복제.md)
> 체크리스트 [`03_팀배정_로직.md`](../../2_Checklist/F01_코어골격_팀ID/03_팀배정_로직.md)

## 할 일

접속한 플레이어를 서버가 팀에 배정한다. **팀 수와 팀 인원을 상수로 박지 않는다.**

```cpp
// ERGameMode.h — 데이터값으로 노출
UPROPERTY(EditDefaultsOnly, Category="Match")
int32 TeamSize = 3;

UPROPERTY(EditDefaultsOnly, Category="Match")
int32 TeamCount = 8;
```

`PostLogin` 또는 그 이후 시점에 서버가 빈 자리를 찾아 `TeamId` 를 넣는다.
지금은 **접속 순서대로 채운다** — 파티 우선 배정은 매치메이킹이 생긴 뒤의 일이다.

`AERGameState` 에 팀 구성(어느 팀에 누가)을 배열로 두고 복제한다.

## 왜 이렇게 하나

- ⭐ **`TeamSize` / `TeamCount` 를 데이터값으로 빼는 이유:** [매치진행 문서](../../0_GameDesign/Systems/매치진행_게임모드_역기획서.md)`:141` — *"팀 인원과 팀 수는 처음부터 데이터값으로 뺀다(`TeamSize`, `TeamCount`)."*
  기본값 3 × 8 = 24명은 [원본 §3.1](../../0_GameDesign/이터널리턴_역기획서.md) 확인값이지만, **테스트는 2~4명으로 한다.** 상수로 박으면 PIE 테스트가 불가능해진다.
- **왜 배정이 GameMode인가:** `AGameModeBase` 는 **서버에만 존재**한다. 배정 로직이 클라에 복제될 이유가 없다.

## 만질 파일

```
Source/EternalReturn/Core/ERGameMode.h / .cpp     (배정 로직, TeamSize / TeamCount)
Source/EternalReturn/Core/ERGameState.h / .cpp    (팀 구성 배열 + 복제)
```

## 검증

- **빌드 통과**
- `Play As Client, Number of Players: 4` + `TeamSize = 2` — **2팀으로 나뉜다.**
- 각 클라가 자기 팀과 상대 팀을 구분한다.
- 서버 로그에 배정 결과가 찍힌다.

## 주의점

- 배정은 **`HasAuthority()` 가드 안에서만.** 클라가 자기 팀을 정하면 안 된다 (`CLAUDE.md` §6).
- 팀 정원이 다 찼을 때의 처리를 정한다 — 접속 거부인지 관전인지. 지금은 **다음 팀으로 넘긴다**로 두고 주석에 자체 결정값임을 표기한다.
- `AGameStateBase` 는 `bAlwaysRelevant = true`, `NetPriority = 10.f` 다 (`Engine/Private/GameStateBase.cpp:26, 41`). 팀 구성 배열은 24명 규모라 문제없지만, **여기에 인벤토리 같은 큰 데이터를 넣지 않는다.**
- `PostLogin` 시점에 `PlayerState` 가 유효한지 확인하고 쓴다. **`nullptr` 체크 없이 역참조하지 않는다** (`CLAUDE.md` §5).
