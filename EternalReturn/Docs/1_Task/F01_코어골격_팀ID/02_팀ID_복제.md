> 체크리스트 [`02_팀ID_복제.md`](../../2_Checklist/F01_코어골격_팀ID/02_팀ID_복제.md)

## 할 일

`AERPlayerState` 에 팀 ID를 두고 복제한다.

```cpp
// ERPlayerState.h
UPROPERTY(Replicated, BlueprintReadOnly, Category="Team")
int32 TeamId = INDEX_NONE;   // INDEX_NONE = 미배정

virtual void GetLifetimeReplicatedProps(TArray<FLifetimeProperty>& OutLifetimeProps) const override;
```

```cpp
// ERPlayerState.cpp
void AERPlayerState::GetLifetimeReplicatedProps(TArray<FLifetimeProperty>& OutLifetimeProps) const
{
    Super::GetLifetimeReplicatedProps(OutLifetimeProps);
    DOREPLIFETIME(AERPlayerState, TeamId);   // ⭐ 이 줄을 빠뜨리면 조용히 복제되지 않는다
}
```

## 왜 이렇게 하나

- **왜 `COND_OwnerOnly` 가 아닌 전체 복제인가:** 적이 어느 팀인지는 **모두가 알아야 한다.** 아군/적군 색 구분, 아군 오사 방지, HUD 표시가 전부 이 값을 쓴다. 숨길 정보가 아니다.
- **왜 `PlayerState` 인가:** 죽어도 유지되어야 하고 매치 내내 안 바뀐다. [네트워크 문서](../../0_GameDesign/Systems/네트워크_서버아키텍처_역기획서.md) §2.2 판정 기준 Q1(죽으면 사라지는가 → 아니오)에 해당한다.
- **왜 `int32` 인가:** 팀 수를 데이터값으로 뺄 예정이라(Task 03) 열거형으로 고정하지 않는다.

## 검증

- **빌드 통과**
- `Play As Client, Number of Players: 2` — 서버가 `TeamId` 를 넣으면 **양쪽 클라가 그 값을 읽는다** (`UE_LOG`).
- 클라에서 `TeamId` 를 직접 바꿔도 서버 값이 변하지 않는다.

## 주의점

- ⭐ **`UPROPERTY(Replicated)` 를 추가하면 `GetLifetimeReplicatedProps` 에 `DOREPLIFETIME` 을 반드시 같이 넣는다.** 빠뜨리면 에러 없이 복제만 안 된다 — 디버깅에 가장 시간을 뺏기는 실수다 (`CLAUDE.md` §6).
- `APlayerState` 는 `bAlwaysRelevant = true`, `NetUpdateFrequency = 1` 이다 (`Engine/Private/PlayerState.cpp:25-27`). **여기에 큰 배열을 얹지 않는다** — 24명분이 전원에게 간다.
- `BlueprintReadWrite` 를 쓰지 않는다. BP가 팀을 바꾸면 안 된다 (`CLAUDE.md` §7).
- 헤더에 `UPROPERTY` 를 추가했으므로 **에디터 재시작이 필요할 수 있다.**
