## 결정할 것

⚠ **먼저 드러난 사실: 기본 공격(평타) 어빌리티가 어느 Task 에도 없다.** `F00~F17` 기능 목록에 "기본 공격" 항목이 없고,
F07-07 은 "다음 평타 강화" 를 검증하려면 평타가 있어야 한다. 그래서 ① 이 생겼다.

① **기본 공격을 무엇으로 만드는가** — 스킬 파이프라인의 파생인가, 별도 시스템인가
② **"다음 평타 강화" 를 평타가 어떻게 아는가** — 재키 W 가 걸어 둔 것을 평타가 읽어 **W 의 피해·둔화**를 얹어야 한다
③ **"적중 시 3초 내 재사용" 을 어떻게 재는가** — `FTimerManager` 는 금지 (CLAUDE.md §8)

## ① 기본 공격의 자리

### A. `UERGameplayAbility` 파생 `UERBasicAttackAbility` + 슬롯 `Ability.Slot.Attack`

```
DA_Attack_<무기>  (UERSkillData) : SlotTag=Ability.Slot.Attack, AbilityClass=GA_BasicAttack,
                                    Shape=SingleTarget, DamageType=BasicAttack, APRatio=[1.0], InitialLevel=1, bUsesSkillPoints=false
UERBasicAttackAbility 오버라이드:
  - 쿨다운 길이 = 1 / AttackSpeed (SkillData.Cooldowns 무시)          ← 공격 속도
  - 사거리     = AttackRange 어트리뷰트 (Shape.RangeMax 무시)          ← 무기 사거리 (F11 이 값을 바꾼다)
  - 생성자      ActivationBlockedTags += State.Block.BasicAttack       ← F06 무장 해제 축
  - OnTargetsResolved: 자기 피해 + **NextAttackBuff 소비**
```
입력은 `DA_InputConfig.SkillSlotActions[Ability.Slot.Attack]` 한 줄 — PC 는 슬롯 하나 늘어난 것만 본다.

- 장점: 조준(18) · 판정(F04) · 피해(F03) · 쿨다운 · 차단 축이 **전부 공짜** · 무기 교체(F11)는 `DA_Attack_*` 애셋 교체 = `TakeSkills/GrantSkills` · 무장 해제가 "평타 슬롯" 하나만 막으면 된다
- 단점: "평타는 스킬이 아니다" 는 직관과 어긋난다 → 클래스 이름과 슬롯 태그로 구분 · 오토 어택(우클릭 추적·자동 반복)은 이번 범위 밖 — 입력 한 번 = 한 방

### B. 별도 컴포넌트 (`UERAttackComponent` — 타이머 · 자체 판정 호출)

- 장점: "스킬" 과 분리된 이름
- 단점: 쿨다운 · 차단 · 조준 · 서버 권위 검증을 **두 번째로** 만든다 (CLAUDE.md §8 "쿨다운은 Cooldown GE") · 재키 W 같은 "스킬이 평타를 바꾼다" 가 두 시스템을 가로지른다

## ② 다음 평타 강화 전달

### A. GE `UERNextAttackBuffEffect` + 컨텍스트 `SourceObject = 버프 스킬의 UERSkillData`

```
재키 W ExecuteSkill : GE 적용 (HasDuration = NextAttackBuffDuration, 0 이면 Infinite)
                       DynamicGrantedTags = State.NextAttackBuff, Context.SourceObject = DA_Skill_Jackie_W
평타 적중 시         : ASC 에서 State.NextAttackBuff 를 가진 활성 GE 를 찾아 SourceObject → DA_Skill_Jackie_W
                       그 데이터로 ApplySkillDamage(대상) + OnHitEffect(둔화)  → GE 제거 (1회성)
```

- 장점: **버프 스킬과 평타가 서로를 모른다** — 만나는 곳은 GE 하나 · 카티야 P · 시셀라 Q · 권총 D 가 같은 GE 를 쓴다 (§8 "4곳") · 만료가 GE Duration · 태그가 복제되어 UI/무장 해제가 본다 · "안 쓰면 남아 있나" 가 데이터(Duration)로 결정
- 단점: 평타가 GE 를 **검색**한다 (`GetActiveEffects(MatchAllOwningTags)` — E09 에서 배운 그 API) · 레벨은 GE Spec Level 로 넘긴다

### B. 버프 스킬 인스턴스가 `bPending` 을 들고, 평타가 모든 어빌리티를 순회해 물어본다

- 장점: GE 없음
- 단점: 평타가 어빌리티 인스턴스 내부를 안다 · 복제 안 됨(클라 UI 가 모름) · 만료 타이머를 따로 (금지)

## ③ 리캐스트 윈도우

### A. GE `UERRecastWindowEffect` (HasDuration = RecastWindow) + 동적 태그 `Recast.Slot.Q` · `CheckCooldown` 오버라이드

```
적중 시 (bRecastOnHit) : 윈도우 GE 적용 — Recast.Slot.Q
CheckCooldown          : ASC 가 Recast.Slot.<자기 슬롯> 을 가지면 쿨다운 무시하고 true
재발동 시              : 윈도우 GE 제거, **쿨다운은 새로 걸지 않는다** (첫 시전에 시작한 쿨이 그대로) — 자체 결정값, 원작 (미확인)
```

- 장점: 쿨다운(16)과 똑같은 패턴 — 태그 하나, GE 하나 · 클라 선판정(인스턴스)이 복제된 태그로 같은 답 · 만료 = GE
- 단점: `CheckCooldown` 우회가 "쿨다운 중인데 발동" 이라 로그를 남겨야 헷갈리지 않는다

### B. `FTimerManager` — CLAUDE.md §8 금지. 비교 대상 아님

## 추천 — **①A + ②A + ③A**

세 결정이 같은 원칙이다: **"상태는 GE, 대기는 태스크, 연결은 태그"**. 16 · 17 과 같은 패턴이라 새로 배울 것이 없고, 무장 해제(F06)가 `State.Block.BasicAttack` 하나로 "평타 + 강화 평타" 를 같이 막는다 — 강화는 평타 **안에서** 소비되니까.
