## 결정할 것

스킬 DA (`UERSkillData`) 값을 텍스트 원본에서 채우는 형식.

## 전제 — 스킬 DA 는 왜 CSV 한 줄이 안 되나

- 윗단 칸은 평평하다: SlotTag · AbilityClass · Cooldowns[] · CastTime · RecoveryTime · Shape(구조체) · MaxLevel …
- 그런데 **조각(Fragments)** 은 `Instanced` 객체 배열 — 스킬마다 **종류 · 개수 · 순서가 다르다** (Q: 피해 + 자기 버프 / E: 자기 이동 + 피해 + 적중 효과 + 자기 버프 / W: 없음)
- 조각마다 칸이 다르다 (피해 10칸 · 자기 버프 = 구조체 배열 · 장판 …) — 열로 펴면 모든 조각의 모든 칸이 열이 된다
- 엔진은 프로퍼티 하나를 **텍스트로 읽는 함수**를 이미 갖고 있다 — `FProperty::ImportText_Direct` (에디터 복사 · 붙여넣기 · 기본값 문자열이 쓰는 것). 배열 `(40,80,120)` · 구조체 `(Effect=/Game/…,Duration=(4))` · enum 이름 · 애셋 경로를 다 읽는다

## 방안

### J1 — 캐릭터별 JSON + 엔진 텍스트 읽기 ⭐
`Docs/3_EditorTasks/Data/Skills/Katja.json` — 스킬마다 칸 이름 → 값(엔진 텍스트 형식). 조각은 `Class` + 칸들.
```json
{ "Skills": [ {
  "Asset": "DA_Skill_Katja_Q",
  "Props": { "MaxLevel": "5", "Cooldowns": "(7,6,5,4,3)", "CastTime": "0.25",
             "Shape": "(Shape=Projectile,RangeMax=11,ProjectileRadius=0.3,ProjectileSpeed=26,ProjectileClass=/Game/…/BP_Proj_Katja_Q.BP_Proj_Katja_Q_C)" },
  "Fragments": [
    { "Class": "ERSkillFragment_Damage", "Props": { "BaseDamage": "(40,80,120,160,200)", "APRatio": "(0.7)", "BaseDamageFar": "(60,120,180,240,300)", "APRatioFar": "(1.05)" } },
    { "Class": "ERSkillFragment_SelfBuff", "Props": { "bOnlyOnHit": "True", "Effects": "((Effect=/Game/…/GE_AttackSpeedUp.GE_AttackSpeedUp_C,Duration=(4),Magnitude=(1.2,1.25,1.3,1.35,1.4)))" } } ] } ] }
```
명령 `ER.Skill.ImportJson <캐릭터|All>` — DA 를 이름으로 찾고(없으면 만든다), 적힌 칸만 덮어쓰고, `Fragments` 가 적혀 있으면 **통째로 새로** 만든다.
- 장점
  - **어떤 칸 · 어떤 조각이든** 코드 수정 없이 들어간다 (새 조각을 만들어도 임포터는 그대로) — F19 6명 · 스킬 30개에 맞다
  - 값 형식이 에디터 복사 · 붙여넣기와 같다 → 에디터에서 칸을 우클릭 Copy 한 문자열을 그대로 붙일 수 있다
  - 엔진 함수(`ImportText_Direct` · `FJsonSerializer`)만 쓴다 — 직접 파서 없음
  - 틀린 칸 이름 · 값은 로그로 바로 (GAS 처럼 조용히 건너뛰지 않게 — CLAUDE §8)
- 단점
  - CSV 가 아니다 (memory 규칙의 예외 — 조각 목록은 표로 못 담는다). 표로 보기 불편
  - 값이 엔진 텍스트 형식이라 처음 보면 낯설다 (괄호 · 경로)

### J2 — 조각 종류별 CSV 여러 장
`DT_SkillBase.csv` (윗단) + `DT_Frag_Damage.csv` · `DT_Frag_SelfBuff.csv` … (행 = 스킬 이름 + 순서)
- 장점
  - CSV 규칙 그대로 · 엑셀로 보기 쉽다
- 단점
  - 조각 종류가 늘 때마다 **CSV + 임포터 코드** 둘 다 는다 (지금 14종)
  - 구조체 배열(자기 버프 Effects) 은 결국 칸 안에 텍스트로 넣어야 한다
  - 한 스킬이 여러 파일에 흩어진다

### J3 — 스킬을 C++ 코드로 만드는 에디터 명령
스킬마다 함수 하나가 DA 를 채운다.
- 장점
  - 타입 검사 (오타가 컴파일 에러)
- 단점
  - **수치가 코드에** — 바꿀 때마다 빌드 (데이터 원본 원칙 위반)
  - 6명 × 5스킬 코드가 쌓인다
