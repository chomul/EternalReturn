# 5. 「추가 공격력」을 어떻게 구할 것인가

> 작성일 2026-09-08 · 대상 기능 [`../1_Task/F03_데미지_ExecutionCalc/02_핵심계산_방어력공식.md`](../1_Task/F03_데미지_ExecutionCalc/02_핵심계산_방어력공식.md)
> 작성 근거: `CLAUDE.md` §1.2
> 관련 [`../1_Task/F03_데미지_ExecutionCalc/01_어트리뷰트_캡처정의.md`](../1_Task/F03_데미지_ExecutionCalc/01_어트리뷰트_캡처정의.md)

## 결정할 것

계산식이 요구하는 **`A.BonusAP`(기본 공격력 제외분)** 를 어떻게 얻을 것인가.

```cpp
// 스탯_데미지공식_역기획서.md §2.2, 3 단계
Raw += A.AttackPower * Ctx.APRatio;
Raw += A.BonusAP     * Ctx.BonusAPRatio;              // ← 이것
Raw += A.SkillAmp    * Ctx.SkillAmpRatio;
```

⚠ **우리 어트리뷰트 33개에 `BonusAP` 가 없다.** F03-01 캡처 정의를 만들면서 드러났다.

### 용어

| | 뜻 | 출처 |
|---|---|---|
| **기본 공격력** | 실험체 고유값 + 레벨 성장 | 데이터 애셋 초기값(F02-05) + F10 |
| **추가 공격력** | 장비·버프로 더해진 분 | F08/F09 장비, 버프 GE |
| **공격력** | 위 둘의 합. 우리 `AttackPower` 어트리뷰트 | — |

즉 **`BonusAP = AttackPower - 기본 공격력`** 이다. 문제는 "기본 공격력"을 어디서 아느냐다.

---

## ⭐ 방안 1 — GAS 내장 `AttemptCalculateCapturedAttributeBonusMagnitude` (채택 추천)

**어트리뷰트를 추가하지 않는다.** GAS 가 이미 이 값을 계산해 준다.

```cpp
// GameplayEffectExecutionCalculation.h:95
bool AttemptCalculateCapturedAttributeBonusMagnitude(
    const FGameplayEffectAttributeCaptureDefinition& InCaptureDef,
    const FAggregatorEvaluateParameters& InEvalParams,
    OUT float& OutBonusMagnitude) const;
```

내부 구현이 정확히 우리가 원하는 뺄셈이다:

```cpp
// GameplayEffectAggregator.cpp:381-384
float FAggregator::EvaluateBonus(const FAggregatorEvaluateParameters& Parameters) const
{
    return (Evaluate(Parameters) - GetBaseValue());
}
```

### ⭐ 왜 이게 정확히 맞는가 — Base / Current 의 의미

GAS 어트리뷰트는 값을 둘 들고 있다 (`AttributeSet.h:19`).

| | 무엇이 바꾸나 | 우리 설계에서 |
|---|---|---|
| `BaseValue` | **`Instant` GE** | 초기 스탯(F02-05) · 레벨 성장(F10) → **기본 공격력** |
| `CurrentValue` | Base + 걸려 있는 `Duration`/`Infinite` GE | 장비 · 버프 → **기본 + 추가** |

이건 우리가 이미 정한 구조 그대로다:

- F02-05 초기화 GE 는 **`Instant`** 다 → `AttackPower` 의 **Base** 를 세팅한다
- F10 레벨 성장도 *"같은 방식(GE)으로 Base를 올린다"*
  ([`../1_Task/F02_어트리뷰트셋/05_초기값_데이터테이블.md`](../1_Task/F02_어트리뷰트셋/05_초기값_데이터테이블.md))
- 장비·버프는 `Infinite`/`HasDuration` 이라 **Current 만** 바꾼다

→ `EvaluateBonus()` 가 돌려주는 값이 **곧 추가 공격력**이다.

**장점**

- ⭐ **어트리뷰트를 추가하지 않는다.** 33개 그대로. 복제 비용 0
- ⭐ **동기화가 깨질 수 없다.** 두 값을 따로 유지하지 않으니 어긋날 여지가 없다
- ⭐ `CLAUDE.md` §8 — GAS 가 제공하는 것을 다시 만들지 않는다
- 캡처 정의를 새로 만들 필요도 없다. **`AttackPowerDef` 를 그대로 재사용**한다
- 공격력뿐 아니라 **방어력·모든 스탯에 같은 방법이 통한다**
  (매그너스 W 의 *"추가 방어력"* 도 이걸로 해결된다)

**단점**

- ⚠ **규율에 의존한다.** 영구 스탯 증가를 `Instant` GE 로 주면 그건 "기본"으로 잡힌다.
  장비·버프는 **반드시 `Infinite`/`HasDuration`** 이어야 한다
- ⚠ 이 규칙이 코드에 안 보인다. GE 애셋을 만드는 사람이 알아야 한다
- 값이 어디서 왔는지 디버깅할 때 한 단계 더 들어가야 한다

**비용**

| | |
|---|---|
| 구현 난이도 | **가장 낮다.** 함수 호출 한 줄 |
| 네트워크 | **0** — 새 복제 프로퍼티 없음 |
| GAS 정합성 | ⭐ 최상 |

## 방안 2 — `BaseAttackPower` 어트리뷰트를 추가한다

기본 공격력을 별도 어트리뷰트로 두고, 뺄셈은 Execution 이 한다.

```cpp
DECLARE_ATTRIBUTE_CAPTUREDEF(BaseAttackPower)   // Source
// ...
const float BonusAP = AttackPower - BaseAttackPower;
```

**장점**

- **명시적이다.** 코드와 에디터에서 값이 보인다
- `Instant`/`Duration` 규율에 의존하지 않는다
- UI 가 *"공격력 50 (+20)"* 을 표시할 때 바로 읽을 수 있다

**단점**

- ⚠ **어트리뷰트가 34개가 된다.** 복제 프로퍼티 +1
- ⚠ **두 곳을 유지해야 한다.** 레벨업 GE 가 `AttackPower` 와 `BaseAttackPower` 를 **둘 다** 올려야 한다.
  하나를 빠뜨리면 추가 공격력이 조용히 틀린다 — GAS 는 경고하지 않는다 (`GameplayEffect.cpp:4238`)
- ⚠ 방어력·다른 스탯도 같은 게 필요해지면 **`BaseDefense` … 로 계속 늘어난다**

---

## 방안 3 — `BonusAttackPower` 어트리뷰트를 병렬로 유지한다

추가분 자체를 어트리뷰트로 둔다.

**장점**

- 읽을 때 뺄셈이 필요 없다

**단점**

- ⚠ **방안 2 의 문제가 더 심하다.** 장비를 끼고 뺄 때마다 `AttackPower` 와 `BonusAttackPower` 를
  **똑같이** 움직여야 한다. 장비 GE 하나가 두 어트리뷰트를 건드린다
- ⚠ 버프가 스택되면 어긋날 확률이 올라간다
- ⭐ **GAS 가 `Duration` GE 를 자동으로 되돌려 주는 이점을 잃는다** — 되돌림을 손으로 해야 한다

---

## 방안 4 — 평가 채널(Evaluation Channel)로 분리한다

GAS 는 모디파이어를 채널로 나눠 "채널 N 까지만 평가" 를 지원한다.

```cpp
// AbilitySystemGlobals.h:334-343
UPROPERTY(config) bool bAllowGameplayModEvaluationChannels;
UPROPERTY(config) FName GameplayModEvaluationChannelAliases[...];

// GameplayEffectAggregator.h:308
float EvaluateToChannel(const FAggregatorEvaluateParameters& Parameters, EGameplayModEvaluationChannel FinalChannel) const;
```

기본 성장은 Channel0, 장비는 Channel1 에 넣고 Channel0 까지만 평가하면 기본 공격력이 나온다.

**장점**

- 계층을 **여러 단계**로 나눌 수 있다 (기본 / 장비 / 버프 / 디버프)
- `Instant` 여부와 무관하게 동작한다

**단점**

- ⚠ ⭐ **Execution 에서 쓸 수 있는 공개 API 가 없다.**
  `FGameplayEffectCustomExecutionParameters` 가 노출하는 것은
  `AttemptCalculateCapturedAttributeMagnitude`(`:59`),
  `...WithBase`(`:72`), `...BaseValue`(`:83`), `...BonusMagnitude`(`:95`) 넷뿐이고
  **`UpToChannel` 변형이 없다.** 캡처 스펙을 직접 꺼내 우회해야 한다
- ⚠ 프로젝트 전역 설정(`bAllowGameplayModEvaluationChannels`)을 켜야 하고,
  **모든 GE 가 채널을 올바로 지정해야 한다.** 안 지정하면 Channel0 으로 떨어진다
  (`GameplayEffectTypes.h:81-83` — *"or Channel0 in the event of a game not using modifier channels"*)
- ⚠ 지금 필요한 것(2계층)에 비해 **과하다**

## ⭐ 결정 — **방안 1 (GAS 내장 `AttemptCalculateCapturedAttributeBonusMagnitude`)** · 확정 2026-09-08

사용자 판단: *"1번으로 가자"*

**새 어트리뷰트를 만들지 않는다.** 33개를 유지하고, F03-01 의 `AttackPowerDef` 를 재사용한다.

### 결정이 강제하는 것

| | |
|---|---|
| **F03-02** | `AttemptCalculateCapturedAttributeBonusMagnitude(AttackPowerDef, ...)` 로 추가 공격력을 읽는다 |
| **F09 (장비)** | ⚠ 장비 GE 는 **반드시 `Infinite`** — `Instant` 로 주면 기본 공격력에 섞인다 |
| **F10 (성장)** | 레벨 성장은 **`Instant`** 유지 (Base 를 올려야 한다) |
| **F17 (UI)** | *"공격력 50 (+20)"* 표시 경로는 Execution 밖이라 별도 확인 필요 **(미확인)** |

### 추천 근거 (원문)

세 가지 이유다.

1. **우리 구조가 이미 정확히 맞다.** 초기값·레벨 성장은 `Instant`(Base), 장비·버프는 `Duration`/`Infinite`(Current).
   `EvaluateBonus()` 의 정의(`Evaluate() - GetBaseValue()`)가 그대로 "추가 공격력" 이다
2. **어트리뷰트를 안 늘린다.** 방안 2·3 은 스탯마다 짝을 만들어야 하고,
   매그너스 W 의 *"추가 방어력"* 까지 가면 최소 2개가 더 필요하다
3. **동기화 누락이 원천적으로 불가능하다.** 방안 2·3 의 가장 큰 위험이 사라진다

### ⚠ 채택 시 반드시 지킬 규칙

**영구 스탯 증가를 `Instant` GE 로 주지 않는다.**

| 무엇 | GE 종류 | 결과 |
|---|---|---|
| 실험체 초기값 · 레벨 성장 | `Instant` | 기본 공격력 (Base) |
| 장비 · 버프 · 아이템 옵션 | `Infinite` / `HasDuration` | **추가 공격력** (Bonus) |

⚠ 이 규칙은 **코드에 드러나지 않는다.** 어기면 추가 공격력이 조용히 작아진다.
→ F09(장비) 작업 시 `Docs/3_EditorTasks/` 문서에 **"장비 GE 는 Infinite 여야 한다"** 를 체크 항목으로 넣는다.

### 되돌리기 비용

낮다. 나중에 방안 2 로 바꾸려면 어트리뷰트 하나와 캡처 하나를 추가하면 되고,
**GE 애셋은 손대지 않는다.** 방안 1 을 먼저 시도해도 잃는 것이 없다.
