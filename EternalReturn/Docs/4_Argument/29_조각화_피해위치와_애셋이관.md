# 29. 조각화의 두 세부 결정 — ① 피해를 조각으로 뺄까 · ② 애셋 18개를 어떻게 옮길까

> F11.5 · 상위 결정 [`28_스킬데이터_기능확장_구조.md`](28_스킬데이터_기능확장_구조.md) (방안 B 조각 조합, 사용자 확인 2026-09-21)
> 대상 애셋: `Content/GAS/Skill/` 6 + `WeaponSkill/` 13 = **18개** (2026-09-21 `ls` 기준, `GA_Test` 제외 하면 17)

## ① 피해(`DamageType` + 계수 8종)를 조각으로 빼나, 핵심(평면)에 남기나

### 방안 A — 핵심에 남긴다
`DamageType · BaseDamage · APRatio · BonusAPRatio · SkillAmpRatio · MaxHPRatio · FixedCurHPRatio · TargetLostHPScaleMax · HealFromDamageRatio` 는 그대로. 조각은 "피해 이외" 만.
- 장점: 애셋 재입력이 적다 (피해 있는 애셋 ~13개는 손 안 댐) · `ApplySkillDamage` 호출부(장판 · 벽 충돌 · 평타 강화)가 그대로
- 단점: **"피해 없는 스킬" 이 여전히 피해 필드 9개를 들고 있다** (단검 망토 · 저격 D · 권총 D 처럼 DamageType None 인 것이 5개) · 피해 옵션이 늘 때(원작: 잃은 체력 · 거리 비례 · 시전자 최대 체력 비례 …) 다시 평면 확장

### 방안 B — `Fragment_Damage` 로 뺀다 ⭐ 추천
`Fragment_Damage { DamageType, BaseDamage, APRatio, BonusAPRatio, SkillAmpRatio, MaxHPRatio, FixedCurHPRatio, TargetLostHPScaleMax, HealFromDamageRatio }`. `ApplySkillDamage` 본체는 `ERSkillDamage::Apply(Ctx, const Fragment_Damage&, Targets, Scale)` 라이브러리로 — 장판 · 벽 충돌 · 평타 강화가 이 함수를 부른다.
- 장점: 조각화의 목적(무관한 필드가 안 보인다)이 **피해에도** 적용 · 피해 옵션 확장이 그 클래스 안 · "한 스킬에 피해 2종" (1차 물리 + 2차 고정) 을 조각 2개로 표현 가능 — 지금은 `FixedCurHPRatio` 가 억지로 두 번째 스펙을 만든다
- 단점: 이관 대상 애셋이 13개 더 · `UERBasicAttackAbility` 의 "다음 평타 강화" 가 강화 스킬의 `Fragment_Damage` 를 찾아 써야 한다 (`FindFragment<Fragment_Damage>()` 한 줄)

**추천 B** — 이관은 어차피 명령 한 번(②)이라 애셋 수는 비용이 아니다. 피해 옵션은 앞으로 가장 많이 늘어날 축이다.

## ② 애셋 이관 — 손으로 다시 찍나, 코드가 옮기나

### 방안 A — 에디터에서 손으로 18개 재입력
- 장점: 코드 0줄
- 단점: 필드 ~35개 × 18개. 오늘 하루에만 복제 잔재로 4번 헛돌았다 (CooldownTagOverride · FollowUpSkill · Mode.Duration · OnHitEffect). **오입력이 확실히 생긴다**

### 방안 B — 임시 이관 명령 `ER.Skill.MigrateFragments` (WITH_EDITOR) ⭐ 추천
1단계 빌드: 새 필드(`Fragments`)와 옛 필드가 **공존**. 명령이 모든 `UERSkillData` 를 열어 옛 필드 → 조각으로 만들고 옛 필드를 기본값으로 지운 뒤 패키지 저장 (`UEditorAssetLibrary::SaveLoadedAsset`). 사용자가 에디터에서 한 번 실행 → 로그로 결과 확인 → 2단계 빌드에서 옛 필드 · 명령 삭제.
- 장점: 결정적 · 재현 가능 · 로그로 대조 가능 (`[이관] DA_Skill_D_Bat: Damage · OnHit · Knockback(+Wall) · Recast`) · 실수 0
- 단점: 임시 코드 ~150줄 (2단계에서 지움) · 빌드 2번 · `Content/` 를 코드가 저장한다 — **사용자가 에디터에서 실행하는 명령**이라 CLAUDE.md §9 의 "Claude 가 애셋을 만지지 않는다" 와 충돌하지 않는다 (같은 이유로 지난번 Python 스크립트를 제안했었다)
- ⚠ Instanced 서브오브젝트는 `NewObject<Fragment>(SkillDataAsset)` 로 애셋을 Outer 로 만들어야 저장된다 (`LyraInventoryItemDefinition` 이 에디터에서 만드는 것과 같은 형태)

**추천 B.**
