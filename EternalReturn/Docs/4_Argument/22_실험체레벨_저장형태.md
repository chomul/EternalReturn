## 방안 A — PlayerState 컴포넌트의 정수

```
UERGrowthComponent (AERPlayerState 서브오브젝트, 인벤토리와 같은 자리)
  Level : int32   ReplicatedUsing=OnRep_Level        — 전원 (HUD 에 상대 레벨 표시)
  Exp   : int32   Replicated, COND_OwnerOnly          — 본인만 (§7 "남의 경험치를 볼 이유가 없다")
  OnLevelUp(int32 NewLevel)  서버 멀티캐스트 델리게이트 — 02 스탯 GE · 03 스킬포인트가 받는다
```

- 장점
  - ⭐ **복제 조건을 값마다 다르게 걸 수 있다.** 레벨은 전원, 경험치는 소유자만 — `DOREPLIFETIME_CONDITION` 한 줄
  - 정수다. 어트리뷰트는 float 라 `19.9999` 클램프 · 비교가 어색하다
  - 레벨업 판정(테이블 조회 · `while` 다중 레벨)이 **한 곳**에 있다. GE 로 경험치를 더하면 `PostGameplayEffectExecute` 에서 판정해야 하고, 그러면 어트리뷰트셋이 테이블을 알게 된다
  - 스킬포인트(`AERPlayerState.SkillPoints`) · 인벤토리와 같은 결(Argument 21) — 부활 · 재접속에 그냥 남는다
- 단점
  - MMC 가 **캡처**할 수 없다. 레벨 비례 공식이 생기면 MMC 가 `Spec.GetContext().GetInstigator()` → PlayerState → 컴포넌트로 읽어야 한다 (캡처보다 한 단계 더). ⚠ 지금 그런 공식이 없다 — F10-02 는 "레벨업 때 Instant GE 한 번" 이라 캡처가 필요 없다

## 방안 B — `UERAttributeSet` 에 `Level` · `Exp` 어트리뷰트

- 장점
  - GE · MMC 가 레벨을 캡처할 수 있다 (레벨 비례 계산이 생기면 편하다)
  - 야생동물도 같은 세트를 쓰니 "레벨" 표현이 플레이어 · 야생동물에서 같다
- 단점
  - ⚠ **경험치를 소유자에게만 복제할 수 없다.** 어트리뷰트 복제는 ASC 가 세트 단위로 한다 — `Mixed` 모드는 GE 만 소유자 한정이고 **어트리뷰트는 전원에게 간다**. 남의 경험치 은닉(§7)을 어기거나, 경험치만 따로 방안 A 로 빼야 한다 → 결국 둘로 갈라진다
  - 경험치 증가를 GE 로 해야 한다 (E05: `SetExp` 직접 호출은 권위를 안 본다). 야생동물 처치마다 GE 스펙 생성 — 정수 더하기에 과하다
  - 레벨업 판정을 `PostGameplayEffectExecute` 에서 하면 어트리뷰트셋이 경험치 테이블에 의존한다. 어트리뷰트셋은 지금 "클램프와 사망 알림" 만 한다
  - 야생동물 레벨은 **스폰 파라미터**다 (F12-03 이 시각 → 레벨 → GE). 어트리뷰트로 갖고 있을 이유가 없다

## 비교

| | A 컴포넌트 정수 | B 어트리뷰트 |
|---|---|---|
| 경험치 OwnerOnly | ✅ 한 줄 | ❌ 불가 (세트 단위 복제) |
| 레벨업 판정 위치 | 컴포넌트 한 곳 | 어트리뷰트셋 ← 테이블 의존 |
| 경험치 추가 비용 | 정수 덧셈 | GE 스펙 |
| MMC 레벨 캡처 | ❌ (Instigator 경유로 읽기) | ✅ |
| 지금 필요한 레벨 비례 공식 | 없음 | — |

## 추천 — A

B 의 유일한 이점(MMC 캡처)이 지금 필요 없고, B 는 경험치 은닉을 못 지킨다.
레벨 비례 공식이 나중에 생기면 그때 **`Level` 어트리뷰트를 미러로 추가**(컴포넌트가 진실, 레벨업 때 Instant GE 로 어트리뷰트 갱신)하면 된다 — 지금 구조를 바꾸지 않는다.
