# 24. 무기 계열의 기본 공격 사거리를 어떻게 적용하나 — Override GE vs Base 교체 vs 어빌리티 직접 읽기

## 결정할 것

`AttackRange` 어트리뷰트는 F02 초기값(실험체 맨몸)이 있고, F07-07 평타가 읽고, F08-03 장비가 **Additive** 로 보너스를 더한다.
무기 계열 사거리는 이 값을 **대체**해야 한다 (더하는 게 아니다). 대체하면서 장비 보너스는 살려야 한다.

---

## 방안 A — 장착 중 Infinite GE 에 `Override` 모디파이어

- 장점: 장비 GE 와 같은 수명 관리 (핸들 제거로 원복)
- 단점 ⚠⚠ **장비 사거리 보너스가 사라진다.** GAS 애그리게이터는 Override 가 하나라도 있으면 **그 값을 바로 돌려주고 Additive 를 전부 무시**한다:
  ```cpp
  // GameplayEffectAggregator.cpp:60-66  FAggregatorModChannel::EvaluateWithBase
  for (const FAggregatorMod& Mod : Mods[EGameplayModOp::Override])
      if (Mod.Qualifies()) return Mod.EvaluatedMagnitude;
  float Additive = SumMods(...);   // ← 여기 못 온다
  ```
  → `sniper_t1` 의 `AttackRange +1.0` (F08-03 검증 완료) 이 무기를 드는 순간 죽는다. 원거리 무기 아이템은 대부분 사거리 옵션을 갖는다

## 방안 B — 장착/해제 때 Instant GE `Override` 로 **BaseValue** 교체

```
장착: Instant · Override · AttackRange = 계열 사거리        → Base 가 바뀐다. 장비(Infinite Additive) 는 Current 에 그대로
해제: Instant · Override · AttackRange = CharacterData.BaseStats.AttackRange (맨몸)
```
- 장점
  - ⭐ 장비 Additive 가 살아 있다 (Base + Bonus 구조, Argument 5 와 같은 결)
  - 어트리뷰트 하나가 진실 — 평타 · UI · AI 가 전부 같은 값을 읽는다. 복제도 어트리뷰트 경로 그대로
  - 사거리 값이 어트리뷰트라 F03 · F07 코드 변경 없음
- 단점
  - "해제 = 맨몸 값 복원" 을 코드가 명시적으로 해야 한다 (Infinite 핸들 제거처럼 자동이 아니다). 한 함수(`ApplyWeaponRange`)에 모아 두면 된다
  - 다른 곳이 `AttackRange` Base 를 Instant 로 만졌다면(레벨 성장은 안 만진다 — 필드 없음) 덮어쓴다. 지금 그런 곳 없음

## 방안 C — 어빌리티가 계열 행을 직접 읽는다

`UERBasicAttackAbility::GetRangeMax = 계열 사거리 + EvaluateBonus(AttackRange)`
- 장점: GE 없음
- 단점
  - `AttackRange` 어트리뷰트가 **거짓말**을 한다 (Base 가 맨몸 값인 채로 남는다) — UI · 다른 스킬 · F12 야생동물이 읽으면 틀린다
  - 사거리 로직이 평타 안에 박혀 두 곳(어트리뷰트 · 행)을 합쳐야 한다. "계산은 한 곳" 원칙 위반

## 추천 — B

A 는 엔진 소스로 탈락(장비 보너스 소멸). C 는 어트리뷰트를 믿을 수 없게 만든다. B 는 F10-02 레벨 성장이 Base 를 Instant 로 올리는 것과 **같은 패턴**이라 새 규칙이 없다.
