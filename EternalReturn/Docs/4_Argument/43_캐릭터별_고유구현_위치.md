## 1. "캐릭터마다 다른 것" 을 종류별로 나누면

F19 개요 · 캐릭터 역기획서(`0_GameDesign/Characters/0N_*.md`)의 고유 요소를 나눴다.

| 종류 | 예 | 성격 | 자연스러운 자리 |
|---|---|---|---|
| **스킬 효과** | 재키 출혈 중첩 · 레니 팀 판정 분기 · 시셀라 체력 코스트 · 카티야 투사체 | 발동 → 판정 → 효과. 쿨 · 코스트 · CC 차단과 엮인다 | **GAS** — 조각(Argument 28) · 조각으로 억지스러우면 **캐릭터 전용 어빌리티 클래스** (`UERGameplayAbility_JackieR`) |
| **지속 상태 · 패시브** | 매그너스 중첩 버프 · 재키 처치 시 쿨 초기화 · 다니엘 표식 | 조건을 듣고 스탯 · 태그를 바꾼다 | **GAS** — P 어빌리티 · GE · 태그 |
| **폰 자체가 달라지는 것** | 매그너스 R **오토바이**(커스텀 이동 · 탈것 메시) · 다니엘 **은신**(가시성 · 메시 숨김) · 시셀라 **소환물** 붙는 자리 · 카티야 **드론**(패시브) | 이동 방식 · 컴포넌트 · 메시 구성이 바뀐다 | **폰** — 캐릭터 C++ 클래스 또는 컴포넌트 |
| **연출** | 모드 자세 · 스킨 · 음성 | 데이터 | 연출 DA (Argument 39 · 42) |

→ 대부분은 **GAS 쪽**이다. 이유: ASC 가 PlayerState 에 있어 **부활해서 폰이 바뀌어도** 어빌리티 · 쿨 · 중첩이 살아남는다 (CLAUDE.md §8 "ASC 배치를 바꾸지 않는다"). 스킬 로직을 폰 클래스에 두면 부활 때마다 상태를 옮겨야 한다.
→ 하지만 **폰 자체가 달라지는 것**(4개 중 적어도 매그너스 · 다니엘)은 폰에 자리가 필요하다 — 여기가 사용자가 말한 "빡센" 지점이다.

## 2. 지금 구조의 진짜 문제 — BP 계층

```
지금:   AERCharacterBase (C++) ─▶ BP_ERCharacterBase (BP · 공통 설정) ─▶ BP_Jackie (BP)
나중에 재키 전용 C++ 가 필요해지면:
        AERCharacterBase ─▶ AERCharacter_Jackie (C++) ─▶ BP_Jackie   ← BP_Jackie 를 이 부모로 Reparent
                                                          ⚠ BP_ERCharacterBase 가 들고 있던 값(메시 위치 · 콜리전 · 이펙트 GE · …)이 빠진다
```

- `BP_Jackie` 의 부모를 `BP_ERCharacterBase` → `AERCharacter_Jackie` 로 바꾸면(Reparent) **`BP_ERCharacterBase` 가 들고 있던 기본값은 더 이상 물려받지 않는다** — 그 값들을 새 부모나 각 BP 에 다시 넣어야 한다
- 캐릭터가 6명일 때 하면 6번 · 24명이면 24번 — **늦게 할수록 비싸다**
- 반대로 스킬 효과는 GAS 쪽이라 언제 만들어도 계층 문제가 없다

## ① 고유 구현의 기본 자리

| 방안 | 방식 | 판정 |
|---|---|---|
| G | 전부 GAS · 폰은 하나 (Lyra 방식 — `ALyraCharacter` 하나 + PawnData) | 스킬 · 패시브는 깔끔. **오토바이 · 은신 · 소환 자리** 같은 폰 차이를 컴포넌트 + 데이터로만 풀어야 한다 — 가능하지만 한 명만 쓰는 컴포넌트가 공용 폰에 쌓인다. ⚠ Lyra 는 캐릭터별 차이가 거의 없다 ([`6_Lyra참조/00_개요.md`](../6_Lyra참조/00_개요.md) 전제 차이 · CLAUDE.md §11) |
| C | 캐릭터 C++ 클래스에 스킬 로직까지 | 부활 · ASC(PlayerState) 와 어긋난다 · 쿨 · 코스트 · CC 차단을 GAS 밖에서 다시 만든다 (CLAUDE.md §8 표 위반) |
| **H** | **섞어 쓰기** — 스킬 효과 · 패시브 = GAS (조각 우선, 억지스러우면 **캐릭터 전용 어빌리티 클래스**) / 폰이 달라지는 것 = **캐릭터 C++ 클래스**(또는 그 클래스가 만드는 컴포넌트) / 연출 = DA | 각자 제자리. 캐릭터 전용 어빌리티 클래스는 Argument 28 "새 기능 = 조각" 의 **예외 통로**로 명시 |

**추천 H.**

## ② 캐릭터 C++ 클래스를 언제 만드나

| 방안 | 방식 | 판정 |
|---|---|---|
| L | 필요해질 때 (F19 매그너스 R 에서) | 그때 BP 계층 재구성 — `BP_ERCharacterBase` 설정을 옮기는 수작업 · 6명이면 6번 |
| **N** | **지금 빈 클래스 6개** `AERCharacter_<Name>` (AERCharacterBase 자식) + **`BP_ERCharacterBase` 의 공통 설정을 C++ 기본값으로 옮기고** `BP_<Name>` 을 `AERCharacter_<Name>` 에 Reparent | 한 번에 정리 · 이후 캐릭터 코드는 자기 클래스에만 · 빈 클래스는 "한 곳에서만 쓰는 추상화"(CLAUDE.md §2)가 아니라 **계층 자리 확보** — 비용은 파일 12개 · 로직 0 |
| N2 | 빈 클래스 없이 `BP_ERCharacterBase` 만 없애고 공통 설정을 C++ 로 (BP_<Name> 부모 = AERCharacterBase) | 나중에 캐릭터 C++ 를 끼울 때 **C++ 부모만 바꾸면 된다**(설정 손실 없음) · 빈 클래스도 안 만든다 — N 과 같은 효과를 필요할 때까지 미룸 |

- N 과 N2 의 공통 핵심: **중간 BP(`BP_ERCharacterBase`)에 설정을 두지 않는다** — 그게 Reparent 비용의 원인
- `BP_ERCharacterBase` 에 무엇이 들어 있는지는 **(미확인)** (애셋 · 바이너리) — 사용자 확인 필요: Class Defaults 에서 부모와 다른 값(노란 화살표)이 있는 항목 목록

**추천 N2** — 빈 클래스를 미리 만들 이유가 "나중에 Reparent 가 비싸서" 뿐인데, 공통 설정을 C++ 로 옮기면 그 비용이 사라진다. 첫 캐릭터 전용 코드가 필요한 순간(F19 매그너스 R 오토바이 · 다니엘 은신) `AERCharacter_Magnus` 하나만 만들고 `BP_Magnus` 의 C++ 부모만 바꾼다.

## 모드 틀(Argument 42) 과의 관계

독립이다 — 모드 연출(자세 · 동작 교체)은 **데이터**라서 캐릭터 클래스가 있든 없든 같다. 모드의 **게임 효과**(전기톱 판정 · 오토바이 이동)는 H 의 GAS / 캐릭터 클래스 쪽에서 만든다.
