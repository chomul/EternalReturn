# 26. 실험체 경험치는 어디서 오나 — 별도 경험치(현재) vs 숙련도 경험치의 합 (원작)

> E18 **A6** · 근거 [`성장_레벨_숙련도_특성_역기획서.md`](../0_GameDesign/Systems/성장_레벨_숙련도_특성_역기획서.md) §3.0 (인게임 확인 2026-09-19) · [`22_실험체레벨_저장형태.md`](22_실험체레벨_저장형태.md)
> 사용자: *"레벨이 사실상 전체 숙련도인데"* — 6종 숙련도 경험치의 합이 실험체 레벨을 올린다. **F11 뒤에 착수** (F10-01 · 04 재설계)

## ⭐ 결정 — (대기)

| 항목 | 추천 |
|---|---|
| 경험치 원천 | **방안 B — 숙련도 적립이 곧 실험체 경험치** (`AddProficiencyExp(Track, Amount)` 한 입구, 실험체 `Exp += Amount × Ratio`) |
| 환산 비율 | (미확인) → **1:1** `[자체]` 로 시작. `UERGrowthSettings.LevelExpPerProficiencyExp = 1.0` 설정값 하나 |
| 트랙 | `EERProficiencyTrack { Weapon×23(무기군), Defense, Hunt, Craft, Search, Move }` — 무기는 지금처럼 **무기군별**, 나머지 5 는 트랙 1개씩 (F10-05) |
| 필요 경험치 | 실험체: `DT_LevelExp` 그대로 (800 · 2,500 확인점) · 숙련도: **`DT_ProficiencyExp` 19행 × 6열** (§3.0 표, CSV 준비됨) |

## 결정할 것

F10-01 은 실험체 경험치를 **별도 파이프라인**으로 만들었다 (`AddExp(Amount, Source)` — 야생동물 · 처치가 값을 직접 넣는다). 인게임 확인으로 원작은 **숙련도가 오르면 실험체도 오른다** 는 것이 드러났다.
"처치 경험치 500" 같은 값도 원작엔 없다 — 처치는 **숙련도**(적 레벨에 따라)로 들어오고, 그게 레벨을 올린다.

---

## 방안 A — 지금 구조 유지 + 숙련도 적립 때 `AddExp` 도 같이 부른다

- 장점: 코드 최소 — `AddWeaponProficiencyExp` 끝에 `AddExp(Amount × Ratio)` 한 줄
- 단점
  - 입구가 둘(`AddExp` · `AddWeaponProficiencyExp`) 이라 "경험치를 직접 넣는" 경로(`PlayerKillExp` · 야생동물 `ExpReward`)가 남는다 → **원작에 없는 경로**가 살아 있어 언젠가 누군가 쓴다
  - 5종 트랙이 추가되면 각각이 `AddExp` 를 부르는 걸 잊기 쉽다

## 방안 B — 숙련도 적립이 유일한 입구

```
UERGrowthComponent
  AddProficiencyExp(FERProficiencyKey Key, float Amount, Reason)     ← 유일한 경험치 입구
    ① 트랙 레벨업 판정 (DT_ProficiencyExp[Track][Lv]) → OnProficiencyLevelUp(Key, Lv)   (무기: D 해금 · 증폭 / 방어 · 사냥 … : 효과 GE)
    ② Exp += Amount × Settings.LevelExpPerProficiencyExp → 실험체 레벨업 (기존 while)
  AddExp(...) 삭제 · PlayerKillExp · Wildlife ExpReward 삭제 — 처치는 "처치 숙련도(적 레벨 함수)" 로만
FERProficiencyKey { EERProficiencyTrack Track; EERWeaponType Weapon (Track==Weapon 일 때) }
```
- 장점
  - ⭐ **원작 구조 그대로** — "레벨 = 전체 숙련도" 가 코드에서도 참
  - 입구 하나. 트랙이 늘어도 실험체 경험치는 자동으로 따라온다
  - 디버그 `ER.Growth.AddExp` 는 `ER.Growth.ProfExp <Track> <n>` 로 흡수
- 단점
  - F10-01 · 04 · F12-02 문서 · 디버그 · 검증 로그를 다시 쓴다
  - 환산 비율이 (미확인) — 1:1 이면 800 (Lv.2) 은 무기 숙련도 Lv.2 (500) 보다 늦다. 인게임 관측으로 보정

## 방안 C — 실험체 경험치를 없애고 레벨 = f(숙련도 레벨 합)

- 단점: "사실상" 이지 정확히 함수라는 근거가 없다. 6종 레벨 합으로 20 을 만드는 규칙을 지어내야 한다 — 탈락

## 추천 — B

A 는 원작에 없는 경로를 남긴다. B 는 재작업이 있지만 F10 이 통째로 "숙련도 6종 + 레벨" 로 정리되고, F10-05(5종 트랙) 가 같은 구조에 얹힌다.
