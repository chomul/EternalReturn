# 33. 몸 충돌 · 클릭 · 스킬 판정을 한 형상으로 할까 — 채널 분리

> F12-01 · 제기: 사용자 2026-09-23 (원작 대조) — *"몬스터의 실제 플레이어랑 부딪히는 콜리전은 거의 캡슐 정도로 작은데, 마우스로 클릭하는 범위는 HitBox 크기 정도는 되는 거 같음. 근데 또 스킬 같은 거 쓰면 HitBox 에 막히는 게 느껴져"*
> 관련 [`32_사거리_측정기준_중심_vs_가장자리.md`](32_사거리_측정기준_중심_vs_가장자리.md) · `Docs/Argument/2. 판정 콜리전 설계.md`(SkillTarget 채널) · E13(커서 트레이스)

## ⭐ 결정 — 2026-09-23 **클릭 전용 채널 `Select` 신설** (사용자 "진행하자")

## 문제

원작의 야생동물은 **세 가지가 서로 다른 크기**다.

| 상호작용 | 원작 (사용자 관측) | 우리 (2026-09-23 이전) |
|---|---|---|
| 몸 부딪힘 · 이동 차단 | **캡슐 정도로 작다** | ❌ HitBox 가 막는다 — 곰 앞 1.5m 에서 걸음이 멈춘다 |
| 마우스 클릭 대상 선택 | **히트박스만큼 크다** | ✅ HitBox (`ECC_Pawn` 트레이스) |
| 스킬 판정 | 히트박스에 막힌다 | ✅ HitBox (`SkillTarget`) |

원인은 **`ECC_Pawn` 하나가 "물리 차단"과 "클릭 트레이스"를 겸하는 것**이다 (`ERPlayerController` 는 커서 아래를 `ECC_Pawn` 으로 쟀다 — 캡슐이 Visibility 를 무시하기 때문, E13).
HitBox 의 Pawn 응답을 끄면 클릭이 죽고, 켜면 몸이 막힌다. **한 채널로는 못 나눈다.**

## 방안 A — 히트박스를 없애고 캡슐 하나로 되돌린다

- 장점: 채널 그대로 · 가장 단순
- 단점: 캡슐은 반지름 ≤ 반높이라 **가로로 긴 몸(늑대 2.9m · 곰 3.0m)** 을 못 담는다 — 히트박스를 넣은 이유 자체가 사라진다 (F12-01 · 사용자 2026-09-22). 클릭·판정이 다시 작아진다

## 방안 B — 히트박스는 두고 물리만 끈다 (Pawn 응답 Ignore)

- 장점: 코드 한 줄
- 단점: **클릭이 같이 죽는다** — 커서 트레이스가 Pawn 채널이라 히트박스를 못 잡는다. 캡슐만 남아 클릭 범위가 원작보다 작아진다

## 방안 C — 클릭 전용 트레이스 채널 `Select` 를 판다 ⭐ 추천 · 채택

| 컴포넌트 | `Pawn` (물리) | `SkillTarget` (판정) | **`Select` (클릭)** |
|---|---|---|---|
| 실험체 캡슐 | Block | Overlap *(현행)* | **Block** — ini `EditProfiles` Pawn 에 추가 |
| 야생동물 캡슐 | Block (몸 부딪힘 · 이동) | Ignore | Ignore |
| 야생동물 HitBox | **Ignore** | **Overlap** | **Block** |

- 커서: `GetHitResultUnderCursor(Select)` → 못 찾으면 기존대로 `Visibility`(지형). 지형은 Select 를 무시하므로 순서가 꼬이지 않는다
- ⭐ HitBox 의 SkillTarget 을 **Block → Overlap 으로 내렸다**: `QueryProjectile` 은 `SweepMultiByChannel` 이라 Block 이면 **스윕이 첫 몸에서 끊겨** 관통 스킬(망치 D 직선 관통)이 죽는다.
  ⚠ **관통 여부는 채널이 아니라 스킬 데이터 `bPenetrate` 가 정한다** (`ERTargeting::QueryProjectile` — 비관통이면 정렬 후 **가장 가까운 하나만** 남긴다).
  그래서 Overlap 으로 내려도 저격 · 권총 같은 비관통 투사체는 **앞의 몸에서 멈춘다** (2026-09-23 05:09 로그: 저지사격 · 데드아이 모두 `적중 1`). 사용자 확인 사항 — "저격 D 는 관통하면 안 된다" 는 지금 구조에서 이미 만족한다
- 장점: 세 가지가 서로 독립 · 실험체 경로는 그대로 · 야생동물 외 액터(설치물)도 같은 규칙으로 확장 가능
- 단점: 커스텀 채널을 하나 더 쓴다 (18개 중 2개째) · `Config/DefaultEngine.ini` 수정 (§9 보고 대상)

## 이 변경이 건드릴 수 있는 곳 — 전수 점검 (2026-09-23)

| 경로 | 쓰는 채널 | 영향 |
|---|---|---|
| 지면 클릭 이동 `OnMoveToCursor` · `ResolveNavigableDestination` | `Visibility` | 없음 — 건드리지 않았다 |
| 스킬 조준 (커서) `ERPlayerController:201` | `Pawn` → **`Select`** | ⚠ 실험체는 **Pawn 프로파일**이어야 잡힌다 (ini `EditProfiles` 로 Select=Block). BP 에서 캡슐이 **Custom** 으로 바뀌어 있으면 Select 가 Ignore 로 들어가 **클릭 선택이 죽는다** → 검증 ④ 로 확인 |
| 반경 · 부채꼴 · 이중반경 `OverlapMultiByChannel(SkillTarget)` | `SkillTarget` | 없음 — 오버랩 쿼리는 Overlap 응답도 결과에 넣는다 (HitBox 가 Block→Overlap 이어도 그대로 잡힌다) |
| 투사체 `SweepMultiByChannel(SkillTarget)` | `SkillTarget` | **좋아짐** — Block 이면 스윕이 첫 몸에서 끊겼다. 비관통은 여전히 가장 가까운 하나만 (`bPenetrate`) |

| 야생동물 몸 충돌 · 이동 | `Pawn` | **의도한 변화** — HitBox Pawn Ignore 라 캡슐 크기에서만 막힌다. 동물끼리도 캡슐로 막히므로 04 AI 에 문제 없다 |
| 사거리 `DistanceToSurface` | `SkillTarget` 응답 조회 | **범위가 넓어졌다** (`== Block` → `!= Ignore`) — 실험체 캡슐(Overlap)이 이제 표면 기준. 대인 사거리가 대상 캡슐(0.34m)만큼 후해진다 (Argument 32 결정대로) |
| 드랍 · 상자 | BP 설정 | Select 응답이 없어 커서 Select 트레이스는 통과 → 기존처럼 `Visibility` 폴백이 잡는다. 클릭 이동 후 근접 획득 경로는 그대로 |
| `HitBox` 오브젝트 타입 `ECC_Pawn` | — | 코드에 `ByObjectType` 쿼리가 없어 영향 없음 (채널 응답만 본다) |

## 검증 (PIE 2인 · `Docs/3_EditorTasks/F12_야생동물.md`)

1. 늑대 **몸통을 통과해 걸어간다** (캡슐 크기에서만 막힌다)
2. 몸 끝(캡슐 밖)을 클릭 → 대상 지정 · 평타 `적중 1`
3. **저격 D 는 관통하지 않는다** — 늑대 뒤에 대상이 있어도 앞의 늑대만 맞는다 (사용자 2026-09-23). 관통은 `bPenetrate` 가 켜진 스킬(망치 D 등)만
4. **실험체끼리 클릭 · 평타** — 가장 중요한 회귀 검사다. 안 잡히면 실험체 BP 캡슐 프로파일이 `Custom` 이라는 뜻 → BP 에서 `Select = Block` 을 켠다
