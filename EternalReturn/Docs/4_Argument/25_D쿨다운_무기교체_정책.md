## 방안 C — 슬롯 승계 (지금 구조 그대로, 코드 0줄)

F07-02 의 쿨다운 GE 는 `Cooldown.Slot.D` **슬롯 태그**를 준다. 망치 D 를 쓰고 방망이로 바꾸면 그 GE 가 ASC 에 남아 방망이 D 도 막는다 = 남은 시간이 새 D 로 넘어간다.
- 장점: 코드 없음 · "D 두 번" 익스플로잇 없음
- 단점 ⚠ **반대 방향 익스플로잇**: 도끼 D(쿨 7초) 를 쓰고 석궁(쿨 40초)으로 바꾸면 **7초 뒤 석궁 D** 가 나간다. 긴 쿨 무기의 D 를 짧은 쿨 무기가 열어 준다. 역기획서 §8.2 "무기별 쿨다운 편차(5초 vs 40초)를 무시" 가 이것

## 방안 B — 무기별 보존 + 스왑 락 (역기획서 제안)

```
D 스킬 데이터: CooldownTagOverride = Cooldown.Weapon.Hammer   ← 슬롯 태그 대신 (UERSkillData 필드 하나, [자체])
  → 망치 D 쿨다운 GE 는 Cooldown.Weapon.Hammer 만 준다. 방망이 D 는 Cooldown.Weapon.Bat 만 본다 → 서로 안 막는다
  → 망치로 돌아오면 GE 가 아직 있으니 남은 시간 그대로 (보존)
스왑 락: 무기 교체 순간 서버가 UERSkillPhaseEffect(HasDuration, State.WeaponSwapLock) 를 SwapLockSeconds 만큼
  → UERGameplayAbility::CanActivateAbility 가 Slot.D 이고 그 태그가 있으면 false. Q/W/E/R · 평타는 무관
```
- 장점
  - 쿨다운이 **무기 계열에 귀속** — 데이터 구조가 자연스럽다 (쿨 값이 무기마다 다른 이유와 일치)
  - C 의 반대 익스플로잇이 없다. B 의 "2무기 D 두 번" 은 락 하나로 막는다
  - `ER.Skill.Cooldown` · UI 는 어빌리티의 `GetCooldownTags()` 를 읽으므로 태그가 바뀌어도 그대로
- 단점
  - 태그 8개(초기 계열) 선언 + 스킬 데이터 필드 1 + 락 GE 적용 코드 — 작지만 있다
  - 락 시간이 `[자체]` — 원작에 교체 딜레이가 있는지 (미확인)

## 비교

| | C 승계 | B 보존 + 락 |
|---|---|---|
| 코드 | 0 | 태그 8 · 필드 1 · 락 ~30줄 |
| 짧은 쿨 → 긴 쿨 무기 즉시 사용 | ⚠ 가능 | 불가 (자기 쿨 그대로) |
| 2무기 D 연속 | 불가 | 락 시간 동안 불가 |
| 복귀 시 남은 쿨 | 슬롯 것 | **그 무기 것** |

## 추천 — B

C 의 반대 익스플로잇(도끼 7초로 석궁 40초를 여는 것)이 실제 플레이에서 더 크다 — 2무기 캐릭터가 도끼를 "쿨 리셋용" 으로 든다. B 는 역기획서 제안 그대로이고 비용이 작다.
