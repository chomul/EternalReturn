## 구현 (2026-10-12 · Editor · Server 빌드 ✅)

- **D4 를 바꾼 이유:** 모디파이어 태그 조건은 **어그리게이터가 다시 계산될 때만** 다시 본다 (`GameplayEffectAggregator.cpp:357-371` — Evaluate 마다 EvaluateQualificationForAllMods). 태그만 붙는 GE 는 이속 어그리게이터를 더럽히지 않아 재계산이 보장되지 않는다 (미확인 — 잴 필요 없이 피했다). → **태그 이벤트**(`RegisterGameplayTagEvent State.DownedSkill.Obstinacy`)에서 빈사 GE 의 SetByCaller 를 `UpdateActiveGameplayEffectSetByCallerMagnitude` 로 바꾼다 (`AbilitySystemComponent.h:414` — 엔진이 모디파이어를 다시 모은다). 태그가 이속을 정한다는 M1 의 뜻은 그대로
- **태그 이름:** `State.DownedSkill.*` — `State.Downed.*` 아래에 두면 부모 일치로 `IsDowned()` 가 참이 된다 (집념 3초가 소생 뒤에 남으면 "빈사" 로 보임)
- **Q · R 은 선딜(CastTime)이 아니라 조각이 활성 유지:** 선딜은 끝에서 코스트를 낸다 (`ERGameplayAbility.cpp` ExecuteAndRecover) — 원작은 쓰는 순간 체력이 빠진다. 그래서 즉발로 커밋하고 조각이 4초 · 20초를 `UAbilityTask_WaitDelay` 로 잡는다 (사망 취소에 같이 죽는다 — Delivery 의 JudgeDelay 는 월드 타이머라 사망 뒤에도 터진다)
- 새 코드: `UERDownedAbility` · 조각 `TimedTag`(W) · `FuseBlast`(Q) · `SelfRevive`(R) · 코스트 `HPCurrentRatio` · 조각 훅 `CancelOnReinput` · PC `ResolveDownedSlot` · PS `SelfDestruct` · `OnObstinacyChanged` · ER Combat `DownedSkills` · `DownedObstinacyMoveSpeedBonus`

## D2. 입력 — Q · W · R 이 빈사 중에는 빈사 스킬로

**문제:** 입력은 슬롯 태그가 맞는 스펙을 찾아 **첫 번째에서 선판정하고 끝낸다** — 실패하면 `return` (`Source/EternalReturn/Core/ERPlayerController.cpp:250-275`). 빈사 Q 가 일반 Q 와 같은 `Ability.Slot.Q` 면 일반 Q 가 먼저 걸려 `클라 선판정 실패` 로 끝날 수 있다 (순서는 부여 순서).

### I1. 별도 슬롯 태그 + 입력에서 바꿔 끼우기 (추천)
`Ability.Slot.Downed.Q/W/R` 태그를 새로 두고, 입력이 빈사면 슬롯을 바꾼다 — 이미 있는 `ResolveModeSlot` (`ERPlayerController.cpp:132-144`, D 모드 중 재입력 = 사격) 과 같은 방식.
```cpp
// ResolveModeSlot 옆 — 빈사면 Q/W/R → Downed.Q/W/R
if (ASC.HasMatchingGameplayTag(ERTags::State_Downed))
{
    if (SlotTag == ERTags::Ability_Slot_Q) return ERTags::Ability_Slot_Downed_Q;
    ...
}
```
- 장점: 일반 스킬과 빈사 스킬이 절대 안 섞인다 · 기존 패턴 재사용 · 선판정 로그가 그대로 빈사 스킬을 찍는다
- 단점: 태그 3개 추가 · 입력 쪽에 빈사 분기 한 곳

### I2. 같은 슬롯 태그 + 선판정 루프가 실패 스펙을 건너뜀
- 장점: 태그 추가 없음
- 단점: 루프를 "실패하면 다음" 으로 바꾸면 **쿨다운 중인 일반 Q 의 실패 로그**가 사라진다 (그 로그로 E41 을 잡았다) · 어느 스펙이 이길지가 부여 순서에 달림

### I3. 빈사 때 부여 · 소생 때 회수
- 장점: 빈사가 아니면 스펙 자체가 없다
- 단점: 부여 · 회수가 복제 왕복 — 쓰러진 직후 클라에 스펙이 아직 없어 첫 입력이 헛돈다 · 쿨다운 GE 는 남는데 스펙이 없어지는 모양 (R 실패 반환 계산이 꼬인다) · 결국 키 충돌은 I1 · I2 문제를 그대로 가진다

## D4. 집념의 이속 +100%

**문제:** 빈사 이속은 **Override 1** 이다 (`Source/EternalReturn/GAS/ERDownedEffects.cpp:24-25` — 둔화 · 이속 버프를 다 덮으려고). GAS 는 Override 가 있으면 **처음 자격 있는 Override 하나**로 값을 정하고 다른 모디파이어를 무시한다 (`Engine/.../GameplayEffectAggregator.cpp:60-63`). 그냥 +100% GE 를 얹으면 **안 먹는다** (조용히).

### M1. 빈사 GE 에 태그 조건 모디파이어 (추천)
빈사 GE 의 Override 를 둘로: `1` (대상 태그 Ignore `State.Downed.Obstinacy`) · `2` (Require `State.Downed.Obstinacy`). 집념은 3초짜리 태그 GE 만 붙인다.
- 장점: 이속 규칙이 빈사 GE 한 곳 · 모디파이어 단위 태그 조건은 GAS 기본 기능 (`FGameplayModifierInfo::TargetTags`) · 태그가 빠지면 자동 복귀
- 단점: "+100%" 가 곱이 아니라 "2 로 덮기" — 빈사 이속이 1 이 아니게 바뀌면 값을 같이 고쳐야 한다 (SetByCaller 로 `빈사 이속 × 2` 를 넣어 완화)

### M2. 집념 GE 가 자기 Override 를 더 앞에 둠
- 단점: 어느 Override 가 "처음" 인지가 적용 순서에 달림 (`:60` 루프) — 보장 안 됨

### M3. 평가 채널 (Evaluation Channel) — Override 뒤 채널에서 ×2
- 장점: 진짜 곱
- 단점: `AbilitySystemGlobals` 설정에서 채널을 켜야 하고 (`bAllowGameplayModEvaluationChannels`) 전 프로젝트 GE 평가에 영향 — 한 스킬 때문에 켜기엔 큼

## 2. 네트워크

- 전부 **서버 권위** — 발동은 지금처럼 클라 선판정 → 조준 실어 서버 (`ERPlayerController.cpp:245`) · 예측 없음 (§8)

## 3. 검증

1. 빌드 Editor · Server 통과
2. PIE 4인: 빈사 → W → `[스킬] … 집념` · 이속 1 → 2 (3초) → 1 · HP −10%
3. Q → 4초 뒤 반경 안 적 HP `150 + 20%` 감소 · 본인 사망 · 처치 = 빈사로 만든 사람 / 4초 안에 맞아 죽으면 폭발 로그 없음
