# 35. 야생동물 AI 를 무엇으로 만들까 — 비헤이비어 트리 vs C++ 상태 머신

> F12-04 · 역기획서 몬스터 §7.2 (AI 는 서버에만) · §7.3 (도먼시 전환 = AI 상태 전환) · [`31`](31_야생동물_ACharacter_vs_APawn.md) (유휴 시 CMC 틱 끔이 ACharacter 유지 조건)
> 전제: 역기획서 결론 — *"야생동물은 AI 가 중요한 게 아니라 스폰 · 리젠 · 드랍이 중요하다"*. 상태는 **대기 · 전투 · 귀환** 셋뿐이다.

> ⭐ 원작 규칙 [확인] (사용자 2026-09-24 · 역기획서 §6.5): **선공 없음** · 대상 = 때린 팀의 가장 가까운 사람 · 자리 10m (움직이는 종은 맞은 지점) · 귀환 시 회복 · 무리 전체.
> → 선공이 없으니 **감지(Perception)가 필요 없다.** 깨우는 계기는 피격 이벤트 하나다 — 방안 A 가 더 유리해졌다.

## 결정할 것

대기 → (피격 / 감지) → 전투(추적 · 평타) → (범위 이탈) → 귀환 → 대기. 이 셋을 무엇으로 굴리나.

## 방안 A — C++ 상태 머신 (`AERWildlifeAIController`) ⭐ 추천

```cpp
enum class EERWildlifeAIState : uint8 { Idle, Combat, Return };
// 생각 주기 0.25초 타이머 (Tick 없음) — Idle 에서는 타이머도 끈다: 깨우는 건 피격 이벤트(OnDamageTaken) · 선공 감지 오버랩
// Combat: 대상 거리 > 사거리 → MoveToActor · 안이면 StopMovement + 평타 어빌리티 발동 (조준 = TargetData, 플레이어와 같은 경로)
// Return: MoveToLocation(자리) → 도착 = Idle + 체력 회복 + DormantAll + CMC · 메시 틱 끔
```
- 장점: 상태 3개 · 전이 5개라 코드 150줄 안팎. **애셋(BT · 블랙보드) 이 없다** — Content 는 사용자 작업인데, 로직을 BT 애셋에 두면 매번 에디터 작업이 필요하다 (CLAUDE.md §7: 로직은 C++)
- 장점: 도먼시 · 틱 on/off 를 **상태 전이 함수 한 곳**에서 한다 (§7.3 "AI 와 복제가 같은 이벤트") — Argument 31 의 필수 조건(유휴 CMC 틱 끔)이 구조로 보장된다
- 장점: 대기 중인 120~200마리는 **타이머조차 안 돈다** (이벤트로만 깨어남)
- 단점: 보스 패턴(05)처럼 복잡해지면 상태가 늘어난다 — 그때 보스만 BT/StateTree 로 가도 된다

## 방안 B — 비헤이비어 트리 + 블랙보드

- 장점: 엔진 표준 · 시각 디버거 · 보스 패턴 확장에 유리
- 단점: BT · 블랙보드 **애셋**이 필요 (Content — 사용자 작업) · 커스텀 태스크(평타 발동 · 귀환 회복 · 도먼시)를 C++ 로 짜서 BT 에 꽂아야 해서 결국 코드 + 애셋 두 곳 · BT 컴포넌트가 **대기 중에도 틱**한다 (끄려면 따로 관리)

## 방안 C — StateTree

- 장점: 5.4 에서 권장되는 차세대 · 상태 머신 모양에 맞음
- 단점: 플러그인 추가(§9 보고) · 애셋 필요 · 팀에 경험 없음 — 상태 3개에 비해 도입 비용이 크다

## 비교표

| | A C++ 상태 머신 | B BT | C StateTree |
|---|---|---|---|
| 구현 | 코드만 (~150줄) | 코드 + BT/BB 애셋 | 플러그인 + 코드 + 애셋 |
| 대기 200마리 비용 | 0 (타이머 없음 · 이벤트로 깨움) | BT 틱 관리 필요 | 관리 필요 |
| 도먼시 · 틱 전환 | 전이 함수 한 곳 | 태스크에 분산 | 분산 |
| 보스 패턴 확장 | 상태 늘리기 | 강함 | 강함 |

## 애니메이션을 같이 생각하면 (사용자 질문 2026-09-24)

**AI 선택과 애니메이션은 거의 독립이다.** AI 는 "무엇을 할지"만 정하고, 모션은 다른 층이 낸다:
- 걷기 · 뛰기 · 대기 = AnimBP 가 **속도**를 읽는다 → AI 가 `MoveTo` 만 하면 저절로 나온다 (A · B 같음)
- 공격 모션 = **평타 어빌리티가 몽타주를 튼다** → AI 는 "어빌리티가 끝났나" 만 본다 (A · B 같음)
- 사망 · 기절 = 복제 상태 → AnimBP (AI 무관)

BT 가 애니메이션에서 이득을 보는 경우는 "공격 전에 포효 → 3초 뒤 돌진" 같은 **연출 순서가 AI 의 일부**인 보스 패턴뿐이다. 일반 야생동물은 해당 없음.
