# 7. 체력 비례 피해 감쇠를 어떻게 판별할 것인가

> 작성일 2026-09-09 · 대상 기능 [`../1_Task/F03_데미지_ExecutionCalc/06_체력비례피해_감쇠계수.md`](../1_Task/F03_데미지_ExecutionCalc/06_체력비례피해_감쇠계수.md)
> 작성 근거: `CLAUDE.md` §1.2

## 결정할 것

**"이 대상은 체력 비례 피해를 50%만 받는다"를 Execution 이 어떻게 아는가.**

⚠ 여기서 말하는 **감쇠**는 **피해량**이 줄어드는 것이다.
[`6_흡혈_적용경로⭐.md`](6_흡혈_적용경로⭐.md) 의 **치유 감소**(회복량이 줆)와 다른 것이다.

## 왜 반드시 필요한가

> *"**위클라인은 체력 비례 피해를 50%만 받는다.**
> 이 한 줄이 없으면 게임이 무너진다. (…) 보스는 체력이 압도적으로 높으므로,
> 비례 피해에 감쇠가 없으면 **탱커 한 명이 보스를 혼자 녹인다.**"*
> — [몬스터 문서 §5.1](../0_GameDesign/Systems/몬스터_야생동물_역기획서.md)

매그너스 W 하나가 11타 × 최대 체력 2.5% = **27.5%** 다. 감쇠 없이는 보스가 네 번 맞고 죽는다.

## ⭐ 지금의 요구사항을 정확히 보자

조사 결과 **(2026-09-09)**:

| | |
|---|---|
| 감쇠를 받는 대상 | ⭐ **위클라인 하나뿐** (알파·오메가는 언급 없음 — 몬스터 문서 §5 표) |
| 감쇠 계수 | **0.5 한 개** |
| 장비가 비례 피해를 줄이는 사례 | ⭐ **없음** — `grep "비례 피해" 장비_아이템_역기획서.md` → **0 건** |
| 0.5 의 근거 | ⚠ *"커뮤니티 자료 기반. 공식 확인 안 됨"* — **(미확인)** |

⚠ **마지막 줄이 중요하다.** 이 값은 확인되지 않았고, **밸런싱하며 바뀔 가능성이 높다.**

## 방안 A — 태그 + C++ 상수

```cpp
float ProportionalScale = 1.f;
if (TargetTags.HasTag(ERTags::Actor_Type_Boss))
{
    ProportionalScale = 0.5f;
}
```

**장점**

- 가장 단순하다. 어트리뷰트도 설정도 안 늘어난다
- ⭐ `Cast<ABossActor>` 를 안 하므로 **F03 이 F12 에 의존하지 않는다**

**단점**

- ⚠ **0.5 가 C++ 상수다.** 미확인 값인데 바꾸려면 **재빌드**해야 한다
- ⚠ 대상 종류가 늘면 `if` 가 늘어난다 (구조물 0.7, 정예 야생동물 0.8 …)
- 장비·버프로 비례 피해를 줄이는 것은 불가능

---

## 방안 B — Target 어트리뷰트 `ProportionalDamageTakenMul`

Task 문서가 *"더 나은 방법"* 이라고 적어 둔 쪽이다.

```cpp
float Scale = 1.f;
ExecParams.AttemptCalculateCapturedAttributeMagnitude(S.ProportionalDamageTakenMulDef, EvalParams, Scale);
```

**장점**

- ⭐ **완전히 데이터 주도.** 보스의 초기값 GE 가 0.5 를 넣으면 끝. 코드에 상수가 없다
- ⭐ **장비·버프가 GE 로 조정할 수 있다.** "비례 피해 저항 아이템" 이 자연스럽게 된다
- 대상 종류가 늘어도 코드를 안 고친다 (각자 자기 값을 갖는다)

**단점**

- ⚠ **34번째 어트리뷰트가 된다.** [`3_어트리뷰트셋_구조⭐.md`](3_어트리뷰트셋_구조⭐.md) E-6 에서
  "야생동물도 33개를 그대로 쓴다"고 정했으므로, **야생동물 200마리가 전부 이걸 들고 다닌다**
- ⚠ **기본값이 1.0 이어야 한다.** 초기화 GE 가 0 을 넣으면 **비례 피해가 전부 사라진다.**
  33개는 전부 기본 0 인데 이것만 1 이다 — 데이터 테이블에서 빠뜨리기 쉬운 형태다
- ⚠ **지금 이 유연성을 쓸 데가 없다.** 장비 사례 0건, 대상 1종 (`CLAUDE.md` §2 — 추측성 코드 금지)

## 방안 C — 태그로 판별하고, 계수는 설정에서 ⭐ 추천

```cpp
float ProportionalScale = 1.f;
if (TargetTags.HasTag(ERTags::Actor_Type_Boss))
{
    ProportionalScale = UERStatCapSettings::Get().BossProportionalDamageScale;
}
```

계수를 이미 있는 `UERStatCapSettings` 에 넣는다. **그 클래스에는 미확인 값을 모으는 자리가 이미 있다:**

```cpp
// ERStatCapSettings.h:53
UPROPERTY(config, EditAnywhere, Category = "자체 결정값 (미확인)", meta = (ClampMin = "0.0"))
float MaxCritChance = 1.0f;
```

**장점**

- ⭐ **미확인 값이 재빌드 없이 조정된다.** Project Settings > Game > ER Stat Caps 에서 바로 바꾼다
- ⭐ **이미 있는 구조를 쓴다.** 새 클래스도 새 어트리뷰트도 없다
- `(미확인)` 카테고리에 들어가므로 **에디터에서 "이건 검증 안 된 값" 이 보인다**
- A 와 같은 이유로 F03 이 F12 에 의존하지 않는다

**단점**

- ⚠ **클래스 이름이 "Stat **Caps**" 인데 이건 상한이 아니다.** 이름과 내용이 어긋난다
  (다만 이미 `MinMoveSpeed` 도 상한이 아니다 — 실질은 "프로젝트 전역 밸런스 상수" 다)
- 대상 종류가 늘면 설정 항목이 늘어난다 (B 만큼 유연하지는 않다)
- 장비로 조정하는 것은 여전히 불가능

## ⭐ 결정 — **방안 C** (확정 2026-09-09)

사용자 판단: *"C로 가자"*

| | |
|---|---|
| 판별 | 태그 `Actor.Type.Boss` |
| 계수 | `UERStatCapSettings::BossProportionalDamageScale` (기본 **0.5**, `"자체 결정값 (미확인)"` 카테고리) |
| 어트리뷰트 | **33개 유지** |

### 추천 근거 (원문)

세 가지 이유다.

1. **0.5 가 미확인 값이다.** 밸런싱하며 바뀔 값을 C++ 상수로 두면(A) 그때마다 재빌드다.
   `ERStatCapSettings` 에는 이미 미확인 값을 모으는 자리가 있고, 이건 그 자리에 딱 맞는다
2. **B 의 이점을 지금 쓸 데가 없다.** 장비가 비례 피해를 줄이는 사례가 **문서에 0건**이고,
   감쇠 대상은 위클라인 **하나**다 (`CLAUDE.md` §2)
3. ⚠ **B 에는 조용히 틀리는 함정이 있다.** 기본값이 1.0 이어야 하는데
   나머지 33개는 전부 0 이다. 초기화 데이터에서 빠뜨리면 **비례 피해가 통째로 사라지고**,
   증상은 "매그너스 W 가 약하다" 정도로만 보인다

### 되돌리기 비용

낮다. C → B 로 옮기려면 어트리뷰트 하나와 캡처 하나를 추가하고
`ProportionalScale` 을 읽는 줄만 바꾸면 된다. **태그(`Actor.Type.Boss`)는 그대로 쓴다** —
B 로 가도 "보스인지" 를 아는 데 태그가 필요하기 때문이다.

⭐ **재검토 조건:** 장비·버프가 비례 피해를 줄이는 요구가 실제로 나오면 B 로 옮긴다.

## 어느 방안이든 함께 지킬 것

### ⭐ 감쇠는 **비례 피해에만** 곱한다

```cpp
// 3-b 단계에서만
float Prop = TargetMaxHP * MaxHPRatio + TargetHP * CurHPRatio + SourceLostHP * LostHPRatio;
Prop *= ProportionalScale;      // ← 여기
Raw += Prop;                    // 일반 피해와 합치기 전에
```

⚠ 일반 피해에 곱하면 **보스가 모든 피해를 절반만 받는** 완전히 다른 게임이 된다.
Task 문서가 *"가장 위험한 실수"* 로 지목한 항목이다.

### ⭐ 「최대」와 「현재」를 혼동하지 않는다

| 사례 | 기준 |
|---|---|
| 매그너스 W · E, 레니 R, 채찍 D | 대상 **최대** 체력 |
| **재키 Q**, 다니엘 단검 D | 대상 **현재** 체력 |
| 시셀라 R, 재키 R | **자신의 잃은** 체력 |

⚠ 재키 Q 를 최대 체력으로 계산하면 **처형기가 된다** — 성격이 정반대가 된다.

### 새로 필요한 태그

| 태그 | 누가 |
|---|---|
| `Actor.Type.Boss` | 보스 액터가 갖는다 (F12 책임). Execution 은 태그만 본다 |

⭐ `Cast<ABossActor>` 를 하면 **F03 이 F12 에 의존**한다. 그러면 야생동물이 없는 지금 F03 을 끝낼 수 없다.

### 새로 필요한 SetByCaller 키

| 태그 | 뜻 |
|---|---|
| `Data.Damage.MaxHPRatio` | 대상 최대 체력 비례 계수 |
| `Data.Damage.CurHPRatio` | 대상 현재 체력 비례 계수 |
| `Data.Damage.LostHPRatio` | 자신의 잃은 체력 비례 계수 |
