## 결정할 것

① **"시전 중" · "후딜 중" 이라는 상태를 무엇으로 표현하는가** — 다른 클라도 봐야 하고(§4.2 "시전 상태 복제"), 서버 타이머가 진실이어야 한다.
② **CC 가 오면 누가 채널링을 끊는가** — F06-03 은 "GE 의 CancelAbilitiesWithTag" 를 전제했는데, ⚠ **그 기능은 GE 에 없다.**
   GE 는 `BlockAbilitiesWithTags` 만 한다 (`GameplayEffect.cpp:4279` — 새 발동을 **막을** 뿐 **진행 중인** 어빌리티를 끊지 않는다).

## 논점 ① — 시전 상태 표현

### A. 네이티브 GE 하나 + 동적 부여 태그 (16번 패턴)

```
UERSkillPhaseEffect : HasDuration, 길이 = SetByCaller, 태그 없음
  선딜: DynamicGrantedTags = { State.Casting, (State.Block.Movement — 이동취소형이 아니면) }
  후딜: DynamicGrantedTags = { State.Recovering }
```
어빌리티가 페이즈 진입 때 적용하고, 끝나면 핸들로 제거. 기다림은 `UAbilityTask_WaitDelay`.

- 장점: **Mixed 모드에서 부여 태그는 전원에게 복제**된다 (`AbilitySystemComponent.h:87`) → "다른 플레이어가 시전 중임을 본다" 공짜 · 길이가 서버 GE 라 진실이 서버 · `ER.CC.List` 같은 기존 도구에 보인다 · Block.Movement 가 F06 배선을 그대로 탄다
- 단점: 페이즈마다 GE 적용/제거 2회 · WaitDelay 와 GE 만료가 **둘 다** 시간을 세므로 끝낼 때 GE 를 명시적으로 지워야 한다(어긋남 방지)

### B. 복제 루즈 태그 (`AddReplicatedLooseGameplayTag`) + WaitDelay

- 장점: GE 없이 태그만. 코드 짧다
- 단점: ⚠ 루즈 태그는 **지속시간이 없다** — 어빌리티가 죽거나(EndAbility 누락) 하면 태그가 남는다 · 이동 차단을 같이 걸려면 태그 2개를 손으로 관리 · 클라 UI 가 "남은 시전 시간" 을 알 수 없다(GE 면 `GetActiveEffectsTimeRemaining`)

### C. `ActivationOwnedTags`

- 장점: 어빌리티 애셋 필드 하나
- 단점: ⚠ **어빌리티 전체 수명** 동안 붙는다 — 선딜/후딜을 구분 못 한다 · 복제는 `bReplicateActivationOwnedTags` 전역 설정(`AbilitySystemGlobals.h`)에 달려 있다

## 논점 ② — CC 취소 경로

### A. 어빌리티가 `UAbilityTask_WaitGameplayTagAdded(State.Block.Skill)` 로 스스로 끊는다

```cpp
// 선딜 진입 시
WaitTag = UAbilityTask_WaitGameplayTagAdded::WaitGameplayTagAdd(this, ERTags::State_Block_Skill);
WaitTag->Added.AddDynamic(this, &ThisClass::OnCastInterrupted);   // -> CancelAbility
```

- 장점: **태그가 어디서 오든** 끊긴다 (CC GE · 디버그 `ER.CC.Block Skill` · 나중의 아이템 효과) · F06-01 의 "차단 축 = State.Block.*" 설계와 정확히 같은 축 · `UAbilityTask` 라 CLAUDE.md §8 준수 · CC 라이브러리가 어빌리티를 몰라도 된다
- 단점: 어빌리티마다 태스크 하나 더 (인스턴스당 1개, 무시할 비용)

### B. `ERCC::ApplyCC` 가 적용 직후 `TargetASC->CancelAbilities(&{Ability.Form.Channeled})`

- 장점: 한 줄
- 단점: ⚠ ApplyCC 를 안 거치는 경로(디버그 · 향후 아이템 GE)는 안 끊긴다 · `CancelAbilities` 는 **클래스 AbilityTags** 를 본다 → 애셋마다 `Ability.Form.Channeled` 를 넣어야 하고 빠뜨리면 조용히 안 끊긴다 (E09·E10 계열 실수를 다시 유발)
- F06-03 문서의 전제가 이쪽이었지만 **"GE 가 끊는다" 는 애초에 틀린 전제**였다

## 추천 — **①A + ②A**

①A: 시전 시간은 "지속시간이 있는 상태" 다. GAS 에서 그건 GE 다. 이동 차단이 F06 배선을 그대로 타고, 클라 UI 가 남은 시간을 읽을 수 있다.
②A: 차단 축(`State.Block.Skill`)이 F06-01 에서 이미 정해졌다. 끊는 쪽도 같은 축을 보면 "GE 가 끊어 주겠지" 같은 틀린 전제가 없다.

⚠ 둘 다 **자체 타이머 상태 머신이 아니다** — 대기는 전부 `UAbilityTask`, 상태는 GE.
