## 어긋난 곳

1. **출처가 둘** — 대기 · 달리기만 에디터에서 BP 변수로 손으로 넣는다 (실험체 × 무기 수만큼 `ABPL_*` 자식 · 야생동물 종 수만큼 자식 AnimBP). 나머지는 전부 동작표 + `ER.Pres.Fill` 자동
2. **상태인데 트는 방식이 둘** — 원칙(36-2)은 "지속 상태 → AnimBP". 모드 · 시체는 따르고 채집만 몽타주 (47 에서 블렌드 품질 때문에 바꿨다 — 원인은 전이의 Linear 블렌드로 추정)
3. **몽타주 경로가 둘** — 스킬은 ASC(복제 · 서버가 끊음), 채집은 AnimInstance 직접(각 머신 · 속도로 끊음). 이동 끊기 규칙도 두 벌

## 방안

### ① 출처

| 방안 | 방식 | 판정 |
|---|---|---|
| S1 | 지금대로 (대기 · 달리기 = 레이어 · 자식 AnimBP 변수) | Argument 40 결정 그대로. 새 무기 · 새 종마다 BP 자식을 손으로 만든다 |
| **S2** | **대기 · 달리기도 동작표 줄**(`Pres.Anim.Idle` · `Pres.Anim.Run`)로 — 모드 애니처럼 C++ 가 AnimInstance 변수에 넣고 AnimBP 가 직접 읽는다. 레이어 · 종별 자식 AnimBP **불필요** (템플릿 1개씩) | 모든 애니가 동작표 한 곳 · Fill 이 전부 채운다 · BP 자식 수십 개가 사라진다. 대신 무기마다 **그래프 자체**가 달라야 하는 경우(블렌드스페이스 · 상체 분리 등)는 레이어가 다시 필요 — 지금은 전부 Sequence 2개라 해당 없음 |

### ② 상태 트는 방식

| 방안 | 방식 | 판정 |
|---|---|---|
| **T1** | **규칙을 "길이"로 다시 정한다** — 끝이 정해져 있지 않은 상태(모드 · 시체 · 이동) = AnimBP 상태 / **몇 초 안에 끝나는 행동**(채집 · 제작 · 상자 열기 · 휴식 진입) = 몽타주 | 지금 코드 그대로 규칙만 명문화. 채집 · 제작 · 상자가 같은 길을 탄다 |
| T2 | 채집도 AnimBP 상태로 되돌린다 (전이 Blend Mode HermiteCubic) | 원칙 36-2 그대로. 몇 초짜리 행동이 늘 때마다 상태머신 상태가 는다 |

### ③ 몽타주 경로

| 방안 | 방식 | 판정 |
|---|---|---|
| M1 | **이동 끊기를 하나로** — 모든 동작 몽타주(스킬 · 채집)를 AnimInstance 가 "움직이면 끊는다" 한 곳에서. `StopActionAnim` 은 서버 판정(후딜 캔슬)만 남긴다 | ⚠ **스킬 중 자기 이동**(도끼 D 돌진 · 단검 블링크 · 넉백 당함)도 "움직임" 이라 스킬 모션이 끊긴다 → "강제 · 자기 이동(루트모션 소스) 중 제외" 예외가 붙는다 — 한 규칙이 아니게 된다 |
| **M2** | **지금대로 두고 규칙을 적는다** — 어빌리티 몽타주(ASC) = 이동 **입력 수락** 때 끊는다 (서버 · 소유 클라 → GAS 복제) / 어빌리티 없는 행동 몽타주(채집 등) = 각 머신이 **속도**로 끊는다 | 스킬은 입력 기준이라 자기 이동에 안 끊긴다. 채집 · 제작 · 상자는 어빌리티가 없어 복제 경로가 없으니 속도 기준이 맞다 — 이유 있는 두 벌 |

**추천: S2 + T1 + M2** — "애니는 전부 동작표 · 끝이 없는 상태는 AnimBP · 몇 초짜리 행동과 사건은 몽타주 · 스킬은 입력으로 · 행동은 속도로 끊는다". ⚠ S2 는 에디터 작업(레이어 · 자식 AnimBP 정리)이 크다 — 지금 할지, F19 전에 할지 같이 정한다.
