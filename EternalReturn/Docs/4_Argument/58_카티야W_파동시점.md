## 방안

### W1 — 즉시 원 (데이터만)
`Area` 원(조준점 · AimRange 23 · 반경 4.5) + `Delivery` 즉시. 조각 없음.
- 장점: 코드 0 · JSON 한 덩어리 · "피해 없는 스킬" 경로 검증(K7 목표)이 바로 된다
- 장점: 파동 효과가 아직 없으니 도착 시간이 달라도 **게임 결과가 같다**
- 단점: 원작과 시점이 다르다 (다트 비행 시간만큼 이르다) — F16 에서 드러냄을 붙일 때 다시 봐야 한다

### W2 — 지연 2차 판정 (기존 조각 `FollowUp`)
W 자체는 판정 없음(반경 0) + `FollowUp` (Delay = 비행 시간 `[자체]`) → 파동 DA 로 2차 판정. 연막 투척(F11-05 C)과 같은 방식.
- 장점: 코드 0 · 시점이 원작에 가깝다
- 단점: DA 2개 · Delay 가 **거리와 무관한 고정값** (가까이 찍어도 같은 시간) · 속도 `(미확인)` 이라 값이 추측
- 단점: 다트 모습은 따로 (연출 단계)

### W3 — 새 발사 방식 "지점까지 날아가서 판정"
`UERDelivery_Projectile` 에 `FirePattern = ToPoint` (또는 새 클래스 `UERDelivery_Lob`) — 투사체가 조준점에 닿으면 `Area` 로 판정 → 적중 조각.
- 장점: 거리만큼 정확한 도착 시간 · 다트 모습이 실제 비행 · 나중 스킬(투척 · 포격류)도 재사용
- 단점: 투사체 액터에 "끝에서 터짐" 경로 추가 (지금은 스윕 적중만) · 속도 `(미확인)` · 지금은 효과가 없는데 구조부터 만든다 (CLAUDE.md §2 추측성 코드)

## 추천

**W1.** 파동이 할 일(드러냄 · 시야)이 F16 전엔 없어서 시점 차이가 게임에 안 보인다. K7 의 목적인 "피해 없는 스킬이 쿨 · 모션 · 로그만 남기고 끝나는지" 를 코드 없이 검증한다. **F16 에서 드러냄을 붙일 때 W3 로 올린다** — 그땐 다트 속도도 다시 찾는다.

### 같이 고칠 것 (어느 방안이든)
- **피해 없는 스킬의 타격 큐** — 지금 즉시 판정은 맞은 대상마다 `GameplayCue.Pres.Hit`(타격음)을 보낸다 (`Source/EternalReturn/GAS/ERGameplayAbility.cpp` `ResolveInstantHits` → `SendPresCues`). W 는 파동에 잡힌 적에게 **타격음이 나면 안 된다** → 적중 조각(`IsHitEffect`)이 하나도 없는 스킬은 타격 큐를 보내지 않는다 (시전 큐는 그대로). 한 줄 조건.

## ✅ 결정 (사용자 2026-10-02): **W 보류 → F16 에서 W3**

> "아직 시야 시스템이 없어서 W 는 보류 · 한다면 날아가는 속도랑 모션도 필요하니까 W3"

- 파동이 하는 일(드러냄 · 시야 · 덫/카메라)이 전부 F16 · F13 이라 지금 만들면 **로그만 남는 스킬** — 검증할 게임 결과가 없다
- 할 때는 W3 (지점까지 날아가서 판정 — 거리 비례 도착 · 다트 모습 · 드론 모션). 그때 다트 속도 `(미확인)` 을 다시 찾는다
- "피해 없는 스킬의 타격 큐" 조건도 W 와 같이 (지금 피해 없는 스킬이 없어 드러나지 않는다)
