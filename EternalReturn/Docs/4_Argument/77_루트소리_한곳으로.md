# 77. 채집 · 상자 소리 — 어디에 적나 통일 (2026-10-08)

## 결정 요약

| 축 | 결정 |
|---|---|
| 방식 | → [Argument 78](78_공용소리_서브시스템.md) 로 넓힘 (사용자 2026-10-11 — 캐릭터와 무관한 소리 전부를 서브시스템으로). 채집 · 상자는 거기서도 U1 (물체 행) |

## 결정할 것

같은 루트 행(`DT_Loot`)인데 채집은 **태그 → 소리**를 거치고 상자는 **소리 애셋 직접**이다 (사용자 2026-10-08 "통일해야하는거 아니야?"). 한 방식으로 맞춘다.

## 지금 (2026-10-08 빌드)

| | 채집 | 상자 |
|---|---|---|
| `DT_Loot` 칸 | `GatherSfx` = 태그 `Pres.Sfx.Gather.Branch` | `OpenSound` = 애셋 `OpenSound_Box_01` |
| 실제 소리가 적힌 곳 | `_Common.json CommonSounds` → Fill → **실험체 6명 기본 DA 마다** 복사 | 루트 행 그 자체 |
| 재생 | 서버 소리 큐 → 각 머신이 **채집한 사람 DA** 에서 고름 (주변) | 서버 → 본인 Client RPC (경로) |

- 태그 방식은 **캐릭터 · 스킨마다 다른 소리**를 위해 만든 길이다 (스킬 소리 · 스킨이 덮어씀). 채집 · 상자 소리는 **캐릭터와 무관** — 6명 DA 에 같은 것이 복사될 뿐이다
- 상자 모양은 원작에 50여 종 (`OpenSound_<가구>`) — 태그로 가면 모양마다 태그를 헤더에 선언해야 한다

## 방안

### U1 — 둘 다 루트 행에 소리 애셋 직접 ⭐
- `GatherSfx` (태그) → `GatherSounds` (소리 애셋 **배열** — 무작위 1~3) · `OpenSound` → `OpenSounds` (배열 — 같은 모양 변형 01 · 02)
- 재생: 채집 = 서버가 소리 큐에 **애셋을 실어** 주변으로 (큐 SourceObject · 받는 쪽이 그 애셋 재생) · 상자 = 지금처럼 본인 RPC
- `_Common.json` 에서 채집 소리 줄 9개 · `Pres.Sfx.Gather.*` 태그 3개 삭제
- 장점: 루트 행 하나만 보면 그 오브젝트의 소리 · 대사가 다 있다 · 모양이 늘어도 태그 · 코드 그대로
- 장점: 6명 DA 복사 없음
- 단점: 스킨이 채집 소리를 바꾸는 길은 없다 (원작에 그런 스킨 소리가 있는지 `(미확인)` — 있으면 그때)

### U2 — 둘 다 태그 → 각 DA
- 상자 `OpenSound` → 태그 `Pres.Sfx.BoxOpen.<모양>` · 소리는 `_Common.json`
- 장점: 스킨 · 캐릭터가 덮어쓸 수 있다
- 단점: 상자 모양마다 태그 선언 (50여 개) · 6명 DA 에 복사 · 루트 행만 봐서는 무슨 소리인지 모른다

## 비교

| | **U1 루트 행 직접** | U2 태그 |
|---|---|---|
| 구현 | 중 (칸 2개 바꿈 · 큐에 애셋) | 중 (태그 · JSON 줄) |
| 확장성 (상자 모양 50종) | 행에 애셋만 | 모양마다 태그 + JSON |
| 네트워크 | 큐 1 · RPC 1 (같음) | 같음 |
| 보기 | 한 곳 | 두 곳 (행 · JSON) |

## 추천

**U1** — 캐릭터와 무관한 오브젝트 소리라 오브젝트 데이터(루트 행)에 두는 게 맞다. 대사(`Voice`)는 캐릭터마다 다르니 지금처럼 태그로 둔다 (그건 캐릭터 몫).
제작 소리(`Pres.Sfx.Craft`)는 루트 행과 무관 — 그대로 둔다.
