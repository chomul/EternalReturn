# 31. 야생동물 베이스 클래스 — ACharacter vs APawn (+ 자체 이동)

> F12-01 · 제기: 사용자 2026-09-22 — "넓은 맵 전체에 많이 뿌려져 있는데 ACharacter 자체가 가지는 무거움을 감안하더라도 캐릭터가 맞나?"
> 관련 역기획서 몬스터 §7.3 (복제 비용 · 120~200마리) · [`30_야생동물_데이터_DT_vs_DA.md`](30_야생동물_데이터_DT_vs_DA.md)

## ⭐ 결정 — **보류 · 측정으로 정한다** (사용자 2026-09-22 "지금도 해보고 그때도 해보자")
> ① 지금(01 · 애니 없음 · AI 없음): `ER.Wild.Stress 200` + `stat unit` — Game ms 를 0마리 / 200마리 틱 켬 / 200마리 틱 끔 으로 비교
> ② 04 (AI · 이동 중) 에서 한 번 더
> 기준: **200마리 유휴 상태에서 Game ms 증가 ≤ 1 ms 면 ACharacter 유지**. 넘으면 방안 B 로 재작업. 결과는 아래 "측정" 절에 기록.
> ① 결과 (2026-09-22): 틱 켬 +5~7 ms · **틱 끔 +0~1 ms** → 유휴 비용 = CMC · 메시 틱. **A 유지** (04 가 유휴 시 틱을 끈다 — 필수 조건). ② 04 이동 중 재측정 남음.
> ② 결과 (2026-09-30 데디 PIE): 0 → 7~8 · 대기 200 → ~32 · 서버 틱 끔 → 30~32 — 늘어난 몫은 클라 화면 애니이고 서버 대기 비용은 ≈ 0 → **A 확정**. 이동 중 수치(추격 20: 24 · 전투 50: 40~45 · 리슨)는 곰 수가 줄던 회차라 참고만.

## 결정할 것

야생동물 액터(`AERWildlifeCharacter`)를 `ACharacter` 로 두나, `APawn` + 자체 이동으로 바꾸나.
전제: 한 판에 120~200마리 · 대부분 유휴 · 어그로 붙은 몇 마리만 이동 · 데디케이티드 서버.

## ACharacter 가 실제로 얹는 것

| 항목 | 유휴 시 비용 | 우리가 쓰나 |
|---|---|---|
| `UCharacterMovementComponent` 틱 | 매 프레임 (Velocity 0 이어도 지면 체크 · 물리 상태 갱신) | ⭐ 04 이동 · 지형 추종 · NavMesh 이동(`AIMoveTo`) — **쓴다** |
| 이동 복제 (`ReplicatedMovement` + CMC 보정 패킷) | 도먼시로 거의 0 | 04 이동 중만 |
| 캡슐 루트 | 없음 | 쓴다 (지형 · 폰 충돌) |
| `USkeletalMeshComponent` 틱 · 애니 평가 | 서버는 애니 평가 안 함 (`bEnableUpdateRateOptimizations` · 서버 기본 `VisibilityBasedAnimTickOption`) | 클라만 |
| 점프 · 웅크리기 · 네트워크 예측 코드 | 실행 안 되면 0 | 안 쓴다 |

→ **유휴 비용의 실체는 CMC 틱 하나**다. 나머지는 안 쓰면 안 돈다.

## 방안 A — `ACharacter` 유지 + 유휴 시 CMC 틱 끔 (지금 코드)

- 04 도먼시가 어그로 없을 때 `CMC->SetComponentTickEnabled(false)` · 메시 틱 끔 (`ER.Wild.Tick 0` 이 같은 일을 손으로 한다)
- 장점: NavMesh 이동 · 지형 추종 · 밀림 · 넉백(`ERForcedMove`) 을 엔진이 다 해 준다. 실험체와 같은 코드 경로 (F04 판정 · F06 CC · 스킬 조각의 `AERCharacterBase` 캐스트만 손보면 됨)
- 단점: 200마리 × CMC 객체 메모리(약 1.5 KB) · 깨어 있을 때 CMC 틱 (수십 마리 동시 이동은 문제 없음 — MOBA AI 규모)

## 방안 B — `APawn` + `UFloatingPawnMovement` 또는 자체 이동

- 장점: 객체 가볍고 틱이 단순 (지면 체크 없음)
- 단점: **지형 높이 · 경사 · 계단을 직접 처리**해야 한다 (라인 트레이스 · 스냅) · NavMesh 이동은 `UPathFollowingComponent` 가 `UNavMovementComponent` 만 있으면 되지만 **밀림 · 넉백 · 캡슐 스윕**은 자체 구현 · 곰 돌진 같은 스킬 이동(`_SelfMove` · `ERForcedMove`) 도 갈라진다. 실험체와 다른 코드 경로가 하나 더 생긴다

## 비교표

| | A ACharacter + 틱 끔 | B APawn 자체 이동 |
|---|---|---|
| 구현 난이도 | 끝남 (04 에서 틱 on/off 만) | 이동 · 지형 · 넉백 재구현 (1~2일) |
| 유휴 200마리 | CMC 틱 끔 → 거의 0 (측정으로 확인) | 거의 0 |
| 이동 중 | CMC 틱 (수십 마리) | 자체 틱 (더 가벼울 수 있음) |
| 메모리 | +CMC · 캡슐 (200 × 수 KB) | 최소 |
| GAS · 판정 · CC · 스킬 조각 정합성 | 실험체와 같은 경로 | `AERCharacterBase` 캐스트 부분 갈라짐 |

## 추천

⭐ **A** — 단, 측정으로 확정. "유휴 비용 = CMC 틱" 이면 틱을 끄는 것으로 해결되고 클래스를 바꿀 이유가 없다.
측정에서 200마리 틱 끔 상태로도 1 ms 이상 남으면(액터 자체 · 복제 · GC 순회 비용) 그때 B 로 간다 — 그 비용은 APawn 도 대부분 같이 내지만 실측이 먼저다 (memory: evidence-before-claims).
