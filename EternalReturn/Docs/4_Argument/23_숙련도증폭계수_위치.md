# 23. 무기 숙련도 증폭 계수(실험체 × 무기군)를 어디에 두나 — 데이터 테이블 vs 실험체 애셋

## 결정할 것

숙련도 레벨당 증폭 계수는 **실험체 × 무기군** 조합마다 다르다 (레니 권총 4.4% 스킬증폭 · 재키 도끼 2.1% 평타증폭 · 재키 단검 2.4%). 이 표를 어디에 두나.
Task 문서는 `FWeaponProficiencyRow` 테이블(RowName `"Jackie_Axe"`)로 썼는데, **실험체를 식별할 키가 없다** — `UERCharacterData` 에 ID 필드가 없고 애셋 이름으로 행을 조합하면 이름 변경에 조용히 깨진다.

---

## 방안 A — 데이터 테이블 `DT_WeaponProficiency` (RowName = "실험체_무기")

- 장점: 33 실험체 × 무기군 전체를 한 표에서 비교 · 밸런싱
- 단점
  - ⚠ **실험체 키가 없다.** `UERCharacterData` 에 `CharacterId : FName` 을 새로 만들어야 하고, 애셋마다 손으로 채워야 한다. 빠뜨리면 계수 0 (GAS 처럼 조용히)
  - 실험체를 하나 추가할 때 애셋 + 테이블 행 두 곳
  - `WeaponTypes`(들 수 있는 무기, F08-02) 는 애셋에 있고 계수는 테이블에 — **같은 조합 정보가 두 곳**

## 방안 B — `UERCharacterData` 에 `TMap<EERWeaponType, FERWeaponAmp>`

```
FERWeaponAmp { EERAmpType AmpType (BasicAttack | Skill); float AmpPerLevel (%) }
UERCharacterData.WeaponProficiencyAmp : TMap<EERWeaponType, FERWeaponAmp>   // 키 = WeaponTypes 와 같은 집합이어야 한다
```
- 장점
  - ⭐ **키 문제가 없다** — 실험체는 자기 애셋, 무기군은 enum
  - Argument 4 의 결정 그대로: "실험체별로 다른 밸런싱 파라미터는 애셋에" (`BaseStats` · `Growth` 와 같은 자리)
  - `WeaponTypes` 와 나란히 — 들 수 있는 무기와 그 계수가 한 화면
  - 밸런싱 비교는 Bulk Edit via Property Matrix (Argument 4 와 같은 답)
- 단점
  - 전 실험체를 한 표로 못 본다 (Property Matrix 로 대체)
  - `WeaponTypes` 에 있는데 맵에 없는 무기 → 계수 0. **읽는 쪽이 Warning** 을 낸다 (CLAUDE.md §8)

## 필요 경험치 — 테이블이 아니라 파라미터 2개

나무위키 가이드 "무기 숙련도": **Lv2 230 · 이후 레벨당 +270** [확인]. 역기획서 §3.3 이 이미 "5종 전부 `Lv2 임계값 + 등차` — 파라미터 2개" 로 읽었다. 실험체 레벨(F10-01)과 달리 곡선이 확인됐으니 19행 테이블을 만들 이유가 없다.
최대 레벨은 (미확인) → `[자체]` 20 (설정값).

## 추천 — B

키 문제 하나로 결정된다. A 는 ID 필드를 새로 만들어야 하고, 그 ID 가 애셋 이름과 어긋나는 순간 조용히 0 이 된다.
