# 54 — 이동 투사체 구조 (카티야 Q · E · R → 매그너스 Q · 시셀라 E · 레니 Q)

> ✅ **결정: P1** (사용자 2026-10-01 "투사체 액터 만들자") — ⭐ **베이스 클래스 하나 + 상속** ("다른 캐릭터 추가 시 다양하게 늘어날 수 있으니"). 세부는 [F19-01 K0 합의안](../1_Task/F19_실험체_킷/01_카티야.md)

> 발단: F19-01 카티야 K2. 지금 `ESkillTargeting::Projectile` 은 **발사 순간 선 판정**(즉시) — 날아가는 동안 피할 수 없고, 거리 비례(Q)도 "날아간 거리" 가 없다
> 근거: [`Characters/01_카티야.md`](../0_GameDesign/Characters/01_카티야.md) §3 (Q 26 m/s · 11m · 적중 시점 거리 보간 / R 40 m/s · 경로상 다른 대상이 대신 맞을 수 있음 — 나무위키 검색 요약 2026-10-01)

## 결정할 것

투사체를 **실제로 날려서** 서버가 적중을 정하는 방식.

## 전제 · 지금 있는 것

- 투사체는 짧다: Q 11m ÷ 26 m/s ≈ **0.42초** · R 23m ÷ 40 m/s ≈ 0.58초 · E 4.5m
- 적중 처리는 이미 있다: 장판 액터가 `Ability->ApplyOnTargets(Skill, {대상}, Scale, Level)` 로 **나중에** 피해 · 적중 효과를 돌린다 (`Source/EternalReturn/Combat/ERSkillAreaActor.cpp:69`) — 투사체도 같은 길
- 서버 액터 복제 · 스폰은 장판 액터가 이미 한다 (`bReplicates = true`)
- **Lyra 는 참고할 게 없다** — C++ 무기는 전부 히트스캔, `bProjectileWeapon = false` 고정 (`Samples/Games/Lyra/Source/LyraGame/Weapons/LyraGameplayAbility_RangedWeapon.cpp:497 · :590`). 수류탄은 BP (Content 없음)
- 엔진 `UProjectileMovementComponent` (`Engine/Classes/GameFramework/ProjectileMovementComponent.h:27`) — 직선 · 속도 · 스윕 충돌 · 멈춤 이벤트

## 방안

### P1 — 투사체 액터 + 엔진 ProjectileMovement ⭐
서버가 액터를 스폰 → `ProjectileMovementComponent` 가 서버에서 스윕하며 날아감 → 겹침/충돌 이벤트에서 팀 · 관통 규칙 검사 → `ApplyOnTargets` → 소멸. 클라는 **스폰만 복제**받고(`bReplicateMovement = false`) 같은 초기값으로 **자기 쪽에서 직선 시뮬레이션** (모습만).
```cpp
// 서버
AERProjectile* P = World->SpawnActorDeferred<AERProjectile>(...);
P->Init(Ability, Skill, Level, Dir, SpeedUU, RangeUU, RadiusUU, PierceFilter);   // 복제 값: 시작 · 방향 · 속도 · 사거리
P->FinishSpawning(...);
// 서버: OnComponentBeginOverlap → 규칙 통과면 Ability->ApplyOnTargets(Skill, {Hit}, Scale, Level) · 비관통이면 Destroy
```
- 장점
  - 이동 · 스윕 충돌을 **엔진**이 한다 — 직접 스윕 코드 없음
  - 장판 액터와 같은 틀 (서버 스폰 · 어빌리티에 되돌려 적중 조각) → 매그너스 · 시셀라 · 레니 재사용
  - 클라 모습이 끊기지 않는다 (0.4초짜리를 위치 복제로 받으면 몇 번 못 받는다 → 시뮬레이션이 낫다)
- 단점
  - 액터 스폰 비용 (한 발에 하나 — 카티야 R 도 3발 · 문제 수준 아님 (미측정))
  - 클라 모습과 서버 적중 위치가 **조금** 어긋날 수 있다 (같은 직선 · 같은 속도라 도착 시각 차이 = 스폰 복제 지연만큼)
  - 콜리전 채널 · 겹침 설정을 맞춰야 한다 (벽에서 멈춤 · 캐릭터는 겹침)

### P2 — 액터 없이 서버 타이머 스윕 + 연출 큐
서버가 "가상 투사체" (시작 · 방향 · 속도) 를 들고 매 틱(또는 짧은 타이머) 구간을 스윕. 모습은 GameplayCue 로 클라가 나이아가라를 날린다.
- 장점
  - 복제 액터 없음 (큐 한 번)
  - 판정이 코드로 다 보인다
- 단점
  - 스윕 · 벽 · 관통 · 수명을 **직접** 만든다 (엔진 ProjectileMovement 를 다시 만드는 셈)
  - 서브시스템 · 목록 관리 코드가 는다
  - 큐가 늦게 relevant 된 클라엔 안 간다 (0.4초라 실제 손해 적음)

### P3 — 발사 순간 판정 + 도착 시간만큼 늦게 피해
지금 선 판정을 그대로 쓰고, 맞은 대상까지 거리 ÷ 속도 만큼 **피해만 늦게**.
- 장점
  - 코드 최소 (타이머 하나)
- 단점
  - **피할 수 없다** — 발사 순간 이미 맞음이 정해진다 (원작은 날아가는 동안 피한다)
  - R "경로상 다른 대상이 대신 맞음" 을 못 한다 (도착 시점 경로가 아니라 발사 시점 경로)

## 추천

**P1.** 이동 · 충돌은 엔진 `ProjectileMovementComponent` 가 원래 하는 일이고, 적중 후 처리는 장판 액터가 이미 쓰는 `ApplyOnTargets` 로 어빌리티 조각을 그대로 돌린다. 투사체 쓰는 실험체가 4명(카티야 · 매그너스 · 시셀라 · 레니)이라 한 번 만들면 계속 쓴다.

### P1 이면 같이 정할 세부 (합의 때)
- 스킬 DA 에 투사체 값: `Shape.Targeting = Projectile` 에 **`ProjectileSpeed` (m/s) > 0 이면 액터**, 0 이면 지금처럼 즉시 선 판정 (기존 DA 호환 — 트리플렛 · 저격 D 그대로)
- 관통 규칙: 기존 `bPenetrate` + 🆕 **야생동물만 관통** (카티야 R)
- 적중 문맥에 **날아간 거리 비율** (0~1) 을 넘긴다 → Q 거리 보간 조각이 읽는다
- 벽: ~~멈추고 소멸~~ → **통과** (사용자 2026-10-01 "원래도 벽은 통과함") — 이동 충돌 없음 (`NoCollision`). 벽에 막히는 투사체가 생기면 파생에서 켠다
