# 67. 자동 공격 — 적 우클릭 = 사거리까지 다가가 계속 평타

## 결정할 것

적을 우클릭했을 때 **사거리 안까지 이동 → 평타를 계속 치는** 동작(자동 공격)을 어디서 · 무엇으로 돌릴 것인가. F07 때 "별도 Task 후보: 오토 어택" 으로 미뤘던 것 (`1_Task/00_기능목록_및_의존성.md` F07 줄).

## 규칙 (사용자 2026-10-05)

| 입력 | 동작 |
|---|---|
| 우클릭 · 바닥 | 그 자리로 이동 (지금과 같음) |
| 우클릭 · **적** | 사거리 안까지 이동 → **평타를 계속** (대상이 죽거나 · 다른 이동 명령까지) |

`(미확인)` → 아래 제안으로 시작 `[자체]`:
- 스킬을 쓴 뒤 자동 공격으로 **돌아가나** — 제안: 돌아간다 (대상이 살아 있고 이동 명령이 없었으면)
- 대상이 사거리 밖으로 달아나면 — 제안: 따라간다 (시야 시스템 F16 전까지는 거리 제한 없음)
- A + 클릭(공격 이동) · S(정지) — 지금은 안 만든다

## 방안

### A1 — 소유 클라가 돈다 (이동처럼) ⭐
플레이어 컨트롤러에 **공격 대상**을 둔다. 매 틱(또는 짧은 타이머) — 사거리 밖이면 대상 쪽으로 `StartMoveTo`(지금 이동과 같은 길) · 안이면 멈추고 평타 쿨이 끝났을 때 **지금의 평타 요청을 그대로** 보낸다(`ServerActivateSkill(Attack, 대상)`). 이동 명령 · 대상 사망 · 다른 대상 클릭이면 끝.
- 장점: 이동 · 평타가 지금 쓰는 길 그대로 — 클라가 먼저 움직여 반응이 빠르다 · 서버는 요청마다 사거리 · 쿨 · CC 를 다시 검사 (지금처럼 클라를 안 믿는다) · 새 복제 없음
- 단점: 요청이 핑만큼 늦다 (지금 평타 키와 같은 수준) · 클라가 끊기면 공격도 끊김

### A2 — 서버가 돈다 (야생동물처럼)
클라는 "이 대상 공격" 한 번만 보낸다(RPC). 서버가 대상을 들고 사거리 · 쿨을 보고 평타 · 추적 이동.
- 장점: 요청 하나 · 서버가 평타 타이밍을 정확히 맞춘다
- 단점: **추적 이동을 서버가 하면** 소유 클라 이동 예측(지금 클릭 이동 = 클라 먼저)과 길이 갈린다 — 이동이 핑만큼 늦게 보이거나, 추적만 클라 · 공격만 서버로 나누면 둘이 따로 논다

### A3 — 자동 공격 어빌리티 (GAS 어빌리티 하나가 루프)
"자동 공격" 어빌리티가 켜져 있는 동안 AbilityTask 로 대상 추적 · 평타 발동.
- 장점: 상태가 GAS 안 (태그로 "공격 중" 을 다른 스킬이 본다)
- 단점: 이동(입력 · 내비)을 어빌리티가 갖게 된다 — 지금 이동은 컨트롤러 일 · 스킬 발동 때 이 어빌리티와 평타 어빌리티 정리 규칙이 하나 더 · 가장 무겁다

## 추천

**A1.** 지금 이동과 평타가 모두 "클라가 먼저 · 서버가 검사" 길이라, 자동 공격은 그 둘을 **이어 붙이는 클라 루프**로 충분하다. 서버 권위는 그대로(요청마다 사거리 · 쿨 · CC 재검사)이고 새 복제가 없다.

"평타 치는 중"(재키 W 초기화)은 **공격 대상이 있는 동안**으로 바꿀 수 있다 — 서버도 알아야 하므로 평타 요청이 올 때 서버가 "자동 공격 중" 을 짧게 기억한다 (마지막 평타 요청 뒤 공속 간격 + 여유) `[자체]`.

## 네트워크 (A1)

- 클라: 대상 · 추적 이동 · 평타 요청 타이밍 (연출 · 조작)
- 서버: 평타 요청마다 지금처럼 `CanActivateAbility`(사거리 · 쿨 · CC) · 판정 · 피해 — 바뀌는 것 없음
- 복제: 없음 (이동 · 평타 · 몽타주 모두 기존 경로)
