## 결정할 것

전술 스킬 F 의 소리를 **어느 데이터에 적고 어떤 길로 틀지**.

## 지금

- F 를 쓰면 무기 공통 소리(`skillOneHandSword` · `hitSkillOneHandSword_r*`)가 난다. 원인은 시전 · 타격 큐가 슬롯 키(`Pres.Sfx.SkillCast.<슬롯>`)를 찾다가 F 가 표에 없어 공통 키 `Pres.Sfx.SkillCast` 로 떨어지기 때문이다 (`Source/EternalReturn/Presentation/ERPresentationComponent.cpp:594-636`). 로그 `[연출] … 소리 skillOneHandSword [무기공통]` (2026-10-14 00:32).
- 소리 파일 31개는 이미 들어와 있다 — `/Game/ER/Audio/SFX/Skill/TacticalSkill_*` (`ER_Asset/03_Log/SFX/전술_스킬.md`).
- 소리 두는 원칙 (Argument 78): **무엇에 따라 달라지나**를 따라간다 — 캐릭터 · 스킨 = 캐릭터 연출 DA · 물체 = `DT_Loot` 행 · 누구든 같음 = ER Sound. 전술 스킬 소리는 **스킬에 따라** 달라지고 캐릭터와 무관하다.
- 이미 있는 길: 소리 조각 `UERSkillFragment_Sfx` (키 하나를 실행 순간에 · `ERSkillFragment_Sfx.h:14`), 애셋을 큐에 실어 보내기 `SendSoundAssetCue` (`ERPresentationComponent.cpp:371` — 채집 소리가 쓴다).

## 방안

### A. 소리 조각에 **애셋 칸** 추가 (실행 · 적중) + F 슬롯은 무기 공통 소리 끄기
```cpp
// UERSkillFragment_Sfx — 키 칸은 그대로 두고 애셋 칸을 더한다
UPROPERTY(EditDefaultsOnly) TObjectPtr<USoundBase> ExecuteSound;   // 실행 순간 · 시전자 자리
UPROPERTY(EditDefaultsOnly) TObjectPtr<USoundBase> HitSound;       // 판정 뒤 · 맞은 대상마다 그 자리 (OnTargetsResolved)
// 둘 다 SendSoundAssetCue (서버 → 모든 클라 · 큐에 애셋이 실림)

// ERPresentationComponent::HandlePresCue — 시전 · 타격 큐에 Ability.Slot.F 면 소리만 건너뜀 (애니는 그대로)
```
JSON: `{"Class": "ERSkillFragment_Sfx", "Props": {"ExecuteSound": "@TacticalSkill_Quake"}}` · Lv2 에만 나는 소리는 `MinLevel: 2` 조각을 하나 더.
- 장점
  - 스킬 데이터 안에 있어 **스킬마다** 다르다 — 원칙(무엇에 따라 달라지나)과 맞다
  - 조각 공통 조건(`MinLevel` · `AttackRangeCond`)을 그대로 쓴다 — Lv2 소리 (퀘이크 회오리 · 무효화 CC 면역 · 블링크 Swift)
  - 큐 · 수신 쪽은 이미 있는 길 (`SendSoundAssetCue` · `[물체 행]` 분기) — 새 RPC 없음
  - `Tactical.json` 만 고치고 다시 임포트 (빌드 불필요)
- 단점
  - 새 UPROPERTY 2개 → 에디터 재시작
  - 스킨이 덮어쓸 길이 없다 — 전술 스킬 스킨은 원작에도 없다 (미확인)
  - "버프가 켜져 있는 동안 반복" 소리(라이트 윙 `_Ing` · 퀘이크 `Cyclone`)는 이걸로 못 한다 → 보류

### B. 스킬 데이터(`UERSkillData`)에 `CastSound` · `HitSound` 칸 — 기존 시전 · 타격 큐가 실어 보냄
- 장점
  - 시전 · 타격 큐 타이밍을 그대로 쓴다 (투사체 발마다의 공격 큐 포함)
- 단점
  - Lv2 에만 나는 소리 · 시전과 판정 사이 다른 순간(버프 시작)을 표현 못 한다
  - 캐릭터 스킬 데이터에도 칸이 생기는데 쓰지 않는다 (캐릭터 소리는 연출 DA)
  - 큐 보내는 곳(시전 · 적중 · 순차 사격 발)마다 SourceObject 를 실어야 한다

### C. ER Sound 키 — 스킬마다 태그 (`Pres.Sfx.Tactical.Quake.Cast` …)
- 장점
  - 공용 소리와 같은 표 (Project Settings › ER Sound)
- 단점
  - 태그가 20개 넘게 늘고, 스킬 데이터와 소리 표가 따로 논다 (스킬 추가 = 두 곳)
  - "누구든 같음" 은 맞지만 "스킬에 따라" 를 태그 이름으로 흉내 내는 셈

## 추천 — A

전술 스킬 소리는 캐릭터가 아니라 스킬에 따라 달라지므로 스킬 데이터(JSON) 안에 두는 게 원칙에 맞고, 소리 조각 · 애셋 큐가 이미 있어 칸 두 개로 끝난다. Lv2 소리를 `MinLevel` 로 그대로 나눌 수 있는 것도 A 만 된다. 반복 소리는 장판 · 버프 액터 갈래라 이번엔 ⏸.
