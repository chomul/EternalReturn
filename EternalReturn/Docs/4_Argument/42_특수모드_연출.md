## ④ 재검토 — 모드를 AnimBP 상태로 (2026-09-28)

> 사용자: *"이 모드 같은 경우도 그냥 애님 블루프린트에서 Locomotion 처럼 만들고 저 태그 이용해서 애니메이션 변경하면 되는 거 아니야? 다 시퀀스랑 몽타주로 처리하지 말고?"*
> ⭐ **맞다 — 우리 원칙이 그렇다.** [Argument 36](36_애니메이션_사운드_연출_레이어.md) 원칙 2 표: *"지속 상태 포즈 (사망 · 기절 · **저격 모드** · 채집 중) → 복제 태그 → AnimBP 상태"*. ①~③ 은 진입을 스킬 애니로, 해제를 로컬 재생으로 풀어 이 원칙에서 반쯤 벗어났다.

### 무엇이 "상태" 고 무엇이 "사건" 인가

| 부분 | 성격 | 자리 |
|---|---|---|
| 진입 (Start) · 유지 (Loop / 모드 대기 · 달리기) · 해제 (End) | 모드가 **켜져 있다 / 꺼졌다** 에 따라 정해진다 = **상태** | **AnimBP 상태머신** — 태그를 C++ 가 bool 로 넘긴다 |
| 모드 중 평타 (사격 · 전기톱 평타) · 모드 중 스킬 | 버튼을 누를 때 한 번 = **사건** | 지금처럼 동작표 → 몽타주 (모드 세트 `Entries` 덮어쓰기 — P1 의 이 부분은 유지) |

### 방안

| 방안 | 방식 | 판정 |
|---|---|---|
| MA | ①~③ 그대로 — 모드 자세 = **레이어 교체**, 진입 = D 발동 애니, 해제 = 태그가 빠질 때 **로컬 재생** | 구현 · 빌드 끝남. 단 진입 · 해제가 AnimBP 밖이라 **블렌드가 거칠고** (레이어가 해제 순간 확 바뀜), 늦게 relevant 된 클라는 해제 동작을 놓친다. 원칙 2 와 어긋난다 |
| **MB** | **상태머신** — 메인 템플릿 `Locomotion` 옆에 `Mode` 상태 묶음: `평소 ─(bInMode)→ 진입 ─(애니 끝)→ 유지(대기 ↔ 달리기) ─(!bInMode)→ 해제 ─(애니 끝)→ 평소`. 애니는 **레이어 인터페이스 함수 4개** `ModeStart · ModeIdle · ModeRun · ModeEnd` — 무기 레이어 템플릿이 변수 4개로 구현 (카티야 저격총 레이어에 저격 모드 애니 · 재키 각 무기 레이어에 전기톱 애니). `bInMode` 는 C++ `UERAnimInstance` 가 (연출 컴포넌트가 이미 `Mode` 태그를 구독 → 넘겨준다) | 원칙 2 그대로 · 블렌드는 상태머신이 · 늦게 들어온 클라도 태그 → 유지 상태로 바로 · **레이어 교체 · 로컬 재생 코드가 빠진다** · 모드 세트는 "모드 중 사건 덮어쓰기" 만 |
| MC | 모드마다 캐릭터 AnimBP 에 따로 상태 | 공용 템플릿을 캐릭터별로 복사 (Argument 40 M1 로 후퇴) |

- 한 캐릭터에 모드가 둘이면(예: 카티야 D 저격 + 다른 모드)? 지금 6명 기준 모드는 캐릭터당 하나 (저격 D · 재키 R · 매그너스 R · 다니엘 가면) — **둘이 되면 그때** `ActiveModeIndex` 로 확장 (CLAUDE.md §2)
