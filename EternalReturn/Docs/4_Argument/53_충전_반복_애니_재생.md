# 53 — 충전 중 반복 애니 (start → loop) 재생

> ✅ **결정: L2** (사용자 2026-10-01 "L2 로 하자") — 몽타주 이름 `AM_<시작 시퀀스 이름>` 이면 Fill 이 같은 키로 잡고 시퀀스 대신 넣는다

> 발단: 위클라인 「격리」 애니가 `ActiveSkill04_start` · `_startloop` · `_end` 세 조각 (사용자 확인 2026-10-01). 충전(선딜)은 **CastTime 2.0** (`Docs/3_EditorTasks/F12.6_야생동물_행동_스킬.md` §F12.6-06a ④)
> 관련: [Argument 52](52_판정시점과_애니_속도_맞추기.md) (선딜 재생 속도) · F19 카티야 저격 `Skill_{Start,Loop,Shot,End}` 도 같은 문제 (`Source/EternalReturn/Presentation/ERPresentationFill.cpp:10` "여러 단계 → F19 에서 몽타주로")

## 결정할 것

선딜(충전) 동안 **시작 애니 한 번 → 반복 애니를 판정 순간까지** 트는 방법.

## 지금

- 선딜은 **애니 하나**를 ASC 동적 몽타주로 튼다 (`ERPresentationComponent.cpp:612` `ASC->PlaySlotAnimationAsDynamicMontage`)
- ASC 판에는 **반복 횟수 인자가 없다** (`AbilitySystemComponent.h:1456`) — AnimInstance 판에만 `LoopCount` (`AnimInstance.h:548`). ASC 판을 써야 몽타주가 다른 클라로 복제된다 (`RepAnimMontageInfo`)
- 판정 순간에는 `R.Execute` 애니(`_end`)가 앞의 것을 덮는다 · 취소면 `MontageStop` (`ERGameplayAbility.cpp:959-962`)
- `_start` 길이 (미확인) — 2.0초보다 짧으면 남은 충전 동안 기본 자세로 돌아간다

## 방안

### L1 — 시작 애니만 (지금 코드 그대로)
- 장점
  - 코드 0 · 이미 들어가 있다
- 단점
  - `_start` 가 2초보다 짧으면 충전 도중 서 있는 자세로 돌아간다
  - 마커로 늘리면 `_start` 가 슬로 모션이 된다 (Argument 52 — 속도 = 마커 ÷ CastTime)

### L2 — 에디터에서 만든 몽타주를 그대로 튼다 ⭐
사용자가 `AM_Wickline_01_ActiveSkill04` 를 만든다: 섹션 `Start`(= _start) → `Loop`(= _startloop, 자기 자신으로 이어짐). Fill 이 몽타주 애셋도 줍고, 재생 쪽은 애셋이 몽타주면 ASC `PlayMontage` 로 튼다.
```cpp
if (UAnimMontage* Authored = Cast<UAnimMontage>(Anim))
{
    ASC->PlayMontage(Ability, ActivationInfo, Authored, Rate);   // 섹션 반복은 몽타주가 한다 · 복제는 ASC 그대로
}
else
{
    ASC->PlaySlotAnimationAsDynamicMontage(...);                 // 지금 길
}
```
- 장점
  - 반복 · 섹션 이어짐을 **엔진 몽타주 기능**이 한다 — 직접 상태 머신 안 만든다
  - 복제 = ASC 가 이미 하는 `RepAnimMontageInfo` 한 번 (늦은 relevant 도 같은 길)
  - F19 카티야 저격 등 여러 단계 애니를 **같은 길**로 푼다
- 단점
  - 에디터 작업 하나 (몽타주 · 섹션 연결) — 애니마다
  - 몽타주의 슬롯이 우리 `AnimSlotName` 과 같아야 한다 (틀리면 안 보인다 → 로그로 잡는다)
  - 선딜 마커 속도(52)는 몽타주에서도 동작하지만 반복 섹션과 섞이면 뜻이 흐려진다 → 반복 몽타주엔 마커를 두지 않는다

### L3 — 코드로 이어 틀기
`_start` 가 끝날 때(몽타주 BlendingOut 델리게이트) 아직 선딜이면 `_startloop` 을 다시 ASC 동적 몽타주로 튼다 · 끝날 때마다 반복.
- 장점
  - 에디터 작업 없음 (Fill 이 `_startloop` 을 `R.Loop` 같은 키로 줍는다)
- 단점
  - 반복마다 새 몽타주 → **복제도 반복마다** 다시 간다
  - 이어지는 순간 블렌드가 끊겨 보일 수 있다 · 새 키 · 델리게이트 · 선딜 상태 확인 코드 — 몽타주 섹션을 다시 만드는 셈
