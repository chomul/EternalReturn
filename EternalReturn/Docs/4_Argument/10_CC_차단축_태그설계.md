# 10. CC 가 무엇을 막는지 어떻게 표현할 것인가 — 차단 축 태그

> F06-01 · 근거 [`전투판정_상태이상_역기획서.md`](../0_GameDesign/Systems/전투판정_상태이상_역기획서.md) §3

## ⭐ 결정 — 2026-09-10

| 항목 | 결정 |
|---|---|
| 차단 표현 | ⭐ **방안 A — 차단 축 태그** |
| 태그 | `State.Block.Movement` · `State.Block.BasicAttack` · `State.Block.Skill` |
| 이동 차단 지점 | **CMC 의 `GetMaxSpeed()` + `GetDeltaRotation()`** (Lyra 패턴) |
| 스킬 차단 지점 | 어빌리티의 `ActivationBlockedTags` — ⏸ **F07** (어빌리티가 아직 0개) |
| 누락 대응 | CC GE 애셋 검사기가 축 태그 유무를 확인 |

사용자 결정: *"둘 다 A 로 해서 진행하자"*

⭐ **Lyra 와 다른 점** — Lyra 는 태그 1개(`Gameplay.MovementStopped`),
우리는 **축 3개**. 패턴은 같고 태그 수만 늘렸다. 이유는 아래 추천 절에.

## 결정할 것

**"기절이면 이동·평타·스킬이 막힌다"는 규칙을 어디에 적을 것인가.**
막는 쪽(CMC · 어빌리티)이 CC 목록을 알게 할 것인가, CC 가 자기가 막는 축을 선언할 것인가.

---

## 문제 — 축은 3개인데 CC 는 계속 늘어난다

역기획서 §3.1 · §3.3 의 표를 축으로 다시 세우면 이렇다.

| CC | 이동 | 기본공격 | 스킬 |
|---|---|---|---|
| 기절 | ✕ | ✕ | ✕ |
| 수면 · 제압 · 에어본 · 경직 | ✕ | ✕ | ✕ |
| 속박 | ✕ | **O** | **O** ⚠ |
| 침묵 | O | O | ✕ |
| 무장 해제 | O | ✕ | △ 평타 판정 스킬만 |
| 붙잡기 | △ 강제 이동 | ✕ | ✕ |

⭐ **이동을 막는 CC 만 이미 6종이다.** 그리고 역기획서 §3.2 의 행동 강제 계열 4종이 나중에 더 붙는다.

## ⭐ Lyra 는 어떻게 하나

```cpp
// LyraCharacterMovementComponent.cpp:119-130
float ULyraCharacterMovementComponent::GetMaxSpeed() const
{
    if (UAbilitySystemComponent* ASC = UAbilitySystemGlobals::GetAbilitySystemComponentFromActor(GetOwner()))
    {
        if (ASC->HasMatchingGameplayTag(TAG_Gameplay_MovementStopped))
        {
            return 0;
        }
    }
    return Super::GetMaxSpeed();
}
```

`GetDeltaRotation` 도 같은 태그로 막는다 (`:106-117`) — **회전까지 막는다.**

⭐ **태그 하나(`Gameplay.MovementStopped`)만 본다.** CC 종류를 모른다.

⚠ **하지만 Lyra 에는 CC 시스템이 없다.** 팀 슈터라 이동을 막는 상황이 한 종류뿐이다.
**"Lyra 가 그랬으니까"는 근거가 아니다** (`CLAUDE.md` §11). 우리는 CC 가 10종을 넘는다.
→ 그래서 **태그 1개로 충분한지**가 이 문서의 논점이다.

## 방안 A — 차단 축 태그를 따로 두고, CC GE 가 함께 부여한다 ⭐

```
State.Block.Movement      이동 차단
State.Block.BasicAttack   평타 차단
State.Block.Skill         스킬 차단
```

`GE_CC_Stun` 의 `GrantedTags`:

```
State.CC.Stun          ← 무엇에 걸렸는지 (UI · 정화 · 저항이 본다)
State.Block.Movement   ← 무엇이 막히는지
State.Block.BasicAttack
State.Block.Skill
```

막는 쪽은 축 태그 **하나**만 본다.

```cpp
// CMC
if (ASC->HasMatchingGameplayTag(ERTags::State_Block_Movement)) { return 0.f; }

// 어빌리티 애셋의 ActivationBlockedTags
State.Block.Skill
```

**장점**

- ⭐⭐ **CC 를 추가해도 막는 쪽을 안 고친다.** 새 CC 는 축 태그를 붙이기만 한다
- ⭐ 어빌리티 애셋마다 `ActivationBlockedTags` 에 **태그 1개**만 넣으면 된다.
  방안 B 라면 스킬 애셋 수십 개에 CC 목록 전체를 넣고 CC 가 늘 때마다 전부 고쳐야 한다
- 역기획서의 **축 표와 1:1 로 대응**한다. 표를 옮겨 적으면 끝이다
- ⚠ **속박의 예외**(이동 차단인데 스킬은 가능)가 자연히 표현된다 —
  `State.CC.Snare` 는 `State.Block.Movement` 만 부여한다

**단점**

- ⚠ GE 애셋에 태그를 **2종류** 넣어야 한다. 축 태그를 빠뜨리면 **조용히 안 막힌다**
  → 방안 A 를 고르면 **검사기가 필요하다** (문서 9 의 검사기와 같은 자리)
- 태그가 3개 늘어난다

## 방안 B — 막는 쪽이 CC 태그 목록을 들고 매칭한다

```cpp
// CMC 가 이동 차단 CC 목록을 들고 있다
UPROPERTY(EditDefaultsOnly)
FGameplayTagContainer MovementBlockingTags;   // Stun, Snare, Grab, Airborne, ...

if (ASC->HasAnyMatchingGameplayTags(MovementBlockingTags)) { return 0.f; }
```

**장점**

- GE 애셋은 `State.CC.Stun` **하나만** 부여하면 된다. 빠뜨릴 것이 없다
- 목록이 한눈에 보인다

**단점**

- ⚠⚠ **CC 를 추가할 때마다 막는 쪽을 전부 찾아 고쳐야 한다.** 이동·평타·스킬 세 곳 + 스킬 애셋 전부
- ⚠⚠ **어빌리티 애셋마다 `ActivationBlockedTags` 에 CC 전체 목록**이 들어간다.
  스킬이 30개면 30곳에 같은 목록이 복사되고, CC 하나를 추가하면 **30곳을 고쳐야 한다**
- 목록이 코드/애셋 여러 곳에 흩어져 **어긋난 것을 알아채기 어렵다**

---

## 방안 C — Lyra 그대로: 태그 1개로 이동만 막는다

`Gameplay.MovementStopped` 하나만 두고 평타·스킬은 나중에 생각한다.

**장점**

- 가장 단순하다. 지금 당장 필요한 것만 만든다 (`CLAUDE.md` §2)

**단점**

- ⚠⚠ **역기획서가 요구하는 축이 3개다.** 침묵(스킬만)·무장 해제(평타만)를 표현할 수 없다.
  §3.3 의 부분 봉쇄 계열이 통째로 빠진다
- 지금 안 만들면 F07 에서 어빌리티 애셋을 만든 **뒤에** 축을 도입하게 되어,
  이미 만든 애셋을 전부 다시 열어야 한다

## ⭐ 추천 — 방안 A

**결정적인 것은 어빌리티 애셋 쪽 비용이다.**

방안 B 는 스킬 애셋 하나하나의 `ActivationBlockedTags` 에 **CC 전체 목록**을 넣어야 한다.
스킬이 30개일 때 CC 를 하나 추가하면 **30개 애셋을 열어 고쳐야 하고**,
하나라도 빠뜨리면 **그 스킬만 조용히 안 막힌다.**

방안 A 는 스킬 애셋에 `State.Block.Skill` **한 줄**이다. CC 가 늘어도 안 건드린다.

⚠ **Lyra 와 다르게 가는 이유**(`CLAUDE.md` §11): Lyra 는 이동을 막는 상황이 **한 종류**다.
우리는 §3.1·§3.3 이 **3축 × 10종 이상**을 요구하고, 속박처럼 **축이 갈리는 CC** 가 있다.
Lyra 의 `GetMaxSpeed` **패턴은 그대로 쓰되**, 태그를 1개에서 **축 3개로 늘린다.**

### ⚠ A 를 고르면 함께 할 것

- CC GE 애셋에 축 태그가 붙어 있는지 **검사기가 확인**한다 (문서 9 의 검사기와 한 자리)
- 축 태그는 `ERGameplayTags.h` 에 선언한다 (`CLAUDE.md` §8 — 문자열 금지)
