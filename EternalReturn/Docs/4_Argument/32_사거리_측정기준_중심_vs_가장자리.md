## 방안 A — 현행: 대상 중심(발밑) 기준

- `GetTargetingLocation` = 액터 위치 − 캡슐 반높이 → 그 점까지의 거리
- 장점: 지금 코드 · 실험체끼리는 캡슐이 다 34cm 라 차이가 없다 · 계산 1회
- 단점: **몸이 큰 대상에 붙어도 빗나간다** (로그의 216cm). 곰은 꼬리 쪽에서 3m 를 넘긴다 → F12-04 에서 AI 가 붙어도 못 때리는 문제로 이어진다

## 방안 B — 대상 가장자리 기준 (거리 = 시전자 중심 → 대상 판정면) ⭐ 추천

```cpp
// ERTargeting: SkillTarget 을 막는 프리미티브(야생동물 = HitBox · 실험체 = 캡슐)의 표면까지
float DistanceToTargetSurface(const AActor* Target, const FVector& From);   // GetClosestPointOnCollision
```
- 적용 범위: **SingleTarget(평타 · 단일 대상 스킬)** 의 `RangeMin/Max` 검사만. 범위기(SelfRadius · Cone · GroundCircle)는 이미 오버랩(형상)으로 잡히므로 손대지 않는다 — 다만 `SortAndMeasure` 의 거리 필터는 중심 기준이라 **범위기도 큰 대상에서 같은 문제**가 있다 (04 에서 확인 후 필요하면 같은 함수로 교체)
- 장점: 실험체끼리는 지금과 사실상 동일(캡슐 34 → 사거리 +0.34m 는 대상 캡슐만큼) · 큰 동물에서 직관과 일치 · 히트박스를 이미 종별로 갖췄으니 추가 데이터 없음
- 단점: `GetClosestPointOnCollision` 는 심플 콜리전 쿼리 1회 (평타 1회당 1번 — 무시할 수준) · 실험체 대 실험체 사거리가 원작 대비 대상 반경(34cm)만큼 늘어난다

## 방안 C — 양쪽 가장자리 (LoL 방식: 시전자 반경 + 대상 반경 둘 다 뺀다)

- 장점: LoL 과 같은 체감 · 대칭적
- 단점: 모든 대인 사거리가 **+68cm** 늘어난다 — 원작 수치(무기별 사거리 표)를 그대로 쓰는 우리 전제와 어긋날 위험이 가장 크다. 근거가 "LoL 이 그렇다" 뿐이다

## ⭐ 방향이 둘이다 — 한 덩어리로 정하지 않는다 (2026-09-23)

지금 로그(216cm 빗나감)는 **플레이어 → 야생동물** 이다. 반대 방향은 문제가 더 크다:

| 방향 | 시전자 | 대상 | 중심 기준일 때 |
|---|---|---|---|
| 플레이어 → 늑대 | 캡슐 34cm | 몸 294cm | 몸에 붙어도 빗나감 (관측됨) |
| 늑대 → 플레이어 (04) | 몸 294cm | 캡슐 34cm | 사거리 1.4m 인데 주둥이가 중심에서 1.47m 앞 → **제 코앞도 못 문다** (플레이어와 겹쳐야 성립) |

## 추천 — B, 단 시전자 쪽은 야생동물에만

- **대상 쪽은 항상 표면까지** (양방향 공통) — 큰 대상에 붙으면 맞아야 한다
- **시전자 쪽은 야생동물(히트박스가 큰 폰)만 자기 표면에서** — 실험체는 캡슐 34cm 로 균일하고 원작 사거리 표(§2.3.6)를 그대로 쓰고 싶으므로 건드리지 않는다. 야생동물 `AttackRange` 는 우리가 정한 `[자체]` 값이라 자유롭다
- 실험체 대 실험체는 대상 캡슐 0.34m 만큼만 후해진다. 이 한 줄만 기억하면 원작 수치와의 차이를 언제든 되돌릴 수 있다

구현 — **대상 쪽은 2026-09-23 완료** (`ERTargeting::DistanceToSurface` · `QuerySingleTarget` · 빗나감 진단 로그). 시전자 쪽은 F12-04:
```cpp
// Combat/ERTargeting
float DistanceToSurface(const AActor* Target, const FVector& From);   // SkillTarget 프리미티브의 GetClosestPointOnCollision
// QuerySingleTarget: 중심 거리 → 표면 거리. 시전자가 야생동물이면 Origin 도 자기 표면에서 (04 근접 공격)
```
범위기(SelfRadius · Cone · GroundCircle)는 오버랩이라 형상 기준이지만 `SortAndMeasure` 의 거리 필터는 중심 기준이다 — 04 에서 큰 동물로 확인하고 필요하면 같은 함수로 바꾼다.
