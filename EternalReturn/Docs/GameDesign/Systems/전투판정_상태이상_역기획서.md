## 0. 이 시스템의 정체

**이 게임의 CC는 "행동 불가"라는 하나의 상태가 아니라, 행동 권한을 축별로 끄는 비트마스크다.**
이동 / 기본 공격 / 스킬 / 시야 — 이 네 축을 각각 독립적으로 잠글 수 있게 만들어 놓았기 때문에
속박(이동만 잠금), 침묵(스킬만 잠금), 무장 해제(기본 공격만 잠금), 실명(기본 공격을 시전은 되게 하되 명중만 잠금)이
**서로 다른 CC로 따로 존재한다.**

세분화된 두 번째 이유는 **저항 스탯의 예외 계층**이다.
"방해 저항"이라는 스탯이 CC 지속시간을 깎는데, **붙잡기·에어본·제압은 이 저항에서 제외**된다.
즉 아이템으로 무력화할 수 없는 **확정 CC 계층**을 따로 남겨 둔 것이다. 이게 없으면 저항템을 쌓은 탱커에게
어떤 이니시에이팅도 통하지 않는다.

> **구현 관점의 결론:** CC를 `enum` 하나로 만들고 `switch`로 분기하면 반드시 무너진다.
> **`CC 종류 → 차단 플래그 세트 + 저항 적용 여부 + 정화 가능 여부`** 를 데이터로 들고,
> 캐릭터는 **현재 걸린 CC들의 플래그 OR 값**만 보고 행동 가능 여부를 판단하는 구조여야 한다.

- `CLAUDE.md` §8 — 데미지 계산은 **한 곳**에 모은다. 캐릭터 클래스에 흩뿌리면 GAS 전환 시 전부 버려야 한다.

## 2. 데미지 적용 순서 — 판정 파이프라인

수식(8단계 곱연산)은 **`스탯_데미지공식_역기획서.md` 담당**이다. 여기서는 **수식 앞뒤에 붙는 판정 게이트**만 정의한다.

```
[0] 히트 판정         : 트레이스/오버랩 → 후보 액터 수집
[1] 대상 유효성 게이트 : 팀 판정 / 대상 지정 불가 / 경직 / 은신·위장 → 후보에서 제외
[2] 실명 게이트       : 시전자가 실명 + 기본 공격이면 → 빗나감(피해 0, 온히트 효과 없음)
[3] 피해 무효 게이트   : 대상이 무적 / 피해 면역 → 피해 0. ⭐ 단 CC는 [5]에서 정상 진행
[4] 데미지 수식        : ← 스탯_데미지공식_역기획서.md (8단계)
[5] CC 적용 게이트     : 저지 불가·면역 검사 → 통과 시 저항으로 지속시간 감산 → 상태 부여
[6] 후처리            : 흡혈(광역 50% / 야생동물 60% 감쇠) → 보호막 차감 → 체력 차감 → 사망 판정
[7] 연출 브로드캐스트  : NetMulticast (히트 이펙트·몽타주·사운드)
```

**게이트별 차단 지점 — 버그의 90%가 여기서 나온다**

| 상태 | 차단 단계 | 결과 |
|---|---|---|
| **대상 지정 불가** | [1] | 후보에서 제외. **이미 적용된 효과는 유지**, 그 외 전부 무시 |
| **경직** | [1] | 피해도 안 받고 대상 지정도 안 됨 |
| **무적** | [3] | 피해 0. CC 차단 여부 **(미확인)** |
| **피해 면역 (시셀라 W)** | [3] | 피해 0. ⭐ **CC는 그대로 들어온다** |
| **저지 불가 / 모든 방해 면역 / 유해 효과 면역** | [5] | 피해는 정상, **CC만** 차단 |
| **실명** | [2] | 시전자 측 차단. 기본 공격 전부 빗나감 |

> ⭐ **[3]과 [5]가 분리되어 있다는 것이 이 시스템의 핵심이다.**
> 시셀라 W는 "1.5초간 모든 피해 무시, 단 해로운 효과·방해 효과는 무시하지 못한다".
> `bIsInvulnerable` 플래그 하나로 피해와 CC를 동시에 막으면 **시셀라가 원작보다 강해진다.**

**구현 메모**
- 게이트 [1]~[3]은 **서버에서만** 판정한다. 클라이언트는 결과만 복제받는다.
- 흡혈 감쇠(광역 50% / 야생동물 60%)는 [6]에 있으므로 파이프라인이 **피해 대상 수와 대상 타입**을 알아야 한다 → 단일 대상 함수가 아니라 **"히트 결과 배열"을 받는 함수**로 설계할 것.

- `?` 항목을 `false`로 슬쩍 기본값 처리하지 말 것. **명시적 "미정" 상수 + `UE_LOG` 경고**를 남긴다 — 그래야 원작 확인값과 자체 결정값이 나중에 구분된다.

### 3.5 강제 이동(넉백 · 그랩)의 서버-클라 처리 — **반드시 읽을 것**

강제 이동은 **유일하게 캐릭터 위치를 바꾸는 CC**이고, 언리얼에서 가장 깨지기 쉬운 부분이다.
`CharacterMovementComponent`는 소유 클라이언트가 이동을 예측하고 서버가 교정하는 구조라,
서버가 위치만 바꾸면 **클라가 원래 자리로 되돌리려 하면서 러버밴딩이 난다.**

| 항목 | 처리 |
|---|---|
| **권위** | **서버 전용.** 넉백 방향·거리·속도, 매 틱 위치, 벽 충돌 판정 전부 서버 |
| **입력 차단** | CC 플래그를 **`Replicated`로 두고 클라에서도 이동 입력을 게이트**한다. 서버에서만 막으면 클라가 계속 움직이려 해서 튄다 |
| **이동 실행 (권장)** | 커스텀 `EMovementMode` + 복제된 CC 파라미터를 보고 **서버·클라가 같은 계산**을 수행. 정합성 최상, 구현 비용 높음 |
| **이동 실행 (간이)** | 서버가 시작점·방향·거리·시간을 `NetMulticast`로 뿌리고 각 머신이 보간, 종료 시 서버가 최종 위치를 확정. 구현 쉬움, 소유 클라 위치 튐 가능 |
| **벽 충돌** | ⭐ **서버에서만** 판정. 이동 중 매 틱 지오메트리 트레이스 → 충돌 시 추가 피해 + 기절 부여 후 `NetMulticast`로 연출 |
| **클라 예측** | **하지 않는다** (`CLAUDE.md` §6). 먼저 서버 권위로 정확히 동작시킨다 |

> **벽 충돌 판정은 최소 3곳이 공유한다** — 매그너스 E(3m 넉백), 레니 R(지정 방향 넉백), 방망이 D(풀스윙).
> **반드시 공용 함수 하나**로 만들 것. 그랩(시셀라 E)은 방향만 반대이므로 **같은 함수에 방향 인자**를 받는다.

## 4. 저항 / 중첩 규칙

| 규칙 | 내용 |
|---|---|
| **방해 저항** | 방해 효과의 **지속시간을 감소**. ⭐ **붙잡기·에어본·제압은 제외** |
| **이동 속도 감소 저항** | 둔화 지속시간을 감소 (방해 저항과 **별개 스탯**) |
| **저지 불가 ↔ CC** | 저지 불가 중 적중된 CC는 즉시 발동하지 않되, **저지 불가 종료 시점에 지속시간이 남아 있으면 그때 발동** |
| **정화(해방)** | 자신·아군의 디버프·CC 제거. ⭐ **에어본·넉백·붙잡힘·경직은 제거 불가** |
| **CC 체감 감소(DR)** | **명시적 DR 규칙은 문서화되어 있지 않다 (미확인).** 저항 스탯 기반 지속시간 감소가 그 역할을 대신하는 것으로 보인다 |
| **CC 동시 중첩** | 동일/이종 CC 동시 적용 시의 갱신 규칙 **(미확인)** |

**6인 중 저항을 요구하는 사례**

| 캐릭터 | 효과 |
|---|---|
| 매그너스 W (17대 1) | **방해 저항 40%** — 4초 채널링을 유지하기 위한 장치 |
| 매그너스 R (폭주 바이크) | **이동 방해 면역** 7초 |

**구현 메모**
- **저지 불가의 "지연 발동"은 CC를 버리지 말고 보류 큐에 넣으라는 뜻이다.** 적중 시각과 원래 지속시간을 기록해 두고, 저지 불가 해제 시 `남은시간 = 원지속 − (해제시각 − 적중시각)`을 계산해 남아 있으면 부여한다. "면역이면 무시"로 구현하면 원작과 다른 게임이 된다.
- 저항 감산은 **부여 시점 1회**로 처리한다(지속 중 아이템을 바꿔도 재계산 안 함). 원작이 어느 쪽인지는 **(미확인)**.
- **DR이 없다는 전제로 만들면 CC 체인이 무한히 연결된다.** 저항 스탯을 먼저 넣고, 실플레이에서 문제가 되면 그때 DR 도입을 별도 안건으로 올린다.
- 중첩 규칙 미정 상태의 임시안: **같은 CC 재적용 시 지속시간 갱신(refresh), 이종 CC는 병렬 유지.** 이건 **자체 결정값이며 원작 확인값이 아니다** — 반드시 기록할 것.

## 데이터 스키마 제안

**설계 전제:** CC는 **`UGameplayEffect` 로 만든다** (`CLAUDE.md` §8).
아래 스키마는 그 GE가 읽는 **데이터 소스**이며, CC를 "코드에 박힌 상태"가 아니라 **`지속시간 + 강도 + 차단 태그`를 가진 데이터 행**으로 다룬다.

```cpp
// 차단 축 — 3.1~3.4 매트릭스의 열이 그대로 비트가 된다
UENUM(meta = (Bitflags))
enum class ECCBlockFlags : uint8
{
    None        = 0,
    Move        = 1 << 0,   // 이동 불가
    BasicAttack = 1 << 1,   // 기본 공격 불가
    Skill       = 1 << 2,   // 스킬 불가
    Item        = 1 << 3,   // 아이템 불가 (전 CC 미확인)
    Vision      = 1 << 4,   // 시야 제한
};

UENUM(BlueprintType)
enum class ECCType : uint8
{
    None,
    // 행동 봉쇄
    Stun, Sleep, Overpower, Airborne, Grab, Knockback, Bind, Mutation, Dance,
    // 행동 강제
    Fear, Charm, Taunt, Insanity,
    // 부분 봉쇄
    Silence, Disarm, Blind, Stiffness, Slow, VisionBlock,
    // 상태 (해로운 효과가 아닌 것 포함)
    Stealth, Camouflage, Invincible, DamageImmune, Unstoppable,
    CCImmune, MoveCCImmune, Untargetable, Channeling, Reveal,
};

// 해제 계층 — §4의 예외 규칙이 여기 들어간다
UENUM(BlueprintType)
enum class ECCCleanseTier : uint8
{
    Normal,        // 방해 저항 감소 O, 정화 O
    ResistExempt,  // 방해 저항 감소 X, 정화 O   ← 제압
    Undispellable, // 방해 저항 감소 X, 정화 X   ← 에어본·넉백·붙잡기·경직
};
```

```cpp
USTRUCT(BlueprintType)
struct FStatusEffectRow : public FTableRowBase
{
    GENERATED_BODY()

    UPROPERTY(EditDefaultsOnly, Category="CC") ECCType        CCType      = ECCType::None;
    UPROPERTY(EditDefaultsOnly, Category="CC") int32          BlockFlags  = 0;   // ECCBlockFlags 비트마스크
    UPROPERTY(EditDefaultsOnly, Category="CC") ECCCleanseTier CleanseTier = ECCCleanseTier::Normal;

    // ⭐ 지속시간·강도를 코드가 아니라 데이터로 다룬다 (GE Duration / Magnitude 에 대응)
    UPROPERTY(EditDefaultsOnly, Category="CC") float Duration  = 0.f;  // 초. 0 = 즉발
    UPROPERTY(EditDefaultsOnly, Category="CC") float Magnitude = 0.f;  // 둔화% / 넉백 거리(m) / 이동속도 고정값

    UPROPERTY(EditDefaultsOnly, Category="Resist") bool bAffectedByCCResist   = true;
    UPROPERTY(EditDefaultsOnly, Category="Resist") bool bAffectedBySlowResist = false;

    UPROPERTY(EditDefaultsOnly, Category="Stack") int32 MaxStack          = 1;    // 출혈 5중첩 등
    UPROPERTY(EditDefaultsOnly, Category="Stack") bool  bRefreshOnReapply = true; // ⚠ 자체 결정값 (원작 미확인)

    // 연출 훅만. 로직 분기는 BP로 넘기지 않는다 (CLAUDE.md §7)
    UPROPERTY(EditDefaultsOnly, Category="FX") TSoftObjectPtr<UNiagaraSystem> HitEffect;
};
```

**GAS 구현 대응표** — 이 문서가 요구하는 것을 GAS의 무엇으로 만드는가.

| 이 게임의 요구 | GAS 구현 |
|---|---|
| CC 정의 데이터 (`FStatusEffectRow`) | ✅ **`UGameplayEffect` 의 데이터 소스로 그대로 사용** |
| CC 종류 (`ECCType`) | `GameplayTag` (`State.CC.Stun` 등) |
| 차단 축 (`ECCBlockFlags`) | `GameplayTag` 기반 `ActivationBlockedTags` / `BlockAbilitiesWithTag` |
| 지속시간 · 강도 | GE의 Duration Policy / Modifier Magnitude |
| 중첩 · 갱신 (`MaxStack` / `bRefreshOnReapply`) | GE의 Stacking Policy |
| 정화 등급 (`ECCCleanseTier`) | 정화 GE의 `RemoveGameplayEffectQuery` |
| CC 컨테이너 · 만료 타이머 · 복제 | ⭐ **`UAbilitySystemComponent` — 자체 컴포넌트를 만들지 않는다** |
| 강제 이동(넉백·그랩) · 벽 충돌 판정 | ⭐ **직접 만든다.** GAS가 제공하지 않는다 |
| CC 적용 시 이펙트 | `GameplayCue` |

**구현 메모**

- ⭐ **`UStatusEffectComponent` 를 만들지 않는다.** ASC가 활성 효과 컨테이너·만료·복제·스택을 전부 갖고 있다 (`CLAUDE.md` §8).
- 야생동물·보스도 ASC를 갖는다 — 곰의 기절기가 여기 붙는다. 단 야생동물은 **Pawn에 ASC**, 플레이어는 **PlayerState에 ASC** 다.
  접근은 `IAbilitySystemInterface` 로 통일해 호출부가 배치를 모르게 한다.
- **강제 이동은 GAS 밖이다.** 넉백 거리·벽 충돌 판정·충돌 시 추가 피해는 직접 만들고, 그 결과 CC(기절)만 GE로 건다.
- ⚠ **행동 강제 계열(공포·매혹·도발·광기)과 수면·에어본은 태그도 만들지 않는다.** 6인 중 요구하는 캐릭터가 없어 **검증할 방법이 없다.** 7번째 캐릭터가 올 때 추가한다.

**구현 메모**
- ⭐ **CC 컨테이너를 직접 만들지 않는다.** ASC 가 활성 효과 목록·만료·스택·복제·Instigator 추적을 전부 갖고 있다.
- 만료도 직접 다루지 않는다 — GE 의 Duration Policy 가 처리한다. `FTimerManager` 를 따로 돌리지 않는다.
- CC 부여는 서버에서 `ApplyGameplayEffectToTarget`. 클라는 태그 변화(`RegisterGameplayTagEvent`)를 듣고 UI·연출만 갱신한다.
- ⭐ **차단 판정은 태그 쿼리로 한다** — 자체 비트 플래그 캐시를 만들지 않는다. 어빌리티 쪽은 `ActivationBlockedTags` 가 자동으로 막는다.
- ⚠ **입력 레이어에도 게이트가 필요하다.** 기절 중이면 클라가 RPC 자체를 안 보내게 한다 (이중 게이트 — 입력 문서 §9).

## 구현 우선순위

```
1순위. CC용 UGameplayEffect + State.CC.* 태그 + ActivationBlockedTags 배선
       → 검증: 서버에서 기절 GE 부여 시 클라의 이동·기본공격·스킬 입력이 전부 막히고 만료 시 자동 해제
2순위. 둔화 (이동속도 % 감소 + 하한 클램프)
       → 검증: 매그너스 Q(60%) 적중 시 서버·클라 이동속도가 동일하게 감소
3순위. 기절 + 채널링(정신 집중) 취소
       → 검증: 카티야 R(0.8초) 채널링 중 기절 적중 시 서버에서 시전이 취소되고 쿨다운이 남음
4순위. 강제 이동 공용 함수(넉백/그랩, 방향 인자) + 벽 충돌 판정
       → 검증: 매그너스 E 넉백 3m 중 벽 충돌 시 서버에서만 추가 피해+기절 발생, 클라는 결과만 복제
5순위. 데미지 판정 게이트 [1][3][5] 분리 (대상 유효성 / 피해 무효 / CC 적용)
       → 검증: 시셀라 W(피해 면역) 중 피해 0, 같은 타이밍의 기절은 정상 적용
6순위. 방해 저항 % + 이동 방해 면역 + 저지 불가 지연 발동 큐
       → 검증: 매그너스 W(저항 40%) 중 기절 지속시간이 60%로 감소, R(면역) 중 넉백이 무시됨
7순위. 은신 + 드러내기 (서버 가시성 판정, relevancy 차단)
       → 검증: 다니엘 E 은신 중 적 클라이언트에 위치가 복제되지 않음
8순위. 침묵 / 무적 / 시야 감소 (단일 사용처)
       → 검증: 다니엘 R 침묵 0.5초 동안 스킬만 막히고 기본 공격은 가능
9순위. 도트(출혈) 중첩 + 표식 상태 (컨테이너 확장)
       → 검증: 재키 출혈 5중첩이 서버 타이머로 갱신되고 만료 시 순차 해제
```

> 멀티플레이 검증은 전부 **`Play As Client, Number of Players: 2` 이상**에서 확인한다.
> 각 단계의 1차 검증은 **빌드 통과**다 (`CLAUDE.md` §4).
> **행동 강제 계열(공포·매혹·도발·광기)과 수면·에어본·제압·변이·춤은 이 목록에 없다.** 6인 중 요구하는 캐릭터가 없어 **검증할 방법이 없기 때문**이며, enum 자리만 만들고 로직은 7번째 캐릭터부터 붙인다.
