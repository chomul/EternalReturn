## 0. 이 시스템의 정체

**매치 진행 시스템은 "시계"가 아니라 이 게임의 유일한 강제 장치다.**
탑다운 MOBA와 배틀로얄을 한 판에 욱여넣으면 최적 전략이 **회피**가 된다 — 숨어서 파밍만 하면 이긴다.
그래서 이 게임은 세 개의 강제 레버를 시간축에 박아놨다.

| 레버 | 무엇을 강제하는가 | 어디에 걸려 있나 |
|---|---|---|
| **보스 스폰 스케줄** | 같은 시각·같은 좌표로 팀을 모은다 | 2/3/4일차 **밤** |
| **제한 구역 확장** | 공간을 뺏어 조우 확률을 올린다 | 매 페이즈 전환 |
| **부활 규칙 3단 전환** | 시간이 갈수록 사망 비용을 올린다 | 자동 → 유료 → 불가 |

> **구현 관점의 결론:** 이건 "게임모드 클래스"가 아니라 **데이터로 정의된 이벤트 큐를 서버가 재생하는 상태 머신**이다.
> 페이즈 길이·이벤트·부활 규칙을 코드에 하드코딩하면 밸런싱 때마다 재빌드해야 한다. **전부 데이터 테이블로 뺀다.**

## 1. 매치 시간축 (스쿼드 = 코어 모드)

### 1.1 단계별 유저 행동

| 구간 | 시간 | 유저가 하는 일 | 핵심 의사결정 | 긴장도 |
|---|---|---|---|---|
| 로비 | — | 실험체·무기·특성·전술스킬·파밍 루트 사전 저장 | "최종 장비 5종 → 재료 → 지역 순회 순서"를 **시작 전에 확정** | 낮 |
| 시작 지역 선택 | — | 팀 3인 협의로 지정 | 상대와 겹칠 리스크(정보 비대칭 도박) | 중 |
| 초반 파밍 | 1일차 낮~2일차 낮 (약 6~7분) | 상자·채집·사냥·**이동 중 제작**·휴식(X) | 상자 vs 사냥 vs 이동의 시간 배분, 팀 재료 트레이드 | 낮→상승 |
| 중반 교전 | 2일차 밤~5일차 (약 10분) | 오브젝트 콜 → 한타 → 격차 확대 | "먹을까 / 먹는 팀을 칠까 / 회피하고 파밍 격차를 낼까" | 급상승 |
| 후반 압축 | 6일차 낮~7일차 (약 6분) | 안전지대 선점, 부활 카운트 정리, 최종 빌드 완성 | "여기서 죽으면 끝" | 최대 직전 |
| 최종 전투 | 7일차 밤~8일차 | 반경 5m 초근접 난전 | 회피 공간이 물리적으로 소멸 | 최대 |

> **설계 해석:** 초반 6분은 MOBA의 라인전(CS 파밍)을 **비동기**로 치환한 구간이다.
> 상대와 접촉하지 않으므로 "라인전 실력"이 아니라 **루트 실행 속도**가 실력이 된다.
> 이 게임 진입장벽의 대부분이 로비와 이 구간에 응축돼 있다.

### 1.2 크로노 스피어 (12.0 신규 — 기존 점령전 대체) [S3]

| # | 단계 | 시간 | 반경 |
|---|---|---|---|
| 1 | 안전지대 생성 | 5초 | 30m |
| 2 | 1차 축소 | 20초 | 30m → **10m** |
| 3 | 이동 대기(목표 지점 표시) | 10초 | 10m |
| 4 | 이동 | (미확인) | 스피어가 목표 지점으로 이동 |
| 5 | 2차 축소 | 15초 | 10m → 5m |
| 6 | 유지 | 40초 | 5m |
| 7 | 3차 축소 | 5초 | 5m → 0m |
| 8 | 승리팀 확정 | — | 반경 최대 확장 |

부가 규칙: 스피어 외부 실험체 **자동 폭사** / 비대상 이동기는 **차단벽에 충돌** / 미니맵·확장맵에 범위 시각 강조.

> ⚠ 위키는 1차 축소 후 반경을 **14m**로 기재 [S5]. **공식 12.0 패치노트의 10m를 채택**한다.

**구현 메모**
- 페이즈 전환은 **서버 GameState의 타이머 하나**가 소유한다. 액터별 개별 타이머를 두면 페이즈 경계에서 어긋난다.
- `Tick` 금지. `FTimerManager`로 "현재 페이즈 종료 시각"에 **1회 타이머**를 걸고, 만료 시 다음 행을 읽어 다시 건다.
- 클라는 `PhaseEndServerTime`(절대 시각)만 복제받아 **로컬에서 카운트다운을 그린다.** 남은 초를 매초 복제하면 대역폭 낭비 + 틱 불일치가 생긴다.
- 크로노 스피어 반경은 **서버가 권위값을 계산**하고, 클라는 시작/끝 반경 + 시작 시각으로 **같은 보간식을 재생**한다. 피해 판정은 서버 값만 쓴다.
- 4단계 이동 목표 지점은 **서버가 뽑아 복제**한다. 클라에서 랜덤을 굴리면 갈라진다.

### 2.3 ⭐ 클론 초기 버전 권고 — **모드는 스쿼드 하나만 만든다**

상위 문서 §12.5는 "모드를 너무 일찍 늘리기"를 명시적 함정으로 지목했다. 원작조차 **아시아1 외 서버의 랭크 매칭을 일시 폐쇄**했고, 론 울프는 **시간대 한정**으로만 연다 [S3], [S15].
24명 로비 하나를 채우려면 동시접속이 최소 수백 명 단위로 필요하다. 모드가 2개면 필요 인구가 2배가 아니라 **양쪽 다 매칭이 안 되는 상태**가 된다.

| 초기 버전 | 판단 |
|---|---|
| **스쿼드 3인 × N팀 (단일 모드)** | ✅ **유일하게 만든다.** 랭크/일반 구분조차 나중 |
| 솔로 / 듀오 | ❌ 원작이 이미 폐기한 구성 |
| 론 울프 | ❌ 스쿼드의 파라미터 변형일 뿐. 인구 확보 후 **데이터로** 추가 |
| 코발트 프로토콜 | ❌ 맵·아이템·성장이 전부 별개. 사실상 **두 번째 게임** |
| 유니온 대전 | ❌ 규칙 자체가 미확인 |

> 단, **팀 인원과 팀 수는 처음부터 데이터값**으로 뺀다(`TeamSize`, `TeamCount`).
> 그래야 나중에 론 울프를 "TeamSize=1, TeamCount=18, 7일 스케줄" 로우 하나로 붙일 수 있다.
> 매치 길이는 원작 26분이 아니라 **15~18분(론 울프 길이)을 권장**한다 — 학습 사이클이 빨라진다 [상위 §12.5].

**구현 메모**
- 모드마다 `AGameMode` 서브클래스를 늘리지 말고 **`FGameModeRow` 1행 + 페이즈 스케줄 테이블 참조**로 표현한다.
- `AERGameState`가 `TeamSize / TeamCount / PhaseScheduleTable / RespawnRuleTable`을 들고, `AERGameMode`는 상태 머신만 돌린다.
- 데디케이티드 서버에서 모드는 **커맨드라인/URL 옵션**(`?Mode=Squad`)으로 받아 GameMode가 해당 로우를 로드한다.

## 3. 밤(Night) 규칙

| 항목 | 내용 |
|---|---|
| 시야 | 밤에는 **시야가 제한**된다 (정확한 감소 수치는 **(미확인)**) |
| 보스 | 주요 필드 보스(알파/오메가/위클라인)가 **전부 밤에** 등장 → [`몬스터_야생동물_역기획서.md`](몬스터_야생동물_역기획서.md) §5 |
| 아이템 가치 | CCTV·감시 카메라·드론 등 시야 아이템의 가치가 급등 |

> **설계 해석:** 밤은 연출이 아니라 **보스 전투를 정보 부족 상태로 만드는 장치**다.
> 시야를 깎아 "보스를 치는 팀이 누가 오는지 모르게" 만들어 오브젝트 한타의 변수를 키운다.
> 클론에서 밤을 단순 조명 변경으로 구현하면 이 긴장이 통째로 사라진다.

**구현 메모**
- 시야는 **연출(포스트프로세스)과 게임플레이 가시성(적 액터 노출)을 분리**한다. 조명만 어둡게 하면 클라 설정으로 밝기를 올려 이득을 본다 — **가시성 판정은 서버 권위**여야 한다.
- `ETimeOfDay` 전환은 페이즈 테이블에서 파생된다. 별도 시계를 두지 않는다.

## 4. 제한 구역(금지 구역) [S5]

| 항목 | 값 |
|---|---|
| 맵 표기 | **노랑 = 다음 차례 금지 예정 / 빨강 = 이미 금지됨** |
| 기본 폭사 타이머 | 진입 시 **20초** |
| 실험체 처치 시 연장 | **+7초** |
| 알파/오메가 처치 시 연장 | **+2초** |
| 타이머 상한 | **30초** |
| 부활 직후 타이머 | 10초 |
| 7일차 회복량 | 15초 (**상한 무시**) |
| 연구소 | 맵 정중앙. **게임 시작부터 금지구역** [S6] |
| 7일차 낮 | 임시 안전지대 밖 사망 확정. 하이퍼루프/VLS 사용 불가, **방화벽 진입자 즉사** |

> **핵심 구조:** 이 게임의 제한구역은 배틀로얄의 "장판 도트딜"이 아니라 **개인별 잔여 타이머**다.
> 처치로 타이머를 벌 수 있으므로 **금지구역이 전투 공간으로 재사용된다.** 도트딜로 바꾸면 이 플레이가 사라진다.

### 4.1 금지 구역 복원 시스템 (12.0 신규) [S3]

| 항목 | 값 |
|---|---|
| 구매처 / 비용 | 루미(LUMI) 상품, **20 크레딧** |
| 구매 가능 시점 | **3~5일차 낮**, 페이즈 시작 **20초 전** |
| 제한 | **한 페이즈당 한 팀만** |
| 부가 효과 | 구매 팀 **CCTV 시야 획득** / 복원 구역 첫 리스폰 야생동물 **변이체 확률 +10%** |

> **기획 의도:** 공간 박탈을 **"자원을 지불해 되사는 전략 선택지"** 로 전환. 파밍이 밀린 팀에게 역전 레버를 주되, 20 크레딧의 기회비용으로 남용을 막는다.
> ⚠ 상위 §12.5는 이 시스템을 **초기 버전에서 잘라낼 것**으로 분류했다. 코어 루프 안정화 후 추가.

**구현 메모**
- 잔여 타이머는 **서버 권위 float**(PlayerState 또는 캐릭터). `COND_OwnerOnly`로 복제하면 충분하다 — 남의 잔여 시간은 볼 필요가 없다.
- 타이머 감소는 `Tick`이 아니라 **1초 주기 타이머 + 0 도달 시 사망 처리**. 상한 30초 클램프를 **한 함수에 모은다**(GAS 전환 시 GameplayEffect로 대체될 지점).
- "한 페이즈당 한 팀만" 복원 → GameState에 **페이즈별 복원 사용 플래그**. 클라 버튼 비활성화는 복제된 플래그로 그린다.
- 구역 상태(`정상 / 예고(노랑) / 금지(빨강)`)는 **지역 단위 배열로 복제**하고, 미니맵이 이 배열만 보고 칠하게 한다.

## 5. 부활 시스템 [S5], [S2], [S3]

| 구간 | 규칙 |
|---|---|
| **1일차 ~ 2일차 낮** | 팀원 생존 시 **자동 부활**. 팀 단위 동기화 |
| **2일차(주입 시점)** | 자동 부활 종료. **팀 전멸 = 게임 오버** |
| **3일차 ~ 5일차** | **크레딧 200 지불 수동 부활**(키오스크). 병원은 **50 크레딧 할인** [S6] |
| **5일차 밤 이후** | 키오스크 부활 종료. 이후 **임시 안전지대만이 부활 수단** |
| **6일차 밤 이후** | 사실상 "죽으면 끝" |
| 부활 대기(선택) 창 | **30초**. 이후 자동 부활 또는 사망 확정 |
| 부활 후 체력 | **최대 체력의 55%** (12.0에서 50→60%, **12.1에서 60→55% 재조정**) [S3], [S2] |
| 전멸 페널티 부활 시간 | 3초 → **5초** (12.0) [S3] |
| 부활 소요 시간(레벨별) | Lv1~6: 3~8초 / Lv7: 10초 / Lv8~11: 25~30초 / Lv12+: **35~40초** |

> **설계 해석:** 부활 비용이 **시간축과 캐릭터 레벨 양쪽**으로 오른다.
> 후반에 죽으면 40초를 잃는데, 이는 8일차 낮(150초)의 1/4이다. **레벨이 높을수록 죽으면 안 되는 구조** = 성장한 쪽이 조심하게 만들어 역전 여지를 남긴다.

**구현 메모**
- 부활 규칙은 **페이즈 행의 필드**(`ERespawnRule`)로 들고 온다. `if (Day >= 3)` 같은 하드코딩 분기를 만들지 않는다.
- 사망 → 30초 선택 창 → 부활/확정사망은 **서버 상태 머신**. 클라는 남은 초와 버튼 활성 여부만 복제받는다.
- 크레딧 차감·체력 55% 세팅은 전부 **서버에서만**. 클라는 `Server RPC(WithValidation)`로 "부활 요청"만 보낸다.
- 부활 지점(키오스크/임시 안전지대)의 유효성도 서버에서 재확인한다. 클라가 보낸 좌표를 믿지 않는다.

## 6. 탈출(Escape) 시스템 [S5]

승리와 별개로 존재하는 **"조기 이탈 = 성과 확정"** 장치.

| 조건 | 값 |
|---|---|
| 가능 시점 | **3일차 ~ 6일차 밤** |
| 필요 아이템 | **루프 카드 키 - RED** (키오스크 100 크레딧) |
| 생존 조건 | 팀원 **2명 이상 생존** |
| 승인 | 팀 **과반 투표** |
| 추가 조건 | 부활 이후 **팀원 1명 이상 사망 상태** |
| 대기 시간 | **5초** (무방비, 이동만 가능) |
| 실패 조건 | 대기 시간 중 팀 전멸 시 탈출 실패 |

> ⚠ **상위 §12.5는 탈출을 초기 버전에서 잘라낼 것으로 분류했다.**
> 이유: 조건이 6개(시점/아이템/생존 인원/투표/사망자/대기)인데 **발동 빈도가 낮다.**
> 탈출 성공 시의 순위·보상 산정 규칙은 **(미확인)** — 매치 종료 판정과 직결되므로 구현 전 반드시 확인이 필요하다.

**구현 메모**
- 6개 조건 검사는 **서버 한 함수에 모은다**(`CanTeamEscape`). 클라의 버튼 활성화는 그 결과를 복제한 bool 하나로 그린다.
- 투표는 `Server RPC` → GameState의 팀별 투표 배열 → 과반 도달 시 서버가 5초 타이머 시작.
- 탈출한 팀은 **살아있지도 죽지도 않은 상태**다. 생존 팀 카운트에서 빼되 최종 순위에는 넣어야 하므로 `bAlive` 하나로 처리하지 말고 **`ETeamMatchResult { Alive, Eliminated, Escaped, Winner }`** 를 둔다.

## 7. 휴식(Rest) 시스템 — 시즌 12 최대 변경점

12.0에서 전투 중에도 쓰는 **3단계 캐스팅**으로 전면 개편 → 커뮤니티 투표 **87%가 롤백 요구** → **12.1에서 즉시 재조정** [S3], [S22], [S23], [S2].

| 항목 | 값 (12.1 이후) |
|---|---|
| 비전투 자동 회복 | **0.5초당 최대 체력/기력 2%** (캐스팅과 별개, **병존**) |
| 캐스팅 휴식 | X키. **전투 중에도 시전 가능**. 3단계 누적형 |
| 1단계 | 캐스팅 3초 → 체력 15% / 기력 20% |
| 2단계 | 체력 15% / 기력 25% |
| 3단계 | 체력 30% / 기력 30% |
| 취소 조건 | 단축키/이동 입력, 피격, 군중제어 적중 → 취소 + **1초 재사용 대기** |
| UI | 휴식 캐스팅 바 + **예상 회복 체력 수치** 표시 |

> ⚠ **2·3단계의 캐스팅 시간은 (미확인).** 12.0 노트는 3/3/4초로 기재했으나 12.1에서 변경됐는지 확인되지 않았다.

> **여기서 배울 것 (상위 §12.5 함정 #1):** 12.0은 기존 "비전투 자동 회복"을 **캐스팅으로 대체**하려다 실패했다.
> 12.1의 해법은 롤백이 아니라 **병존**이었다. 클론 개발 시 **온보딩 장치로 기존 시스템을 치우지 말 것.**

**구현 메모**
- 캐스팅 상태·단계·회복량 판정은 전부 **서버**. 클라는 예측 없이 캐스팅 바만 그린다(프로젝트 지침 §6: 예측은 요청받았을 때만).
- 취소 트리거가 4종(입력/이동/피격/CC)이므로 **취소 진입점을 한 함수로 모은다**. 흩어놓으면 "가끔 안 끊기는" 버그가 난다.
- 회복량은 **최대 체력 %** 기준 → `UERAttributeSet` 의 `MaxHealth` 어트리뷰트를 읽는다. 회복 자체는 `UGameplayEffect` 로 적용한다. 멤버 직접 접근 금지(GAS 전환 대비).

## 8. 승리 조건 · 매치 종료 판정

| 모드 | 종료 조건 |
|---|---|
| 스쿼드 / 랭크 | **생존 팀 1팀**만 남거나, 크로노 스피어 반경 0 도달 → 내부 팀 승리 |
| 론 울프 | 생존 **1인** |
| 코발트 프로토콜 | 상대 라이프 40 → 0. 미결 시 **서든데스(30초 내 선취 킬 승리)** |

**스쿼드 종료 판정 순서 (서버)**

```
매 사망 / 탈출 이벤트마다:
  1. 팀 전멸 판정   → 해당 팀 Eliminated (단, 부활 가능 구간이면 보류)
  2. 탈출 확정      → 해당 팀 Escaped, 생존 카운트에서 제외
  3. 생존 팀 수 == 1 → 그 팀 Winner, 매치 종료
  4. 생존 팀 수 == 0 → 무승부 (동시 전멸 규칙 (미확인))
크로노 스피어 반경 0 도달 시:
  5. 스피어 내부 팀 = Winner (복수 팀 잔존 시 처리 (미확인))
```

> ⚠ **동시 전멸·복수 팀 잔존 시의 순위 규칙은 (미확인).** 랭크 RP 산정과 직결되므로 구현 전 확인 필요.

**구현 메모**
- 종료 판정을 사망 처리 함수 안에 넣지 말고 **GameMode의 `CheckMatchEnd()` 한 곳**에 모은다. 여러 곳에 흩어지면 이중 종료가 난다.
- `bMatchEnded` 가드를 두고, 종료 후 들어오는 사망/부활 RPC는 전부 무시한다.
- 순위는 **탈락 시각 역순**으로 확정한다. 종료 시점에 한꺼번에 계산하면 동시 전멸에서 순위가 갈리지 않는다.

## 9. 서버 권위 · 리플리케이션 표

> 이 프로젝트는 **데디케이티드 서버 타겟**이 있다. 아래는 전부 **서버 권위**이며, 클라는 표시만 한다.

| 항목 | 권위 | 복제 방식 | 클라가 하는 일 |
|---|---|---|---|
| 현재 페이즈(일차/낮밤) | 서버 | `AERGameState`에 `Replicated` + `OnRep_Phase` | HUD 갱신, 낮/밤 연출 전환 |
| 페이즈 종료 시각 | 서버 | **절대 서버 시간 1개**만 복제 | 로컬 카운트다운 렌더 |
| 제한구역 상태(지역별) | 서버 | 지역 상태 배열 `Replicated` | 미니맵 색칠(노랑/빨강) |
| 폭사 잔여 타이머 | 서버 | `COND_OwnerOnly` | 본인 HUD 경고 |
| 크로노 스피어 중심/반경 | 서버 | 시작·목표 반경 + 시작 시각 복제 | 동일 보간식으로 시각화 |
| 스피어 외부 피해 / 즉사 | **서버 전용** | 복제 없음(결과인 사망만 복제) | — |
| 부활 규칙(자동/유료/불가) | 서버 | 페이즈에서 파생, `Replicated` | 부활 UI 활성/비활성 |
| 부활 실행·크레딧 차감·체력 55% | **서버 전용** | 결과 스탯만 복제 | `Server RPC`로 요청만 |
| 탈출 조건 충족 여부 | 서버 | 팀 단위 bool | 버튼 활성화 |
| 탈출 투표 집계 | 서버 | 팀 투표 상태 복제 | `Server RPC`로 투표 전송 |
| 휴식 캐스팅 단계·회복량 | 서버 | 캐스팅 상태 복제 | 캐스팅 바만 표시 |
| 보스·야생동물 스폰 | 서버 | 액터 스폰이 곧 복제 | — |
| 금지구역 복원 구매 | 서버 | 페이즈별 사용 플래그 복제 | 구매 버튼 상태 |
| 팀별 매치 결과·순위 | 서버 | 종료 시 일괄 복제 | 결과 화면 |
| 밤 시야 판정(적 가시성) | **서버 전용** | 가시 액터만 복제(relevancy) | 조명 연출만 로컬 |

> ⚠ **밤 시야를 클라 조명으로만 구현하면 치팅이 된다.** 가시성은 반드시 서버 판정으로 처리한다.
> ⚠ `UPROPERTY(Replicated)`를 추가하면 **반드시** `GetLifetimeReplicatedProps`에 `DOREPLIFETIME`을 넣는다. 빠뜨리면 조용히 복제되지 않는다.

## 11. 구현 우선순위

```
1순위. 매치 페이즈 상태 머신 (EMatchPhase + FMatchPhaseRow 기반 타이머 체인)
       → 검증: 데디 서버에서 페이즈가 테이블 순서대로 전환되고,
               클라 2대의 남은 시간 표시가 서로 1초 이내로 일치
               (Play As Client, Number of Players: 3, Dedicated Server 체크)

2순위. 페이즈 이벤트 큐 (PhaseEventTags → 보스 스폰 / 키오스크 개방 / 규칙 전환)
       → 검증: 2일차 밤 알파, 3일차 밤 오메가, 4일차 밤 위클라인이
               서버에서 스폰되고 모든 클라에 보인다

3순위. 제한 구역 (지역 상태 배열 + 개인 폭사 타이머 + 즉사 처리)
       → 검증: 빨강 구역 진입 20초 후 사망. 실험체 처치 시 +7초, 상한 30초에서 클램프

4순위. 부활 규칙 3단 전환 (자동 → 크레딧 200 → 불가)
       → 검증: 1일차 사망 시 자동 부활 / 3일차 사망 시 크레딧 차감 후 체력 55%로 부활 /
               6일차 밤 사망 시 부활 UI가 뜨지 않음

5순위. 크로노 스피어 3단 축소 + 외부 즉사
       → 검증: 30m→10m→5m→0m 축소가 서버 값과 클라 시각화에서 일치하고,
               경계 밖 캐릭터가 서버 판정으로 사망

6순위. 승리 / 종료 판정 + 순위 산정 (탈락 시각 역순)
       → 검증: 마지막 1팀이 남는 순간 즉시 종료되고, 결과 화면 순위가 전 팀 채워짐.
               종료 후 도착한 사망 RPC가 무시되는지 로그로 확인

7순위. 밤 시야 제한 (서버 가시성 판정 + 로컬 조명 연출 분리)
       → 검증: 밤에 시야 밖 적 캐릭터가 클라에 복제되지 않음 (net relevancy 로그)

8순위. 휴식 시스템 (비전투 자동회복 + 3단계 캐스팅 병존)
       → 검증: 입력·이동·피격·CC 4가지가 모두 캐스팅을 끊고 1초 쿨다운이 걸림

── 이하 초기 버전 제외 (상위 §12.5) ──
   탈출 시스템 / 금지구역 복원 시스템 / 론울프·코발트·유니온 모드
```
