# 성장 시스템 — 레벨 · 숙련도 · 특성 · 전술 스킬 — 개발자용 역기획서

> 상위 문서: [`../이터널리턴_역기획서.md`](../이터널리턴_역기획서.md) §9, §5.4, §5.5

## 0. 이 시스템의 정체

**이 게임의 파워는 한 줄이 아니라 세 줄로 자란다 — 레벨 / 숙련도 / 장비.**
셋은 서로 다른 행동으로, 서로 다른 속도로, 서로 다른 이유로 오른다.
레벨은 **교전과 사냥**(위험을 감수한 만큼), 숙련도는 **반복 행동**(무엇을 했는지), 장비는 **계획과 동선**(어디를 돌았는지)을 파워로 환전한다.
축이 셋으로 쪼개져 있으면 **한 축에서 밀려도 다른 축으로 따라잡을 여지**가 생긴다 — 배틀로얄에서 초반에 밀린 플레이어가 게임을 포기하지 않게 만드는 장치다.
동시에 이것은 **신규 유저가 이해해야 할 성장 시스템이 3개**라는 뜻이고, 상위 문서 §12.3이 지적한 학습 부담의 큰 축이다.

> **구현 관점의 결론:** 세 축은 **전부 다른 데이터 테이블과 다른 이벤트 소스**를 갖는다.
> 하나의 "성장 컴포넌트"에 몰아넣지 말고 **경험치 축적기(누가 무엇을 했는가) → 레벨 판정 → 스탯 재계산**의 3단 파이프라인을 공유하되, 축별로 인스턴스를 분리하는 편이 낫다.

## 1. ⭐ 성장축 3개 비교

| 항목 | **실험체 레벨** | **숙련도 (6종)** | **장비** |
|---|---|---|---|
| **획득 방법** | 야생동물 처치 / 실험체 처치·관여 / 시간 경과(미확인) | 해당 행동 수행 (피해·제작·이동·채집) | 재료 채집 + 2개 조합 제작 |
| **성장 속도** | 계단형 (레벨업 순간 점프) | 계단형이지만 **잘게 쪼개짐** (레벨당 1~4% 수준) | 계단형 + **큰 점프** (등급 상승 시) |
| **되돌릴 수 있는가** | ❌ 불가 (하락 없음) | ❌ 불가 | ⚠ 부분적 — 장비 교체로 스탯 구성 변경 가능 |
| **팀원과 공유되는가** | ❌ 개인 (킬 관여로 분배) | ❌ 개인, 행동한 사람만 | ⚠ 아이템 **양도 가능** → 실질적으로 팀 자원 |
| **파워 기여도** | **최대** — 스킬 레벨 + 기본 스탯 전부 | **중** — 단 **D스킬 해금**이라는 이산 보상이 붙어 체감은 큼 | **최대** — 후반으로 갈수록 지배적 |
| **밸런싱 단위** | 실험체 | **실험체 × 무기** (조합 셀) | 아이템 |
| **매치 내 상한** | Lv.20 | 무기 숙련도 15+ (상한 미확인) | 초월 등급 |
| **클론 초기 버전 필수 여부** | ✅ 필수 | ⚠ **무기 숙련도만** | ✅ 필수 |

> **가장 중요한 관찰:** 세 축 중 **되돌릴 수 있는 축이 장비 하나뿐**이다.
> 즉 레벨·숙련도는 **한 번 벌어지면 좁혀지지 않는 격차**이고, 이 게임에서 역전의 여지는 사실상 **장비와 포지셔닝**에만 있다.
> 12.1이 초반 필요 경험치를 낮춘 것(§2.2)도 "되돌릴 수 없는 축의 초반 격차"를 줄이려는 조정으로 읽힌다.

## 2. 실험체 레벨

### 2.1 기본 규칙

| 항목 | 값 | 상태 |
|---|---|---|
| 최대 레벨 | **20** | 확인 |
| 레벨당 스킬 포인트 | **1** (Lv.1에 1포인트 지급, Q/W/E 중 1개 습득) | 확인 |
| Q/W/E 최대 레벨 | **5** | 확인 |
| R(궁극기) 최대 레벨 | **3** | 확인 |
| P(패시브) | 레벨업으로 **자동 강화** (대개 3단계), 포인트 소모 없음 | 확인 |
| 스킬별 습득 가능 레벨 제한(R 해금 시점 등) | — | **(미확인)** |

> ⚠ **포인트 수지가 맞지 않는다.** 최대 소비는 `Q5 + W5 + E5 + R3 = 18`인데 Lv.20까지 지급되는 포인트는 20이다.
> **2포인트가 남는다.** → 레벨업당 1포인트 지급이 아닌 별도 규칙(특정 레벨 미지급 / R이 레벨 제한으로 늦게 열림 등)이 있을 가능성이 높다. **(미확인)**, 인게임 확인 필요.

### 2.2 레벨업 필요 경험치

| 구간 | 12.1 이전 | **현재 (12.1 하향)** |
|---|---|---|
| 1 → 2 | 900 | **800** |
| 5 → 6 | 2,700 | **2,500** |
| 그 외 전 구간 | — | **(미확인)** |

> ⚠ 웹 검색에서 "230 시작 / 레벨당 +270"이라는 값이 잡히지만, 이는 **방어 숙련도 곡선(§3.3)의 오인**이다. 실험체 레벨 경험치가 아니다.
> 확인된 두 점(800 / 2,500)만으로는 곡선 형태를 특정할 수 없다. **선형 가정 시 레벨당 약 +425 증가**로 계산되지만 이는 **검증되지 않은 역산값**이며, 12.1이 두 구간을 서로 다른 비율(−11.1% / −7.4%)로 낮춘 것을 보면 **애초에 단순 등차가 아닐 가능성**이 크다.

### 2.4 레벨별 스탯 증가 (실측 사례)

| 실험체 | 체력 /Lv | 공격력 /Lv | 방어력 /Lv | 체력 재생 /Lv |
|---|---|---|---|---|
| 재키 | +95 (940 → 2,745) | +4.7 (36 → 125) | +3 (50 → 107) | +0.077 |
| 아야 | +76 (905 → 2,349) | +4.1 (43 → 120) | +2.3 (51 → 94) | +0.06 |
| 매그너스 | +95 (1,030* → 2,875) | +4.4 (44 → 127) | +3.2 (49 → 109) | +0.85 |

\* 12.2 하향 반영. **이동 속도·공격 속도는 레벨로 증가하지 않는다.**
12.2에서 아드리아나 레벨당 체력 **감소**, 블레어 레벨당 체력 **증가** → **레벨당 성장치 자체가 개별 밸런싱 파라미터**다.

> ⭐ **성장 곡선은 선형이다.** `940 + 95 × 19 = 2,745`(재키)가 정확히 맞는다. 아야·매그너스도 동일.
> → **20행짜리 레벨 테이블이 필요 없다.** `기본값 + 레벨당 증가` 두 필드면 충분하다 (§8 스키마).

**구현 메모**
- 레벨업 판정·스탯 재계산은 **서버 전용**. 클라는 `OnRep_Level`에서 UI만 갱신한다.
- 스킬 포인트 배분은 **클라 → `Server` RPC(`WithValidation`)**. 서버가 잔여 포인트와 슬롯 상한(5/5/5/3)을 검증한다. 클라 값을 신뢰하면 스킬 레벨 조작이 뚫린다.
- 스탯은 `UERAttributeSet` 의 어트리뷰트다. **레벨업 증가도 `UGameplayEffect` 로 적용**한다 — 코드에서 직접 세팅하면 클램프를 우회한다 (`CLAUDE.md` §8).

## 3. 숙련도 (Proficiency) — 두 번째 성장축

### 3.1 무기 숙련도 (6종 중 유일하게 중요)

| 항목 | 값 |
|---|---|
| 레벨당 보상 | **공격 속도(%)** + (**기본 공격 증폭(%)** 또는 **스킬 증폭(%)** 중 **1개**) + 공격력 |
| **D스킬 해금** | **숙련도 5레벨** |
| **D스킬 강화** | **10레벨(1차) / 15레벨(2차)** |
| 계수 단위 | **실험체 × 무기 조합마다 다름** |
| 공격 속도·공격력 증가량 | **(미확인)** — 패치노트에 공개된 것은 증폭 계수뿐 |
| 레벨별 필요 경험치 | **(미확인)** |

**경험치 획득** (확인값)

| 행동 | 획득량 |
|---|---|
| 실험체에게 피해 100당 | **63** |
| 야생동물에게 피해 100당 | 5 |
| 실험체 처치 | 100 |
| 무기 제작 (등급 1~5) | 100 / 200 / 350 / 550 / 800 (**최초 제작 시 +25%**) |

> ⭐ **실험체 피해가 야생동물의 12.6배다.** 무기 숙련도는 사냥이 아니라 **교전으로 올리라는 설계**다.
> D스킬 해금이 여기 걸려 있으므로, 이는 곧 **"초반에 싸운 쪽이 먼저 스킬 하나를 더 얻는다"** 는 뜻이다. 매우 공격적인 스노우볼 설계이며, 초반 교전을 강제하는 장치다.

> **스킬 증폭 계열은 4%대, 기본 공격 증폭 계열은 1~2%대**로 뚜렷하게 갈린다. 약 **2배 차이**다.
> 스킬 증폭 1%와 기본 공격 증폭 1%의 **실질 가치가 다르기 때문**으로 읽힌다 (기본 공격은 상시 발동, 스킬은 쿨다운 제약).
> → 클론에서 미확인 캐릭터의 계수를 채울 때 **"스킬 증폭형 4%대 / 기본 공격 증폭형 2%대"** 를 출발선으로 쓰되, **자체 결정값임을 반드시 기록**할 것 (§11 표기 규칙).

### 3.3 나머지 5종 숙련도

| 숙련도 | 레벨당 효과 | Lv2 필요 EXP | 이후 증가 | 주요 획득처 |
|---|---|---|---|---|
| **방어** | 기본 공격 피해 **−1%**, 스킬 피해 **−0.8%** | 230 | +270 | 실험체 피해 100당 60 / 함정 20 / 동물 10 / 처치 시 (80 − 상대 레벨×?) 최소 50 / 머리 방어구 제작 100·200·350·600·1000 |
| **사냥** | 야생동물 피해 **+2%** | 180 | +200 | 동물에게 받은 피해 100당 10 / 준 피해 100당 35 |
| **제작** | 비전투 체력 재생 **+10%** (최대 **+200%**) | 430 | +120 | 모든 방어구·무기 제작 100·200·350·600·1000 / 음식 제작 50·120·200·360·406 |
| **탐색** | 시야 **+0.01** | 350 | +60 | 항공 보급 350 / 상자 70 / 채집 100 / 보안 콘솔 100 / 카메라·드론 제작 62~625 |
| **이동** | 이동 속도 **+0.01** | 300 | +20 | 지역 이동 180 / 50m 이동당 55 / 다리 방어구 제작 100·140·250·500·800 |

> **곡선 형태가 5종 전부 동일하다: `Lv2 임계값 + 등차 증가`.** 파라미터 2개만 다르다.
> → **5종을 각각 구현할 이유가 없다.** `ProficiencyTrack` 클래스 하나 + 데이터 행 5개면 끝난다.
> 단, 제작 숙련도만 **상한(+200%)** 이 있으므로 `MaxTotalBonus` 필드가 추가로 필요하다.

**설계 의도 해석**
숙련도는 **"플레이 스타일을 스탯으로 환전하는 시스템"** 이다. 사냥만 해도 사냥이 빨라지고, 이동만 해도 이동이 빨라진다.
→ **선형 보상 루프 6개를 병렬로** 깔아, 어떤 행동을 해도 "성장 중"이라는 감각을 준다. 상위 문서 §UI가 지적한 대로 HUD 좌하단에 6종 진행도를 **상시 노출**하는 것이 이 감각의 전달 장치다.
반대급부는 명확하다 — **신규 유저가 파악해야 할 시스템이 6개 늘어난다.**

**구현 메모**
- 숙련도 경험치 축적은 **전부 서버**. 데미지 파이프라인 종단에서 **"가한 피해 / 받은 피해" 이벤트를 하나로 모아** 각 트랙에 분배하는 구조가 깔끔하다 (무기·방어·사냥이 같은 피해 이벤트를 공유한다).
- 숙련도 값은 `DOREPLIFETIME_CONDITION(..., COND_OwnerOnly)`을 **권고**한다. 적의 무기 숙련도가 클라에 있으면 **D스킬 해금 여부를 미리 알 수 있어** 정보 우위가 생긴다. (원작 처리 방식은 **(미확인)**)
- D스킬 해금/강화는 **숙련도 레벨 변화 시점의 서버 판정**이다. 5/10/15는 데이터 테이블 값으로 두고 하드코딩하지 않는다.

| 구조 | 계열마다 **핵심 4종 + 보조 1군 4종 + 보조 2군 4종** = 계열당 12종, 총 **48종** |
| 선택 규칙 | 핵심 1개 → 그 핵심 계열의 보조 1군·2군에서 각 1개 → **이후 다른 계열의 보조도 선택 가능** |
| 최종 장착 수 | **5개** |
| 선택 시점 | **로비(매치 전)**. 매치 중 변경 가능 여부 **(미확인)** |
| 프리셋 슬롯 | 기본 3개, A-Coin / NP로 확장 (BM 연동) |

|---|---|---|---|
| **파괴** | 급소 노리기, 흡혈, 아드레날린, 가속기 | 열등감 극복, 광란, 약자 멸시, 흉터 | 곰 가면, 멧돼지 가면, 늑대, 들개 탑승 |

### 4.2 시즌 12 조정 — 특성 데이터 구조를 보여주는 유일한 사례

| 특성 | 변경 |
|---|---|
| **폭발 선인장** | 12.0 보조 → **핵심 승격** ⚠(12.2 확인 시 지원 계열 보조 표기 유지 — **표기 불일치**) / 아군 이동속도 **2초간 15%** 추가 / 피해 10~150 → **8~160** / 부착 3초 → **4초** / 쿨다운 8초 → **대상별 8초** / 대상 최대 체력 비율 피해 **4% → 5%**(12.2) |
| **초재생** | 핵심 → **보조 강등** / 회복량 8% → **5%** / 맞춤형 능력치 증가 **제거** |

> ⭐ **이 두 사례에서 필요한 필드가 그대로 드러난다.**
> `계열 / 등급(핵심·보조1·보조2) / 고정 피해 범위 / 비율 피해 / 지속시간 / 쿨다운 / 쿨다운 스코프`.
> 특히 **"쿨다운 8초 → 대상별 8초"** 는 쿨다운을 **키(전역 / 대상별)로 관리**해야 한다는 뜻이다. 단일 float 타이머로 짜면 나중에 갈아엎어야 한다.
> **등급(핵심↔보조)이 패치로 이동한다**는 점도 중요하다 — 등급을 클래스 계층이 아니라 **데이터 필드**로 두어야 한다.

**구현 메모**
- 특성은 **매치 시작 전 확정 → 서버 검증 후 고정**. 매치 중 변경이 없으면 복제는 초기 1회로 충분하다.
- 선택 규칙(핵심 1 → 같은 계열 보조 각 1 → 이후 자유)은 **서버에서 반드시 재검증**한다. 로비 UI만 믿으면 불법 조합이 들어온다.
- ⭐ **특성 1개 = `UGameplayEffect` 1개**로 만든다 (`CLAUDE.md` §8). 48종을 개별 C++ 클래스로 만들지 않는다.
  - **상시 효과**(스탯 증가) → Infinite GE의 Modifier. 코드가 없다.
  - **트리거 효과**(피격 시 / 처치 시 / 주기적) → `GameplayEffect` + `GameplayCue`, 또는 트리거가 필요하면 `UGameplayAbility` 를 grant하고 `WaitGameplayEvent` 로 받는다.
  - **주기 효과** → GE의 `Period` 가 이미 한다. 자체 타이머를 만들지 않는다.
- ⭐ **§4.2가 드러낸 두 요구가 GAS에서 자연스럽게 풀린다.**
  - *"쿨다운 8초 → **대상별** 8초"* → 쿨다운 GE를 **대상에게** 거는 것으로 표현된다. 자체 키 관리 테이블이 필요 없다.
  - *"폭발 선인장: 보조 → **핵심** 승격"* → 등급을 `GameplayTag`(`Trait.Tier.Core`)로 두면 패치로 태그만 바꾸면 된다. 클래스 계층으로 만들면 갈아엎어야 한다.
- 특성 선택 검증(핵심 1 → 같은 계열 보조 각 1 → 이후 자유)은 GAS가 해주지 않는다 — **직접 만든다.**

**로비에서 선택하는 전략 슬롯. D키와 스왑 가능. 기본 1레벨, 전술 강화 모듈(영웅 재료) 소비로 2레벨.**

**구현 메모**
- F는 **D와 같은 슬롯 시스템**을 쓴다(스왑 가능). 스킬 실행 파이프라인을 D/F 공용으로 만들 것.
- ⚠ **상위 문서 §12는 초기 버전에서 F를 완전 삭제하고 D만 운영할 것을 권고한다.** 본 문서도 같은 결론이다 (§9).

## 6. 파워 스파이크 — 시간축 위의 3축

```
 파워
  │                                                 ┌────────── 평탄화
  │                                          ┌──────┘ 4일밤 초월 + VF
  │                                 ┌────────┘ 3일밤 포스코어
  │                        ┌────────┘ 2일밤 미스릴
  │             ┌──────────┘ 무기숙련 5 → D스킬 해금
  │─────────────┘
  └──────────────────────────────────────────────────────────── 시간
    1일차   2일차   3일차   4일차   5일차   6일차   7일차   8일차

 축별 기여 (▓ = 그 시점의 주 성장 동력)
  레벨    ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░  Lv.20(6~7일차) 이후 정지
  숙련도  ░░░▓▓▓▓░░░░░░▓▓▓░░░░░░░░▓▓▓░░░░░░░░░░░░░░  5 / 10 / 15레벨 = D스킬 계단
  장비    ░░░░░░░░░▓▓▓▓░░░░▓▓▓▓░░░░░▓▓▓▓▓░░░░░░░░░░  보스·보급 등장 시각에 동기화
                     ↑알파      ↑오메가     ↑위클라인
                    (2일밤)     (3일밤)     (4일밤)
```

| 구간 | 시점 | 원인 | 담당 축 |
|---|---|---|---|
| 초반 스파이크 | 1일차 밤 ~ 2일차 낮 | 무기 숙련도 **5레벨 → D스킬 해금**. 스킬 4개 → **5개** | **숙련도** |
| 1차 아이템 | 2일차 밤 | 알파 → 미스릴 → 전설 무기 제작 진입 | 장비 |
| 2차 아이템 | 3일차 밤 | 오메가 → 포스코어 → 코어 전설 방어구 완성 | 장비 |
| 숙련도 2차 | 3~4일차 | 무기 숙련도 **10레벨 → D스킬 1차 강화** | **숙련도** |
| 3차 스파이크 | 4일차 밤 | 위클라인 + 초월 보급 → **초월 방어구 + VF 혈액 샘플**. 사실상 최종 빌드 | 장비 |
| 숙련도 최종 | 5~6일차 | 무기 숙련도 **15레벨 → D스킬 2차 강화** | **숙련도** |
| 레벨 캡 | 6~7일차 | **Lv.20 도달, R 3레벨** | **레벨** |
| 후반 평탄화 | 7~8일차 | 성장 종료 → 순수 실력·포지셔닝 | — |

> ⭐ **세 축의 스파이크가 시간축에서 서로 어긋나게 배치되어 있다.**
> 숙련도는 초반(1~2일)과 중반(3~4일), 장비는 밤마다, 레벨은 상시 누적 후 6~7일차에 캡.
> → **"지금 이 순간 성장 중인 축이 항상 최소 하나 있다."** 성장 정체감이 생기는 구간을 구조적으로 제거한 설계다.
> 그리고 장비 스파이크가 **필드 오브젝트 등장 시각에 못 박혀 있으므로**, 파워 스파이크 스케줄러가 곧 **강제 조우 스케줄러**로 기능한다.
> **클론에서 이 시각표를 임의로 바꾸면 교전 리듬이 통째로 무너진다.** 시각표는 몬스터·장비 문서와 **같은 데이터 소스**를 봐야 한다.

```
  ExpIncrement      : int32   // +270 / +200 / +120 / +60 / +20
  EffectStatType    : EStatType
  EffectPerLevel    : float   // -1% / +2% / +10% / +0.01 / +0.01
  MaxTotalBonus     : float   // 제작만 +200%. 0이면 무제한
```

```
FTraitRow : FTableRowBase               // RowName = 특성 ID
  DisplayName   : FText
  Line          : ETraitLine      // Destruction | Chaos | Resistance | Support
  Tier          : ETraitTier      // Core | Sub1 | Sub2  ← 패치로 이동한다. 데이터 필드로 둘 것
  EffectId      : FName           // 효과 핸들러 키. 48개 클래스를 만들지 않는다
  EffectParams  : TArray<float>   // 고정 피해 범위 / 비율 피해 / 지속시간 등
  Cooldown      : float
  CooldownScope : ECooldownScope  // Global | PerTarget  ← 폭발 선인장 12.2 변경 대응
```

> ⭐ **`EAmpType`이 핵심이다.** 무기 숙련도는 기본 공격 증폭과 스킬 증폭 중 **하나만** 준다.
> 두 필드를 다 두고 한쪽을 0으로 채우는 대신 enum + 값 1개로 가야, "이 조합이 평딜형인가 스킬형인가"가 데이터에서 즉시 읽힌다. 밸런스 표를 뽑을 때도 이 필드가 정렬 키가 된다.
> **증폭 계수는 데미지 계산 함수 한 곳에서만 소비할 것** (CLAUDE.md §8 — 데미지 계산은 한 곳에 모은다).

## 9. 클론 초기 버전 — 잘라도 되는 성장축

| 대상 | 판단 | 근거 |
|---|---|---|
| **실험체 레벨** | ✅ **유지 필수** | 스킬 레벨업이 여기 걸려 있다. 빼면 게임이 성립하지 않는다 |
| **무기 숙련도** | ✅ **유지** | **D스킬 해금**이라는 이산 보상이 있어 체감이 크다. 1~2일차 파워 스파이크의 유일한 원천 |
| **나머지 5종 숙련도** | ❌ **전부 잘라낸다** | 레벨당 0.8~10%의 미미한 수치. 인지 부하 5개 대비 재미 기여도가 낮다 |
| **특성 48종 5슬롯** | ⚠ **12종 3슬롯으로 축소** | 계열 3개 × 4종. 46종 수치가 (미확인)이라 어차피 자체 설계해야 한다 |
| **전술 스킬 (F)** | ❌ **초기 버전 삭제** | D와 역할이 겹치고 슬롯 2개는 초심자에게 과하다. **D만 운영** |
| **특성 프리셋 확장 (BM)** | ❌ 후속 | 코어 루프와 무관 |

> ⚠ **범위 충돌 주의.** [`../Characters/00_공통_구현규약.md`](../Characters/00_공통_구현규약.md) §2.5는 "무기 숙련도 시스템을 이 단계에서 넣지 않는다"고 했다.
> 이는 **캐릭터 6인을 만드는 단계 한정**의 지침이다. 게임 루프를 성립시키는 단계에서는 **무기 숙련도가 반드시 들어와야 한다** — 빼면 1~2일차에 아무 일도 일어나지 않는다.
> 두 문서의 적용 범위가 다르다는 점을 팀에 명확히 공유할 것.

## 10. 구현 우선순위

```
1순위. 경험치 축적 파이프라인(서버) + 실험체 레벨 + FCharLevelStatRow(기본값+레벨당 증가)
       → 검증: 야생동물 처치 시 서버 EXP 증가 → Lv.2 → 체력 +95 / 공격력 +4.7 정확히 반영,
               Play As Client(2인)에서 클라 HUD에 레벨이 복제되어 보임
2순위. 스킬 포인트 배분 (Server RPC + WithValidation, 상한 5/5/5/3)
       → 검증: 클라가 Q에 6번째 포인트를 요청해도 서버가 거부하고 포인트가 줄지 않음
3순위. ProficiencyTrack 1종(무기) + 데미지 파이프라인 종단에 경험치 분배 연결
       → 검증: 실험체에 100 피해 = 63 EXP, 야생동물에 100 피해 = 5 EXP
4순위. D스킬 해금·강화(숙련도 5/10/15) + 무기 교체 시 D슬롯 교체
       → 검증: 숙련도 5 도달 순간 D 슬롯 활성화, 무기를 바꾸면 D스킬이 통째로 교체됨
5순위. FWeaponProficiencyRow의 AmpType별 증폭을 데미지 계산 한 곳에 반영
       → 검증: 레니 권총 숙련도 10 = 스킬 증폭 +44%, 증폭 가산이 단일 함수에서만 일어남을 코드로 확인
6순위. 특성 12종 3슬롯 + 서버 조합 검증 + EffectId 핸들러 4종(피격/처치/주기/상시)
       → 검증: 불법 조합(핵심 2개)을 클라가 보내도 서버가 거부
7순위. 파워 스파이크 스케줄러 연동 (보스·보급 시각과 동기화)
       → 검증: 2일차 밤 알파 / 4일차 밤 초월 보급 — 몬스터·장비 문서의 시각표와 일치
8순위. 나머지 5종 숙련도 (같은 클래스 + 데이터 행 5개)
9순위. 전술 스킬(F) — 초기 버전에서는 하지 않는다
```

> **1~2순위가 끝나면 "성장하는 게임"이 되고, 4순위가 끝나야 "이 게임"이 된다.**
> D스킬 해금이 없으면 무기 숙련도는 그냥 숫자 증가일 뿐이다.
