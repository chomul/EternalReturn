## 0. 이 시스템의 정체

**포그 오브 워는 렌더링 기능이 아니라 리플리케이션 필터다.**

"안 보이는 적을 안 그린다"는 건 클라이언트 렌더링 문제이고, **"안 보이는 적의 좌표를 애초에 보내지 않는다"** 는 건 서버 네트워크 문제다.
전자만 구현하면 패킷에 좌표가 그대로 실려 있으므로 **메모리를 읽는 것만으로 완성된 맵핵**이 된다.
이건 추론이 아니라 이 프로젝트가 이미 네 번 독립적으로 도달한 결론이다:

| 문서 | 이미 내려진 결정 |
|---|---|
| `매치진행_게임모드_역기획서.md`:165 | *"시야는 **연출(포스트프로세스)과 게임플레이 가시성(적 액터 노출)을 분리**한다. 조명만 어둡게 하면 클라 설정으로 밝기를 올려 이득을 본다 — **가시성 판정은 서버 권위**여야 한다"* |
| `매치진행_게임모드_역기획서.md`:334 | *"⚠ **밤 시야를 클라 조명으로만 구현하면 치팅이 된다.**"* |
| `Characters/00_공통_구현규약.md`:161 | 은신 — *"⚠ 클라에 위치를 보내면 **핵에 뚫린다.** 서버에서 relevancy로 걸러야 함"* |
| `맵_지역_이동_역기획서.md`:279 | *"클라에 위치를 다 보내고 클라에서 숨기면 그대로 맵핵이 된다"* |

> **구현 관점의 결론:** 이 시스템의 산출물은 이펙트가 아니라 **`bool IsVisibleToTeam(Actor, TeamId)` 함수 하나와, 그 함수를 리플리케이션 경로에 꽂는 배선**이다.
> 나머지(포스트프로세스, 미니맵 아이콘, 실루엣)는 전부 그 함수의 소비자다. 반대로 하면 소비자마다 판정이 복제되어 하나가 반드시 어긋난다.

**⚠ 사실 밀도 경고.** 원본 역기획서에서 시야에 관해 **확인된 문장은 열 줄이 채 안 된다.** 반경 수치, 밤 감소량, 은신 감지 조건, 수풀의 차폐 여부 — 전부 미확인이다.
그래서 이 문서는 **[관측]**(원본·패치노트·프로젝트 문서에서 확인된 사실) 과 **[설계]**(원작 확인값이 아닌, 이 프로젝트가 정해야 하는 결정) 를 표기로 구분한다.

## 1. 시야의 단위 — 개인이 아니라 팀

| 항목 | 값 | 근거 |
|---|---|---|
| 매치 규모 | **3인 × 8팀 = 최대 24명** (론울프 솔로 18명) | `맵_지역_이동_역기획서.md`:27 |
| 가시성 상태의 개수 | **팀 수 = 8개** (24개가 아니다) | [설계] |
| 팀원이 본 것 | **팀 전체가 본다** | [설계] — MOBA 표준. 원본에 명시 없음 |
| 관전자 / 사망자 | 전체 시야 부여 여부 **(미확인)** | — |

**"개인 시야"가 아니라 "팀 시야"로 접는 것이 이 시스템의 최대 최적화다.** 개인 단위면 관측자 24 × 피관측자 24 = 576쌍이지만,
팀으로 접으면 **관측 팀 8개 × 피관측 액터 N개**가 되고 **네트워크 연결 3개가 같은 가시성 집합을 공유**한다.
이건 성능 이야기이기 전에 **게임 규칙**이다 — 팀원이 본 적이 내 화면에 안 뜨면 3인 파티 게임이 성립하지 않는다.

> **팀 ID는 이 시스템의 선행 조건이다.** 현재 프로젝트에는 `Source/EternalReturn/Core/ERPlayerState.h`만 있고 팀 개념이 **아직 없다** — 시야보다 먼저 만들어야 한다.
> 그리고 소환물·설치물은 자기 팀을 모르므로 `Instigator → PlayerState → TeamId` 로 거슬러 올라가는 **공용 함수 하나**(`GetTeamId(const AActor*)`)가 필요하다.
> 스킬마다 따로 구현하면 레니 발판·시셀라 윌슨·카티야 드론에서 각각 다르게 틀린다 (소환물 목록: `전투판정_상태이상_역기획서.md` §5.1).

### 3.1 ⭐ 수풀(bush)은 존재하는가 — 확인 결과

**존재는 확인됐다. 시야를 차단하는지는 확인되지 않았다.**

원본에서 수풀이 등장하는 곳은 **단 한 줄**이다 — `이터널리턴_역기획서.md` §7.5 (`:1004`):

> | **부쉬(수풀)** | 감시 카메라 설치 시 반투명 표시, 커서 강조 효과로 설치 판별 지원(12.0) [S3] |

| | 내용 |
|---|---|
| **읽어낼 수 있는 것 [관측]** | ① 맵에 "부쉬"라는 오브젝트가 존재한다 ② 그 안에 **감시 카메라를 설치할 수 있다** ③ 12.0에서 설치된 카메라가 수풀 안에서 잘 안 보여 **반투명 표시로 판별을 도왔다** |
| **읽어낼 수 없는 것 (미확인)** | ① 수풀에 들어간 실험체가 **은폐되는가** ② 밖에서 안이 안 보이는가 ③ 안에서 밖은 보이는가 ④ 공격 시 노출되는가 ⑤ 수풀 안끼리는 서로 보이는가 |

> **③이 결정적 간접 근거다.** "수풀 안의 설치물이 잘 안 보인다"는 문제가 실재했다는 건 **수풀이 최소한 시각적 은폐 효과를 갖는다**는 뜻이다.
> 하지만 그것이 *렌더링 은폐*인지 *게임플레이 가시성 차단(LoL식 부쉬)* 인지는 이 한 줄로 판별할 수 없다. **추측으로 LoL식 부쉬를 구현하면 안 된다** — 교전 구도가 통째로 달라진다.

**[설계] 임시 결정:** 초기 버전은 **수풀을 차폐물로 구현하지 않는다.** `AERVisionBlockerVolume` 볼륨 타입만 만들어 두고 수풀 액터에 붙일지는 **인게임 확인 후 결정**한다.
볼륨 자체는 연막·건물에 어차피 필요하므로 버려지는 코드가 아니다.

### 3.2 차폐 판정 방식

| 방식 | 비용 | 정확도 | 판단 |
|---|---|---|---|
| **차폐 없음** (반경 원판만) | 0 | 낮음 | 프로토타입 1단계. **여기서 시작한다** |
| **라인 트레이스** (관측자 → 대상, 전용 콜리전 채널) | 쌍당 트레이스 1회 | 중 | **채택 후보.** 벽 하나 뒤에 숨는 것만 처리하면 MOBA 체감은 대체로 만족된다 |
| **2D 가시성 폴리곤 / 시야 메시** | 높음 | 높음 | 24명 규모에 과설계. 컷 |
| **NavMesh 레이캐스트 재사용** | 낮음 | 중 (높이 무시) | 섬 전체가 단일 NavMesh다(`맵_지역_이동_역기획서.md` §1) — **탑다운이라 높이 정보가 덜 중요**하므로 검토 가치 있음 |

**전용 콜리전 채널(`ECC_GameTraceChannel_Vision`)을 반드시 판다.** `ECC_Visibility`를 재사용하면 커서 픽킹·스킬 조준·시야 판정이 채널을 공유하게 되어,
"연막은 조준은 막지 않지만 시야는 막는다" 같은 요구가 오면 전부 뜯어야 한다. `Config/DefaultEngine.ini` 변경이므로 **에디터 작업 문서로 넘긴다**(`CLAUDE.md` §4, §9).

### 4.1 ⭐ 연출과 가시성의 분리 — 이미 내려진 결정을 구체화한다

`매치진행_게임모드_역기획서.md`:165 의 결정을 이 문서가 이어받는다. **두 층으로 나눈다.**

| 층 | 무엇 | 실행 위치 | 치팅 가능성 |
|---|---|---|---|
| **A. 게임플레이 가시성** | 시야 반경 배율(밤에 축소) → `IsVisibleToTeam()` → **릴리번시** | **서버 전용** | **없음.** 데이터가 클라에 없다 |
| **B. 연출** | 포스트프로세스 어둡게, 라이트 강도, 안개 | 클라 로컬 | **있지만 무해**하다 |

**핵심은 "B를 조작해도 A가 안 바뀐다"는 구조 자체다.** 클라가 감마를 올리거나 포스트프로세스 볼륨을 우회하거나 `r.` 콘솔 변수를 만져도,
**애초에 보내지 않은 적의 좌표는 밝기를 올린다고 나타나지 않는다.** 이게 "클라 밝기 조절 치팅을 어떻게 막는가"의 유일하고 완전한 답이다 — 밝기 조작을 *탐지*할 필요가 없다.

**[설계] 실패 모드 하나만 경고한다.** "밤에는 시야 반경을 줄이되, 이미 보내진 액터는 클라에서 어둡게 처리" 같은 절충안을 만들면
**낮에 잡힌 채널이 밤에도 유지**되어 그대로 뚫린다(§6.4의 `RelevantTimeout` 문제와 결합). **밤 진입 = 시야 반경 재계산 = 릴리번시 즉시 재평가**가 한 트랜잭션이어야 한다.

### 6.2 두 구현 경로

| | **A. `IsNetRelevantFor` 오버라이드** | **B. 커스텀 ReplicationGraph 노드** |
|---|---|---|
| 방식 | `AERCharacterBase::IsNetRelevantFor()`에서 `RealViewer`→팀 ID→캐시된 가시성 조회 | 팀별 `AlwaysRelevant_ForTeam` 노드 + 그리드 노드 조합 |
| 구현 난이도 | **낮음** | 높음 (플러그인 활성화 + 노드 설계) |
| 24명 규모 적합성 | **충분** | 오버스펙 |
| 비용 구조 | 커넥션 × 액터 루프 (`Private/NetDriver.cpp:5039` `IsActorRelevantToConnection`) | 노드가 리스트를 유지 → 재계산 최소 |
| 두 방식 병용 | ❌ **불가** (`ReplicationGraph.h:20`) | ❌ |
| 판단 | ⭐ **A로 시작한다** | 100인 규모로 갈 때만 |

> **[설계] A를 고른다.** 근거는 규모다. ReplicationGraph는 *"number of actors × number of connections"* 확장성을 위한 것인데
> (`ReplicationGraph.h:16`), 이 프로젝트는 커넥션이 **최대 24개**다. 지금 그래프를 짜면 검증할 수 없는 복잡도만 늘어난다(`CLAUDE.md` §2).
> **단, A의 판정 로직을 `IsNetRelevantFor` 안에 인라인으로 쓰지 않는다.** 별도 `UTeamVisionSubsystem::IsVisibleToTeam()`으로 빼 두면
> 나중에 B로 옮길 때 **판정은 그대로 두고 배선만 바꾸면 된다.**

### 6.3 24명 규모의 실제 비용

**판정 쌍의 수**

| 접근 | 쌍 수 | 비고 |
|---|---|---|
| 개인 × 개인 | 24 × 24 = **576** | 순진한 계산 |
| **팀 × 액터** | 8 × 24 = **192** | 팀으로 접은 결과. **1/3** |
| 팀 × (액터 + 소환물·설치물) | 8 × (24 + α) ≈ **250~350** | α = 소환물·카메라·CCTV 추정 (미확인) |

**단계별 비용** — 브로드페이즈에서 대부분 잘린다:

1. **거리 제곱 비교** (`FVector::DistSquared`) — 350쌍 × 부동소수 뺄셈 3회. **측정할 가치도 없는 비용**이다.
2. **은신·팀 사전 검사** — 분기 몇 개. 무시.
3. **차폐 라인 트레이스** — ⭐ **여기만 비싸다.** 1단계를 통과한 쌍에만 수행.
   24명이 21개 지역에 흩어지는 게임 특성상 **동시에 시야 반경 안에 있는 쌍은 실전에서 한 자릿수~수십 개**로 추정된다(**미측정**).

**갱신 주기별 초당 트레이스 수 (통과 쌍을 보수적으로 30이라 가정)**

| 주기 | 초당 트레이스 | 판단 |
|---|---|---|
| 매 프레임 (서버 60fps) | 1,800 | 낭비 |
| 서버 넷 틱 (30Hz 가정) | 900 | 과함 |
| ⭐ **10Hz** | **300** | **채택 후보** |
| 5Hz | 150 | 반응 지연 200ms — 교전에서 체감될 위험 |

> ⚠ **위 "30쌍"은 측정값이 아니라 가정이다.** 실제 값은 PIE에서 `stat` 카운터를 붙여 계측해야 한다.
> `CLAUDE.md` §1.2가 요구하는 "측정 방법까지 적기"에 따라, **계측 전에는 이 수치를 근거로 쓰지 않는다.**

### 6.4 ⚠ 반드시 알아야 할 함정 — `RelevantTimeout` 5초

**릴리번시를 `false`로 만들어도 액터 채널은 즉시 닫히지 않는다.**

| 사실 | 위치 |
|---|---|
| `RelevantTimeout` 설정 프로퍼티 | `Source/Runtime/Engine/Classes/Engine/NetDriver.h:889` |
| **기본값 = 5.0초** | `C:/UnrealEngine-5.4.4/Engine/Config/BaseEngine.ini:1637` (`RelevantTimeout=5.0`) |
| 히스테리시스 로직 | `Private/NetDriver.cpp:5346` — `bIsRecentlyRelevant = bIsRelevant \|\| (Channel && ElapsedTime - Channel->RelevantTime < RelevantTimeout) \|\| ...` |
| 소유 기반 조기 종료 | `Private/NetDriver.cpp:5183~5185` — `RelevantTimeout` 경과 후에야 `Channel->Close(EChannelCloseReason::Relevancy)` |
| 최종 채널 종료 | `Private/NetDriver.cpp:5450~5461` |

**즉, 기본 설정으로는 시야에서 벗어난 적의 위치가 최대 5초 더 복제된다.**
이건 포그 오브 워로서 **완전한 실패**다 — 교전 후 도주하는 적을 5초간 추적할 수 있는 맵핵이 그대로 남는다.

**[설계] 대응:**
- `Config/DefaultEngine.ini`에서 `RelevantTimeout`을 낮춘다 (⚠ **전역 설정 변경 — 사용자 승인 대상**, `CLAUDE.md` §9).
- 또는 시야 이탈 시 **명시적으로 채널을 닫는다.** 값은 [설계] 미정 — 0으로 두면 시야 경계에서 채널이 깜빡이며 재생성 비용이 폭증한다.
- **1차 검증은 로그다:** `LogNetTraffic` 의 `"- Closing channel for no longer relevant actor"` (`NetDriver.cpp:5459`) 가
  시야 이탈 후 **몇 초 뒤에** 찍히는지 확인한다. 이게 `매치진행_게임모드_역기획서.md`:446 이 요구한 "net relevancy 로그" 검증의 구체적 형태다.

### 6.5 위치를 끊었을 때 생기는 부작용

| 부작용 | 원인 | [설계] 대응 |
|---|---|---|
| ⭐ **시야 재진입 시 액터가 "튀어나온다"** | `NetDriver.cpp:5453~5454` 주석 — *"Non startup (map) actors have their channels **closed immediately, which destroys them**"*. 재진입 시 **새로 스폰**된다 | 스폰 지점 보간 금지. **등장은 즉시 + 짧은 페이드 인**으로 연출. 위치 보간을 걸면 "허공에서 미끄러져 오는" 더 나쁜 그림이 된다 |
| **진행 중이던 스킬 연출이 통째로 없다** | 연출은 `NetMulticast`인데, ⭐ **멀티캐스트 RPC 자체가 릴리번시로 필터링된다** — `NetDriver.cpp:7531` 이 `IsNetRelevantFor`를 검사한 뒤에만 전송 | 채널링·지속 연출은 **RPC 이벤트가 아니라 복제 상태**로 표현한다. `UStatusEffectComponent`의 `ReplicatedUsing=OnRep_` 배열(`전투판정_상태이상_역기획서.md` 데이터 스키마)이 이미 이 형태다 — **재진입 시 `OnRep_`가 현재 상태로 다시 불린다** |
| **사운드가 안 들린다 / 갑자기 들린다** | 위와 동일 경로 | **사운드는 시야와 다른 축이다.** 발소리처럼 "안 보여도 들려야 하는" 것은 릴리번시로 끊으면 안 된다 → **위치 없는 이벤트**(대략적 방향/거리만 담은 `Client` RPC)로 별도 처리. ⚠ 정밀 좌표를 실으면 소리로 맵핵이 된다 |
| **HP 바·상태이상 UI가 리셋** | 액터 파괴 | 위와 동일 — `OnRep_`이 복원한다 |
| **적 처치·킬로그** | 죽는 순간 relevant가 아닐 수 있음 | 킬로그는 액터가 아니라 **`AERGameState`의 복제 이벤트**로 처리 |
| **네비/AI 야생동물** | 같은 문제 | 야생동물도 같은 파이프라인을 탄다. `bAlwaysRelevant`로 도망가지 말 것 |

> **[설계] 위 표에서 가장 중요한 것은 두 번째 줄이다.** "연출은 `NetMulticast`"라는 기존 규약
> (`Characters/00_공통_구현규약.md`:155~165)은 **포그 오브 워와 정면으로 충돌한다.**
> 시야가 들어오면 그 규약에 **"단, 지속형 연출은 복제 상태 + `OnRep_`"** 이라는 예외가 추가돼야 한다.

## 7. 갱신 주기 — `Tick`을 켜야 하는가

`CLAUDE.md` §2는 *"`Tick`은 정말 매 프레임 필요할 때만 켠다"* 고 요구한다. 시야는 그 예외인가?

| 후보 | 판단 | 근거 |
|---|---|---|
| 액터별 `Tick` | ❌ | 24개 액터가 각자 돌면 판정이 프레임 내 서로 다른 시점에 흩어져 **같은 프레임에 A는 보이고 B는 안 보이는** 불일치가 생긴다 |
| ⭐ **`UWorldSubsystem` + `FTimerManager` 고정 주기 (10Hz)** | ✅ **채택** | 판정이 **한 곳에서 한 번에** 끝난다. 8팀 결과가 같은 스냅샷에서 나온다 |
| 이벤트 기반(이동 시에만) | ❌ 단독으로는 불가 | MOBA에서 실험체는 거의 항상 이동 중이다. 이벤트가 곧 매 프레임이 된다 |
| 하이브리드 (10Hz + 즉시 이벤트) | ✅ **부분 채택** | 은신 시작/해제, 카티야 W 드러내기, 밤 전환, CCTV 활성화는 **`ForceNetUpdate()`(`Actor.h:3507`)로 즉시 반영** |

> **결론: `Tick`을 켜지 않는다.** 시야는 "매 프레임"이 필요한 게 아니라 **"일정하고 짧은 간격"** 이 필요하다.
> 그리고 릴리번시 자체가 이미 서버 넷 틱 주기로만 평가되므로(`NetDriver.cpp:5039` 의 `ServerReplicateActors` 경로),
> **판정을 렌더 프레임보다 자주 돌려도 소비되지 않는다.**
> 참고: `UI_HUD_역기획서.md`:76 은 *"매 프레임이 정당한 요소는 미니맵 아이콘 위치 하나뿐"* 이라고 이미 판정했다 — 그건 클라 보간이고, 서버 판정과 다른 축이다.

**[설계] 10Hz는 자체 결정값이다.** 원작의 갱신 주기는 **(미확인)**이다.
반응 지연 100ms가 교전에서 체감되면 20Hz로 올리되, **올리기 전에 §6.3의 트레이스 수를 실측**한다.

## 8. CCTV — 시야 시스템 위에 얹는 작은 기능

`맵_지역_이동_역기획서.md`:280 이 이미 결정했다 — *"시야 시스템을 먼저 만들고 CCTV는 나중에 추가하는 순서가 맞다."*
**이 문서는 그 결정을 뒤집지 않는다.** CCTV의 규칙·수치는 맵 문서 §8이 주인이고 여기서 중복하지 않는다.

시야 시스템 관점에서 CCTV가 요구하는 것은 **네 줄**뿐이다:

| 요구 | 구현 |
|---|---|
| 지역 범위 시야 제공 | `UVisionSourceComponent`를 붙인 맵 고정 액터. **실험체와 같은 컴포넌트** |
| 팀 단위 귀속 | 활성화한 팀의 `TeamId`를 컴포넌트에 세팅 (금지구역 복원 구매 팀도 동일 경로 — `이터널리턴_역기획서.md` §3.2.2) |
| ⭐ **금지구역 진입 시 즉시 비활성화** | 12.2에서 고친 실제 버그다(`이터널리턴_역기획서.md` §4.7 `:451`). 지역 상태 변경 델리게이트 → 컴포넌트 `Deactivate()` |
| 적 CCTV 감지 범위는 **항상 표시** | 시야 판정이 아니라 **정적 맵 데이터**다. 미니맵 오버레이가 읽는다 (`맵_지역_이동_역기획서.md` §8) |

> **CCTV가 시야 시스템의 좋은 회귀 테스트가 된다.** "움직이지 않고, 팀이 바뀔 수 있고, 조건에 따라 꺼지는 시야 소스"이므로
> 시야 소스를 캐릭터에서 제대로 분리했는지가 여기서 즉시 드러난다.

## 9. 미니맵과의 관계

**시야가 데이터의 주인이고, 미니맵은 소비자다.** 위젯 구현은 [`UI_HUD_역기획서.md`](UI_HUD_역기획서.md) §4가 담당한다.

| 미니맵 표시물 | 시야가 결정하는가 | 비고 |
|---|---|---|
| 자기 · 팀원 아이콘 | ❌ 항상 표시 | `UI_HUD_역기획서.md`:87 |
| **적 실험체 아이콘** | ⭐ **O — 릴리번시로 자동 해결** | 액터가 클라에 없으면 미니맵이 그릴 대상 자체가 없다 |
| 야생동물 | O | 같은 파이프라인 |
| 상자 · 채집물 | ❌ 정적 맵 데이터 | `UI_HUD_역기획서.md`:248 |
| 지역 경계 · 금지구역 | ❌ 정적 / `GameState` | |
| 적 CCTV 감지 범위 | ❌ 정적 (항상 표시) | §8 |
| 핑 / 신호 | ❌ 팀 한정 `NetMulticast` | `UI_HUD_역기획서.md`:92 |

> **⭐ 가장 중요한 구조적 이점:** 시야를 릴리번시로 구현하면 **미니맵이 시야를 신경 쓸 필요가 없어진다.**
> 미니맵은 "내 클라에 존재하는 적 액터를 전부 그린다"로 끝나고, 그게 자동으로 정답이다.
> 반대로 클라 필터링으로 만들면 미니맵·월드 렌더·실루엣·조준 보조가 **각자 시야 조건을 다시 구현**하게 되고,
> 그중 하나는 반드시 빠뜨려서 그 경로로 정보가 샌다.

## 10. GAS와의 접점 (1항목)

이 프로젝트는 **GAS 기반이다** (`CLAUDE.md` §8). 시야 시스템이 GAS와 만나는 지점은 **한 곳뿐이다.**

**은신·드러내기·시야 차단은 "상태"이므로 `GameplayTag` 로 표현한다.**
시야 판정 함수는 그 태그를 **조회만** 하고, 자기 상태를 따로 들지 않는다.

| 이 문서의 개념 | GAS 구현 |
|---|---|
| 은신 상태 조회 | `ASC->HasMatchingGameplayTag(State.Stealth)` |
| 드러내기 | `State.Vision.Revealed` 태그 |
| 시야 차단 (연막 등) | `State.CC.VisionBlock` 태그 — CC 문서와 같은 자리 |
| 시야 반경 스탯 | `UERAttributeSet` 의 `Sight` 어트리뷰트 |
| 은신 부여·해제 | `UGameplayEffect` (지속시간·해제 조건 포함) |
| `UTeamVisionSubsystem` (팀별 가시성 계산 + 릴리번시 배선) | ⭐ **GAS와 무관 — 직접 만든다** |

> ⭐ **가시성 계산 자체는 GAS와 아무 상관이 없다.** GAS는 팀 시야를 제공하지 않는다.
> GAS가 관여하는 것은 "은신 중인가?"를 묻는 **한 줄의 조회 방식**뿐이다.
> 이 한 줄을 함수로 격리해 두면 시야 시스템 전체가 GAS를 몰라도 된다.
>
> ⚠ **은신 판정을 태그 조회로만 끝내지 않는다.** 태그는 "은신 상태다"를 말할 뿐이고,
> **적 클라에 위치를 복제하지 않는 것**은 릴리번시 배선(§3)의 몫이다. **클라에서 숨기기만 하면 핵에 뚫린다.**

## 구현 우선순위

**잘라낼 수 없는 것 (1~4순위)** — 이게 없으면 게임이 성립하지 않거나, 맵핵이 남는다.

```
1순위. 팀 ID 인프라 (AERPlayerState::TeamId + GetTeamId(const AActor*) 공용 함수)
       → 검증: 빌드 통과 + Play As Client(4인, 2팀)에서 각 클라가 자기 팀 ID를 올바로 읽는다
       ⚠ 현재 프로젝트에 팀 개념이 전혀 없다. 시야보다 먼저다.

2순위. UVisionSourceComponent + UTeamVisionSubsystem (반경만, 차폐 없음, 10Hz)
       → 검증: 서버 로그에서 팀별 가시 액터 집합이 거리에 따라 바뀐다

3순위. ⭐ IsNetRelevantFor 배선 + RelevantTimeout 조정
       → 검증: Play As Client(4인, 2팀). 적이 시야를 벗어난 뒤
         LogNetTraffic 의 "- Closing channel for no longer relevant actor" (NetDriver.cpp:5459) 가
         목표 시간 내에 찍히고, 그 이후 위치 갱신이 0이다
       ⚠ 여기까지가 "맵핵이 아닌 상태"의 최소선이다. 3순위 없이 4순위 이후를 하지 않는다.

4순위. 은신 연동 (다니엘 E · 단검 D) + 팀 내부 항상 가시
       → 검증: 은신 중 적 클라에 위치가 복제되지 않고, 팀원 클라에는 정상 표시된다
         (Characters/00_공통_구현규약.md:206 과 동일한 검증 항목)
```

**나중에 얹을 것 (5순위~)** — 시야 시스템이 서 있으면 각각 며칠짜리다.

```
5순위. 차폐 판정 (전용 콜리전 채널 + 라인 트레이스) + AERVisionBlockerVolume
       → 검증: 벽 뒤 적이 사라지고, 벽을 나오면 즉시 나타난다

6순위. 밤 시야 배율 (NightRadiusScale) — 연출과 완전 분리
       → 검증: 밤 진입 시 릴리번시가 즉시 재평가되고, 클라 감마를 올려도 적이 나타나지 않는다
       (매치진행_게임모드_역기획서.md:445 의 7순위와 같은 작업)

7순위. 드러내기 (카티야 W) + 시야 감소 CC (다니엘 W · 시셀라 투척 D)
       → 검증: 3초간 은신 대상이 적 팀에 복제되고 만료 시 즉시 끊긴다

8순위. 소환물·설치 카메라·드론의 시야 소스화
       → 검증: 소환물 파괴 시 그 팀의 가시 집합이 즉시 축소된다

9순위. CCTV (§8) — 금지구역 연동 포함
       → 검증: 활성화한 팀만 시야를 얻고, 해당 지역 금지구역 전환 시 즉시 꺼진다 (12.2 버그 재발 방지)

10순위. 수풀 차폐 — 인게임 확인 후 결정 (§3.1). 확인 전에는 착수하지 않는다
```

> 멀티플레이 검증은 전부 **`Play As Client, Number of Players: 4` (2팀 × 2인) 이상**에서 확인한다.
> 각 단계의 1차 검증은 **빌드 통과**다 (`CLAUDE.md` §4).
